# 海运出口订单闭环验收

## 目标与当前状态

以当前已开放的海运出口 `SE` 为样板业务，验证订单、单证、费用审核、账单、收付核销与
提成能组成完整业务闭环。海运进口、空运、陆运和铁路目前未注册录单入口，不纳入本清单。

2026-10-19 本次更新仅核对代码、契约与既有记录，未执行脚本、浏览器或真实数据库验收。
下列清单是待验证标准，不代表已全部通过。已有单项测试或历史任务结果不能代替当前版本
的全链路验收；真实钉钉登录与通知收件需要分别记录人工结果。

## 验收准备

- 使用专用验收环境及脱敏业务样例；数据库按正式 SQL 迁移初始化，不清空或重置日常业务库。
- 准备同一公司的操作、费用审核、财务及普通员工账号，按动作授予所需权限；另准备另一公司账号验证隔离。
- 确认公司、成员、角色、客户及供应商启用，编号规则、费用目录、币种、所需周汇率和提成方案可用。
- 登录后明确选择公司工作台。系统管理工作台不能替代公司办理订单与财务业务。
- 为样例使用可辨认的验收标识，记录创建的订单和财务单据；数据保留或清理方式单独明确。

## 既有自动化脚本与限制

现有入口为 `pnpm run acceptance:se-order`，源码为
[`scripts/acceptance-se-order.mjs`](../../scripts/acceptance-se-order.mjs)。静态核对发现：

- 不带 `--apply` 时，脚本仍会登录并建立会话，然后查询组织、客户和编号规则，不创建订单；并未查询或验证已发布状态模板。
- 带 `--apply` 时，脚本计划创建两张关联同一主单的订单及货物，检查自拼汇总与订舱流转，之后将首张订单退关并完结。它会保留这些写入，不适合作为一张可继续编辑的订舱样例。
- 脚本仍提交并断言 `loadingTerms`；该字段已在当前 `server/api/order/v1/order.proto` 中退役并保留名称。
- 脚本直接使用登录建立的工作台，没有显式选择或切换公司；多工作台管理员不能据此保证落在目标公司。

因此，当前脚本不能作为本清单的有效自动化验收门禁。后续需同步当前契约、显式选择公司、
明确样例最终状态，并在隔离环境运行验证后，再更新自动化覆盖说明。本次不修改脚本，
不增加历史兼容或自动回退。此前文档中“前置检查通过后直接追加 `--apply`”的流程不再适用。

仓库还有财务批量建账、应付及外币验收入口，见根 `package.json` 的 `acceptance:*`。
其覆盖范围与当前可运行性需各自核对，不将脚本存在视为本轮业务验收通过。

## 人工验收清单

### 订单与单证

- [ ] 在目标公司创建海运出口订单，订单编号、客户、人员分工、港口、货物及单证信息正确，刷新后数据一致。
- [ ] 按实际业务选择单证结构，检查主单、运输执行与分单关联；不强制每张订单都有分单。
- [ ] 从 `DRAFT` 流转至 `BOOKED`，当前节点与审计记录一致。
- [ ] `BOOKED` 及后续合法主流程中，`ACTIVE + OPEN + 未锁定` 且有编辑权限的订单仍可编辑；不因离开草稿状态自动只读。
- [ ] 退关、完结或业务锁定后，内容写入按当前门禁拒绝，界面给出明确原因；解锁与费用审核分别校验。
- [ ] 两人读取同一版本后先后保存，后一次旧版本写入返回 409，提示刷新重试且不覆盖已提交内容。
- [ ] 按样例需要验证拆票、改配或共享箱，件重尺守恒、关联及历史记录正确；未验证的分支单独列出。

### 费用至财务结算

- [ ] 完整录入应收和应付，原币、汇率、折算与利润口径正确；表单输入与展示格式分开。
- [ ] 提交整票费用审核，由具备目标公司审核权限的人员处理；批准后冻结费用内容，建账再次校验有效审核。
- [ ] 同方向、结算单位与币种的合格费用正确分组建账；已占用费用不能重复建账。
- [ ] 完成账单后续处理、收付款与核销，已核销及未核销余额与原始费用一致，刷新后结果保持一致。
- [ ] 多币种或对冲样例分别验证原币与本位币口径，不将不同币种金额直接相加。
- [ ] 审核后补录成本或费用更正走对应受控流程，检查审批快照、账单及提成影响；待审记录按规则阻止相关后续办理。
- [ ] 在允许的状态下验证账单取消或反核销，关联与余额正确释放或恢复，重复操作不产生额外金额。
- [ ] 发票如进入试用范围，单独验证登记、关联、作废或红冲；系统记录不代表外部税控系统已执行。

### 提成、完结与权限

- [ ] 订单提成归属与有效方案正确，计提金额和来源核销或对冲记录能够对应。
- [ ] 普通员工按自然月查看候选、申请与查询审批结果，仅能访问本人允许查看的资料。
- [ ] 财务完成整单审批及净额发放；已确认调整参与抵扣，已付后续调整按独立流程处理。状态登记不代表银行已实际转账。
- [ ] 订单满足当前完结条件后可完结；不满足时说明原因，不能只凭主流程节点跳过费用或结算门禁。
- [ ] 普通用户看不到无权动作，直接调用接口同样被拒绝；公司 A 不能读写公司 B 的经营数据。
- [ ] 切换公司后页签、草稿、候选及请求结果正确隔离；系统管理工作台不获得公司经营办理旁路。
- [ ] 审计能定位关键创建、编辑、状态和财务动作，错误提示不暴露数据库内部信息或敏感数据。

## 独立验收边界

- 订单附件入口当前登记外部对象存储引用与元数据，不直接上传或下载二进制文件；真实附件闭环需后续实现并验收。
- 拆票、改配、共享箱及单证修订按实际试用场景验收；单票常规流程通过不代表所有复杂分支通过。
- 报关外部申报、外部物流跟踪、真实钉钉扫码和通知收件分别验收，本清单不代替外部系统结果。
- 生产同域部署、备份恢复与上线操作演练单独记录，不由开发环境的业务操作结果推定通过。
