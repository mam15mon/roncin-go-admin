# 海运出口订单闭环验收

## 目标

以海运出口 `SE` 为首条样板业务，验证现有主数据、编号规则、订单、提单、货物明细、
状态模板与查询能力能够组成可重复的最小闭环。本验收不代表财务、附件、报关、提醒或
外部集成已经完成。

## 自动化验收范围

在仓库根目录执行只读前置检查：

```bash
pnpm run acceptance:se-order
```

检查通过后，显式创建一张带 `ACC-SE-` 标识的本地验收订单：

```bash
pnpm run acceptance:se-order -- --apply
```

脚本使用 `.env.local` 中的冷启动管理员凭据登录，只输出组织、测试客户、状态模板、
编号规则和验收订单摘要，不输出密码或 Cookie。`--apply` 会在当前本地开发数据库中
保留验收订单，便于从管理后台继续人工检查。

自动化场景覆盖：

1. 管理员登录和当前组织识别。
2. 启用客户、默认已发布 `SE` 状态模板和启用订单编号规则的前置检查。
3. 创建 `SE` 草稿订单，并验证号码由订单规则和 `SE` 业务代码组成。
4. 同时创建一组主单、分单并重新读取验证。
5. 更新草稿备注，确认提单不会在更新时丢失。
6. 新增并查询货物明细。
7. 将订单从 `DRAFT` 流转到 `BOOKED`。
8. 重新读取详情并通过订单编号检索列表。

## 人工验收清单

自动化通过后，在前端使用脚本输出的订单编号继续检查：

- 订单列表能检索并打开验收订单。
- 详情页正确显示客户、业务类型、订单号、主单号、分单号、货物和当前状态。
- `BOOKED` 状态下不再提供草稿编辑入口，或后端明确拒绝草稿编辑。
- 当前用户能看到权限允许的操作，普通用户看不到越权操作。
- 页面刷新后订单、提单和货物信息保持一致。
- 审计日志能够定位订单创建、草稿更新和状态流转操作。
- 错误提示使用业务语言，不暴露数据库或内部堆栈信息。

## 暂不纳入

- 分单号自动生成；当前仍由操作人员录入。
- 实箱、封条与提单关联；订舱阶段箱型箱量和实际集装箱属于不同阶段。
- 附件真实上传、下载和对象存储。
- 报关、跟踪事件、提醒和消息投递。
- 应收应付费用、账单、汇率快照、收付款与核销。
- 海运进口、空运、陆运和铁路线路验收。
