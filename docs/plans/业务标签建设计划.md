# 业务标签建设计划

## 1. 文档目的

本文用于指导 `roncin-go-admin` 通用业务标签功能的设计、实施与验收：继续使用配置
管理中的组织级标签字典，并将同一份标签分别关联到企业、订单、订单费用和财务账单，
提供标签展示、筛选、批量添加和批量移除能力。

本文以 2026-08-29 的仓库代码为基线，并引用同日对易云竞品的实测查证结论。本文
是实施计划，不代表功能已经完成。

## 2. 需求范围与业务语义

本期标签可关联四类业务对象：

| 业务对象 | 当前数据模型 | 本期能力 |
| --- | --- | --- |
| 企业 | `Partner`，已通过 `EnterpriseResourcePartner` 关联标签资源 | 保留现有企业关联、独立存在与配置管理能力 |
| 订单 | `Order` | 展示、筛选、批量添加、批量移除 |
| 费用 | `OrderFee`，同时出现在订单费用页和财务费用台账 | 展示、筛选、批量添加、批量移除 |
| 账单 | `FinanceBill` | 展示、筛选、批量添加、批量移除 |

标签关联相互独立，不做隐式继承或自动复制：

- 给订单添加标签，不自动给该订单下的费用添加标签。
- 给费用添加标签，费用进入账单时不自动把标签复制到账单。
- 给账单添加或移除标签，不反向修改账单内的费用或所属订单。
- 给企业添加标签，不自动传播到该企业关联的订单、费用或账单。

该规则避免对象状态变化时产生无法解释的连锁修改。后续如果需要“从订单复制标签到
费用”或“从费用汇总标签到账单”，必须设计为用户显式触发的独立功能，不在本期增加
自动回退或隐式同步。

## 3. 竞品查证结论

2026-08-29 在易云生产界面实测确认：

- 海运出口订单列表的“批量操作”包含“添加标签、删除标签”。
- 费用明细（`/cost/detail`）的“批量操作”包含“添加标签、删除标签”，与标记对账、
  费用锁定、归档等批量操作并列。
- 账单管理（`/cost/bill`）的“批量操作”包含“添加标签、删除标签”，与核销、录入
  发票号、归档等批量操作并列。
- 订单的添加标签弹窗已确认按标签组展示配置管理维护的字典标签，并提供快捷新增标签
  入口；费用和账单弹窗是否具有完全相同的分组展示与快捷新增能力，尚未逐项验证。
- 订单和账单的默认表头、默认搜索区未见标签展示或标签筛选；自定义列和扩展筛选能力
  尚未验证。

因此，订单、费用和账单三类对象的批量添加、删除标签能力属于竞品已验证的功能基线。
本项目的强类型关联模型、标签筛选、分域权限、删除约束、两个费用入口共用关联数据，
以及标签不自动继承或传播等规则，仍是结合本项目业务边界作出的设计决策，不作为竞品
已验证能力。

## 4. 当前实现基线

1. **标签字典已经存在**：`EnterpriseResource` 的 `TAG` 类型保存标签公共字段，
   `EnterpriseTag` 保存标签组关系，`EnterpriseTagGroup` 保存组名和颜色。标签具备
   组织隔离、启停、排序、拼音检索、组内重名校验和事务审计。
2. **企业关联已经存在**：标签与其他企业资源一样，可以通过
   `EnterpriseResourcePartner` 关联一个或多个 `Partner`，也可以不关联企业而独立
   存在。
3. **订单已有另一套自由文本标签全链路**：`orders.tags` 为 `[]string` JSON 字段并
   建 GIN 索引；Proto 暴露自由文本写入、返回和筛选，Service 层已有省略保留与显式
   清空语义，但前端没有标签界面。这套字段与组织级字典构成双重真相。
4. **费用实体是 `OrderFee`**：订单费用页和财务费用台账读取的是同一批费用记录；
   费用没有直接 `organization_id`，组织归属通过 `Order` 确定。
5. **账单实体是 `FinanceBill`**：账单直接保存 `organization_id`，通过
   `FinanceBillLine` 关联进入账单的 `OrderFee`，但账单不是费用标签的副本。
6. **权限分属不同领域**：订单和订单费用使用动态权限
   `business.order.{业务类型}.{操作}`；财务费用台账使用 `system.finance.fee.*`；
   账单使用 `system.finance.bill.*`；标签配置管理使用
   `business.enterprise_resource.*`。

## 5. 已确认决策

### 5.1 标签字典继续复用现有模型

本期不复制第二套标签字典，也不把标签名称存入各业务表。所有关联都引用组织内现有
的 `EnterpriseResource(TAG)`，公共标签 ID 统一使用标签资源的 `resource_id`。

`EnterpriseTag` 是现有标签资源的详情表，不单独成为另一个对外聚合 ID。这样快捷
新建标签返回的企业资源 ID、配置管理使用的 ID 和各业务关联使用的标签 ID 保持一致。

### 5.2 不使用多态万能关联表

不建立以下结构：

```text
tag_assignments(target_type, target_id, tag_id)
```

这种设计无法让 `target_id` 同时对订单、费用和账单建立真实外键，删除对象时也无法
依靠数据库维护引用完整性。本期使用三张强类型关联表，每张表都有明确外键。

### 5.3 自由文本订单标签直接删除

系统尚未首次投产，现有本地 `orders.tags` 不迁移：

- 删除 `orders.tags` 字段和 `order_tags_gin` 索引。
- 删除 Proto 中的自由文本标签返回、筛选、`OrderTagMatchMode` 和 `OrderTagsInput`。
- 删除 Service、Biz、Data 中对应的自由文本合并与筛选逻辑及测试。
- 不保留新旧字段并行读写，也不增加运行时回退。

首次生产基线直接包含最终的字典关联结构。

### 5.4 停用与删除语义

- 标签停用后，企业、订单、费用和账单上的历史关联继续展示。
- 停用标签不能添加到任何新对象。
- 停用标签仍允许从已有对象上移除。
- 标签仍关联任一企业、订单、费用或账单时禁止删除，不提供级联清除分支。
- “不再使用”的正常路径是停用；真正删除前必须先解除全部关联。

标签删除冲突返回结构化影响数量：

```text
partner_count
order_count
order_fee_count
finance_bill_count
```

前端根据错误 metadata 展示具体影响范围，不解析数据库错误或拼接在 Data 层的错误
字符串。

### 5.5 标签不受业务状态冻结限制

标签是分类元数据，不改变订单状态、费用金额、账单金额和会计结果：

- 已锁定、已关闭或已终止的订单仍可维护标签。
- 已确认、已出账或已取消的费用仍可维护标签。
- 已确认或已取消的账单仍可维护标签。
- 标签变更不增加订单、费用或账单的业务版本号，不触发生命周期事件。

标签操作仍必须通过各对象所属领域的标签写权限，且单独写审计日志。

## 6. 数据模型

```text
EnterpriseResource(TAG)                 组织级标签公共字段与公共标签 ID
└── EnterpriseTag                       标签组详情
    └── EnterpriseTagGroup              标签组名称、颜色与排序

EnterpriseResourcePartner              标签 ↔ 企业（现有）
OrderEnterpriseTag                      标签 ↔ 订单（新增）
OrderFeeEnterpriseTag                   标签 ↔ 费用（新增）
FinanceBillEnterpriseTag                标签 ↔ 账单（新增）
```

三张新增关联表均包含：

```text
id
organization_id
业务对象 ID
tag_resource_id → enterprise_resources.id
created_at
updated_at
```

具体约束：

| 表 | 唯一约束 | 查询索引 |
| --- | --- | --- |
| `order_enterprise_tags` | `(order_id, tag_resource_id)` | `(organization_id, tag_resource_id)`、`order_id` |
| `order_fee_enterprise_tags` | `(order_fee_id, tag_resource_id)` | `(organization_id, tag_resource_id)`、`order_fee_id` |
| `finance_bill_enterprise_tags` | `(finance_bill_id, tag_resource_id)` | `(organization_id, tag_resource_id)`、`finance_bill_id` |

领域校验不能仅依赖 `tag_resource_id` 外键：写入时还必须确认目标资源的
`resource_type=TAG`，且标签与业务对象属于同一组织。

业务对象删除时可以级联删除其标签关联；标签资源删除时应用层必须先执行使用中检
查。批量添加标签与删除标签使用相同的标签资源行锁，并统一按标签 UUID 排序加锁，
防止“删除检查刚通过时并发新增关联”的竞争和不同锁顺序导致的死锁。

## 7. 批量操作语义

- 批量请求必须显式提交对象 ID 和标签 ID，不接受“当前筛选全部”隐式语义。
- 请求中的对象 ID、标签 ID 先去重，再按排序后的稳定顺序加锁和写入。
- 重复添加已经存在的关联视为成功，不报冲突，`affected_count` 不计入该关联。
- 移除原本不存在的关联视为成功，`affected_count` 不计入该关联。
- 数据库唯一约束是并发最终防线，不把唯一约束错误直接暴露给调用方。
- 任一对象越权、跨组织、类型不匹配或任一待添加标签已停用时，整批拒绝，不做部分
  成功。
- 业务关联写入与审计日志在同一个事务中提交，审计失败时全部回滚。

列表筛选统一采用“命中任一标签”的 any 语义。后续如果需要“同时包含全部标签”，
再增加显式匹配方式，不复用或猜测当前参数语义。

## 8. 后端接口与分层

### 8.1 公共返回对象

订单、费用和账单返回相同的标签概要：

```protobuf
message BusinessTagSummary {
  string id = 1;          // EnterpriseResource(TAG) 的 resource_id
  string name = 2;
  string group_id = 3;
  string group_name = 4;
  string group_color = 5;
  bool enabled = 6;
}
```

候选接口支持服务端 `keyword`、`page` 和 `page_size`，`page_size` 最大值为 `200`。
关键字覆盖标签名称、标签组名称、标签名称拼音全拼和拼音首字母；候选行一次返回完整
的标签与组信息，前端不再先查组、再逐组查询标签。

### 8.2 订单标签接口

独立定义 `OrderTagService`：

```http
GET  /api/v1/order-tag-options
POST /api/v1/order-tags/batch-assign
POST /api/v1/order-tags/batch-remove
```

候选和批量请求必须携带 `business_type`。批量写入还必须验证每个订单的实际业务类型
与请求一致，防止使用某一业务类型权限修改另一业务类型订单。

`ListOrders` 增加 `tag_ids` 筛选并返回 `BusinessTagSummary`；`GetOrder` 返回标签明细。

### 8.3 费用标签接口

费用有订单上下文和财务总台账两个入口，共用同一个 Biz Usecase 和同一张关联表，但
使用不同传输端点和权限：

```http
# 订单费用页：请求携带 order_id，由动态订单权限解析业务类型
GET  /api/v1/orders/{order_id}/fee-tag-options
POST /api/v1/orders/{order_id}/fee-tags/batch-assign
POST /api/v1/orders/{order_id}/fee-tags/batch-remove

# 财务费用总台账：按组织权限操作跨业务类型费用
GET  /api/v1/finance/fee-tag-options
POST /api/v1/finance/fee-tags/batch-assign
POST /api/v1/finance/fee-tags/batch-remove
```

订单上下文端点必须验证所有 `fee_ids` 都属于路径中的 `order_id`。财务端点必须验证
所有费用通过所属订单归属于当前组织。

`ListFees` 与 `ListFeeLedger` 返回标签概要并支持 `tag_ids` any 筛选。订单费用页和财
务费用台账展示的是同一组关联，不复制数据。

### 8.4 账单标签接口

账单接口放在现有 `SettlementService`：

```http
GET  /api/v1/finance/bill-tag-options
POST /api/v1/finance/bill-tags/batch-assign
POST /api/v1/finance/bill-tags/batch-remove
```

`ListBills` 增加 `tag_ids` any 筛选并返回标签概要；`GetBill` 返回标签明细。

### 8.5 标签快捷新建与删除防线

快捷新建继续调用企业资源 `CreateEnterpriseResource(TAG)`，成功后刷新当前领域的标
签候选并自动选中新标签。调用方必须同时拥有当前对象的标签写权限和
`business.enterprise_resource.create`；后端两个接口各自独立授权，不因前端显隐放宽
任一权限。

`DeleteEnterpriseResource` 删除 TAG 类型时，在事务内锁定标签资源并统计企业、订
单、费用和账单关联。任一数量大于零时返回冲突错误及四项 metadata；不存在关联时，
标签删除和审计日志在同一事务提交。

### 8.6 Kratos 分层

- Proto 是 HTTP/gRPC 契约唯一真相源，生成代码不手工修改。
- Service 只转换请求与响应并调用 Biz，不写对象归属或标签状态规则。
- Biz 定义标签概要、批量规则、错误和 Repo 接口。
- Data 使用 Ent 完成组织校验、行锁、关联写入、筛选、审计和错误映射。
- 订单、费用、账单分别保留自己的 Service/Usecase 边界，共享的标签查询与关联写入
  只在 Data/Biz 的明确公共接口中复用，不建立跨层万能 Service。

## 9. 权限设计

### 9.1 企业标签

- 查看和筛选企业标签：`business.enterprise_resource.read`。
- 添加或移除企业标签关联：`business.enterprise_resource.update`。
- 新建标签：`business.enterprise_resource.create`。
- 标签字典配置管理继续使用 `business.enterprise_resource.*`。

### 9.2 订单标签

- 查看标签、筛选和读取候选：`business.order.{业务类型}.read`。
- 添加或移除：`business.order.{业务类型}.update`。

### 9.3 费用标签

- 订单费用页查看标签和读取候选：`business.order.{业务类型}.fee.read`。
- 订单费用页添加或移除：`business.order.{业务类型}.fee.update`。
- 财务费用台账查看标签、筛选和读取候选：`system.finance.fee.read`。
- 财务费用台账添加或移除：新增 `system.finance.fee.tag`，并要求
  `system.finance.fee.read` 作为依赖权限。

不能使用 `system.finance.fee.read` 修改业务标签；现有费用台账只有读取权限，标签
写入属于新的业务变更，需要独立授权。

### 9.4 账单标签

- 查看标签、筛选和读取候选：`system.finance.bill.read`。
- 添加或移除：`system.finance.bill.update`。

权限 Manifest、后端访问规则和前端权限生成物必须同阶段交付。新增
`system.finance.fee.tag` 后执行 `pnpm run generate:permission-keys`，不在前端复制第
二套权限字符串。

## 10. 前端交互

### 10.1 公共标签选择弹窗

实现一个业务标签选择组件并由三个领域页面复用：

- 按标签组展示，组标题使用标签组颜色。
- 支持服务端关键字搜索和分页，不一次加载无限量标签。
- 添加模式默认只显示启用标签。
- 移除模式必须显示对象已有的停用标签，确保历史关联可以解除。
- 显示当前选择对象数量和待操作标签数量。
- 没有选择业务对象时不给后端发送请求。
- 同时拥有当前对象写权限和企业资源创建权限时，显示“新增标签”入口。

组件只复用展示和选择逻辑；订单、费用、账单各自调用本领域接口，不在组件内根据
对象类型拼接 URL 或绕过生成客户端。

### 10.2 订单

- 订单列表增加行选择与“批量添加标签、批量移除标签”。
- 增加可由列设置控制的标签列和标签多选筛选。
- 订单详情展示标签。

### 10.3 费用

- 订单费用页复用现有费用表格选择能力，增加标签列、筛选和批量标签操作。
- 财务费用台账增加标签列、筛选和批量标签操作。
- 两个入口操作同一份 `OrderFeeEnterpriseTag` 数据，刷新后结果一致。
- 现有“选择费用创建账单”与“批量标签”必须使用同一组选中行，不建立互相冲突的
  第二套选择状态。

### 10.4 账单

- 财务账单列表增加标签列、筛选和批量添加/移除。
- 账单详情抽屉展示标签。
- 标签操作不受账单是否草稿、已确认或已取消限制，但仍按账单更新权限显隐。

所有新增或修改的 Ant Design 组件在实施前查询对应组件 API，完成后执行：

```text
antd lint <changed-path> --format json
```

## 11. 审计动作

```text
order.tag.batch_assign
order.tag.batch_remove
order.fee.tag.batch_assign
order.fee.tag.batch_remove
finance.fee.tag.batch_assign
finance.fee.tag.batch_remove
finance.bill.tag.batch_assign
finance.bill.tag.batch_remove
```

审计详情至少包含：

- `target.ids`
- `tag.ids`
- `assigned_count` 或 `removed_count`
- 费用操作的入口域（订单费用或财务费用台账）由审计动作本身表达。

审计 `ResourceID` 在单对象操作时记录对象 ID；批量操作时留空，不写零值 UUID 字符
串。审计与关联变更必须在同一个事务中提交。

## 12. 数据库迁移

以 Ent Schema 为结构真相源：

1. 新增三张强类型关联 Ent Schema 及相关边。
2. 从 `Order` Schema 删除自由文本 `tags` 字段与 GIN 索引。
3. 编写版本化 SQL：创建关联表、外键、唯一约束和索引，再删除旧订单标签字段与索
   引。
4. 费用和账单当前没有标签数据，不执行猜测性回填。
5. 从空 PostgreSQL 数据库执行完整迁移链，核对最终结构与 Ent Schema 一致。
6. 首次生产发布前按数据库基线冻结策略将开发期迁移压缩进正式基线；首次生产后只
   允许追加迁移。

日常开发仍必须维护可执行的版本化迁移，不因未来会压缩正式基线而使用 Ent 自动迁

## 14. 针对性测试

后端至少覆盖：

- 跨组织标签或对象整批拒绝。
- 订单批次中混入其他业务类型时拒绝。
- 订单上下文费用接口混入其他订单费用时拒绝。
- 财务费用接口不能操作其他组织费用。
- 重复添加与重复移除返回成功且影响数正确。
- 停用标签不可新增但可以移除。
- 标签删除返回企业、订单、费用和账单使用数量。
- 标签删除与并发新增关联不能造成静默级联。
- 审计失败时关联变更回滚。
- 标签筛选只返回命中任一标签的对象，分页总数正确。
- `page_size=200` 成功，`page_size=201` 失败。

前端至少覆盖：

- 未选择对象不发送批量请求。
- 添加模式不允许选择停用标签。
- 移除模式能展示并移除停用标签。
- 订单、费用和账单按各自权限显示操作入口。
- 没有企业资源创建权限时不显示快捷新增，但仍可使用已有标签。
- 两个费用入口读取并更新同一组标签。
- 列表筛选、分页和刷新后选择状态正确。

## 15. 非目标

- 标签在企业、订单、费用和账单之间自动传播或继承。
- 发票、流水、核销、提成、附件等其他对象的标签关联。
- 根据标签自动改变业务状态、权限、金额或审批流程。
- 标签使用统计报表和自动推荐。
- 从未投产的自由文本 `orders.tags` 猜测性迁移数据。
- 通用多态关联表或运行时对象类型回退。

## 16. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 万能关联表失去外键完整性 | 每种业务对象使用独立强类型关联表 |
| 标签在订单、费用、账单间隐式传播 | 明确互不继承，所有关联只由用户显式操作产生 |
| 自由文本与字典标签形成双重真相 | 未投产阶段删除旧字段、索引、契约和实现 |
| 使用中标签被删除导致业务标识丢失 | 删除前锁定标签并统计四类关联，存在任一关联即拒绝 |
| 财务费用读取权限被用于写标签 | 新增 `system.finance.fee.tag`，读取权限不授权写操作 |
| 订单权限跨业务类型越权 | 请求携带业务类型并逐条核对订单实际类型 |
| 费用两个入口写出不同结果 | 共用一张关联表和一个 Biz Usecase，仅传输授权不同 |
| 批量操作部分成功难以追踪 | 任一无效对象或标签导致整批事务回滚 |
| 停用标签无法从历史对象移除 | 添加候选过滤停用，移除候选保留已关联停用标签 |

## 17. 完成定义

- 同一份组织级标签字典可以独立关联企业、订单、费用和账单。
- 订单、订单费用、财务费用台账和财务账单均可展示、筛选、批量添加和批量移除标
  签。
- 订单费用页与财务费用台账对同一费用展示一致标签。
- 标签不会在企业、订单、费用和账单之间自动继承。
- 自由文本 `orders.tags` 字段、索引、契约和实现全部删除。
- 标签操作满足组织隔离、领域权限、幂等、事务审计和并发锁约束。
- 停用标签保留历史展示、禁止新增并允许移除；使用中的标签禁止删除。
- 迁移链、生成物、后端测试、前端测试、类型检查、Ant Design 专项检查、漏洞扫描和
  生产构建全部通过。
