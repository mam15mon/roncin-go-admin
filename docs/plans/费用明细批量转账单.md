# 费用明细批量转账单实施方案

## 目标

将已确认的订单费用通过服务端拆单预览和单事务批量建单，固化为可审计的财务账单批次。账单、税务发票、资金核销和会计凭证保持独立领域边界，前端通过连续工作台推进，不复制财务真相。

## 领域边界

### 账单

账单负责对账和应收应付结算，保存结算单位、方向、币种、账期、对账单抬头及费用快照。`statement_title` 仅表示对账单抬头，不作为发票抬头。

### 发票

发票类型、发票抬头、纳税人识别号、开户地址电话和银行账号属于税务领域。同一结算单位可以维护多套开票抬头，默认抬头只用于界面预选；创建发票时必须明确提交所选抬头，并在发票上固化不可变快照。不在账单上复制 `invoice_type`。

### 核销

核销继续以已确认账单和已确认资金流水为输入，通过显式分配记录多对多冲销。批量建单不静默执行核销。

### 会计凭证

会计凭证后续使用独立的凭证头、借贷分录和业务来源关联建模，不在账单上增加单值 `voucher_no`。

## 拆单规则

服务端是拆单结果的唯一真相源。以下字段始终作为强制分组键，前端不得关闭：

1. 收付方向 `direction`
2. 结算单位 `settlement_party_id`
3. 原币币种 `currency`
4. 本位币 `base_currency`

用户可增加以下分组维度：

1. 订单 `order_id`
2. 税率 `tax_rate`

费用台账和账单明细必须返回并固化税率快照，禁止用税额除以未税金额反推税率。

## 服务端预览

`PreviewBillBatch` 接收费用编号和可选拆单策略，重新读取当前组织内的费用并校验：

- 数量为 1 至 500 笔且编号不重复；
- 状态为 `CONFIRMED`；
- 尚未存在有效账单明细；
- 税率存在且可解析；
- 结算单位、币种和金额快照完整。

服务端返回确定排序的分组、各组费用和金额合计，以及由组织、费用快照版本和拆单策略共同计算的 `preview_token`。令牌用于发现预览后费用发生变化，不替代创建时的重新校验和行锁。

## 原子批量建单

`CreateBillBatch` 接收费用编号、拆单策略、预览令牌、批次幂等键和每组账单资料。仓储在单个 PostgreSQL 事务中：

1. 按确定顺序锁定全部费用；
2. 重新校验费用状态和有效账单占用；
3. 重新计算分组及预览令牌；
4. 校验客户端为每个分组提交且只提交一份账单资料；
5. 创建账单批次；
6. 为每组分配账单编号并创建账单、账单明细；
7. 将全部费用更新为 `BILLED`；
8. 写入批次审计日志；
9. 任意步骤失败时回滚整批。

批次幂等键在组织内唯一。相同键和相同请求返回原批次；相同键但请求意图不同返回冲突。账单批次保存规范化请求摘要，供重试判断与审计使用。

## 数据模型

### `finance_bill_batches`

- `organization_id`
- `batch_no`
- `idempotency_key`
- `request_hash`
- `split_by_order`
- `split_by_tax_rate`
- `fee_count`
- `bill_count`
- `total_base_amount`
- `base_currency`
- `created_by`
- `created_at`

### `finance_bills` 扩展

- `batch_id`：旧单据允许为空；新批量账单必填
- `statement_title`：对账单抬头快照
- `payment_terms_days`：账期天数快照

### `finance_bill_lines` 扩展

- `tax_rate`：费用进入账单时的税率快照

## 状态与后续流程

批量创建结果均为 `DRAFT`，费用在创建事务内变为 `BILLED`。后续流程保持显式：

1. 批量确认账单；
2. 应收账单发起销项开票，应付账单登记进项来票；
3. 在核销分配矩阵中匹配已确认资金流水和账单余额；
4. 外部开票平台通过任务和 Outbox 最终一致性接入，不占用数据库长事务。

## 前端工作台

账单管理页和订单费用页共用同一个创建工作台：

1. 选择已确认费用；
2. 配置可选拆单策略；
3. 调用服务端预览并展示拆单原因；
4. 为每组填写对账单抬头、账单日、到期日、账期和备注；
5. 原子提交整个批次；
6. 展示批次及全部账单结果，并提供确认、开票/收票、核销入口。

订单费用页的生成账单按钮必须复用 `system.finance.bill.create` 权限，不能因入口位于订单模块而放宽服务端授权。

## 验收条件

- 不同方向、结算单位、币种和本位币必然拆单；
- 按订单、按税率策略产生稳定结果；
- 预览后费用变化导致创建被拒绝并要求重新预览；
- 整批幂等重试返回相同批次和账单；
- 相同幂等键的不同请求返回冲突；
- 并发争抢同一费用时仅一个批次成功；
- 任一费用失效时整批不产生账单；
- 账单生成后全部费用为 `BILLED`；
- 取消账单后对应有效费用释放为 `CONFIRMED`；
- 跨组织费用不可预览或建单；
- 迁移可在现有库幂等执行，并可在空 Schema 从零执行；
- 前后端测试、类型检查、构建及真实 API E2E 全部通过。
