# 提成管理增强计划

## 1. 文档目的

本文用于指导 `roncin-go-admin` 提成管理三项增强的设计、实施与验收：

1. **导出提成**：按当前筛选条件导出提成列表（本位币与 CNY 双口径）。
2. **CNY 折算展示**：提成生成时快照 CNY 口径金额，列表与详情双口径展示。
3. **提成归属日期**：从核销单派生不可变的提成归属日期，支持按月份筛选。

本文以 2026-08-30 的仓库代码为基线，并引用同日对易云竞品 `/company/commission`
的实测结论。本文是实施计划，不代表功能已经完成。

## 2. 竞品参照（2026-08-30 实测）

易云提成管理具备：列表"导出提成"按钮；新增提成页的订单选择表同时展示本位币与
CNY 各五组金额（应收/应付/利润/实收/结余）；"提成时间"作为独立字段与筛选条件。

采纳边界：

- **采纳**：导出能力、提成金额的本位币/CNY 双口径展示、"提成时间"独立维度。
- **部分采纳**：竞品的五组 CNY 金额是逐订单明细级的；本项目第一版只做主提成单
  级的双口径（原始、调整、有效提成），不宣称完整采纳五组金额。
- **不采纳**：展示时实时折算（提成金额全部为不可变快照，CNY 同样在生成时一次
  性固化）；"提成时间"由用户手工选择（本项目从 `verification_date` 派生）。

## 3. 当前实现基线

1. **提成模型已完整**：`FinanceCommission` 锚定 `verification_id`，状态机
   DRAFT→CONFIRMED→PAID/CANCELLED，规则名/版本/口径/人员归属均为 immutable
   快照，`source_fingerprint` 防来源漂移；金额字段为本位币
   （`base_currency`），无 CNY 字段，无独立归属日期。
2. **有效提成为动态汇总**：`effective_commission_amount = commission_amount +
   已确认/已支付调整`（冲减方向相减），草稿与已取消调整不计入；调整金额不落
   库，读取时汇总。
3. **核销单已具备汇率折算体系**：`FinanceVerification` 保存 `currency`、
   `exchange_rate`、`exchange_rate_source`、`exchange_rate_date`、`base_amount`、
   `verification_date`（全部 immutable）。
4. **汇率解析的方向约束**：`ExchangeRateUsecase.Resolve` 只解析"任意币种 → 当前
   组织本位币"；汇率配置创建时强制 `to_currency = 组织本位币`。**不存在直接的
   "本位币 → CNY"解析能力**，本位币非 CNY 时必须经倒数派生。
5. **预览与生成是两次独立计算**：`Preview` 直接计算返回，`Create` 在事务内重新
   计算并写入；两者之间汇率配置可能变化。
6. **导出先例**：`ExportPartners` 为同步 JSON 导出接口（独立权限
   `business.partner.export`），按每页 200 条循环拉取，前端生成 CSV（带 BOM）。
7. **筛选现状**：`CommissionFilter` 仅有 keyword/status/分页，无日期维度。
8. **权限现状**：读取 `system.finance.commission.read`，生成与规则维护
   `system.finance.commission.manage`；无导出权限。

## 4. 方案决策

### 4.1 已确认决策

- **CNY 快照时机**：提成生成（写入草稿事务）时解析并固化，确认、支付阶段不再
  变动；预览结果仅用于提示，不作为最终快照。
- **归属日期派生**：`commission_date = verification.verification_date`，生成时
  快照，immutable；重新生成时从本次关联核销单重新派生，不沿用已取消提成的归
  属日期与汇率快照（同一有效核销单在旧提成取消后重新生成是允许的路径）。
- **展示口径**：列表与详情双口径（本位币 + CNY），导出同口径；不做实时折算。
- **导出形态**：同步 JSON 导出接口 + 前端 CSV（BOM），沿用 `ExportPartners`
  先例；导出条件与列表筛选一致并叠加归属月份区间；导出记录业务审计。

### 4.2 阶段 0 必须冻结的业务口径

以下决策在阶段 1 开始前必须全部确认；任一项未确认时，不进入模型与迁移实现。

#### 4.2.1 CNY 汇率来源与换算方向

- 提成锚定应收核销，CNY 折算统一采用 `WRITE_OFF` 汇率类型和 `RECEIVABLE`
  方向。
- 汇率日期固定使用 `verification.exchange_rate_date`，不使用提成生成时间、
  确认时间或支付时间。
- 当 `base_currency = CNY` 时：
  - `cny_exchange_rate = 1`
  - `cny_exchange_rate_source = BASE_CURRENCY`
  - `cny_exchange_rate_date = verification.exchange_rate_date`
  - `cny_exchange_rate_setting_id = null`
- 当 `base_currency ≠ CNY` 时，现有汇率体系先解析 `CNY → base_currency` 的核销
  汇率，再取倒数得到 `base_currency → CNY` 的提成折算率：
  - `cny_exchange_rate = round(1 / source_rate, 8)`
  - `cny_exchange_rate_source = DERIVED`
  - `cny_exchange_rate_setting_id = source_setting_id`（被反算的原始 CNY 汇率配
    置 ID，与核销汇率快照的可追溯方式一致）
  - `cny_exchange_rate_date = source_rate_date`
- CNY 金额统一按 `round(base_amount × cny_exchange_rate, 8)` 计算；禁止浮点数，
  汇率倒数及金额计算使用 decimal。
- 阶段 0 需用至少一组非 CNY 本币数据验证倒数精度，并确认 `numeric(18,8)` 的汇
  率精度是否足以保证金额舍入结果；不足时提高字段精度，不通过补差逻辑修正。

#### 4.2.2 汇率缺失与预览语义

- 预览和生成草稿均必须解析 CNY 汇率。
- 汇率缺失、冲突或汇率日期无效时，明确报错并阻止生成；不允许写入零汇率、零
  CNY 金额、空汇率日期或"未折算"记录。
- 预览结果仅用于提示。生成草稿时在写入事务内重新解析并固化汇率，创建响应中的
  汇率和 CNY 金额为最终快照。
- 创建接口不得依赖客户端已经调用预览；直接调用创建接口时执行相同验证。

#### 4.2.3 调整单与有效 CNY 提成

- 第一版不为 `FinanceCommissionAdjustment` 保存独立 CNY 汇率快照。
- 增提和冲减统一继承所属提成单的 `cny_exchange_rate`，保证同一提成归属期使用
  同一折算口径。
- 接口返回以下 CNY 金额（均按主单汇率折算，不落库）：
  - `cny_commission_amount`：原始提成 CNY 快照（持久化）；
  - `cny_adjustment_amount`：已确认、已支付调整金额折算后的合计（动态汇总）；
  - `cny_effective_commission_amount`：原始 CNY 提成加 CNY 调整金额（动态汇
    总）。
- 草稿和已取消调整不计入有效 CNY 提成。
- 已取消提成仍保留原始快照，页面明确显示"不计入应发"。

#### 4.2.4 第一版折算范围

- 第一版仅提供主提成单的原始、调整及有效 CNY 提成金额。
- 不为 `FinanceCommissionLine` 和费用快照增加 CNY 字段。
- 不增加没有明确页面、导出或报表消费方的 `cny_realized_profit`。
- 若后续需要逐订单 CNY 报表，单独设计明细级快照；禁止从主单 CNY 金额反向分摊。

#### 4.2.5 归属月份筛选

- `commission_date_from` 和 `commission_date_to` 均为包含边界的 `YYYY-MM-DD`
  日期（字符串存储，与 `verification_date` 的 `varchar(10)` 一致）。
- 前端月份范围转换为首月第一日和末月最后一日（如 2026-07 至 2026-08 →
  `2026-07-01` / `2026-08-31`）。
- 后端校验日期格式及 `from <= to`；允许只传单边。
- 列表和导出复用同一筛选实现。
- 默认排序为 `commission_date DESC, created_at DESC, id DESC`，保证分页与导出
  顺序稳定。

#### 4.2.6 导出上限与字段口径

- 单次同步导出上限固定为 10000 行。
- 后端先按当前筛选条件查询总数；总数超过上限时拒绝导出并提示缩小范围，不截断
  结果，也不只导出前 10000 行；总数不超限时按稳定排序分批查询。
- 导出字段明确区分本位币与 CNY 两组口径：原始提成、调整金额、有效提成各两
  列，另有提成编号、状态、核销编号、归属日期、提成员工、考核角色、规则名称、
  计提口径、比例、本位币币种、创建时间。
- CSV 统一处理 BOM、字段转义（逗号、双引号、换行）与电子表格公式注入。
- 文件名包含归属月份区间或导出日期。

#### 4.2.7 存量数据前提

- 阶段 1 前确认生产环境是否存在历史提成记录。
- 若不存在历史记录：新字段直接使用非空约束且不设置零值业务默认值；本地开发库
  通过重建获得最终结构。
- 若存在历史记录：暂停阶段 1，另行制定可审计的历史快照回填方案（评估历史汇率
  配置是否被编辑过）；禁止以零金额、空日期或当前汇率静默填充历史记录。

## 5. 数据模型变更

`FinanceCommission` 新增字段（全部 immutable）：

| 字段 | 持久化 | 说明 |
| --- | --- | --- |
| `commission_date` | 是 | varchar(10) 归属日期，派生自核销单 verification_date |
| `cny_exchange_rate` | 是 | numeric(18,8)，本位币乘到 CNY 的折算率；本位币为 CNY 时为 1 |
| `cny_exchange_rate_source` | 是 | BASE_CURRENCY 或 DERIVED（倒数派生时） |
| `cny_exchange_rate_date` | 是 | varchar(10)，来源汇率日期 |
| `cny_exchange_rate_setting_id` | 是 | 可空 UUID，被反算的原始 CNY→本位币汇率配置 ID |
| `cny_commission_amount` | 是 | numeric(28,8)，原始提成 CNY 快照 |
| `cny_adjustment_amount` | 否 | 动态汇总：已确认/已支付调整 × 主单汇率 |
| `cny_effective_commission_amount` | 否 | 动态汇总：原始 CNY + CNY 调整 |
| ~~`cny_realized_profit`~~ | 删除 | 无明确消费方，不做猜测性扩展 |

索引：`organization_id + commission_date`（按月筛选）。

存量数据按 4.2.7 的前提处理，不使用零值或空值兜底。

## 6. 后端契约

```http
GET /api/v1/finance/commissions/export   // 权限 system.finance.commission.export
```

- 请求复用列表筛选（keyword、status、commission_date_from/to），响应返回
  `CommissionExportItem` 列表，字段按 4.2.6 的双口径清单。
- `ListCommissions` 增加归属日期筛选并返回新字段（含动态 CNY 调整与有效金额）；
  `GetCommission` 同步返回。
- `PreviewCommission` 响应增加将使用的 CNY 折算率、汇率日期与来源，让用户在生
  成前看到折算依据；`CreateCommission` 在事务内重新解析并固化，创建响应为最终
  快照。

## 7. 权限

新增 `system.finance.commission.export`（依赖 `system.finance.commission.read`），
目录归入"费用管理 · 提成"，与 `business.partner.export` 先例对齐。权限键同步生
成前端常量。

## 8. 前端

- 列表：新增"归属月份"区间筛选（转换为包含边界日期）、"CNY 提成"列（展示有效
  CNY，悬浮或详情区分原始/调整）、"导出提成"按钮（按导出权限显隐）。
- 生成弹窗预览区：展示 CNY 折算率、汇率日期与来源；生成成功后以创建响应刷新数
  据（不沿用预览数值）。
- 详情：金额区按本位币/CNY 双口径展示原始、调整、有效三组金额及汇率信息。

## 9. 审计与事务

- CNY 快照与归属日期在生成草稿的同一事务内写入，随既有
  `finance.commission.*` 审计动作记录 `cny.exchange_rate`、`cny.rate_date`、
  `cny.source` 详情。
- **成功导出记录业务审计**（提成涉及员工收入，导出比普通查询敏
  感）：后端成功返回导出数据时写入 `finance.commission.export`，详情
  记录操作人、组织、筛选条件与导出行数，不保存完整导出内容。
- 超上限、后端查询错误等失败请求由结构化请求日志记录；无权限请求
  由访问控制中间件与请求日志记录。后端不将前端 CSV 生成或浏览器下
  载结果视为可审计的业务结果。

## 10. 分阶段实施

- **阶段 0**：冻结 4.2 全部口径；用非 CNY 本币数据验证倒数精度与字段精度；确
  认生产无历史提成记录；核对 `Resolve` 在 CNY→本位币方向的 rateType 传参。
- **阶段 1**：模型与迁移（新字段 + 索引，非空无默认值），生成事务内解析并写
  入 CNY 快照与归属日期，预览返回折算依据。提交：
  `feat: 增加提成 CNY 快照与归属日期`。
- **阶段 2**：导出接口（先计数后分批、上限拒绝、稳定排序）+ 导出权限 + 导出审
  计。提交：`feat: 增加提成导出`。
- **阶段 3**：前端归属月份筛选、CNY 列、详情双口径、预览汇率展示与测试补齐。
  提交：`feat: 增加提成 CNY 展示`。

测试至少覆盖：

- 本位币为 CNY 时汇率恒为 1、来源 BASE_CURRENCY、汇率日期等于核销
  汇率日期、setting ID 为空。
- 非 CNY 本币时倒数折算、来源 DERIVED、setting ID 回填；倒数精度断言。
- 汇率缺失/日期无效时预览与创建均报错，不落库。
- 预览后修改汇率配置，创建按事务内重新解析的结果写入。
- commission_date 等于核销日期；同核销单重生成按新快照。
- CNY 调整/有效金额与调整状态机一致（草稿、取消不计入）。
- 导出：无权限拒绝、超上限拒绝且不加载、行数与列表一致、CSV 转义与公式注入。
- 既有生成、确认、支付、调整链路不回归。

## 11. 非目标

- 展示时实时折算或可切换多币种视图。
- 提成明细行（`FinanceCommissionLine`）与费用快照的 CNY 字段。
- `cny_realized_profit` 及其他无消费方的折算字段。
- 异步导出中心与 Excel（xlsx）格式。
- 归属日期手工调整与跨期重算。

## 12. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 汇率体系只有"币种→本位币"单方向，倒数派生口径不清 | 4.2.1 冻结倒数规则并标 DERIVED，保存来源配置 ID |
| 生成时汇率缺失导致提成无法出具 | 按冻结策略显式报错，不写零汇率快照 |
| 预览与生成之间汇率变化导致口径漂移 | 生成事务内重新解析，创建响应为最终快照 |
| 调整单滞后发生时汇率口径不一致 | 调整继承主单汇率，不按调整日折算 |
| 导出被当作数据导出通道滥用 | 独立权限 + 总数预检上限 + 业务审计 |
| 分页/导出顺序不稳定导致重复遗漏 | 排序含唯一 ID，列表与导出同谓词 |
| 存量数据被零值或当前汇率污染 | 4.2.7 前提确认，有历史则暂停另定回填方案 |

## 13. 完成定义

- 生成草稿的提成包含完整 CNY 快照（折算率、来源、汇率日期、配置 ID、原始 CNY
  金额）与归属日期；确认、支付不改变这些字段。
- 列表可按归属月份（含边界）筛选，展示本位币与 CNY 双口径的有效提成；预览可见
  折算依据，生成后以创建响应为准。
- 拥有导出权限的用户可按当前筛选导出双口径 CSV（BOM、转义、防公式注入），超上
  限明确拒绝；导出行为有审计记录。
- 迁移链、后端测试、前端测试、类型检查与构建全部通过。
