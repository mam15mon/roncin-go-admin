# 订单标签建设计划

## 1. 文档目的

本文用于指导 `roncin-go-admin` 订单标签功能的设计、实施与验收：把配置管理中的
企业标签字典接入订单模块，提供订单打标签、按标签筛选和标签展示能力。

本文以 2026-08-29 的仓库代码为基线，并引用同日对易云竞品的实测查证结论。本文
是实施计划，不代表功能已经完成。

## 2. 竞品查证结论（实测，非推断）

2026-08-29 在易云生产界面实测确认标签的实际用法：

- 入口：海运出口订单列表（`/order/sea_export`）→ "批量操作"下拉 → **添加标签、
  删除标签**，与"修改字段、批量导入、锁定、完结、退关、归档"等订单批量操作并列。
- 勾选订单后点击"添加标签"，弹窗按标签组展示字典标签：组"谛达"下有"谛达支付、
  默认、部分核销"三个复选项，**与配置管理 → 标签管理维护的是同一份数据**。
- 弹窗内提供"新增标签"快捷入口，不必返回配置页。
- 订单表格默认列中无标签列（是否作为可选列存在未深挖）。

结论：竞品标签挂靠对象是**订单等业务单据**，不是企业。配置管理的标签管理承担
纯字典角色。

## 3. 当前实现基线

1. **订单侧已有自由文本标签**：`orders.tags` 为 `[]string` JSON 字段并建 GIN 索引
   （`server/internal/data/ent/schema/order.go:61` 与 `:125`）；`CreateOrder` 与
   `UpdateOrder` 契约中已暴露 `OrderTagsInput`（`server/api/order/v1/order.proto`）。
2. **前端未实现标签编辑**：`web/src/pages/orders/` 下没有任何 tags 相关界面代码，
   该字段处于"后端可写、前端不可见"的半成品状态。
3. **订单列表没有批量操作框架**：`web/src/pages/orders/list.tsx` 无行选择与批量
   操作区。打标签是本项目订单模块第一个批量操作需求。
4. **企业标签字典已建成**：`EnterpriseTagGroup`（组名、颜色）与 `EnterpriseTag`
   （组内标签）已随企业资源模块交付，含组织隔离、重名校验与审计。
5. **订单权限为动态格式**：`business.order.{业务类型}.{操作}`
   （`server/internal/access/manifest.go:280`），业务类型含 SE/SI/AE/AI/LAND/RAIL。
6. **审计动作惯例**：`order.{子域}.{动作}`，如 `order.abnormal_case.mark`。

## 4. 方案决策

核心问题：订单标签沿用现有自由文本 `tags` 字段，还是改为字典引用。

**采用字典引用**：新增 `OrderEnterpriseTag` 关联表（N:M），订单标签必须引用组织内
已存在的 `EnterpriseTag`。理由：

- 自由文本无法防拼写错、无法承载组的颜色、无法与配置管理的字典对齐，会形成
  "订单一套标签、配置一套标签"的双重真相，违反本仓库单一存储真相约束。
- 竞品实测即为字典引用模型。

阶段 0 必须决策的事项：

1. **存量 `orders.tags` 处理**：迁移为字典标签（为每个去重标签名在默认组下创建
   `EnterpriseTag` 并建关联），还是字段冻结只读。若系统尚未投产且无有效数据，
   直接在版本化迁移中删除该字段与 GIN 索引最干净。
2. **字典标签停用语义**：标签资源 `enabled=false` 后，已打的订单标签是否保留展示
   （建议保留、不允许新增）。
3. **删除字典标签的连带行为**：企业资源删除会级联删除其全部关联行。订单标签关联
   必须纳入同一删除事务，且删除前向用户提示影响范围（阶段 0 确认提示文案与是否
   需要二次确认）。

## 5. 领域与数据模型

```text
orders（现状不变，存量 tags 字段按阶段 0 决策处理）
└── OrderEnterpriseTag（订单-标签关联，N:M）
    ├── organization_id（冗余，订单与标签同组织校验依据）
    ├── order_id → orders.id
    └── enterprise_tag_id → enterprise_tags.id
```

表约束与索引：

- 唯一约束 `(order_id, enterprise_tag_id)`，重复打标签幂等拒绝。
- 索引 `(enterprise_tag_id, organization_id)`，支持按标签反查订单。
- 列表按标签筛选使用 `order_id IN (子查询)` 或 JOIN，遵循现有分页排序结构。

领域规则：

- 订单与标签必须属于同一组织，Data 层在同一事务内校验，任一越界整体拒绝。
- 打标签不改变订单状态机，不触发订单生命周期事件。
- 一个订单可打多个标签；同一标签可打多个订单。

## 6. 数据库迁移方案

以 Ent Schema 为结构真相源：

1. 新增 `OrderEnterpriseTag` Schema 与边（Order、EnterpriseTag），生成 Ent 代码。
2. 基于 Schema 差异编写版本化 SQL 迁移：建表、外键、唯一约束与索引。
3. 存量处理（按阶段 0 决策）：
   - 迁移方案：对 `orders.tags` 去重后逐个创建 `EnterpriseTag`（归入默认标签组）
     并建立关联，迁移后做数量断言（源标签引用数 = 关联表行数）。
   - 废弃方案：直接删除 `orders.tags` 列与 `order_tags_gin` 索引。
4. 从空库执行完整迁移链并运行迁移清单测试。

不修改已执行的历史迁移；不引入"新旧字段并行读"的回退。

## 7. 后端契约与分层

新增订单标签 RPC（挂在 OrderService 或独立 `OrderTagService`，以评审为准）：

```http
POST /api/v1/orders:batchAssignTags   // order_ids + tag_ids
POST /api/v1/orders:batchRemoveTags   // order_ids + tag_ids
```

契约要求：

- `ListOrders` 增加 `tag_ids` 筛选（any 语义：命中任一标签即返回）并返回标签概要
  （标签名、组名、颜色）。
- `GetOrder` 返回标签明细。
- 批量请求必须显式携带订单 ID 列表，不接受"当前页全选"隐式语义。
- Biz 层校验：订单归属当前组织、标签归属当前组织且 `enabled`、列表非空。

分层遵循现有约定：Proto 生成物不手改；Service 不写业务规则；Data 层事务内完成
写入、组织校验与审计。

**快捷新建标签的权限口径**：打标签弹窗内的"新增标签"复用企业资源
`CreateEnterpriseResource(TAG)`；前端仅对同时拥有订单更新权限与企业资源创建权限
的用户显示该入口。不为此新增独立权限，也不放宽现有授权。

## 8. 权限设计

不新增独立标签权限，避免权限项膨胀：

- 打标签 / 移除标签：`business.order.{业务类型}.update`（与竞品一致，标签属于订单
  批量操作的一部分）。
- 查看标签列、按标签筛选：`business.order.{业务类型}.read`。
- 读取字典选项（组与标签列表）：`business.enterprise_resource.read`
  （`ListEnterpriseTagGroups` 已具备）。
- 快捷新建标签：`business.enterprise_resource.create`。
- 后端权限注解与实现同阶段交付，不出现无权限注解的可用端点。

## 9. 前端页面

- **订单列表**：
  - 新增行选择（`rowSelection`）与"批量操作"下拉，第一版仅放"添加标签、移除
    标签"两项——这是订单模块批量操作框架的起点，控件按可扩展设计。
  - 新增标签列：以 Ant Design `Tag` 展示，颜色取标签组颜色；列可在列设置中开关。
  - 搜索区新增标签筛选（多选，任一命中）。
- **打标签弹窗**：按标签组分区展示字典标签复选；展示已选标签；拥有双权限时显示
  "新增标签"快捷入口（组选择 + 名称，调用企业资源创建接口后刷新选项）。
- **订单详情**：展示标签列表。
- 未选择任何订单时点击批量操作给出统一提示，不发送空请求。

## 10. 审计与事务

```text
order.tag.batch_assign
order.tag.batch_remove
```

审计详情至少包含 `order.ids`、`tag.ids`、`assigned_count` / `removed_count`。
资源写入与 `writeAudit` 在同一事务，失败整体回滚。删除字典标签清除订单关联时，
随企业资源删除审计一并在同一事务完成。

## 12. 非目标

- 订单标签与企业资源的企业关联互相同步（两回事，不打通）。
- 费用、账单等其他单据打标签（后续按同一模式复制）。
- 标签使用统计报表。
- 订单标签变更消息通知。

## 13. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 删除字典标签连带清除订单关联 | 删除事务内一致处理，审计记录影响数量，前端删除前提示 |
| 自由文本标签与字典标签并存造成双真相 | 阶段 0 二选一处理存量字段，不留并行写入 |
| 批量操作误选订单 | 明确展示选择数量，接口只处理显式提交的订单 ID |
| 权限组合缺失导致快捷入口 403 | 前端按双权限显隐；后端授权仍是最终边界 |
| 订单列表引入行选择影响现有交互 | 阶段 0 核对并在阶段 3 回归现有用例 |

## 14. 完成定义

- 订单列表可勾选订单并批量添加或移除字典标签，重复操作幂等。
- 订单列表展示带组颜色的标签列，并支持按标签筛选。
- 打标签弹窗按组展示字典；有权限用户可快捷新建标签并立即选用。
- 订单详情展示标签。
- 存量 `orders.tags` 按决策完成迁移或移除，无双真相残留。
- 批量操作、组织隔离、事务审计具备针对性测试；迁移链、后端测试、前端测试、
  类型检查与构建全部通过。
