# ADR 0007: 选择器拼音检索——服务端 keyword 覆盖全拼与首字母

- 状态：已采纳
- 日期：2026-08-27 上线，2026-08-30 修复检索缺口
- 主题：接口与主数据

## 背景

主数据（往来单位、港口、船司等）大量实体只有中文名称，而操作员在选择器
里习惯输入拼音或拼音首字母。若检索只做 `LIKE '%关键词%'` 匹配名称字段，
输入 `shanghai` 或 `sh` 找不到「上海」。前端做拼音又要求全量拉取数据，
与大数据集服务端分页策略（ADR 0006）冲突。

## 决策

- 所有动态候选项的 `keyword` 查询在服务端完成，且必须覆盖：业务代码、
  中文名称、英文名称、别名（字段存在时）、中文无声调全拼及拼音首字母。
- 检索键由平台包
  [../../../server/internal/platform/searchtext/searchtext.go](../../../server/internal/platform/searchtext/searchtext.go)
  统一维护：为可搜索实体生成拼音检索键列并建索引，查询时在检索键上匹配。
- 新增可搜索的中文候选实体时，同步维护后端拼音检索键、索引和历史数据
  回填逻辑，三件事随同一变更交付。

## 理由

- 检索在服务端做才能与「大数据集服务端分页 + keyword 过滤」的组合兼容，
  前端无需为获取候选项循环翻页或全量加载。
- 检索键预计算成列，避免查询时实时调拼音库转换（无法走索引）。
- 别名与无声调全拼覆盖实际使用习惯（如「上港集团」别名、多音字场景按
  常用读音归一）。

## 后果

- 每个新增可搜索实体多一项固定成本：检索键列 + 索引 + 回填迁移。
- 2026-08-30 曾出现「业务标签鉴权与拼音检索」缺口修复（`43df26d0`），
  说明检索键必须与权限过滤叠加验证，不能只测检索本身。
- 契约原文见 [../../../AGENTS.md](../../../AGENTS.md)「后端列表分页约定」
  与 [../server/backend/database-guidelines.md](../server/backend/database-guidelines.md)。
