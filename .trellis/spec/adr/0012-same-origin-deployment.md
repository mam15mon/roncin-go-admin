# ADR 0012: 生产同域部署——Go 服务托管 API 与静态资源

- 状态：已采纳
- 日期：2026-08-20（健康检查与同域托管前端）
- 主题：部署

## 背景

前端是 Umi 开发服务器（带代理），后端是 Go Kratos。生产部署若前后端分域，
需要处理 CORS、Cookie 跨域策略、双证书与双入口运维。对一个快速上线阶段
的货代后台，这些成本不产生业务价值。

## 决策

- 生产采用同域部署：Go 服务同时提供 `/api/*`、`/health/*` 以及 React
  打包后的静态资源；传输层注册与静态资源服务在
  [../../../server/internal/server/](../../../server/internal/server/)。
- 开发期前端走 Umi 代理转发到本地 Go 服务；生产同域直连。
- 修改静态资源打包或前端路由时，必须同时验证开发期代理和生产同域路径
  两种访问方式。

## 理由

- 同域消除了 CORS 与跨域 Cookie 配置整类问题，鉴权 Cookie 天然作用域
  正确。
- 单进程部署降低上线与运维成本，符合「最小业务闭环优先」的交付阶段
  约束（见 [../../../AGENTS.md](../../../AGENTS.md)）。
- 备选的反向代理（Nginx 双上游）方案多一层配置真相源；在当前规模下，
  Go 内置静态服务更简单且无额外故障面。

## 后果

- 前端路由必须是同域相对路径，页面禁止自行拼接后端主机地址（与 ADR
  0009 请求层约定互为约束）。
- Go 服务成为唯一入口：健康检查、静态资源缓存策略、路由兜底都在服务端
  一处治理。
- 若未来拆分独立前端域名，需要重新评估 Cookie 与 CORS 契约；当前无此
  计划，不留兼容层。
- 相关规范：[../web/frontend/state-management.md](../web/frontend/state-management.md)
  「请求客户端」一节。
