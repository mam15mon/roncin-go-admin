# 公共主数据与公司独立配置

## 适用范围
公共字典、费用目录、业务汇率、公司经营资料及维护权限。系统不存在集团，系统管理工作台不作为公司的业务上级。

## 归属矩阵
| 类型 | 实体 | 维护与消费 |
| --- | --- | --- |
| 公共标准资料 | 国家、币种、行政区划、标准箱型、费用大类、货物分类、异常类型、计费单位、船公司、航空公司、港口、机场 | 系统管理身份及对应权限维护，各公司读取同一记录 |
| 系统初始目录 | FeeSettingTemplate | 系统管理维护；新建公司同事务复制为本公司的税务项目和费用科目 |
| 公司独立配置 | FeeSetting、TaxableService、FinanceCustomSetting | 当前公司有权人员维护，不跨公司共享、不继承系统设置 |
| 公司独立配置 | ExchangeRateSetting | 公司维护和消费当周业务汇率；旧 NULL 公共行仅保留历史事实，不参与新取值 |
| 公司经营数据 | 客户、供应商、国外代理、订单及财务单据 | 公司成员资格和公司角色授权，经营读写仅当前公司 |

## 必须遵守的契约
- 公共资料写入使用 `RequireGlobalMasterDataWrite`：系统管理工作台身份和权限码缺一不可。公司administrator角色不等于系统管理角色。
- 港口机场无organization_id，不存在本地同码覆盖。按保存ID读取允许停用记录展示；新选择和写入要求启用。缺失地点继续显式报错，禁止吞错。
- 费用模板只保存税务文本默认值，不引用某公司的TaxableService ID。复制时建立本公司合法关联；已有公司配置不会随模板更新而变化。
- 公司费用科目organization_id必填；订单费用和费用补录按目标公司校验科目与税务引用，系统模板不能直接用于经营单据。
- 公司财务编辑与信用管控策略按目标公司读写和审计，使用统一事务与版本冲突检查；禁止沿组织树查找系统节点来继承经营策略。
- 新建公司无父工作台，部门/团队只归所在公司；系统管理维护身份不自动授予公司成员资格或经营权限。

## 迁移与回归
- 正式迁移保留原ID和单据快照，地点同码或税务配置冲突必须显式拒绝，不擅自合并覆盖；不得重置开发库。
- 旧集团结构转换在原子迁移内先复制有效公司策略，再拆除公司父关系。现有成员资格保留；停止bootstrap自动补公司资格及权限穿透。
- 真实PostgreSQL隔离测试覆盖冷启动、升级、冲突回滚、已有订单引用、费用普通与补录引用映射、公司策略独立。
- 权限验证覆盖系统维护公共资料、公司拒绝公共写、系统拒绝经营读写、公司ALL仍仅本公司、模板修改不影响公司副本。

## 旧管理目录转换与开发种子
旧管理节点费用经明确批准转为系统初始模板，保留原科目ID、时间和税务默认文本；不自动填充已有公司。原税务记录完整保留，但不提供系统经营CRUD，也不进入公司选择器。模板同码冲突或原系统科目仍有经营费用/补录引用时原子拒绝。
开发seed必须在统一事务内执行，测试员工与经营数据归独立公司；系统管理员不自动获得公司成员资格。验证seed需在隔离数据库真实执行并重复运行，不能以编译通过代替实际落库验证。

## 初始目录种子迁移（20260923120000）
- 系统初始目录 122 条模板由正式迁移落库（`fee_catalog_seed.sql`）；迁移同时幂等补齐基础费用类别（与 `data.CreateDefaultOrderOptions` 同值）、异常情况与计费单位（含 `quantity_must_be_integer` 标志，故该迁移必须排在 20260923115000 之后），并向每个既有公司追加模板副本：同码跳过、应税劳务按（公司,名称）复用或按模板文本创建、同名但税率/简称/商品码不一致时显式拒绝，口径与 `initializeCompanyFeeSettings` 一致。
- 全新库顺序为：迁移先行（此时无组织，公司追加空转）→ bootstrap 建 system 组织并按 kind+code 幂等补种其余 A 型主数据（国家/箱型/货物分类）→ `CreateDefaultBranchCompanies` 新建公司时同事务复制模板。bootstrap 与后台建组织不再以"存在任意主数据行"跳过默认种子。
- SQL 种子行的 `search_keywords` 必须与 `internal/platform/searchtext.Build` 的输出逐字一致：迁移是纯 SQL，无法执行 Ent 钩子，检索键须经该函数预计算后写入（费用种子由一次性生成器产出后删除）。
