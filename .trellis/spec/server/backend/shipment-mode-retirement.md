# 订单集运／跨境模式及自拼汇总退役

## 1. 适用范围

海运出口、海运进口、空运出口、空运进口的本票业务输入、读取、数据库列，以及“自拼汇总”列表入口。当前产品不经营独立集运／跨境小单业务，不以预留枚举占位未来业务。

## 2. 签名与数据结构

- `order.v1.Order`、`CreateOrderRequest`、`UpdateOrderRequest` 不再包含 `shipment_mode`；原字段号分别为13、11、12，字段号与字段名均声明 `reserved`，其他字段不重编号。
- `ShipmentMode` Proto 枚举、`biz.OrderShipmentMode`、Ent `orders.shipment_mode` 及其读写/转换/校验全部删除。
- `OrderService.ListOrderConsolidations`、`/api/v1/orders/{id}/consolidations`、专用请求响应及成员/汇总/件重尺投影已退役；不保留空列表兼容接口。
- 前端四类表单不再注册 `shipmentMode`，领域适配器、创建默认、回显、更新及测试夹具不携带该字段。

## 3. 契约与保留边界

迁移仅删除失效模式列，不删除订单、主分单、共享箱、货物费用或活动关联；历史迁移仍保持原文件和执行顺序。现存列中的传统货代／跨境／NULL 值随列退役，不转换为另一种业务状态。

普通海运 `ShipmentType` 的 FCL/LCL/散杂、`ContainerOwnership`、MBL/MAWB 与 HBL/HAWB、共享成员、拆票改配、重量确认及财务流程继续存在。自拼汇总曾只是共享 MBL 下普通 LCL 订单的查询投影，删除该投影不授权删除底层关联。

费用列表 `/finance/fees` 的中文标题统一为“费用明细”，路由和页签身份规则保持既有协议。企业名称中的“集运”、历史任务、审计与不可变快照不做词语替换。

Proto、Ent、OpenAPI、访问规则和客户端只通过既有生成器同步。订单创建幂等意图按当前业务字段计算，删除模式后不添加旧哈希或旧载荷回退。

## 4. 校验与错误矩阵

| 输入或动作 | 当前结果 |
| --- | --- |
| 四类合法订单不提供模式字段创建、更新 | 按正常经营字段保存，不写入默认模式 |
| 读取已有订单 | 不返回模式字段，普通单证与货物字段正常 |
| 访问已删除汇总端点 | 无对应业务路由，不返回伪成功空数据 |
| 普通LCL共享主单或维护货物 | 沿原权限、版本、状态与锁规则执行 |
| 迁移包含旧模式值的订单 | 仅失效列消失，其他列与关系保持 |
| 同键创建重放但改变真实经营字段 | 仍按原幂等规则冲突，不因退役模式而放宽 |

## 5. 正常、基准与错误场景

- 正常：LCL订单保存普通运输与主分单资料，列表可使用费用、附件、异常入口，不显示自拼汇总。
- 基准：海运箱量与散杂RT展示继续由托运类型控制；空运计费重与主单成员不依赖运输模式。
- 错误：仅隐藏单选框，却继续在adapter中默认写 `shipmentMode=1`，或为缺失字段补一个旧模式。

## 6. 必需验证

- Proto描述符验证3个旧字段号和名称reserved，旧枚举/RPC移除；生成客户端及访问规则无旧字段与方法。
- 四类表单/适配器验证创建、编辑、回显没有模式；列表菜单退役汇总后相邻动作可用，费用标题与详情页签正确。
- PostgreSQL以正式历史前缀构造NULL和两种模式值，再升级；核对删列、其他订单字段、单证/成员关系、重复迁移和空库完整链。禁止用Ent自动建表，SKIP不算通过。
- 回归普通LCL共享、终止活动链接、拆票复制及创建幂等；更新测试夹具与验收脚本，不只检查词语消失。

## 7. 错误与正确

```text
错误：隐藏“集运／跨境”，保留shipmentMode默认值、数据库列和空汇总接口。
正确：删除源契约及完整读写链，正式迁移删列，按生成流程更新客户端，并保留普通运输能力。
```
