# 客商信用额度公司本币契约

## 1. 适用范围

客户主档内嵌收款约定、抽屉独立维护、开发种子、信用候选与建账预览。信用额度和未核销应收均以所属公司本币计算。

## 2. 签名

`PartnerSettlementRule.credit_limit_minor` 与 `credit_currency` 成对，均可省略。信用摘要的 `CreditLimitBase` 与 `UnsettledReceivableBase` 均为公司本币。`ErrPartnerCreditCurrencyMismatch` 对应 `PARTNER_CREDIT_CURRENCY_MISMATCH`（HTTP 400），提示在客户收款约定中重新填写本币额度。

## 3. 契约

- 独立 Create/Update 与主档 Create/Update/Import 共用 data 层校验，在写入事务内以目标公司的本币验证已填写的额度。
- 信用摘要只读客户角色唯一的约定。正额度参与额度判定前先校验币种。正额度缺币种或与公司本币不同会明确报错。
- 维护接口可以读取异常配置。前端显示原金额与币种，修改约定时要求明确重录本币额度。
- 开发种子只为客户角色设置公司本币额度。未结余额按账单本币、核销与对冲聚合。零额度与未设额度均不触发额度限制。
- 正式迁移在删改之前验证所有启用的正额度客户规则。异常使整份迁移回滚。重复组取最大正额度及其币种，全组无正额度时保留最近更新行原值。

## 4. 校验矩阵

| 场景 | 行为 |
| --- | --- |
| 公司本币 CNY，额度 CNY | 合法，额度与 CNY 欠款比较 |
| 公司本币 USD，额度 USD | 合法，额度与 USD 欠款比较 |
| 写入额度币种不等于公司本币 | 明确拒绝，整笔事务不部分落库 |
| 信用消费读到旧外币/缺币种正额度 | 明确报错，禁止直接比较或放行 |
| 维护读取异常旧额度 | 原值可见，重录本币金额后才允许提交修正 |
| 正额度与余额相等 | 不超额；严格大于才超额 |

## 5. 正常、基础与错误场景

在 CNY 公司设置 7,000 CNY 额度，并与 2,000 CNY 应收余额比较。留空表示不设额度。提交 1,000 USD 作为 CNY 公司的额度返回币种错误。

## 6. 必需验证

真实 PostgreSQL 覆盖 CNY/USD 公司、独立与嵌套创建/更新、异常正额度读取失败、原配置可维护，以及迁移守卫失败后的完整回滚。表单覆盖异常额度明确重录，并保留余额边界、模式与散客测试。

## 7. 错误与正确

错误：直接把未校验币种的 `creditLimitMinor / 100` 用于本币额度判定。

正确：维护入口显示公司本币额度。后端校验约定额度的币种，再与本币余额比较。
