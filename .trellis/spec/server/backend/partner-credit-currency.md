# 客商信用额度公司本币契约

## 1. 适用范围

客商主档嵌套结算规则、独立结算规则维护、开发种子、信用候选与建账预览。既有产品决定来自 `09-11-partner-terms-credit`：额度为公司本币，不在查询时实时换汇；结算币种与额度币种是两个字段。

## 2. 签名

`PartnerSettlementRule.credit_limit_minor` 与 `credit_currency` 成对；信用摘要的 `CreditLimitBase` 与 `UnsettledReceivableBase` 均为公司本币。`ErrPartnerCreditCurrencyMismatch` 的 reason 为 `PARTNER_CREDIT_CURRENCY_MISMATCH`（HTTP 400），提示到往来单位结算规则重填本币额度。

## 3. 契约

- 公司权威本币来自目标组织上下文，不能硬编码 CNY，也不能用结算币种代替。
- 独立 Create/Update 与完整客商创建/更新/导入内嵌规则全部验证额度币种；共用 data 层校验，并在原事务中执行。金额未设置遵循既有空值语义。
- 信用聚合在所有有效正额度参与最大值比较前校验币种；已有缺币种或异币正额度显式错误，不能跳过规则、重标本币或吞成空候选。
- 原始配置管理接口仍允许读取异常旧规则。前端展示原金额/币种并要求明确重录本币额度，不能在编辑其他字段时把旧金额静默改挂本币。
- 新建种子同步填写公司本币；不为修复自动运行 sync-dev 或改写已有规则。
- 未结余额继续使用既有账单本币、核销与对冲聚合。零/未设额度、散客、仅提醒与直接干预模式不改变。

## 4. 校验矩阵

| 场景 | 行为 |
| --- | --- |
| 公司本币 CNY，结算 USD，额度 CNY | 合法，额度与 CNY 欠款比较 |
| 公司本币 USD，结算 CNY，额度 USD | 合法，不固定 CNY |
| 写入额度币种不等于公司本币 | 明确拒绝，整笔事务不部分落库 |
| 信用消费读到旧外币/缺币种正额度 | 明确报错，禁止直接比较或放行 |
| 维护读取异常旧额度 | 原值可见，重录本币金额后才允许提交修正 |
| 正额度与余额相等 | 不超额；严格大于才超额 |

## 5. 正常、基础与错误场景

正常：USD 结算客户在 CNY 公司录入 7,000 CNY 额度，与 2,000 CNY 欠款比较。基础：未设额度不限制。错误：1,000 USD 直接当作 1,000 CNY，或打开编辑后把原金额不变仅币种换为 CNY。

## 6. 必需验证

真实 PostgreSQL 覆盖公司本币 CNY/USD、独立与嵌套创建/更新、事务回滚、旧异币/缺币种正额度聚合失败、原配置可维护；表单覆盖外币结算与本币额度独立、异常旧额度明确重录；保留余额边界、模式与散客相邻测试。

## 7. 错误与正确

错误：`creditCurrency = settlementCurrency`，然后把 `creditLimitMinor / 100` 同本币欠款比较。

正确：维护入口显示公司本币额度，后端据目标公司本币验证每条有效额度，再与本币余额比较；错误币种配置显式暴露。
