# 海运退关完成后的详情读取

## 1. 适用范围

海运订单完成退关进入 `TERMINATED` 后，详情和单证仍须可读。活动关联用于运输执行与
写入资格，不能同时作为全部详情读取的必要条件。修改退关状态流转、单证读取、详情
聚合或变动提示时遵循本契约。

## 2. 签名与数据事实

- `GET /api/v1/orders/{order_id}/sea-documents`，仓储入口
  `GetSeaOrderDocuments(ctx, organizationID, orderID)`。
- `TransitionTermination` 完成退关，在同一事务中写入订单 `terminated_at`，并将活动
  Link 改为 `ENDED`、`ended_reason = "订单退关"`、`ended_at = terminated_at`。
- MBL/HBL 工作实体保留；Link 不得因读取或恢复状态而自动复活。恢复须新建ACTIVE关系，与状态原子提交，见[恢复契约](./sea-order-restore.md)。

## 3. 读取及刷新契约

- 非终态只接受同组织、同订单的 `ACTIVE` Link。
- 终态只接受与本次 `terminated_at`、退关结束原因匹配的 `ENDED` Link；不能按最近
  创建时间或结束时间任取一条历史关联，改配和往次退关关系不是本次退关的读取依据。
- 沿匹配关联组装 `documentStructure`、`linkVersion`、MBL/HBL；终态
  `allowedActions` 为空。ProtoJSON 省略空数组仍表达无操作能力。
- 这是关联单证的保留记录读取，不保证共享 MBL 的可变正文冻结在退关时刻；不可变
  单证版本仍通过既有历史接口查询。终态 MBL「版本与事件」保持可读，版本列表与
  单证详情共用本次退关关联定位规则；HBL历史保持原契约。活动成员统计和业务写入
  门禁继续按原契约处理。
- 详情仍要求完整有效的单证响应，不能把 `SEA_DOCUMENT_NO_ACTIVE_LINK` 或其他失败
  吞成空数据、显示保存成功。
- 本人状态操作后的变动检查仅可识别该次实际写响应。不能把随后查询到的更晚外部版本
  当成本人操作接纳；不能借清除提醒重置未保存输入、草稿或表单提交基线。订单身份切换
  后旧操作的响应失效，原本存在的外部变更提醒仍保留。
- 状态响应是提交后重读，识别本人操作时至少要求订单版本精确递增一次，并验证预期
  关联变化。终态已无活动主单，变动检查比较订单身份与版本；保留单证的 MBL 版本
  不与缺省活动摘要比较。终态关账/反关账沿用相同口径。

## 4. 校验与错误矩阵

| 条件 | 预期 |
| --- | --- |
| 本次退关结束关系完整，DIRECT 或 HOUSE | 单证读取成功，终态只读，详情可重新打开 |
| 有多条旧改配关系 | 仅本次退关关系参与单证组装 |
| 非终态没有活动关联，或终态无本次退关关联 | 保持明确业务错误，不隐藏结构损坏 |
| 组织与订单不匹配 | 维持订单不可访问错误 |
| 终态尝试修改 MBL/HBL | 服务端生命周期门禁继续拒绝 |
| 完成退关后详情重读失败 | 提示刷新失败，保留输入，不宣称数据已刷新 |
| 状态操作后另有外部更新 | 外部变动提示继续有效 |

## 5. 正常、基础与异常场景

- 正常：经过多次改配的订单完成退关，再打开仍能看到本次退关关联的单证。
- 基础：未退关与退关中仍读取活动关系，取消退关不结束 Link。
- 异常：已终止订单只剩旧改配关联，必须报错，不能显示其他航次单证掩盖缺失数据。

## 6. 必需测试

- 正式迁移隔离 PostgreSQL 夹具，从真实创建、发起退关、完成退关链路验证 DIRECT/HOUSE
  单证可读、关联不复活、活动成员数减少、写入仍拒绝。
- 覆盖旧改配、错误结束原因或时间、缺少关联及跨组织读取。
- 前端覆盖终态初次加载、完成退关后状态刷新、本人操作提醒处理、刷新失败、迟到响应、
  外部变更以及未保存输入和提交基线保护。
- 禁止把缺少测试库导致的 `SKIP` 记作真实库通过。

## 7. 错误与正确做法

错误：所有读取都查询 `status = ACTIVE`；或接口报错后前端忽略单证继续显示旧状态。

正确：按订单生命周期选择严格匹配的关联，保持完整读取与明确错误，再验证操作后的
整页重读。状态流转测试除了断言写库成功，也必须断言用户随后能重新打开详情。

## 终态船公司名称展示

- `SeaBasicInfoSection`只读船公司字段不调用远程搜索；不得仅把当前名称埋在搜索回调
  的seed中。复用已加载的`seaDocuments.masterBill`作为展示来源，按当前表单
  `shippingLineId`匹配后注入选项；不将保留关系写回活动`seaMasterBill`。
- 活动主单和来源加票同样按当前ID匹配名称，防止切换船公司后展示旧名称；缺名显示
  「船公司名称读取失败」，不向业务人员展示UUID。
- 回归覆盖终态首开/重新进入、缺名、只读不请求候选，以及共享活动主单名称与禁改。

## 退关后的主单历史入口

- `ListMasterBillVersions(ctx, orgID, orderID, page, pageSize)` 与单证详情共用精确
  可读关联定位：非终态ACTIVE，终态仅本次退关的ENDED关系；不以任意最近历史代替。
- GetDocumentVersion继续按同公司、订单与目标主单的真实历史关系验证，事件列表沿
  原订单历史关联范围；本期不新增时间截断或共享主单快照。
- 前端版本与事件读取不受业务写入disabled限制，改单/作废等写按钮仍禁用。
- 回归须真实创建v1/v2与改单事件后完成退关，验证列表、单版本内容、事件和分页；
  另查旧改配关系不混入本次版本列表、公司隔离、缺失关联及终态写入拒绝。
