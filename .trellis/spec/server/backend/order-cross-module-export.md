# 四类订单横切与完整筛选CSV

## 1. 适用范围

SE/SI/AE/AI订单完整筛选导出、本人工作台待办/异常、通知深链及财务查询导航。
四类创建、详情、服务与主分单依各自规范；本规范只接通其既有事实的读取与输出，
不增加新业务类型、标签、通用流程或异步导出平台。实际验证以对应任务research为准。

## 2. 签名与分层

- `OrderService.ExportOrders`：`GET /api/v1/orders/export`，独立`ExportOrdersRequest`，
  不含`page/pageSize`。`business_type`必填，只接受SE/SI/AE/AI，其余筛选及
  `sort_by/sort_order`与`ListOrdersRequest`语义一致。
- 响应为标准封套及完整`Order[] data`、`total`、`generated_at`。常规列表继续
  `1 <= pageSize <= 200`，不得用巨型pageSize或前端/后端循环翻页实现导出。
- 静态`/export`在Proto的动态`/{id}`之前声明，绑定经正规生成器更新；真实HTTP
  注册测试断言operation、实际handler与合法详情相邻，不能只检查文件顺序。
- 仓储复用列表筛选/排序内核，在`Data.withReadSnapshot`回调内经`Data.client(ctx)`
  读取完整行及海空资源投影；service沿用列表子资源授权裁剪，不读取Ent。
- `OrderContainerRequest`增加只读`container_spec_code=7`、`container_spec_name=8`，
  biz纯展示值，`attachOrderDisplayNames`按真实箱型ID及Kind批量投影；Get/List/Export
  共用，Export在RR回调内取得标签。不为该投影新增数据库列，前端箱量计划不得
  在导出后再请求当前字典拼名称，避免同一文件混用其他时刻的标签。

## 3. 数据与身份合同

### 完整导出

- 当前启用公司工作区及该真实业务类型的`read`权限共同决定数据范围。
  系统治理权限不能办理公司业务，无对应类型权限不能借另一类型权限。
- 同一响应的所有行、总数和资源投影来自同一只读快照，稳定排序与列表一致。
  导出是请求时的新完整快照，返回生成时刻，不承诺固定此前页面的行值。
- optional资源字段保持未授权/未设置与明确零的区别；沿列表授权列输出。
  不能仅有订单read就暴露原需独立读取权限的费用、附件等内容。
- 前端只在官方ProTable `onLoad`采纳成功结果后持有可导出的筛选/排序快照。
  发起新筛选或排序时旧快照立即失效；迟到request不能更新它。空成功列表仍可
  采纳，失败不得伪装成空列表。
- 导出只请求一次专用接口；返回完整行数须匹配`total`，缺少真实业务标识
  明确失败。导出在途若已提交筛选、排序、公司、用户或页面会话变化，旧响应不能下载。
- 本组列表、专用导出和财务费用详情以封套`success === true`确认成功；该字段
  非optional，ProtoJSON省略时表示false。省略或显式false即使夹带旧data也不得
  采纳或下载，不借通用工具的宽松缺省行为放行，不机械改动领域布尔值。
- 订单read仍保留、仅箱号或附件读取权被收回时同样重建导出会话；真实access位
  必须参与旧响应失效判断，不能继续用先前闭包按旧授权列下载。
- CSV复用`utils/csv`的BOM、CRLF、引号/多行转义及文本公式防护。金额输出
  两位且不带千分位，数量/单价/汇率保精度；时间和文件名复用`formatDate`
  本地格式，纯日期保持日期，不截UTC字符串冒充换算。

### 工作台、通知与财务查询

- 本人费用待办与异常的摘要、明细复用同一真实四类公司/本人协作及权限交集，
  不因进口类型漏计，也不扩大为全公司。逐类订单read与fee/abnormal read分别判断。
- 四类详情、费用和异常深链来自统一业务类型导航入口及集中路由；未知业务
  类型显式不可跳转，不能默认落海运出口。
- 正式通知的四类业务内容与动作链接可用无网络受控夹具核验。系统通知测试页
  继续只提供示例/首页动作，`canSelectOrder=false`，传真实orderId仍拒绝；
  不为验证深链给系统工作台增加经营读取资格。
- 财务台账主单搜索、经营日期与报表消费真实海空实体：出口ETD、进口ETA，
  转中国自然日；订单经营日期、确认流水交易日和当前余额账龄分别保持原口径。
- 四类当前自由文本的既有长度合同按字符贯通biz与Ent。Order本票文本、航空
  主单notes及海运真实`SeaTransportExecution.vessel_name/voyage_no`使用对应
  字符计数，不能在下游把合法中文按UTF-8字节拒绝。只调整既有验证口径，不改变
  列尺寸、运输拆分、模式适用性或锁/版本；航空夹带海运船名航次仍拒绝。

## 4. 校验与错误矩阵

| 条件 | 结果 |
| --- | --- |
| businessType缺失/非法/不在本期四类 | 参数错误，不默认SE/AE |
| 非当前公司、系统工作台或缺对应类型read | 拒绝，不返回别的公司或类型 |
| 非法筛选/排序 | 与列表同样明确失败，不降级或截页 |
| 完整筛选超过200行 | 完整返回并稳定排序，普通列表分页上限保持200 |
| 子资源无权限 | 相应投影及导出列保持裁剪，不把未知造为0 |
| 新筛选/排序/身份在途变化 | 旧结果不能成为采纳快照或触发下载 |
| 真实必填标识缺失、total与行数不一致 | 明确失败，不下载不完整文件 |
| success省略或false、仍携带旧data | 失败，不采纳/不挂业务区/不下载 |
| 通知测试页系统会话传真实orderId | 原权限拒绝，上游零发送 |

## 5. 正常、基准与错误案例

正常：AI筛选得到250票，列表采纳ETA升序后发一次专用导出，250行均为当前公司AI，
同号出口票不混入；文件保留中文、引号、多行与6.7183等精度。

基准：只有SI订单与费用读取者能看本人SI待办；没有AE权限也能直达SI费用页，
同时AE待办及费用不暴露。

错误：导出按钮取当前页50行；循环pageSize200拼全量；只有AE权限读取AI；
筛选切换后旧请求结束仍下载；系统管理员为测试通知读取真实公司订单。

## 6. 必需验证

- 真实HTTP路由与权限：四类单独授权、两公司/系统拒绝，`/export`命中专用handler，
  合法UUID详情不回退；当前列表所有筛选/排序和普通分页边界保持。
- 正式迁移后的真实PG：四类完整结果、超过200行、稳定排序/授权投影、零与空、
  同一read snapshot；工作台摘要明细四类一致与相邻出口路径。
- 前端真实ProTable采纳：迟到请求、失败/空成功、提交筛选/排序、组织切换、
  pending导出和卸载；wire省略默认/显式零/optional未设/必填缺失；CSV实际内容。
- 一次性库真实四类业务与应收应付→建账→票据或免票→收付款核销→提成，
  台账/报表日期和只读权限分别核对；CSV真实下载超过200行及清理本次资源。
- 源/生成物幂等、独立全scope复核、最终`check:fast`；本组若改变生产入口
  再按风险build/同域验证，不能借前组门禁替本组。

## 7. 错误与正确实现

错误：`ListOrders(pageSize=100000)`，或者在request Promise结束时保存导出条件。

正确：列表保持200上限；`ExportOrders`用独立无page合同和同一读快照，
前端只采纳官方onLoad的筛选/排序，再调用一次专用导出并复验当前会话。
