# 企业微信下线契约

## 1. 适用范围

企业微信功能于 2026-10-09 下线。当前系统支持本地账密登录和钉钉认证；修改认证、用户管理或恢复历史数据库时需保持本契约。历史迁移和历史前态夹具中的企业微信字段只描述当时结构，不代表当前支持该能力。

## 2. 接口与数据库签名

以下端点不再注册：

```text
GET  /api/v1/auth/wecom/login-config
POST /api/v1/auth/wecom/login
POST /api/v1/admin/users/{id}/wecom-authorization
```

`AdminUser` 不再返回 `wecomUserid` / `wecomName`。正式迁移
`20261009130000_retire_wecom.sql` 删除 `users.wecom_userid`、`users.wecom_name`
和 `users_wecom_userid_key`。用户记录及其组织、角色、业务关联保持原值。

## 3. 跨层与环境契约

- auth/admin/conf Proto 删除专属 RPC、消息及配置；删除的字段编号和名称 reserved，其他字段不重编号。
- 服务端没有企业微信身份提供器、授权用例、状态 Cookie 或注入依赖。前端没有企业微信登录按钮、回调路由、用户列表列或授权分支。
- 配置示例不再声明 `WECOM_*`；权限 Manifest 不再声明 `system.user.authorize_wecom`，正式迁移命令沿用权限同步清理目录及角色关联。
- 用户检索键仅保留当前姓名来源。迁移清空 `users.search_keywords`，`cmd/migrate` 随后通过 `BackfillSelectorSearchKeywords` 重建，避免删除字段后仍命中旧企业微信姓名。
- 已有用户名/密码、钉钉身份、启停状态、组织关系、角色和审计不自动转换。只有企业微信登录资格的用户失去该登录方式，系统不自动设置密码或开通账号。
- `pnpm run migrate:dev` 用于开发迁移，生产仍使用严格校验的 `pnpm run migrate:server`；不得通过 Ent 运行期建表替代正式迁移。

## 4. 校验与错误矩阵

| 场景 | 结果 |
| --- | --- |
| 调用已删除企业微信端点 | 不匹配业务路由，不进入认证或授权用例 |
| 用户列表 / 登录页 | 无企业微信列、按钮、专属提示和配置请求 |
| 本地用户 / 已开通钉钉用户 | 继续按现有凭据、启停和成员资格规则登录 |
| 钉钉待分配 / 停用用户 | 不因企业微信下线而获得会话或组织权限 |
| 正式迁移前态结构不符 | 显式失败，禁止 IF EXISTS 掩盖结构差异 |
| 删除字段后检索旧专属姓名 | 不命中；保留姓名的中文、拼音和首字母仍可查询 |

## 5. 正常、基准与错误场景

- 正常：已有开发库执行增量迁移，删除两个字段和索引，人员数及组织角色关联数量保持不变。
- 基准：空库按完整正式迁移链初始化，当前用户模型可以读写，钉钉同步与本地登录继续可用。
- 错误：只隐藏表头、仅关闭配置、手改生成客户端、清空用户表或自动给旧用户开通密码。

## 6. 必要验证

- 隔离 PostgreSQL Schema 验证已有绑定前态升级，断言专属字段/索引移除、用户 ID 和状态、用户名/密码、组织关系、角色及历史审计保留。
- 空库正式迁移链验证当前模型；检索回填后断言旧企业微信姓名来源已移除。
- 本地与钉钉认证、用户密码管理、待分配开通、停用和组织切换相邻测试。
- OpenAPI、当前绑定代码、生成客户端与权限键无专属能力；历史迁移/前态夹具引用须结合执行时点判断。
- 运行页面验证用户表头、登录入口及请求；API 验证用户响应无专属字段、权限集无专属授权码。

## 7. 错误与正确示例

```text
错误：删 userColumns 列 → 保留企业微信接口、配置和数据库字段
正确：Proto / Schema 源文件变更 → 删除各层实现 → 正式增量迁移 → 再生成 → 相邻路径验证

错误：清空 users 或给旧账号自动生成密码
正确：只删除专属绑定字段，保留账号和所有业务关联，其他登录方式按原规则使用
```
