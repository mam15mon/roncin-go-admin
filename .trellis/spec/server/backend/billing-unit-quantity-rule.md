# 计费单位数量规则

## 1. 适用范围

计费单位公共主数据、订单费用新建/编辑、复制新增和锁后补录。单位规则由系统管理员维护，公司费用读取同一记录。

## 2. 字段与接口

- 数据库 `billing_units.quantity_must_be_integer`：非空布尔，默认 false。
- Protobuf `quantity_must_be_integer`、前端 `quantityMustBeInteger`：计费单位读写与订单费用候选项均传递。
- 管理界面显示“数量规则：整数 / 允许小数”。新增属性不新增权限体系，沿用系统工作台身份和费用配置权限。

## 3. 契约

- 运行时根据单位 ID 读取权威属性，不能根据名称、代码或箱型标记推断，也不能信任费用请求携带的客户端规则。
- 正式迁移一次性初始化系统已知离散单位；未识别单位默认允许小数。开发种子仅为新建单位赋初值，不覆盖管理员配置。
- 新建、复制新增及补录申请创建必须按当前规则校验。
- 编辑仅在数量数值或计费单位 ID 变化时追加整数规则；数量比较用 decimal 数值，`2` 与 `2.0000` 相同。
- 规则变更不重写已有费用。仅修改备注、单价等其他字段不被新增整数限制拦截，但仍执行已有正数/金额精度、权限、锁定、字段及版本校验。
- 已提交补录申请保留不可变快照，审批不重套当前单位规则。新申请执行当前规则。
- 新建箱型默认整数只属于表单默认行为，管理员可以覆盖；修改已有单位不得默默改变数量规则。

## 4. 校验与错误矩阵

| 输入或操作 | 结果 |
| --- | --- |
| 整数单位，1 或 2.0000 | 通过单位数量校验 |
| 整数单位，4.4 或 0.5 | 拒绝，`ORDER_FEE_QUANTITY_MUST_BE_INTEGER`，中文提示该单位数量必须为正整数 |
| 小数单位，4.4 | 通过单位数量校验 |
| 零、负数、超原有精度/上限 | 由既有数值约束拒绝 |
| 旧小数费用只改备注/单价 | 不追加单位整数限制 |
| 旧小数费用改数量或单位 | 执行当前目标单位规则 |
| 请求使用过期候选配置 | 后端权威配置决定结果 |

## 5. 正常、边界与错误案例

- 正常：2 箱；4.4 CBM；管理员主动将特殊单位改为允许小数。
- 边界：旧 4.4 票后规则收紧，仅改备注允许；改为 4.5 票拒绝；改为 5 票通过。
- 错误：将 4.4 自动取整；只在 UI 限制；复制旧小数费用时跳过新建校验；重新运行种子覆盖管理员选择。

## 6. 必需验证

- 属性管理读写和候选响应完整；整数/小数表单交互，箱型默认与用户主动选择不冲突。
- 普通新增、复制、编辑、补录直接 API 行为；编辑数值等价、改变单位、版本冲突和已建账限制。
- 正式有序迁移验证新库/已有库、已知与未知单位、费用数量不变，种子重复执行保留配置。
- 单位切换、费用项目带入默认单位、缓存刷新、旧表单提交反馈及补录审批快照。

## 7. 错误与正确做法

- 错误：`code == BL` 或名称包含“票”就在业务运行时判整数。
- 正确：代码表只用于一次性种子初始化；运行时从所选单位记录读取 `quantity_must_be_integer`。
- 错误：每次更新都对旧费用套用新规则，导致改备注也失败。
- 正确：在既有版本保护内比较数量数值和单位，只有本次改变计费数量组合才追加整数限制。
