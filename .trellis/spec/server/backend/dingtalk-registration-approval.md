# 钉钉通讯录同步与人员开通契约

## 1. 适用范围

适用于钉钉通讯录同步、无组织待分配人员、管理员开通与扫码登录。邀请、手机号匹配自动激活、自助注册、注册审批和转派入口已移除；本文件保留路径以维持任务引用，但内容以当前契约为准。消息机器人和订单解锁审批仍走各自业务链路。

## 2. 签名与持久化模型

```text
POST /api/v1/admin/dingtalk/directory-syncs         发起同步
GET  /api/v1/admin/dingtalk/directory-syncs/latest  最近任务（声明在参数路由前）
GET  /api/v1/admin/dingtalk/directory-syncs/{task_id} 任务详情与失败分页
POST /api/v1/admin/users/{id}/dingtalk-authorization 单人分配开通
POST /api/v1/admin/dingtalk/authorizations           批量分配开通
权限：system.user.dingtalk_directory.sync / system.user.authorize_dingtalk
```

- `users.pending_assignment` 默认为 false；为 true 时必须禁用账号，没有活动组织资格和角色。
- 来源资料包括姓名、头像、企业身份、工号、联系方式、来源部门快照和最近同步时间。
- `DINGTALK_DIRECTORY_SYNC` 是专用任务种类，不能使用仅公司工作台可用的 `INTEGRATION`。
- `ding_talk_directory_syncs` 与后台任务一对一；按 `corp_id WHERE active=true` 唯一索引限制同企业活动任务。调度状态与业务结果必须在同一事务结束。
- 历史迁移 `20261009120000_dingtalk_directory_provisioning.sql` 只迁移符合明确谓词且有成功注册审计证明的旧待审批占位，排除本地用户名/密码、企业微信身份和登记后已开通、离职或驳回者。符合候选形态但缺乏审计确证时原子阻断迁移，不能猜测分类。保留用户 ID、邀请静态历史、本地账号、企业微信、已开通与离职账号，不得重置数据库。

## 3. 跨层与环境契约

- 同步由系统管理员手动发起。服务端查询应用授权范围，递归部门、分页成员并按企业 userid 去重；仅同步应用可见范围，不自动映射系统组织。
- 钉钉授权范围字段为 `auth_org_scopes.authed_dept` / `authed_user`，字段可用性来自 `auth_user_field`。根部门授权代表范围覆盖全企业，仍须核验部门/人员读取权限；范围接口成功不能替代成员接口验收。
- 必需接口权限包括 `qyapi_get_department_list`、`qyapi_get_department_member`；成员信息接口另按当前钉钉应用授权核验。手机号、邮箱属于可选资料权限。
- 按 UnionID 与企业 UserID 一致性匹配已有人员，不按姓名或手机号自动重绑。身份冲突逐人报告。
- 新人员禁用且待分配；重复同步只维护钉钉资料，不更改组织、角色、默认工作台或账号开通状态。未返回人员不会自动离职，离职人员不会自动复职。
- 可选资料无授权时清空本地相应快照；已授权资料键缺失或 null 时逐人失败并保留本地资料，明确空字符串表示源资料为空。不能展示未经授权的旧敏感快照；畸形 API 响应不可当作成功零人。
- 钉钉资料在 UI 与服务端都只读；扫码昵称、头像不能覆盖通讯录资料。角色编辑不应提交只读资料。
- 开通只接收人员 ID、业务组织、角色。公司/部门/团队目标解析到所属公司角色库，至少一角色，不能把普通员工开通到系统管理工作台。
- 每人 `WithTx` 事务内锁用户行，再复核状态、操作者权限、组织启用和角色归属；写 membership/角色/primary/状态/审计/USER_AUTHORIZED 通知原子提交。并发第二次开通返回 409，不覆盖第一次分配。
- 批量每人独立事务，部分成功保留，响应逐人成功或错误；重试只发失败人员。密码、普通编辑与成员管理入口不能绕过待分配开通。
- 未同步/待分配/停用扫码不发会话。只有已开通人员进入有效公司工作台；本地管理员行为按认证规范执行；企业微信已下线，历史迁移中的身份排除条件仅用于构造旧前态。
- 同步执行时间受租约限制；每笔人员写入与任务结束均核验 token 和有效期。租约耗尽、DEAD_LETTER 或回放必须同步维护活动唯一约束，不让旧 worker 迟到写入。
- 旧注册/邀请通知的未完成任务正式迁移为终态，运行处理器不再支持这些模板，也不得人工回放。其他通知保留。
- 凭据继续使用 `DINGTALK_ENABLED/CLIENT_ID/CLIENT_SECRET/CORP_ID/REDIRECT_URI`；注册 token 密钥已移除。请求 URL 含 token 时，禁止向上包装原始 `url.Error`，不记录完整敏感请求响应。

## 4. 校验与错误矩阵

| 条件 | 结果 |
| --- | --- |
| 公司工作台访问同步或全局待分配 | 拒绝，无范围泄漏 |
| 同企业已有活动同步任务 | 409 DINGTALK_DIRECTORY_BUSY |
| 必需通讯录读取权限缺失 | 明确失败，不标成成功零人 |
| 身份映射冲突 | DINGTALK_IDENTITY_CONFLICT，不改原绑定 |
| 并发或重复开通成功者 | 409 DINGTALK_ASSIGNMENT_CONFLICT |
| 开通目标停用、角色错误、权限变化 | 整人回滚，无残缺成员/通知 |
| 修改钉钉基础资料 | DINGTALK_PROFILE_READ_ONLY |
| 旧 lease 迟到写入或完成 | 拒绝，账号与任务不被覆盖 |
| 9 人成功 1 人失败 | 保留 9 人开通，返回 1 人具体失败 |

## 5. 正常、基准与错误场景

- 正常：同步员工进入无组织待分配；管理员选公司或其部门和公司角色开通；员工扫码进入所属公司。
- 基准：已开通员工再次同步保留原 ID、权限和公司；离职员工只更新资料，需明确管理员重新开通。
- 错误：扫码创建账号；权限接口失败显示“同步成功 0 人”；按手机号自动合并本地账号；批量重试覆盖成功者；给待分配人员直接新增 membership。

## 6. 必要验证

- 网关：多级部门、分页、去重、多部门、独立人员范围、空/畸形响应、缺权限、部分失败、可选字段缺失、错误串令牌不泄漏。
- biz/service：四种登录状态不越权发会话；单人/批量载荷和分页上限；只读资料与公司隔离；HTTP latest 静态路由实际分发。
- 正式 PostgreSQL：身份冲突、重复/并发开通、每人事务回滚、批量部分提交、停用不复职、lease fencing、同企业活动唯一与回放、迁移前后五类用户、旧通知终结。
- UI：系统/公司视图隔离、同步终态停止轮询、来源只读、正确公司角色、成功选择清除和失败重试。
- 实际钉钉权限验证与网关夹具分别记录；真实 PostgreSQL PASS 与 SKIP 分开记录。

## 7. 错误与正确示例

```text
错误：GET scope 成功 → 宣称可同步全员；API 失败 → people=[] + SUCCEEDED
正确：独立核验部门/成员接口，错误显式终结同步并显示原因

错误：批量开通共享一个事务，失败后全回滚；重新发送全部选中员工
正确：逐人提交并返回结果，前端保留失败记录，只重试失败人员

错误：扫码昵称覆盖 display_name；普通用户修改接口提交钉钉姓名
正确：通讯录是资料写入来源；角色编辑只提交角色相关字段
```
