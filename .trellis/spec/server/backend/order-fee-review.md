# 统一订单审核、费用写入与建账准入

## 1. 适用范围

适用于六类订单的人工审核锁、普通费用维护、费用台账、建账入口及锁后费用补审。
唯一运行态审核事实来自 `Order.locked_at/locked_by/lock_generation` 与 `OrderLockRecord`。
旧整票费用审核写 RPC、独立审核权限及提成财务锁已退役；历史审核事件仅供审计读取。
单证锁及解锁契约见 [订单审核锁](./order-lock-and-document-version.md)，补审见 [费用更正](./order-fee-correction.md)。

## 2. 接口与快照

- `OrderLockService.GetOrderLockState/LockOrder`：预读订单版本、费用内容版本、指纹与收入/成本/利润摘要；执行同时固化审核费用快照及单证版本。
- `LockOrderRequest` 必传 `expected_order_version`、`expected_fee_content_version`、`fee_content_fingerprint`、`idempotency_key`；亏损时审核意见必填。
- `biz.BuildFeeReviewSnapshot` 只纳入完整经济内容及确定性排序，不纳入账单关联、通用行版本、更新时间或往来单位展示名。金额计算复用录费的 `RoundBank(8)`。
- `GetOrderFeeReview` 保留当前费用摘要和审计历史的只读能力；状态只按订单是否锁定投影为 `APPROVED/UNSUBMITTED`，不可从旧持久化状态恢复独立审批。
- `OrderFee` 返回逐费 `can_edit/can_delete/can_bill/can_correct/has_pending_change/blocked_reasons`；前端消费能力，不能把整票摘要能力替代逐费检查。

## 3. 人工审核与普通费用

- 审核资格是同公司、目标品类的有效 `business.order.<type>.lock` grant；同一角色同时持有该品类 read/update/fee.read。用户、成员、角色及公司均须有效，不跨角色拼接资格；允许有资格者自审。
- 事务内按 User → Membership → Role → 排序后的完整 Order 集合 → 子资源取锁，并在权威锁内重验权限、版本、费用快照和状态。
- 普通新增要求订单 ACTIVE、OPEN、未审核锁定并具备 create；修改与删除再要求当前有效费用没有有效账单关联，并分别校验 update/delete。
- 有效账单关联为活动账单行且所属账单未取消，包含 DRAFT。账单创建成功即禁止改费，不等待确认、开票或核销。
- 订单锁定后的新增、替换、调减、作废一律走费用更正申请；补审前正式费用及利润不变。解锁不释放账单占用。
- 已确认/已支付提成不再冻结整票费用；普通增改删必须在同事务执行经济重算及差额调整，保留已发事实。

## 4. 分批建账与七状态

- 建账不要求订单或整票费用先审核；可先建 A 供应商账单，再录 B 供应商费用。锁定订单的正式费用继续允许建账、收付、核销及对冲。
- 选中费用须为当前正式、需要账务处理的费用，无有效账单占用，且自身没有 PENDING 更正申请。某票的无关费用及 ADD 申请都不阻塞其他正式费建账。
- 单张、批量及费用台账三个入口复用相同服务端准入，并保留公司、方向、币种、结算单位、账户与整批原子性校验。
- 财务进度为账单关联的只读投影：未建账、未核销未开票、已开票未核销、已核销未开票、已开票部分核销、部分核销未开票、已完成。开票与核销并行，不新增手工费用状态机。
- 回退使用现有发票取消/红冲、反核销、取消/反对冲、账单取消，全部依实际依赖及权限办理；不能手改投影状态。

## 5. 错误与前端

| 场景 | 必须行为 |
| --- | --- |
| 审核期间费用内容或订单版本变化 | 409，刷新后重试，保留用户意见 |
| 订单锁定后普通改费 | 拒绝，提示申请补录补审 |
| 源费仍有有效账单 | 拒绝修改、删除、提交/批准更正，提示先回退 |
| 自身有待审更正 | 原费不可建账，无关费用继续办理 |
| 用户撤权、停用或不属于目标公司/品类 | 拒绝审核或补审，无部分写入 |

页面只展示未审核/已审核锁定；费用台账筛选使用 `order_locked`，订单列表复用 `is_locked`。
旧整票提交、撤回、批量审核、单独补录写入口不再出现。写入成功后刷新锁、费用、申请和财务缓存；失败不清表单及幂等键。

## 6. 必须验证

真实 PostgreSQL 验证未锁/已锁 × 未建账/DRAFT/CONFIRMED、分供应商建账、锁后建账、逐源费待审占用、
审核/编辑与建账/编辑竞争、撤权及故障回滚；SKIP 不算通过。前端验证逐费能力、delete-only 权限、
失败保留输入、公司切换迟到响应及七状态一致性。结清、建账、核销/对冲、删除最后未建账费用均不得自动审核锁单。
