# 公司英文名称与自签 HBL 抬头

## 1 适用范围

维护公司档案、默认公司种子、组织检索或 HBL 输出抬头时适用。公司英文名由管理员或用户明确规则确认，运行时不能从中文翻译、替换城市或按工作台猜测。

## 2 签名与字段

- Ent：`Organization.name_en`，可空字符串；biz：`AdminOrganization.NameEn`。
- `admin.v1.CreateOrganizationRequest`、`UpdateOrganizationRequest`、`AdminOrganization` 追加 `name_en`；Web 为 `nameEn`，沿现有组织管理 API 及权限读写。
- 当前 `SeaHouseBill.issuer_organization_name_en` 为只读投影（Web `issuerOrganizationNameEn`），来自真实 `issuer_organization_id` 的公司档案。
- 模板统一 `RONCIN_SELF`，不再识别旧 `RONCIN_BEIJING`；正文及印字写接口没有新增可改公司抬头字段。
- PDF 模型：`HblPdfModel.issuerNameEn: string`，必须显式提供。
- 正式迁移：`20261104100000_organization_name_en.sql` 新增字段及北京补值；`20261104110000_chengdu_company_name_en.sql` 按用户城市拼音规则补齐成都。

## 3 契约与数据流

- 只有 `kind=company` 可维护非空英文名；系统节点、部门和团队不维护或继承该字段。
- 输入 trim 首尾空白，保留大小写；最多 200 个 Unicode 字符，拒绝内部控制字符、换行和 Unicode 行/段分隔符。空值可保存，明确清空时前端发送空串，仓储清列。
- Ent 使用 `MaxRuneLen(200)` 与业务层和前端保持字符口径；不能使用按 UTF-8 字节计数的 `MaxLen(200)`，否则合法重音字符等名称会被落库校验误拒。
- 公司创建、编辑、列表及详情映射完整往返，更新其他字段不能漏传已有名称。沿用原有范围、事务、审计、本币及初始管理员规则，不新增组织版本字段。
- 组织检索键包含编码、中英文名和既有中文拼音；维护页用已有全量列表在客户端匹配英文名称。
- HBL 按真实签发公司投影抬头；不能从当前工作台、订单所属公司或模糊名称推断。普通制单人员不为此额外请求管理接口或取得管理权限。
- 缺名不影响同一 HBL 正文编辑/保存，但四种 PDF 输出均需明确补齐名称。客户/其他代理签发仍按未支持模板反馈；不从中文名、固定北京名或默认值回退。
- 页眉、PDF 作者、条款中的公司名称、签发区统一读取本次模型的 `issuerNameEn`，字体支持校验覆盖该字段；长名称正常折行并增加固定页眉与正文预留空间。
- HBL 变动指纹包含签发公司 ID、英文名和模板；名称变更同样触发前台 15 秒、回焦及输出前检查，保留输入和旧提交基线、关闭旧预览，刷新覆盖输入先确认。
- 公司英文名属于当前主数据，不写入 HBL 正文哈希或不可变历史；已有下载文件不随后续公司改名而修改。
- 北京既有公司通过正式迁移补入用户参考模板已确认英文名；成都依用户确认的城市拼音替换规则补入 `RONCIN (CHENGDU) SUPPLY CHAIN MANAGEMENT CO., LTD`。新环境种子仅在新建 BJ/CD 时写各自固定名称，不覆盖既有公司人工值或主动清空；未知公司仍人工维护。

## 4 校验与错误矩阵

| 条件 | 结果 |
| --- | --- |
| 英文名空白或明确清空 | 公司保存成功，HBL 仍可编辑但输出被阻止 |
| 名称超过 200 字符、含控制符或内部换行 | `ADMIN_ORGANIZATION_NAME_EN_INVALID`，不写入 |
| 非公司请求非空英文名 | 同上明确拒绝，不能经直接 API 绕过前端 |
| 更新公司其他字段 | 携带原英文名，不能意外清空 |
| 公司英文名变化而 HBL version 未变 | 仍提示变动并阻止旧抬头输出，保留输入 |
| PDF 名称缺失或字体无法表示 | 明确提示具体问题，无旧名称回退 |
| 公司种子再次执行 | 既有名称及主动空值保持原样 |

## 5 正常、基准与错误场景

- 正常：成都按用户规则补齐名称后，HBL 四版本的抬头、条款及签发区均使用该名称。
- 基准：北京、成都经正式迁移各自补齐确认名称；保留非空人工值，不修改未知公司或 HBL 正文/历史。
- 正常：操作员打开 HBL 后管理员改公司名，页面提醒并保留未保存货描，刷新确认后采用新名称。
- 错误：以工作台英文名冒充另一公司签发主体；空名称时套用北京；普通公司修改导致英文名被遗漏清空。

## 6 必需验证

- biz/service：公司英文名创建/更新/清空往返、Unicode 长度边界、换行/控制符、非公司拒绝。
- PostgreSQL：正式迁移前态升级与北京/成都准确补值、非空人工值及非目标组织不变；组织范围与原子审计；真实 HBL 签发主体读取；种子幂等且不覆盖人工修改/清空。
- Web：新建/编辑/清空、拓扑与树表详情、英文搜索、非公司隐藏；缺名可保存但四版本阻止；名称变更提示/关闭旧预览/保留输入/确认刷新/输出前校验。
- PDF：不同公司、作者及条款中无北京常量、200 字符长名及正文极值，逐字数量/坐标/实际图片验证；同 Blob 预览下载打印。
- 契约与 Ent 正规重生成后内容稳定，最终全栈门禁及生产构建通过。

## 7 错误与正确实现

错误：`issuerCode == "BJ"` 才给模板，PDF 运行时常量永远使用北京英文名。

正确：按真实签发公司判定自签模板并投影 `issuerOrganizationNameEn`；PDF 完整消费显式传入名称，缺名反馈维护入口，生成前重新检查基线。
