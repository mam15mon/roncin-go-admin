# 海运 HBL 制作与 PDF 输出

## 1. 适用范围

修改海运出口 HBL 的制作资料、入口、PDF 模板或历史版本时，除海运单证原有契约外同时遵循本文。业务结果为同一份真实 HBL 的编辑、预览、打印与 PDF 下载，不是另一份打印稿，也不是放货凭证登记。

自签模板统一为 `RONCIN_SELF`：适用于真实签发主体为公司（`kind=company`）的本公司签发 HBL，不按 `BJ` 等公司编码限制。英文抬头来自该 HBL 的真实签发公司 `name_en`；不能用当前工作台、订单归属公司或固定北京名称代替。公司字段及迁移规则见[公司英文名称](./company-english-name.md)。客户和其他代理签发模板不在本期范围。

## 2. 签名与入口

- 制作页：`/orders/sea-export/:id/hbl`；路由沿用 `canReadSEOrders`，切换组织回海运列表。
- 查询沿用 `GET /api/v1/orders/{order_id}/sea-documents` 与订单详情。
- 保存沿用 `PUT /api/v1/orders/{order_id}/sea-documents/house-bills/{id}`，请求带 `expected_version`、`expected_link_version` 和完整 `house_bill`。
- Protobuf 源：`server/api/order/v1/sea_document.proto`，新增 `SeaHouseBillPrintDetails`；`SeaHouseBill`、`SeaHouseBillInput`、`SeaDocumentVersion` 携带 `print_details`，当前 HBL 另返回只读 `print_template` 和 `issuer_organization_name_en`。
- Ent 当前表 `sea_house_bills.print_details` 与不可变版本表 `sea_house_bill_versions.print_details` 为可空 JSONB，正式迁移为 `20261104090000_sea_house_bill_print_details.sql`。
- 固定 JSONB PO 定义在 `data/ent/schema/sea_house_bill_print.go`，biz 纯 Go 对象在 `biz/sea_house_bill_print.go`，service 逐字段转换，不跨层泄漏类型。

## 3. 数据与输出契约

### 同一 HBL

收发通知人、货描、唛头、件重尺、条款仍由 `SeaBillContent` 管理。`print_details` 仅补充本票印字：联系方式、订舱号/参考、前后程运输与收货地、原产地、船名港口印字、箱号文字、正本份数、装船日、签发地日、交货联系人和页脚参考。

普通保存、创建、改单、审核快照、作废、模式切换与历史 DTO 都要完整传递新字段。HBL 内容哈希、改单差异及请求指纹覆盖印字。历史记录读取自己的 JSONB，不回读当前 HBL；不能只在新制作页保存成功，回订单再保存却把印字清空。

没有已保存印字时，首次展示可从已保存订单带入订舱号和运输名称；初始化不标脏，后续手工值不被来源刷新覆盖。运输印字只写本票，不修改共享主单/航程。箱号带入只能来自实际箱与本票的共享箱分配，权限不足或加载失败明确反馈，不以箱计划或其他订单代替。

### 审核与权限

草稿、正本、电放、副本均可由操作人员选择，**不以利润审核锁单为输出前置条件**。输出标识不修改 `release_type`、`bill_form`、审核状态或 HBL 状态，不代表系统办理了电放或电子签章。

已有审核锁、生命周期和普通编辑规则继续约束写入；锁定单仍可按读权限预览、打印、下载已保存内容。保存复用 `WithTx`、`Order → MBL → Active Link → HBL` 和 HBL/Link 预期版本，不另设写事务或绕过锁单。

制作表单前台默认 15 秒检查变化，回焦立即检查，后台暂停。签发公司 ID、英文名及模板也进入指纹，公司的主数据变更不依赖 HBL 版本变化才被发现；发现变化关闭旧预览。发现变化保留输入、持续提示，不能自动推进提交基线；刷新覆盖未保存编辑先确认。组织、用户、订单切换后清理旧查询和 PDF，不能保留可提交到旧目标的闭包。

### PDF

使用按需加载的 `@react-pdf/renderer`，同一个生成 Blob 用于预览、下载和浏览器 PDF 打印入口。不得另画一份网页打印版导致内容不一致，也不把表单本身当提单打印。

公司名称作为 `HblPdfModel.issuerNameEn` 传入页眉、作者、条款和签发区，缺名或字体不支持明确阻止输出。页眉按实际名称折行数预留空间，不截断正式英文名。

模板为 A4 竖版，常规数据单页，长地址/货描/箱号/联系人正常续页；各页显示 HBL 号、版本标识和页码。大段正文不能整体设成 `wrap={false}`，不能靠隐藏溢出、截图或无限缩小字体保单页。固定页眉页脚只放有界标识，长联系方式/参考应进入可分页正文。

当前 renderer 的超高并排单元格跨页重排会压缩或裁切内容；使用按字体列宽保守折行的 `FlowTable`，逐行提交短表格行，只有一行不可拆分。极值验证同时核对字符总数、坐标和实际图片，不能仅检查末尾标记。页脚号码摘要折叠连续空白，正文 B/L NO 保留原号及换行，不改写持久化内容或截断号码。

字体从本站同域加载，嵌入静态中文字体，不运行时访问第三方 CDN；授权、来源及再生方法随资产记录。PDF 必须实际渲染看图；可提取出中文不意味着实际显示正确。版本变化、重试、关闭和换单时不得下载上一份结果。

## 4. 校验与错误矩阵

| 条件 | 要求 |
| --- | --- |
| 短印字超过 500 字符，说明/联系人超过 3000，箱号文字超过 12000 | biz 拒绝，`SEA_HOUSE_BILL_INVALID_ARGUMENT`，零写入 |
| 正本份数不在 0～99 | 明确拒绝；空值和显式零不同 |
| 装船日/签发日不是合法 `YYYY-MM-DD` | 明确拒绝；不从 ETD、当前日期或样例补齐 |
| 缺可选印字 | 可以保存和输出；缺项留空，不新设正本/电放必填门槛 |
| 签发公司未维护英文名称 | 允许制作编辑和保存，禁止四版本预览/打印/下载，明确提示补齐公司档案；不能回退中文名或北京名称 |
| 无真实 HBL、直单或模板主体不适用 | 明确反馈，不伪造 HBL、不转换单证模式 |
| 版本变化或订单锁定，提交制作修改 | 沿用原有冲突/业务锁错误，不能部分写入 |
| 订单锁定，仅预览或下载 | 按已有读权限可用，不要求先撤销利润审核 |
| 字体无法表示输入字符 | 提示具体字段，保留输入，不悄悄显示空白字形 |
| PDF 生成失败/版本变化/请求迟到 | 错误与重试明确，不输出旧文件，不跨单覆盖 |

## 5. 正常、基准与错误案例

- 正常：任一自签公司已维护正式英文名的 HBL 在制作页调整货描、填写实际装船日，保存后订单中看到同样内容，再选择电放版导出；订单审核状态不变。
- 基准：锁定 HBL 从未维护过印字，仍能用已保存正文和订单资料预览四种版本，可选印字空白，不强制解锁保存初始化值。
- 正常：120 行货描、多个箱号和中英文地址续页完整，预览/下载/打印内容一致。
- 错误：把成都公司自签 HBL 统一冠以北京抬头，或把样例客户、日期、联系人留在模板底图中。
- 错误：制作页保存印字后，订单普通保存的完整 HBL 载荷遗漏该字段，造成已有印字被清空。

## 6. 必需验证

- biz/service：19 个补充字段往返、零和空、长度/日期/控制字符边界。
- data/PostgreSQL：正式迁移仅增加目标列；普通更新/整单保存、哈希、版本冲突、锁定阻断、审计原子性、历史快照及拆票原票/新票语义。
- Web：公司英文名维护/清空、缺名输出阻止但仍可保存、英文名外部变化与输入保护、入口、真实目标、模板范围、保存失败/冲突保留输入、四版本不受利润审核限制、15 秒及回焦检查、组织/订单隔离和首次初始化不标脏。
- PDF/浏览器：中英文实际字形、正常单页、超长字段续页、末尾文字不丢、HBL 号/页码/版本标识、同一 Blob 下载打印、字体同域及失败重试。
- 新增 PDF 依赖、字体和路由需要生产构建验证；普通页面首屏不应拉取 PDF 字体和渲染器。

## 7. 错误与正确实现

错误：把四种版本做成审核后的按钮；另存可自由编辑打印稿；以下载按钮点击或文件非空当成打印验收。

正确：输出版本只控制同一 HBL 的文件表现，写入继续受原有权限、锁和版本保护；用实际保存往返、完整 PDF 提字、独立渲染图片及浏览器路径验证闭环。
