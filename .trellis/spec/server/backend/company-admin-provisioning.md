# 公司初始管理员初始化与补齐契约

## 1. 适用范围

适用于手工创建公司、默认公司种子、bootstrap-admin 及 sync:dev 的必要公司初始化调用。仅补齐 `users.is_bootstrap_admin=true` 标识的唯一初始管理员，不授予后来创建的普通系统管理员公司资格。

## 2. 签名

```text
pnpm run bootstrap:admin
go -C server run ./cmd/bootstrap-admin --seed-branches
pnpm run sync:dev  # 先完成 bootstrap
```

```go
data.BootstrapAdministrator(ctx, tx, BootstrapAdministratorInput)
data.AdministratorProvisioningSummary // 只在事务提交成功后报告
BootstrapAdministratorInput.HashPassword func(string) (string, error) // 命令入口提供，重复补齐不调用
```

首次环境变量：DATABASE_SOURCE、BOOTSTRAP_ADMIN_USERNAME、BOOTSTRAP_ADMIN_DISPLAY_NAME、BOOTSTRAP_ADMIN_PASSWORD；系统组织由 BOOTSTRAP_ORGANIZATION_CODE/NAME 配置。重复补齐不需要首次密码和姓名，非空用户名必须与唯一初始管理员一致。

## 3. 契约

- 非空用户表只能找到唯一启用且非待分配的初始管理员；不按用户名、administrator 角色或普通同名账号推断。
- 密码工具由 cmd 入口注入首次 HashPassword 回调，data 不导入 security 包；仅空账号锁内首次创建分支调用，缺少回调明确失败，重复补齐不处理密码。
- 首次账号、系统工作台、默认 BJ/CD 公司、成员、角色绑定和权限目录在同一事务建立；旧公司保留配置，所有实际存在的有效公司也纳入本次补齐。
- 手工创建 company 在同一事务建立公司、公司管理员角色、初始管理员公司成员和绑定。缺少有效初始管理员时公司创建失败，不留下半套数据。
- 手工公司创建要求初始管理员的系统成员、管理员角色及绑定已经完整且有效；缺失明确要求先运行 bootstrap 补齐，不在建公司时顺带修复系统资格。系统工作台必须唯一；已有身份时缺失或多个系统工作台均拒绝，sync:dev 不自动重建系统工作台。
- 角色库归公司根工作台，部门和团队不重复创建管理员成员。新增公司管理员权限由 Manifest 过滤系统专属权限；系统权限不自动成为公司权限。
- 已有成员/绑定复用，缺少时追加；不清空该成员其他角色，不更改账号密码、姓名、角色名称。可用 administrator 角色补齐清单缺少的合法权限；跳过项不改角色配置。
- 初始账号或系统必要资格不可用属于全局失败。停用公司、公司角色或既有公司成员是明确跳过，保持状态并报告需人工恢复；旧 self 角色已由范围退役迁移显式停用，补齐不得重新启用，也不能新建替代绕过停用。
- 已有身份分支先锁初始 User，再锁组织、成员和角色，各类多行按主键排序；初始用户锁序列化公司创建与补齐。空账号路径锁内复核账号表，唯一索引兜底冲突，不自动重试。
- 管理员角色预检使用 FOR NO KEY UPDATE，从首次读取即阻止状态/配置并发写，避免共享锁升级；该锁与权限清单同步插入关联所需的外键 KEY SHARE 相容，防止角色独占锁与权限目录更新反向等待。
- sync:dev 先按主键排序独占锁定所有现有用户，再补公司和开发员工；不能先持初始管理员锁后才锁员工，否则会与按用户排序的批量授权形成反向等待。新建用户尚不可见，无需另锁。
- 预检在任何授权写入前完成，成功审计同事务；数据库失败全回滚。摘要区分 CompaniesCreated/MembershipsCreated/BindingsCreated/Satisfied/Skipped，存在跳过时不声称全部授权成功。
- 普通权限目录同步与本次补齐分离：bootstrap 不调用会修改全部 administrator 角色的全局角色同步，而在同一事务同步清单并仅处理本次有效工作台。

## 4. 校验与错误矩阵

| 条件 | 结果 |
| --- | --- |
| 用户表非空且无/多个初始管理员 | ADMIN_BOOTSTRAP_IDENTITY_INVALID，零授权写入 |
| 初始账号停用或待分配 | ADMIN_BOOTSTRAP_INACTIVE，零授权写入 |
| 配置用户名冲突 | 明确失败，不改身份 |
| 系统工作台无效或必要资格停用 | ADMIN_BOOTSTRAP_SYSTEM_INACTIVE，零授权写入 |
| 手工建公司时初始管理员系统成员/角色/绑定缺失 | ADMIN_BOOTSTRAP_SYSTEM_REQUIRED，先运行 bootstrap 补齐 |
| 公司/管理员角色/管理员成员停用 | 摘要 Skipped，人工恢复后重跑 |
| 缺成员、角色或绑定 | 同事务补建，保留其他授权 |
| 后续公司或审计写入失败 | 本次全部可处理项回滚，不返回成功摘要 |

## 5. 正常、基准与错误场景

- 正常：初始管理员只在系统管理；重复 bootstrap 为实际启用公司追加成员和管理员绑定，能通过真实成员候选切换进入。
- 基准：重复两次，密码哈希/姓名及成员数量不变；普通系统管理员不被自动加入新公司。
- 错误：按同名员工接管身份；停用管理员角色时建立另一个管理员角色；通过 bootstrap 标记直接绕过成员资格。

## 6. 必要验证

- 首次空账号及保留公司的初始化、重复幂等、不改密码/姓名、无/多身份与用户名冲突。
- 新公司与种子同构、默认仅 BJ/CD、所有实际公司覆盖、部门/组无重复成员。
- 停用账号/系统资格无授权写入，公司/角色/成员停用保持并明确跳过。
- 后段失败和审计失败整批回滚；公司创建与补齐并发后成员、绑定完整且无重复。
- ResolvePrincipal 和工作台候选验证实际准入及公司权限过滤，不只断言角色数。

## 7. 错误与正确示例

```text
错误：公司只建管理员角色，无成员；bootstrap 重复执行重设密码；停用项自动恢复。
正确：角色+初始管理员成员+绑定同事务；重复只补缺项；停用项保留并报告。

错误：初始化预检前先全局同步管理员权限；跳过公司后输出“所有公司授权成功”。
正确：锁内预检后仅处理有效计划；提交后摘要明确新增、已满足和跳过。
```
