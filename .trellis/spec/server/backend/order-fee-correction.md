# 锁后费用补录补审与账务回退

## 1. 适用范围与契约

六类订单人工审核锁定后，通过 `OrderFeeCorrectionRequest` 统一办理 ADD/REPLACE/VOID；调减是 REPLACE 的金额变化。
原只支持应付新增的独立补录写流程已退役。已结案订单仍可受控补审，订单终止限制保留。
同票已有待审申请阻止结案及解锁；批准不解锁、不反结案。

- API：Create/List/GetOrderFeeCorrectionRequest(s)、PreviewOrderFeeCorrectionApproval、Approve/Reject/WithdrawOrderFeeCorrection。
- 创建字段：`operation`、可选 `source_fee_id/source_fee_expected_version`、正数 `target_fee`、原因及幂等键。
- 申请保存 `lock_record_id/lock_generation`、源费版本、前后快照、申请人/决定人及版本。
- 预览/批准绑定申请版本与 `preview_token`，令牌复核费用、人工锁依据、财务事实及提成影响；批准保存当时利润及提成快照。

## 2. 先回退原账务，再申请补审

- REPLACE/VOID 的源费在提交、预览和批准时均必须没有有效账单占用；DRAFT 也占用。不能对仍已建账原费直接生成冲回账务来绕过回退。
- 新增 ADD 无须回退其他费用；申请内容批准前不进入正式费用、利润及建账候选。
- 回退使用原接口：发票草稿取消或已开票红冲、反核销、草稿对冲取消或确认对冲反转，清除依赖后再取消整张账单。
- 失败提示应包含实际阻断单据及下一动作。合并账单/发票按整单回退，操作前明确受影响订单和费用范围，不提供静默单行拆账或一键自动回退。
- 反核销释放分配，不等于实际退款。资金流水、票据及已发提成保留；取消账单后重新读取源费版本再申请。
- 订单未锁时回退后可按普通权限维护；订单仍锁定时须补审通过才生效。

## 3. 正式费用与历史

- 同票最多一份 PENDING 申请；它仅阻止自身引用的源费用建账，无关费用继续办理。ADD 待审不占用任何既有费用。
- 批准在同一事务标记原费 superseded、保留历史冲回（accounting_required=false），并按操作创建替代或新增正式费用。作废不创建零金额账单。
- 当前经济费用仅为未被替代的 INCREASE；历史冲回与现行费用不可混入同一汇总。
- 订单费用内容版本递增；人工 OrderLockRecord 的原审核快照保持不可变，每次补审人及批准结果保存在申请与审计。
- 解锁后的当前有效替代费用若未建账，可按普通权限修改/删除；已被替代的历史原费不可普通修改、删除或转移。
- 历史已结束的旧整票审批、补录与既有更正账务只供审计追溯，新写入不恢复旧状态机。

## 4. 权限、事务与并发

- ADD 使用目标品类 fee.create，REPLACE 使用 fee.update，VOID 使用 fee.delete；前端对应动作分开授权。
- 批准/退回使用同公司目标品类的有效 lock grant，原审核人和另一合格人员都可补审，不要求 locked_by 本人。撤回仅本人可办。
- 用户、公司、成员及角色即时有效，同一 grant 具备必要 read/update/fee.read/lock；不以角色名、旧 system.finance.fee.review 或 bootstrap 身份替代。
- 仅本人查看能力时逐条及列表都按 requested_by 限定，不因同票有一条本人申请暴露其他申请。
- 审核授权父行 → 排序后的完整经济关联 Order 集合 → 申请/费用及提成子资源；订单闭包锁内重验，变化则 409，不中途补锁。
- 建账/申请、批准/撤回、批准/发放、回退/批准、解锁/申请在共同权威锁内串行化。版本、预览或权限过期返回冲突，所有费用、申请、系统调整、审计与通知零部分写入。
- 同键同意图提交及同版本同令牌批准重放只返回原事实，不重复生成费用或调整。

## 5. 提成与历史清偿

当前费用按统一经济投影重算，保留原员工/规则/已支付及人工奖惩；系统差额规则见 [提成保护](./finance-commission-lock.md)。
旧经济链的退款、对冲、行级清偿仍按 `source_fee_id` 及实际分配读取：内部更正对冲不新增收入，成本冲回收款不冒充营业收入。
不得用合并账单余额侵占其他订单，或用旧客户/旧币种收款当作新对象付款。
本轮补审源费已未建账，批准不自动执行财务资金动作。

## 6. 错误与验证矩阵

| 场景 | 行为 |
| --- | --- |
| 未人工审核锁定或锁代次不一致 | 拒绝新申请/批准 |
| 原费仍有草稿或确认账单 | 提示先回退，零写入 |
| 原费版本、预览、提成事实变化 | 409，刷新预览且保留意见 |
| 跨公司、其他品类、撤权或停用 | 拒绝补审 |
| 更正后亏损且无意见 | 拒绝批准 |
| 本人以外撤回或同票另有待审 | 拒绝 |
| 同版本同令牌重放 | 返回原结果，不追加事实 |

功能后补验证，禁止 TDD。真实 PostgreSQL 覆盖 ADD/REPLACE/调减/VOID 的待审不生效与一次批准、
草稿/开票/部分及全额核销/对冲依赖、合并单据范围、解锁/结案、四类提成支付状态及竞争/故障回滚。
前端验证 canCorrect 源费禁选、分别授权、版本令牌透传、失败保留输入与幂等键；SKIP 不算通过。
