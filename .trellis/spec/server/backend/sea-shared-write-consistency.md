# 海运共享资料写入一致性

### 1. 适用范围

关联已有 MBL 创建操作票、修改共享箱资料/撤销确认、整票改配到其他航次时适用。
这些入口不得绕过共享资料的审核锁，也不得把货物分配遗留在旧航次。

### 2. 接口与签名

- 创建：`CreateOrderRequest.sea_master_bill.candidate_id` 与
  `sea_document.master_bill_content`。
- 共享箱：`SeaSharedContainerRepo.Update` / `Withdraw`，均携带箱 `expectedVersion`。
- 改配：`GetChangeActions`、`PreviewReassignment`、`ExecuteReassignment`；
  `target.target_type = NEW` 可表达同母单的新运输执行。

### 3. 行为契约

- 关联已有母单只提交本票 HBL 与关联信息，前端不提交默认或手填的母单正文。
  服务端显式拒绝候选关联夹带 `master_bill_content`，不能静默忽略；独立新建
  母单仍正常保存正文。候选母单已作废时拒绝关联。
- 加票不改变既有母单正文、内容版本或任何已有订单的审核状态。母单正文修改
  只能经过已有的版本与全部成员审核锁门禁。
- 共享箱资料修改及撤销确认先按主键锁定锚点与全部分配成员订单，复用
  `ensureOrderBusinessContentEditable`，再锁箱并重验成员集合；成员变化则冲突退出，
  禁止锁箱后补锁新成员。全部检查、箱版本递增及审计在同一事务完成。
- 本票仍有任何 `SeaSharedContainerAllocation` 时禁止整票改配，草稿和已确认
  分配均占用。动作资格、预览、执行采用同一存在性判定；执行在订单写锁之后
  重验，防止并发新增分配。提示先撤销共享箱确认并移除本票分配，不自动搬运或删除。
- NEW 目标的船公司与规范化母单号都等于原母单时，保留原 MBL，仅新建运输执行，
  结束旧 Link 并创建新 Link；HBL 身份和历史按既有改配契约保留。其他 NEW 和
  CANDIDATE 仍执行各自既有校验，不能通过号相似或空字段推测复用。

### 4. 校验与错误矩阵

| 条件 | 结果 |
| --- | --- |
| 候选加票夹带母单正文（包括空对象） | 400 `SEA_DOCUMENT_INVALID_ARGUMENT`，整单零写入 |
| 候选母单已作废 | `SEA_DOCUMENT_VOIDED`，不建立新关联 |
| 共享箱任一分配成员审核锁定或进入终止流程 | 沿用订单业务锁/终止错误，箱状态、资料、版本不变 |
| 共享箱锁后成员集合变化或箱版本过期 | `SEA_SHARED_CONTAINER_CONFLICT`，不补锁/不写入 |
| 整票改配存在共享箱分配 | 409 `SEA_ORDER_REASSIGNMENT_BLOCKED`，旧 Link、HBL 和事件不变 |
| 同母单 NEW 新航次 | 保留 MBL ID，新增 TE 和活动 Link，预览与执行一致 |

### 5. 正常、基准与错误场景

- 正常：A 票已维护母单正文并审核，创建同母单 B 票只增加关联，A 的正文与审核保持原样。
- 正常：同母单新航次改配后仍是一张 MBL，旧 Link 可追溯，新 Link 指向新 TE。
- 基准：先撤销确认并移除本票共享箱分配，再执行合法改配。
- 错误：从未锁 B 票修改共享箱，间接改动已锁 A 票的箱号或封号。
- 错误：只在预览检查分配，执行时不重验；或前端不传正文但 API 仍可覆盖。

### 6. 必需验证

- 实际创建路径：新 MBL 正文可保存；已有 MBL 的默认/不同正文被拒且无部分订单；
  省略正文可加票，原 MBL 正文、版本与已锁成员状态保持不变。
- 前端：候选创建载荷省略母单正文，独立创建保留；候选模式不能引导用户编辑不提交的正文。
- 真实 PostgreSQL：已锁/终止成员阻断共享箱 Update/Withdraw、全员可编辑时通过；
  箱版本冲突及并发成员变化拒绝，失败无部分状态与审计。
- 改配：草稿/确认分配均阻断，移除后通过；锁内复验不依赖先前预览；同母单新航次
  成功且重放不生成重复 TE/事件，其他 NEW/CANDIDATE 相邻路径正常。

### 7. 错误与正确实现

错误：`candidate_id` 命中后仍把创建表单默认 `master_bill_content` 写到共享 MBL。
正确：候选路径显式拒绝正文载荷，前端只发送本票数据；改正文走专属写入口。

错误：共享箱只锁箱自身；改配只更新 Link/HBL，不检查旧分配。
正确：以成员订单锁串行化共享箱修改和改配，锁内重验成员及占用，所有失败整体回滚。
