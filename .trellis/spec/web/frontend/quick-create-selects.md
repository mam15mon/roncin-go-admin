# 下拉候选快捷创建

## 1. 范围与触发

业务录入过程中需要的档案不存在时，在下拉底部提供新增入口，创建成功后选用该档案，保留原业务表单的其他输入。当前范围如下：

| 档案 | 接入位置 |
| --- | --- |
| 费用科目 | 订单费用行已有入口；费用补录与更正表单补齐 |
| 往来单位 | 费用补录与更正、批量修改结算单位、收付登记、核销、进口换单代理、海运分单第三方签发合作方、企业资源单条与批量关联 |
| 结算账户 | 建账工作台和账单编辑 |
| 开票抬头 | 独立发票登记与建账组内共用的登记编辑器 |
| 货物或应税劳务 | 公司费用科目维护和快捷新增费用科目 |

不把固定状态或条款改为可维护字典；不改变公共主数据只能由系统管理工作台写入的边界；不修改历史发票抬头快照。

## 2. 组件与接口

- `@/components/ui` 的 `QuickCreateSelectFooter({ children, label, onCreate, disabled })` 仅组合候选菜单与新增按钮，不包含领域请求或权限判断。
- `@/features/partners` 的 `PartnerQuickCreateSelect` 遵循受控 Select 的 `value/onChange` 协议；`sessionIdentity` 表示来源会话，`active` 表示父弹窗是否打开，`role` 固定业务身份；未固定角色时按 `defaultRole` 预选一个身份。远程候选按当前公司身份门控，关键词去空白并防抖 300ms，保留加载态与满宽控件。
- `resolveCreatedOption(partner, signal)` 用于财务等有专用候选接口的入口。新建档案仍须满足当前用途的候选资格。
- `@/features/finance/settlement-party-options` 的 `searchFinanceSettlementPartnerOptions` 共用收付和核销的用途查询与稳定候选映射。
- `@/features/finance/fee-catalog` 公开 `FeeSettingQuickCreateModal` 和 `TaxableServiceQuickCreateSelect`；订单原快捷新增弹窗作薄包装，不能让费用设置页面反向导入订单页面。
- `@/features/partners/settlement-account` 公开 `SettlementAccountQuickCreateModal` 与 `settlementAccountLabel`，建账和账单编辑共用。
- `InvoiceProfileQuickSelect` 留在发票登记领域内部，由 `InvoiceRegistrationEditor` 组合；独立登记和建账内登记自然共用。

业务写入继续调用 OpenAPI 生成客户端；不新增平行接口，不手改生成物。

## 3. 创建与回填契约

- 创建动作同时校验当前公司、创建权限及父级编辑状态。无身份、系统工作台、失权、父级禁用或受保护单据均不可借新增入口写入。
- 往来单位沿用单身份快捷建档：上下文可固定供应商等身份，其他入口允许单选客商类型，默认勾选单次合作。多角色维护仍在主档完成。
- 单选创建成功替换当前值；多选追加且按 ID 去重。新选项保留名称与候选元数据，不让字段退化为只显示 ID。
- 费用科目创建成功后，补录表单按普通选项选择的同一入口带入币种和计费单位、更新汇率与数量校验；不清空补录原因、单价等无关输入。
- `taxRate` 和应税劳务 `defaultTaxRate` 均为百分数文本，6% 提交 `"6"`，禁止提交 `"0.06"`；科目创建的 `taxableServiceId` 必填。
- 账户绑定来源结算单位、原币及应收/应付用途，不允许在快捷表单中改挂其他单位或币种。
- 新开票抬头选中后沿用原 `applyProfile` 规则带入默认票种；用户已手选的票种保留。专票要求登记地址、电话、开户银行和账号齐全；已有发票修订的抬头保持只读。
- 子弹窗通过 Portal 渲染自己的表单，`QuickCreateModal` 以 `useId` 生成独立 Form 名称，防止父子同名字段的 DOM ID 和标签关联冲突；新增操作不提交父业务表单。新增失败不重置输入，不关闭表单。
- 弹窗取消、父会话关闭、公司/来源/用途变化及卸载均使旧请求失效；按请求所属会话核验后才执行回填。关闭后重开同一对象也属于新会话。
- 创建已成功但专用候选确认失败时，后续重试只确认并选用已创建档案，不重复创建。
- 只使相关档案候选缓存失效，不因创建一条候选刷新整张业务草稿或替换编辑版本基线。

## 4. 校验与错误矩阵

| 场景 | 结果 |
| --- | --- |
| 有权限、当前公司、可编辑 | 下拉底部显示新增；保存后选用新档案 |
| 无权限、父级禁用、受保护账单 | 无可操作的新增入口，不发写请求 |
| 请求层已处理的失败或空响应 | 保留输入，不触发成功或二次技术错误 |
| 成功响应缺少档案 ID | 明确提示契约错误，不能伪装新增成功 |
| 财务候选不合资格或信用控制禁用 | 不能自动选用刚创建的档案 |
| 关闭、换公司/实体/用途后旧请求返回 | 不回填、不关闭或重置新表单 |
| 多条发票移除或重新排列 | 返回结果仍只属于原登记记录，不写入新占据同索引的记录 |

## 5. 正常、基础与错误场景

- 正常：在费用补录中创建科目，自动选中该科目并带入币种、单位，原原因与单价仍保留。
- 基础：费用设置表单中已有应税劳务继续正常选择；新增入口只在具备创建权限时出现。
- 错误：创建结算单位后直接塞入核销候选，绕过原用途接口及信用限制；或通过刷新整个表单取得新选项并覆盖草稿。

## 6. 验证要求

功能实现后覆盖成功回填、失败保留、缺 ID、权限与禁用、公司及会话变化的迟到响应、多选追加、父表单不误提交。分别验证费用科目百分数载荷、应税劳务嵌套创建、账户币种与用途、抬头专票必填及手选票种保护。公共能力提取后运行架构检查、类型检查和风险匹配的前端门禁；不能用全字段 mock 代替真实省略默认值的响应。

## 7. 错误与正确

```tsx
// 错误：创建一项候选后重置业务表单，覆盖用户未保存输入。
form.resetFields();

// 正确：先核对当前会话和候选资格，仅更新触发字段及其明确依赖。
form.setFieldValue('settlementPartyId', option.value);
```
