# 疑似重复逻辑发现

## 1. 使用场景与边界

新增共享能力前、怀疑多处复制了同一业务规则时，运行函数级扫描辅助代码审查。覆盖前端手写 TS/TSX/JS/JSX 与后端手写 Go，分别在各语言内比较；排除测试、生成物、依赖与构建产物，保留手写 Ent schema。

扫描结果只证明特定规范化方式下的结构相似，不证明业务等价；没有结果也不代表没有重复业务规则。不得根据报告自动合并代码。

## 2. 命令

在仓库根目录运行：

```bash
pnpm run report:duplicates
pnpm run report:duplicates --format json --output /tmp/roncin-duplicates.json
pnpm run report:duplicates --min-nodes 100
pnpm run report:duplicates --baseline scripts/duplicate-baseline.json
```

`--format` 为 `text`（默认）或 `json`，`--min-nodes` 为正整数（默认 60），`--output` 可选；省略时写标准输出，不在仓库生成文件。程序消费输出宜使用 `--output` 文件，避免 pnpm 命令提示混入 JSON。

命令需 Node.js、pnpm 与 Go 工具链；只解析本地源码，不启动应用、不连接数据库、不调用外部模型。

### 定期周报与基线

`.github/workflows/duplicate-report.yml` 每周一 11:00（北京时间）自动扫描并与已提交的基线 `scripts/duplicate-baseline.json` 对比，产出「新增 / 消失 / 成员变化」增量写入运行摘要；疑似重复本身不使工作流失败，扫描或解析错误才失败。对比只看重复组指纹与成员位置，文件/函数计数随仓库自然漂移不报变化。

基线维护：有意提取重复或确认新增合理重复后，运行 `pnpm run baseline:duplicates`
重新生成（只保留 `groups`，不带 exactOnly 等易漂移明细）并随代码同一提交，周报即可
继续以新基线报告增量。基线是审查快照不是绩效指标，不为清零而清零。

## 3. 匹配契约

- 相同结构比较移除位置、注释和格式，保留字面量、操作符、属性、类型与外部符号。
- 局部改名比较按词法绑定处理参数及局部变量，不能全局替换所有标识符。
- 无法可靠处理的绑定结构仅参与相同结构比较，并在结果统计中说明。
- 默认最小函数阈值为 60 个语法节点；阈值与扫描范围必须随报告记录。
- 输出位置、符号、匹配依据和覆盖统计，不复制整段源码到报告。

JSON `version: 1` 包含 `modes`、`minNodes`、`roots`、`statistics`、`limitations`、`exactOnly`、`groups`、`errors`。每组包含语言、匹配模式（`exact` / `renamed`）、指纹、节点数、文件数、证据与成员；成员提供 `path`、`symbol`、`startLine`、`endLine`，不包含完整源码。统计中列出只参与 exact 的函数，便于识别覆盖限制。

JS 的 JSX、解构、var、嵌套函数声明、switch、计算方法名等复杂绑定采用保守 exact-only；Go 匿名函数不单独列为候选，但仍参与外层结构比较。局部类型和匿名结构体等 Go 复杂绑定同样仅参与 exact。准确范围以报告 `limitations` 与各函数原因字段为准。

## 4. 验证与错误矩阵

| 情况 | 处理 |
| --- | --- |
| 扫描成功，无候选 | 成功退出，明确说明覆盖范围 |
| 扫描成功，有候选 | 成功退出，供人工审查，不作为重复违规阻断 CI |
| 解析失败、无效参数、缺少工具链或读取失败 | 非零退出，明确失败原因，不能当作零重复 |

## 5. 正常与异常案例

- 两个函数只修改局部参数名称且绑定关系相同：可列为改名候选。
- 字面量、属性名、外部调用不同：不能列为完全相同结构。
- 同样的 DTO 转换出现在不同实体：即使结构相同，也需先核对领域、类型与演进原因，允许保留独立实现。

2026-09-20 首轮实仓审查结论：8 组候选中 5 组确认为同义重复并已提取共享实现
（汇率模板下载、财务组织 ID 校验、业务标签列渲染、订单费用候选合并、汇兑损益
展示）；3 组判定合理重复保留——跨 v1 协议的业务标签 DTO 映射 ×2 与跨层
（server/service）订单类型枚举映射，合并会引入反射/泛型框架或双向层间依赖。
`validFinanceOrganizationIDs`（严格口径：拒绝重复 UUID）与
`validFinanceBillOrganizationIDs`（宽松口径：允许重复）为语义差异的合法共存，
不得在后续重构中顺手统一。

## 6. 必要验证

工具实现后补充相同/局部改名、作用域遮蔽、闭包、属性简写、外部符号与字面量差异、生成物与测试排除、解析失败、稳定排序和 JSON 输出测试。`pnpm run test:duplicates:web` 纳入 `check:web`，`pnpm run test:duplicates:go` 纳入 `check:server`；全仓扫描按需执行，普通前端门禁无需 Go 工具链。

## 7. 错误与正确做法

错误：报告列出两个相似仓储函数，就抽象成跨实体通用仓储或修改其事务流程。

正确：先看两处源码及其调用方，核对是否同一业务含义、权限和事务边界，再决定提取最小共享部分或记录合理重复。把结论与报告位置一同保存，禁止把相似组数量当作必须减少的绩效指标。
