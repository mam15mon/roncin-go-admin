# 资金流水登记的重试幂等

## 1. 适用范围

收付管理中的资金流水登记及失败重试。后端唯一键为公司与 `idempotency_key`，不能把银行参考号当成必然唯一的业务事实。

## 2. 签名

`settlementServiceCreateCashflow(CreateCashflowRequest)`；页内 `buildCashflowCreateIntent(organizationId, values)` 生成不含幂等键的规范化载荷。服务端 `FinanceCashflowUsecase.Create` 在实时汇率解析前优先重放原请求。

## 3. 契约

- 载荷和指纹使用同一规范化结果：币种大写，金额和显式汇率按 decimal 数值归一，日期为 `YYYY-MM-DD`，账户及可选文本去首尾空白，空可选文本与未设置等价。
- 页面实例内保留「规范化意图 → UUID」映射；A→B→A 时仍复用 A 的键，不能只记最后一次提交。
- `undefined`、超时、错误、缺 ID 均不能清除意图。未知结果关闭弹窗再打开仍保留映射，成功被当前提交会话采纳后才移除已确认意图。
- 旧弹窗迟到成功不能关闭新表单，也不能提前清除新会话重试需要的旧键；再次提交可由服务端同键回放确认。
- 公司工作区重建沿用既有组件生命周期隔离。当前保障限定于页面实例存活期间，不声称页面刷新或浏览器重启后有持久防重；不引入全局财务幂等平台。

## 4. 校验矩阵

| 条件 | 结果 |
| --- | --- |
| 同一金额 100 / 100.00、可选文本空白差异 | 同一载荷语义及同一键 |
| 实质字段变化 | 新意图；返回原载荷时复用原键 |
| 请求已落库但响应未知 | 保留输入与键，再次提交回放同一流水 |
| 未知后关闭重开、旧成功迟到 | 不影响新会话；重试键仍可确认原结果 |
| 当前会话确认成功后再次登记相同内容 | 新键，可登记另一笔真实资金 |

## 5. 正常、基础与错误场景

正常：100 CNY 请求超时，重试返回同一流水 ID。基础：首次成功后重新登记同额另一笔流水。错误：在每次 `onFinish` 内无条件 `generateUUID()`，或旧响应未通过会话校验就删除键。

## 6. 必需验证

组件测试断言真实客户端载荷的键、规范化字段、失败输入、成功关闭与刷新；覆盖 A→B→A、关闭重开和迟到成功后重试。服务端覆盖同键同意图回放、同键不同意图拒绝，保持公司、汇率与散客账户校验。

## 7. 错误与正确

错误：`create({ ...values, idempotencyKey: generateUUID() })` 每次重试变键。

正确：先构造规范化载荷，用其指纹取回本次页面会话已分配的键；确认成功且属于当前会话后才移除。


## 核销工作台的差额流水

`CreateVerificationRequest.shortfallCashflow` 附带新流水资料；空 `allocations.cashflowId` 表示该笔差额。最终保存时原子创建、确认流水并核销，取消与自动分配没有写入。差额金额必须恰好等于这些分摊合计，不随已有余额并发变化自动增大。

工作台沿用规范化意图 → UUID 映射，未知结果、关闭重开不删键；只有成功被当前输入会话采纳时才移除。金额规范化为8位小数，超过8位输入显式拒绝；继续修改输入、切换核销范围、关闭或工作区销毁均使旧响应失去关闭/清空当前表单的资格。

分摊在服务端按「资金ID＋账单ID＋金额」集合比较，顺序无业务含义；前端仅为意图指纹排序，不能因候选重选后顺序变化而更换重试键，也不因此调整实际提交分配。候选新增、移除、全清和范围切换须在事件中同步使旧提交会话失效；生成空分配同样不能让旧成功关闭新输入。单纯选择查询范围不标记为已编辑业务草稿，实际分配和金额输入沿原离开保护。

后端 `VerificationUsecase.CreateWithCashflow` 在共享事务内复用流水创建/确认和核销，子流水键以主核销键的 SHA256 派生。同键同内容重放不重新取汇率；不同内容冲突。同键并发唯一约束失败后，仅在整个原组合已提交且流水、核销意图均匹配时回放。服务层逐项校验核销创建、流水创建、流水更新（确认）及显式汇率维护权限与同一公司范围。反核销只释放关联，已发生的真实流水保留，后续取消仍走既有流水权限与状态规则。


## 核销候选分页与所选来源

资金候选 `ListVerificationCashflowCandidates` 与账单候选 `ListVerificationBillCandidates` 各自通过ProTable官方request按page/pageSize/keyword查询，pageSize上限200；公司、方向、结算单位与币种均为固定范围。搜索不加载另一表、不循环拼接全量。往来单位代码、中英文名称、别名与拼音由后端现成Partner检索键支持。

跨页所选资金和账单保留独立来源快照；换页、搜索或空结果不丢已选来源，自动分配只消费明确所选记录。关闭或切换核销范围清选择与分配，所有勾选变动同步作废旧提交的页面采纳资格。Decimal.js的`isPositive()`包括正零，金额/余额必须用`gt(0)`判断严格正数；自动分配跳过已分完账单，不生成零金额行。服务端最终仍按最新余额拒绝超用，不根据页面快照扩大差额。
