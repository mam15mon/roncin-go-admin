# 资金流水登记的重试幂等

## 1. 适用范围

收付管理中的资金流水登记及失败重试。后端唯一键为公司与 `idempotency_key`，不能把银行参考号当成必然唯一的业务事实。

## 2. 签名

`settlementServiceCreateCashflow(CreateCashflowRequest)`；页内 `buildCashflowCreateIntent(organizationId, values)` 生成不含幂等键的规范化载荷。服务端 `FinanceCashflowUsecase.Create` 在实时汇率解析前优先重放原请求。

## 3. 契约

- 载荷和指纹使用同一规范化结果：币种大写，金额和显式汇率按 decimal 数值归一，日期为 `YYYY-MM-DD`，账户及可选文本去首尾空白，空可选文本与未设置等价。
- 页面实例内保留「规范化意图 → UUID」映射；A→B→A 时仍复用 A 的键，不能只记最后一次提交。
- `undefined`、超时、错误、缺 ID 均不能清除意图。未知结果关闭弹窗再打开仍保留映射，成功被当前提交会话采纳后才移除已确认意图。
- 旧弹窗迟到成功不能关闭新表单，也不能提前清除新会话重试需要的旧键；再次提交可由服务端同键回放确认。
- 公司工作区重建沿用既有组件生命周期隔离。当前保障限定于页面实例存活期间，不声称页面刷新或浏览器重启后有持久防重；不引入全局财务幂等平台。

## 4. 校验矩阵

| 条件 | 结果 |
| --- | --- |
| 同一金额 100 / 100.00、可选文本空白差异 | 同一载荷语义及同一键 |
| 实质字段变化 | 新意图；返回原载荷时复用原键 |
| 请求已落库但响应未知 | 保留输入与键，再次提交回放同一流水 |
| 未知后关闭重开、旧成功迟到 | 不影响新会话；重试键仍可确认原结果 |
| 当前会话确认成功后再次登记相同内容 | 新键，可登记另一笔真实资金 |

## 5. 正常、基础与错误场景

正常：100 CNY 请求超时，重试返回同一流水 ID。基础：首次成功后重新登记同额另一笔流水。错误：在每次 `onFinish` 内无条件 `generateUUID()`，或旧响应未通过会话校验就删除键。

## 6. 必需验证

组件测试断言真实客户端载荷的键、规范化字段、失败输入、成功关闭与刷新；覆盖 A→B→A、关闭重开和迟到成功后重试。服务端覆盖同键同意图回放、同键不同意图拒绝，保持公司、汇率与散客账户校验。

## 7. 错误与正确

错误：`create({ ...values, idempotencyKey: generateUUID() })` 每次重试变键。

正确：先构造规范化载荷，用其指纹取回本次页面会话已分配的键；确认成功且属于当前会话后才移除。
