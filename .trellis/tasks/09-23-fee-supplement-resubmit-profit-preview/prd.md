# 费用补录重提与审批毛利预览

## 目标与价值

锁后应付费用补录填错时，发起人能沿用原申请内容快速重提而不改写审批历史；审批人先了解成本对订单毛利的预计影响，再决定通过或驳回。

## 已确认事实

- 普通费用表支持行内编辑，但订单锁定后费用写入动作被禁用（`web/src/pages/orders/components/fees/OrderFeeTableTabs.tsx:1347`、`web/src/pages/orders/fees.tsx:279`）。
- 补录申请费用快照创建后不可变，待审批申请已有撤回接口；撤回与审批按申请版本竞争，只有一方成功（`server/internal/data/ent/schema/order_fee_supplement_request.go:16`、`server/api/order/v1/order_fee.proto:118`）。
- 审批会重新解析费用事实、汇率和金额，再创建未建账应付费用；预览只能是时点估算，不能代替提交时复核（`server/internal/biz/order_fee_supplement_usecase.go:343`）。
- 订单费用页当前毛利口径为有效应收折本币金额减有效应付折本币金额，毛利率以应收折本币金额为分母（`web/src/pages/orders/fees.tsx:595`、`web/src/pages/orders/components/fees/OrderFeeTableTabs.tsx:1494`、`web/src/pages/orders/components/fees/OrderFeeTableTabs.tsx:1636`）。

## 需求

1. 不在补录申请列表中直接行内修改已提交快照。待审批申请的发起人在仍具备新建补录资格时，可以从该行发起“撤回并重提”：确认撤回成功后，以原申请可编辑字段预填现有补录表单；保存时创建一条新申请，旧申请仍为已撤回历史。撤回失败时不能打开重提表单或假装已撤回。
2. 预填内容包括费用项目、结算单位、计费单位、币种、单价、数量、发生日期、补录原因、备注，以及仍具备手动汇率权限时的原手动汇率。当前失效的选项或缺失的权限不得被静默替换；用户须明确修正后才可提交。关闭预填表单不得创建新申请或恢复旧申请。
3. 列表将“通过”“驳回”合并为“审核”。审批人在做决定前先进入审核视图查看申请事实与服务端计算的订单费用毛利变化预览，同时展示本次补录折本币成本、当前有效应收/应付、当前毛利与毛利率、预计应付/毛利/毛利率及毛利差额；通过与驳回都在该视图完成。金额和币种使用订单所属公司的本币口径，与费用页现有汇总一致。
4. 预览是只读时点估算，不修改申请、费用、提成或锁状态；若申请版本、状态、审批资格或锁依据已变化，应阻止在旧预览上继续通过并提示刷新。正式审批仍保留现有事务、版本与实时资格检查；预览到提交之间其他费用变化时，审批以提交时事实为准并刷新页面结果，不新增毛利阈值拦截。

## 验收条件

- [ ] 待审批本人申请在有新建资格时可“撤回并重提”；确认撤回后表单字段准确预填，修改提交生成新申请，旧申请仍显示已撤回；取消表单不产生新申请。
- [ ] 非本人、非待审批、无新建资格或订单不再处于补录适用锁状态时，不出现“撤回并重提”入口；既有单独撤回、审批、驳回及作废能力保留，审批与驳回入口按新设计合并为“审核”。
- [ ] 撤回与审批并发冲突时，列表刷新且不打开重提表单；旧申请与新申请不会同时被误判成功。
- [ ] 管理者从中性“审核”入口查看申请事实、最新服务端毛利变化及应收、应付、毛利率明细后，再决定确认通过或驳回；金额与现有费用页有效费用口径一致，非 CNY 本币正确标注，零应收时毛利率为不可计算。
- [ ] 预览失效或请求失败时不能沿用旧数值审批；正式审批仍按既有版本、锁依据与资格规则校验，成功后费用表和申请表刷新。
- [ ] 前后端契约及生成物同步，针对预填、权限/冲突、金额计算、预览失效与相邻审批路径有定向测试，全栈风险门禁通过。

## 不在本期

- 不允许修改已通过、已驳回、已撤回申请的不可变快照；不把历史申请改写为“编辑后同一条申请”。
- 不预览或修改提成冲减建议明细，不新增负毛利审批阻断、毛利阈值、额外审批层级或历史数据迁移。
- 不重做普通费用行内编辑、整页费用汇总或其他订单类型的费用工作台。

## 子任务与集成验收

- `09-23-fee-supplement-resubmit`：负责撤回并预填重提的页面交互，不改变既有补录写接口。
- `09-23-fee-supplement-profit-preview`：负责审批毛利预览的服务端契约、计算和审核视图。
- 两个子任务按“重提 → 审批预览”顺序执行，避免同时修改补录申请组件；各自验证、提交，最终联验动作互不干扰，审批通过后的费用及毛利汇总同步刷新。父任务只负责需求映射和集成复核，不直接修改产品代码。
