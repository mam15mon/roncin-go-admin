# UI交互修复：最终规划摘要

## 目标

完成审查确认的12项修复，统一保存/失败反馈、工作保护、查询上下文、键盘能力与窄屏行为。

## 范围及交付顺序

1. 保存保护（A01/A02/A06）：客商创建更新、订单保存、账单编辑及流水登记失败保持输入，不执行成功/关闭/清草稿；客商真实离开有未保存确认，详情失败可重试。
2. 计息移除（A03）：按用户明确选择，移除未完成入口、启用摘要、生效承诺及专属本地代码；保留既有账期/信用额度/结算规则。
3. 列表状态（A04/A05/A12）：收起保留筛选输入，已提交查询回显与request一致；60秒真实自动刷新；客商、共享订单和费用/账单/流水列表在同工作区返回时恢复查询与分页。
4. 键盘交互（A07/A08/A09）：顶栏菜单与分节键盘可操作，Esc/焦点恢复有效，页签及关闭按钮焦点可见。
5. 窄屏（A10/A11）：同权限菜单入口可发现，375/390及767/768/769px订单无整页横向溢出，1440px布局保持原规范。

公共文件按上述顺序串行提交，父任务负责最终集成而非直接产品实施；批准后首个启动10-12-ui-save-protection。

## 非目标与关键边界

完整逾期计息延期，无后端/Schema/生成物/真实数据变更。P3列宽键盘触屏、候选联系人名称与全面可访问性治理暂缓。保持既有高密度全宽风格和权限，不引入全站KeepAlive、自动保存或兼容回退。
查询快照只保存轻量已提交条件/回显/分页，用户组织角色隔离；关闭页签清理，整页刷新不要求恢复。收起面板则保留未提交输入。订单背景重查失败不撤销已落库保存成功。

## 验收与验证

每项按子任务R/AC测试失败保留、离开取消、列表一致与隔离、键盘焦点和窄屏容器。先实现再按风险补定向回归，修改文件Biome/必要tsc/diff检查，独立trellis-check；最终pnpm run check:web及真实浏览器桌面/窄屏/模拟失败复测。所有模拟写请求在浏览器拦截或mock，不更改真实业务数据。

## 风险及技术核实

跨公共层guard、查询快照、菜单/样式影响多个消费者，需要完整前端集成门禁。窄屏唯一根因尚需浏览器定位；不得猜测性CSS或裁切兜底。生成客户端options与目标响应已完成只读核查，其余实际service成功字段按任务研究核实。遇到改变产品范围的新事实才回规划。
