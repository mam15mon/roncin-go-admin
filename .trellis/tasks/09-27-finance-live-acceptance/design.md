# 真实链路验收设计

## 复用路径

优先复用 scripts/run-acceptance-finance-disposable.mjs，核对其创建、迁移、初始化、启动真实服务、脚本、浏览器和资源回收的实际覆盖。它要求显式凭据且有固定端口，执行前检查权限和冲突，不能假定 pnpm dev 已满足编排条件。仅清理本轮创建的唯一命名资源，不接管既有开发服务或数据库。

## 测试数据与链路

HTTP 三场景独立标识；浏览器场景也使用唯一订单标识，避免选取历史数据或脚本已经耗尽可核销余额的账单。管理员/公司工作台等授权按现行规则准备。应收及外币基于场景输入给出期望金额，核对费用→账单行→核销分配→计提来源，不从最终返回值反推期望。

## 浏览器覆盖

复用 web/tests/e2e/finance-bill-batch.e2e.ts 与 Playwright 配置；按实际代码决定扩展或增加独立用例。API 只承担基础准备和只读校验，费用录入、建账、收款核销及必要计提操作走 UI。截图或操作记录覆盖关键节点，失败保留 trace；日志与附件脱敏，认证 storage state 不入 Git。自动化与人工执行分别标记。

## 诊断和修复

前置条件失败、脚本漂移、UI 缺陷、服务端错误分别定位，修复实际原因后重跑失败场景和相邻路径。若涉及 API 契约，按 proto→生成物→前端客户端流程，不手改生成代码。取消账单后重建使用独立未核销辅助样本。

## 运行限制

缺少凭据、数据库能力或浏览器时先尽可能完成独立准备，准确记录缺少项。计划审批不等于授权清空/重建开发库；如确需改变已存在数据，先提供具体对象与影响供用户决定。
