# 完成财务链路真实服务与浏览器验收

## 目标与背景

对当前费用模型进行真实使用验收，使费用、账单、核销、提成之间的数据与页面操作可复核。现有脚本和 UI 入口证据见父任务 research/evidence.md；本轮没有运行实弹验证，历史成功不能替代当前版本证据。

## 要求

- R1 运行环境：真实 PostgreSQL、正式迁移、真实服务与前端，优先复用现有一次性验收编排；明确数据库、公司工作台、账号、编号规则、结算对象、公司本币/汇率、提成归属及生效方案等前置条件。
- R2 HTTP：真实执行应收批量建账至核销和提成、应付建账至付款核销、外币至提成折算三个既有场景。按现行契约修复脚本漂移，保留原有幂等、拒绝和金额精度断言，不降低业务门槛。
- R3 浏览器：使用可识别的同一订单完成页面录费、建账、收款登记、核销、提成预览/生成（按现行产品流程）及详情查看。允许 API 准备订单和基础主数据，关键财务步骤必须经真实页面交互；只读 API 可辅助确认结果。
- R4 新费用口径：费用不再依赖独立状态字段；草稿账单也占用费用，已建账不可重复建账和普通修改/删除；在独立辅助样本验证取消账单释放占用后可重新建账，避免扰动主闭环。
- R5 证据：保存同一链条的订单、费用、账单、流水、核销、提成关联编号与金额对照；刷新后持久化一致，报告区分脚本、浏览器自动化、人工走查及未覆盖项。

## 验收标准

- [ ] A1（R1/R2）：应收、应付、外币脚本均对当前真实服务执行完成、退出码为零；无 --apply 的前置检查不算通过。
- [ ] A2（R3/R5）：真实浏览器完整执行同一订单闭环，账单来源、核销分配、提成来源和金额相符；不能从全局列表任选一条旧提成充数。
- [ ] A3（R4）：草稿占用、重复建账拒绝、已建账编辑/删除拒绝、取消后释放并重建的正反场景真实验证。
- [ ] A4（R5）：页面金额符合 formatAmount / trimDecimal 规范，时间为本地可读时间；无阻塞主流程的页面错误或未处理请求失败，刷新后结果一致。
- [ ] A5（R1/R5）：报告有运行 SHA、命令、环境、截图/trace 或等价操作记录和脱敏数据摘要；环境缺失或某阶段未执行时明确阻塞，不假报 PASS。

## 不在范围与约束

不建设通用 E2E 平台，不要求用户替代开发者跑脚本，不要求人工重复所有自动化场景；人工是否亲自走查单独记录，不能声称浏览器自动化等于用户人工验收。不删除或重建日常开发数据库，不以关闭权限/业务检查解决验收失败。

## 执行关系

可先检查环境；最终验收必须包含历史失败子任务的最终修复。任何执行后影响链路的代码变更都需重跑对应场景。
