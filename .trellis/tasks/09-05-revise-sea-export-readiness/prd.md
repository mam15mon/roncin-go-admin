# 修订海运出口审计业务口径

## Goal

按用户确认的简化人工流程重新评级海运出口上线就绪度，使报告准确回答当前产品边界内是否可以正式使用，不再用用户明确不需要的复杂货代 ERP 能力作为上线阻断。

## Background

- 原审计报告位于 `.trellis/tasks/archive/2026-09/09-05-sea-export-readiness-audit/research/`，结论为“受限上线 / 受控试运行”。
- 用户进一步确认：当前业务流程简单，所有步骤都由人员判断完成后在 UI 点击对应流程按钮；不要求系统从外部平台自动取得或验证事实。
- 用户明确不需要新增实际开航、到港、交付或操作完成状态，也接受“已放单”作为当前主流程终点；现有异常和费用门禁满足后可以人工结案。
- 用户不要求每张真实 MBL/HBL 具备独立的确认、签发和放单工作流；订单级流程状态是当前权威业务口径。
- 用户不要求复杂节点任务、SLA、自动提醒或异常工单；外部提交已经在原审计中确认为不适用。
- 若共享成本由人员在线下计算后逐票录入，系统暂时无需保存自动分摊过程；若文件由现有受控外部文件库管理，订单附件暂时无需成为唯一文件真相源。

## Requirements

- 只修订原审计任务中的 `prd.md`、能力矩阵、现状盘点和上线就绪度报告；保持审计证据、测试结果及已发现的软件缺陷不变。
- 将“缺少实际开航/操作完成结案门禁”改为用户确认的业务规则，不再作为 P0/P1 缺口。
- 将“真实 Sea MBL/HBL 缺独立确认/签发/放单流转”改为当前不适用或可接受的模型冗余，不再作为上线阻断；同时保留 UI 不应误导显示冲突状态的说明。
- 将复杂节点、SLA、自动提醒和完整异常工单降为不适用或后续增强，不得继续作为当前上线限制。
- 将共享费用自动分摊明确限定为后续增强：人工计算并逐票录入是当前批准流程；不得因此声称系统已保存分摊依据或自动守恒。
- 将附件完整上传/预览/下载闭环明确限定为后续增强：现有受控外部文件库是当前批准的文件真相源；不得声称订单附件本身已具备完整文件能力。
- 最终结论调整为“在已确认的简单人工流程和明确边界内，可以正式使用”，并列出仍真实存在的软件缺陷和临时操作限制。
- 下列已证实问题必须保留，不得因业务简化而删除：SE 列表旧分单入口、ReleasePod 仍引用旧 HBL、箱/货物删除漏传 `expectedVersion`、拆票并发失败错误语义不稳定。
- 原报告中的测试事实必须原样准确保留：全量 Go/Web 检查与构建通过，多项 PostgreSQL 验证通过，但完整拆票/改配 PostgreSQL 父测试失败。

## Out of Scope

- 修改产品代码、数据库、API、权限或前端页面。
- 重新运行整个海运出口审计或重新定义已确认的人工流程。
- 实施共享费用分摊、附件管理、复杂节点、异常工单或单证状态流。
- 将人工流程描述为系统自动验证或外部事实自动同步。

## Acceptance Criteria

- [x] 原审计四份文档均与用户最新业务口径一致，不再把已明确排除的能力列为 P0/P1。
- [x] 最终报告明确结论为“在批准边界内可以正式使用”，并清楚列出边界和人工责任。
- [x] 共享费用和附件仅在批准的人工/外部真相源前提下降级，事实性能力描述没有被美化。
- [x] 四个已证实的软件缺陷及拆票完整 PostgreSQL 质量门失败仍被保留并准确分级。
- [x] 能力矩阵、现状盘点、最终报告及原审计 PRD 之间不存在相互矛盾的上线结论。
- [x] 仅修改 Trellis 审计文档，不修改产品代码，不触碰或提交 `clash-for-linux/`。
