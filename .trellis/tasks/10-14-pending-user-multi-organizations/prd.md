# 统一待分配人员的多组织加入与角色选择

## 目标

修复 `/admin?tab=users` 中待分配开通只能选择一个组织的问题，使人员一次加入多个组织，并按组织独立选择对应公司角色。

## 已确认事实

- 用户于 2026-10-14 同意创建任务并推进修复，明确要求待分配人员同时加入不同组织。
- `web/src/pages/admin/components/users/DingTalkAssignmentModal.tsx:16` 使用单组织 + 共用角色载荷；开通接口与仓储也只接收一个目标组织。
- `web/src/pages/admin/components/users/UserMembershipModal.tsx:157` 已开通的加入组织支持组织多选、各组织角色选填、单人整批原子保存。
- 现有待分配开通必须至少一角色，系统工作台管理员才能操作；批量开通各人员独立成功或失败。
- 已有登录页面的三处未提交改动不属于本任务，须保留。

## 需求

- R1：待分配与停用人员重新开通支持公司、部门、组的多选，排除系统工作台和停用组织。
- R2：每个所选组织独立一行选择角色；候选来自该组织所属公司，删除组织清除对应角色，保留其他行输入。
- R3：同一批所选人员使用相同组织配置；每个人全部组织、角色、开通状态、通知与审计在一个事务内提交，失败不留下该人的部分开通。
- R4：人员之间沿用独立结果；成功人员移出重试范围，失败人员保留所选组织角色。
- R5：保留系统工作台权限边界、公司角色归属、防提权与新鲜权限校验。

## 验收标准

- 单人和多人都能一次加入同公司多个部门及不同公司，各组织角色不串用。
- 任一目标组织无效或角色不属于其公司时，该人所有本次新增/恢复成员和授权均不落库，状态保持原状。
- 部分人员失败后仅重试失败人员；请求中断不误报开通成功。
- 已开通人员的加入、编辑成员操作保持正常。
- 契约与生成物同步，针对性测试和最终门禁通过，提交本任务代码与文档。

## 范围外

不支持为同批每个人分别配置不同组织矩阵；不改登录页面；不新增 Schema、版本字段、权限码或历史兼容。

## 已确定规则与交付

- 用户最新目标明确授权完成原因分析、建任务、修复、合并和安全删除分支，持续推进到完整交付。
- 未授权取消首次开通的角色要求，沿用现有最小规则：各组织角色选填，所选组织整体至少一个角色。已开通加入组织仍可角色全空。
- 本任务专用分支合并到本地 main；核验提交已包含后用 git branch -d 删除，不强制删除、不推送远程。
