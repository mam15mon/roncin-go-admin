# 第二阶段实施计划草案

## 当前入口

用户要求继续完成既有任务。先解决 PRD Q1 并收敛设计，再进入实现；当前只编辑任务文档，不将研究完成标成产品完成。尤其应收更正后的来源收入归属、内部对冲和退款不得留作实现时猜测。

## 实施顺序

1. [ ] 收到 Q1 答复；固定各来源的有效经济收入分配、来源继承、退款/反向动作重算和舍入规则，以数值例子验证合计守恒。
2. [ ] 收敛 PRD/design；列明 Ent 字段、唯一约束、CHECK、正式迁移、Proto DTO、全部调用方和实际锁序；更新 implement/check.jsonl。独立审查设计中的金额闭环。
3. [ ] 服务端实现：申请状态机、权限及组织范围、预览指纹、费用冲回与替代、建账用途与不重复占用，按源生成 Ent/Proto/OpenAPI/Wire。禁止先写测试替代实现。
4. [ ] 资金与票据实现：调整账单、显式更正内部对冲、开票有效经济行、原单取消/反核销/反对冲依赖校验；保留原事实与真实执行职责。
5. [ ] 提成实现：确定性经济来源分配、原快照重算、费用系统净额与手工调整分离、未执行系统调整净重建、已付补付/追回、首次计提及月申同步。
6. [ ] 前端实现：订单费用更正申请/历史/审批、费用台账/建账/票据待办、提成影响与执行状态；统一候选、金额和时间口径。
7. [ ] 实现后补定向测试，运行真实 PostgreSQL 正式迁移隔离环境回归；Trellis check 子代理独立审查并修复，主会话更新规范并提交各可验证组。
8. [ ] 联合回归第一阶段自动锁单和业务结案；完整门禁通过后归档本子任务，最后验收父任务全部 AC，不能提前把父任务标完成。

## 必测矩阵

- 追加应收/应付；正向增额、优惠、成本调减、结算对象/币种错录、作废为零；未建账/草稿/已确认/部分核销/全收付/已开票。
- 1,000→100 且已有补录冲减；父提成未付/已付，原调整未执行/已执行，连续补录封顶、亏损转盈利、手工奖励并存。
- 应收 1,000、成本 400、收 500、比例 10%，优惠至 800，按用户确认 Q1 断言明确金额；全收后优惠不得出现超额已实现收入。
- 原未收与冲回对冲不计收入；原已收的冲回与新费内部对冲不重复计提；后续新收、退款及反转分别可复算。
- 合并账单某一行更正、原发票整张红冲后重开，其他订单/行金额不丢失；冲回费用不得混入普通开票候选。
- 同单补录与更正互斥；待审结案阻断，结案后更正不反结案；未建账调整阻止新锁单。
- 无权限、跨组织、授权被撤回、预览过期、重复提交/批准、并发建账/发放/源反转；失败零部分写入。

## 验证与交付

开发阶段只跑受影响 Go 包/用例、前端定向 Vitest、Biome、tsc 与 `git diff --check`。真实库测试必须实际 PASS，SKIP 不算验收；使用临时数据库/角色和正式 SQL 迁移，不重置已有开发数据。

契约生成顺序：修改 Proto/Ent 源 → 对应生成目标 → `pnpm run generate:web-client`；权限 Manifest 如变更须同步权限键生成。最终 `pnpm run check:fast`，记录测试数、跳过项与不能覆盖的边界。此轮规划文档只检查引用、JSON/JSONL 与差异，不把未执行的测试写成通过。
