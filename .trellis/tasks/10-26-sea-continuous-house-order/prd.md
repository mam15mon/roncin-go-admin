# 连续新增海运分单

## 目标与批准依据

用户要求评价主分单填报与多票建单后，明确回复「好，开始改」，批准上一轮三点建议：主单旁新增入口、带入主单上下文、分单号就近填写。创建任务和实施沿用本次明确授权，不重复请求同一批准。

## 已确认事实

- 海运新建/详情共用模板。主单号附近已有只读分单摘要，正式HBL号码在下方页签注册（`SeaTransportSection.tsx:320`、`HouseBillIdentityFields.tsx:45`）。
- 现有候选可继承当前航程并事务复验；来源摘要包含当前TE ID，但多航程hook需显式选择（`useSeaMasterBillCandidate.ts:154`）。
- 当前海运使用一个模块页签、即时保存表单草稿与关闭守卫；来源草稿可在现有规范键中按资源地址隔离（`OrderFormTemplate.tsx:139/300`）。

## 需求与验收

| 编号 | 需求 | 验收条件 |
| --- | --- | --- |
| R1 | 从已有主单新增分单 | 详情主单区有「从此主单新增分单」，单票/多票HOUSE且上下文完整、有同组织create能力时可见；来源审核锁不影响独立新票，DIRECT与无权限不显示。 |
| R2 | 主单上下文带入 | 点击后进入新建页，读取同组织来源，自动填船公司和主单号；在最新候选中定位来源明确TE，使用候选当前航程与版本，显示已有N票、保存后N+1票。 |
| R3 | 本票资料独立 | 客户、HBL号码、收发货/单证正文、件重尺、目的地与费用不复制；来源无权、失败、DIRECT、缺主单/航程或已失效时明确阻断，不静默创建错误主单。 |
| R4 | HBL号码就近填写 | 新建HOUSE在MBL旁正式填写HBL，只有一个注册位置；必填、批次重复及晚到候选重验保留，原载荷字段不变。DIRECT不产生HBL必填。 |
| R5 | 正式单证操作保留 | 新建HBL页签保留签发方/内容；新建号码错误定位上方，其他HBL错误仍揭示页签；详情与模式切换正式单证命令行为不变。 |
| R6 | 来源资源隔离 | 普通新票、来源A/B各自恢复草稿；按规范来源身份重建表单及幂等键，来源加载不覆盖已恢复输入，旧请求不能导航新表单；关闭/组织切换沿用现有保护。 |

## 范围与限制

仅前端入口、来源查询、表单字段位置及必要测试。继续使用现有订单读取、候选和创建接口；不新增批量创建、自动保存下一票，不复制整票，不修改后端、Schema、唯一性、锁规则或开发业务数据。不改全站页签归组和通用模板生命周期，不新增路由离开确认。

## 验收方式

先实现后补针对性验证；定向测试覆盖R1—R6、生成载荷与失败路径，真实浏览器使用已有两票演示订单验证入口和未保存新建；最终完整前端门禁。
