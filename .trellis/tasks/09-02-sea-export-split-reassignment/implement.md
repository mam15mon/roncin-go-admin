## 实施步骤

### 1. Schema、权限与正式迁移

- 新建 `SeaOrderSplitEvent`、`SeaOrderSplitResult`、`SeaOrderReassignmentEvent`，落实不可变
  字段、JSONB 快照、责任枚举、幂等/指纹唯一索引和结果唯一索引。
- 新建 `OrderAttachmentAsset`，把 `OrderAttachment` 改为订单—资产引用；补齐资产、订单、
  上传人/创建人边和引用唯一索引。
- 扩展 `OrderLifecycleEvent` 的 `ORIGIN` 维度与可空引用类型/ID；新票使用
  `CREATED_BY_SPLIT`，不伪造 FLOW 流转。
- 为新实体补 Order、Organization、User、Partner、MBL 等必要边，不添加单父订单字段。
- 权限 Manifest 新增仅 SE 适用的 split/reassign 操作过滤；`attachment.register` 名称改为
  “管理附件”，键保持不变。
- 生成 Ent 和权限键；创建正式 SQL 迁移。迁移开头对旧附件及受影响海运业务表执行空表
  门禁，非空失败，不做回填或兼容。

### 2. Proto、生成代码与服务注册

- 新增 `sea_order_change.proto`：动作摘要、拆票上下文、拆票预览/执行、改配预览/执行、
  事件列表/详情、结构化阻断和逐字段航程差异。
- 写请求使用字符串十进制、预期版本集合、客户端结果/目标键、幂等键；禁止客户端提交
  可由分配事实计算的货物数量和箱计划数量。
- 扩展附件契约，增加解除引用命令，继续使用 `attachment.register`。
- 运行 API、OpenAPI/Web 客户端、Wire/Ent 和权限生成；注册 HTTP/gRPC 服务，静态路由
  位于通用动态路由之前，不手改生成物。

### 3. Biz 领域规则与编排

- 定义拆分/结果/改配领域对象、责任类型、目标类型、版本集合、动作摘要、阻断项和错误。
- 使用 `decimal.Decimal` 实现结果汇总、货物三维守恒、HBL/实际箱不可跨票检查和 FCL
  箱计划重算；错误顺序确定且携带可定位 metadata。
- 实现可选拆票说明、必填改配原因/责任方、责任单位组织归属、内部编号和三类备注规则。
- 实现新票显式继承白名单，以及销售人员与提成归属快照继承规则；禁止重跑客户当前归属。
- 实现 split/reassign 幂等指纹：相同请求返回既有事件，不同请求稳定 409。
- 所有写用例通过 `Transactor.WithinTransaction` 编排，回调错误原样外传，提交后普通
  上下文重读。组合拆票发现不同目标时显式校验 reassign 权限。

### 4. Data 原子写入与并发门禁

- 建立只读动作摘要/上下文查询和锁后提交查询；全部 Ent 客户端经 `Data.client(ctx)`。
- 严格采用 design 的类别锁序；同类 UUID 排序后 `FOR UPDATE`，首次写读不使用 SHARE。
- 锁后重验组织、SE/ACTIVE/OPEN、唯一活动关系、HBL/MBL DRAFT、箱货状态、费用状态、
  账单/核销/提成事实、来源/目标版本和目标航程。
- 在同一事务实现：事件前快照、新订单号与新票、初始关系、货物按结果重建、HBL/箱移动、
  分配重建、箱计划重算、草稿费用与标签整行移动、附件引用、提成归属复制、结果快照。
- 组合目标与独立改配复用同一写入原语：结束旧 Link、新建目标 Link、迁移 HBL/分配、
  保持分配/流程状态、更新订单航程投影并写改配事件。
- 附件解除按资产后引用的固定锁序执行；最后引用才登记现有对象删除任务并删除资产。
- 审计写入与业务写入同事务；约束错误映射为稳定领域错误，不泄漏 Ent/驱动错误。
- 检查并对齐本阶段触碰的既有 MBL/HBL/箱货/费用入口锁序，不进行无关重构。

### 5. Service、安全与查询返回

- service 只做 Principal、UUID、枚举、十进制字符串和 DTO 转换；业务错误原样外传。
- 动作摘要仅返回动作/阻断，不泄漏费用或附件明细；拆票上下文必须具备 split 权限。
- 中间件校验接口主权限；组合拆票由 service 对每个非当前目标再次校验 reassign，不能
  依赖前端隐藏目标选择。
- 事件列表使用公共分页校验（最大 200），按 `created_at DESC, id DESC` 稳定排序。
- 附件列表/登记继续输出原有合并视图，避免页面感知资产表；解除引用严格校验订单范围。

### 6. Web 页面与交互

- 新增 `/orders/sea-export/:id/split` 全页，并放在动态详情路由前；使用
  `PageHeaderShell`、默认展开的 `SectionCard`、`StickyFooterBar`。
- 详情页根据权限和服务端动作摘要显示拆票/改配入口及具体阻断原因。
- 拆票页实现原票 + N 新票、完整 HBL 分配、真实箱交叉阻断、件重尺/箱量实时数字与
  蓝绿红状态、目标 MBL、内部编号、三类备注、费用单选、附件多选和可选说明。
- 前端用十进制库做即时计算；服务端 Preview 再确认，Execute 前展示最终摘要。不得出现
  审核人、审批状态、服务器草稿或拆票后特殊补录入口。
- 改配使用详情页宽抽屉，展示承运人、港口、船名航次、ETD/ETA 前后差异、成员数、原因
  和责任方；明确提示订单号和流程状态保持不变。
- 增加默认展开的变更记录区块和原票/新票/MBL 互链；附件抽屉增加解除当前票引用与最后
  引用删除提示。
- 只消费生成客户端和权限键，不手写请求地址或第二套权限真相。

### 7. 实现完成后补测试

- biz：1/多新票、精确三维守恒、空原票/空新票、HBL/箱跨结果、箱计划不足/超计划、
  备注、原因、责任方、目标键、幂等同键同/异指纹和确定性错误 metadata。
- data：白名单、流程继承、人员/提成归属复制、客户参考号谱系、货物旧新映射、HBL/箱、
  分配 CONFIRMED、费用/标签/汇率快照、附件多引用、生命周期来源事件和航程投影。
- 门禁：DIRECT 部分拆票、HBL/MBL 非 DRAFT、非草稿费用、账单行、核销、提成/调整、
  组织越界、旧活动 Link、过期版本全部阻断且无写入。
- service/API：权限组合、DTO、分页边界 1/200/201、静态路由、错误 reason/metadata。
- web：即时剩余量和颜色、具体号码错误、费用单选守恒、附件默认原票、配舱备注规则、
  航程差异确认、无审批/补录 UI 和权限隐藏。
- PostgreSQL：完整成功、每个关键中途失败、审计失败、两个并发拆票、拆票与改配竞争、
  相同目标多结果、同一命令重放；证明无死锁、无孤儿票、无双活动 Link、无重复费用。

## 主会话复核重点

- 是否只实现阶段 4，完全没有审批、外部申报、版本签发、Switch 或费用自动分摊。
- 拆票数量是否只从 CONFIRMED 分配推导，客户端能否伪造货物/箱计划数字。
- HBL/真实箱是否绝不跨结果；货物、分配、费用旧新 ID 是否能由事件快照重现。
- 新票是否继承流程、人员和提成归属快照而不复制账单、核销或提成事实。
- 草稿费用财税/汇率快照和标签是否逐字段一致，是否出现比例拆分或重新取汇率。
- 目标 MBL 是否锁后重验且从未被源票反向覆盖；订单当前投影是否正确切换。
- 附件是否只复制引用、最后引用才删资产，是否仍存在 `d.db` 直连或物理对象误删。
- 权限是否只新增 SE split/reassign，组合动作和附件解除能否绕过后端。
- 固定锁序、乐观版本、幂等键、审计失败和所有中途失败是否完整回滚。
- UI 是否默认展开、数字即时、错误具体，且没有审批/补录/虚拟实体。
