# 提成管理增强总体设计

## 设计目标

把 CNY 快照、归属日期、导出和前端展示拆成三个可顺序交付的子任务，同时保证
字段契约、筛选条件、金额公式和审计口径只有一个定义。

## 边界与所有权

| 能力 | 所有者 | 下游消费者 |
| --- | --- | --- |
| CNY 快照、归属日期、动态 CNY 金额 | 阶段 1 服务端 | 列表、详情、导出、前端 |
| 日期筛选谓词与稳定排序 | 阶段 1 数据层 | 列表、阶段 2 导出 |
| JSON 导出、上限、权限、成功审计 | 阶段 2 服务端 | 阶段 3 前端 |
| 月份转换、展示、CSV 安全序列化 | 阶段 3 前端 | 浏览器用户 |

父任务不直接修改产品代码。每个子任务独立规划、启动、检查和提交，后一阶段只依赖
前一阶段已经提交的契约，不在同一阶段交叉实现。

## 共享数据流

```text
核销单不可变日期/币种
  → 创建事务内解析 CNY→本位币汇率
  → 倒数得到本位币→CNY 汇率
  → 提成主单固化日期、汇率依据、原始 CNY 金额
  → 读取时汇总本位币调整并派生 CNY 调整/有效金额
  → List/Get/Export 共享字段和筛选口径
  → 前端仅展示或序列化，不重新计算金额
```

## 共享契约

- 所有金额和汇率通过字符串跨 Proto/OpenAPI 边界，服务端使用 decimal。
- `commission_date`、`commission_date_from/to` 使用 `YYYY-MM-DD`。
- CNY 来源只对外表达 BASE_CURRENCY/DERIVED；DERIVED 保存被反算设置 ID。
- 动态 CNY 调整与有效金额不持久化，防止调整状态变化后出现双重真相。
- 列表与导出排序相同：`commission_date DESC, created_at DESC, id DESC`。

## 兼容与发布

当前为开发阶段且没有历史提成数据，因此不设计迁移回填、默认值或兼容读取。阶段 1
通过重建开发数据库验证最终 Schema。若实施前事实发生变化并出现历史记录，立即停止
阶段 1，返回规划重新设计回填。

## 取舍

- 复用现有共享事务，不增加新的事务抽象。
- 同步导出沿用现有产品形态，不增加异步中心和一致性快照。
- 只做主单 CNY，不扩展明细行或逐笔调整快照。
- CSV 安全逻辑就近放在提成页面目录，保持可测试但不抽象为全站框架。

## 回滚边界

- 每个阶段单独提交，可按阶段提交回滚。
- 阶段 1 包含 Schema、迁移和契约，回滚时必须整体回滚源文件与生成物。
- 阶段 2 回滚权限时同步回滚 manifest、Proto access rule 和生成权限键。
- 阶段 3 只消费既有契约，可独立回滚页面变化而不影响服务端数据。
