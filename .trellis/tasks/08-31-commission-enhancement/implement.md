# 提成管理增强执行计划

## 阶段门禁

- [ ] 父任务和三个子任务的 PRD、设计、实施计划已完成收敛。
- [ ] 每个待启动子任务的 `implement.jsonl`、`check.jsonl` 校验通过。
- [ ] 用户批准最新总体规划摘要。
- [ ] 只启动拥有下一交付物的子任务，不启动父任务。

## 执行顺序

1. 启动 `08-31-commission-cny-snapshot`。
   - 完成模型、迁移、事务内快照、契约、日期筛选和后端测试。
   - 检查并提交 `feat: 增加提成 CNY 快照与归属日期`。
2. 阶段 1 提交验证通过后启动 `08-31-commission-export`。
   - 完成后端导出、权限、上限、排序和成功审计。
   - 检查并提交 `feat: 增加提成导出`。
3. 阶段 2 提交验证通过后启动 `08-31-commission-cny-ui`。
   - 完成页面筛选、展示、权限按钮和 CSV。
   - 检查并提交 `feat: 增加提成 CNY 展示`。
4. 三个子任务完成后执行父任务整合验收。

## 整合验证

- [ ] `pnpm run check:server`
- [ ] `pnpm run check:web`
- [ ] `pnpm run check`
- [ ] `pnpm run build`
- [ ] 检查生成物均由对应源文件生成。
- [ ] 检查三次提交边界与任务阶段一致。
- [ ] 对照父 PRD 的跨子任务验收标准逐项确认。

## 回滚点

- 阶段 1：Schema/迁移/Proto/生成物与实现作为一个原子提交回滚。
- 阶段 2：导出 RPC、权限、访问规则、生成权限键和审计作为一个原子提交回滚。
- 阶段 3：前端页面与测试独立回滚。
