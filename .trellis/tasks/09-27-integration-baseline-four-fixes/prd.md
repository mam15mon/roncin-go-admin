# 修复四项存量集成失败

## 目标

使已登记的四项失败恢复真实回归保护，区分测试漂移与实际产品错误，不能通过删测试或放宽约束制造绿灯。

## 背景

父任务 `09-27-finance-acceptance-closure/research/evidence.md` 记录四个完整测试名、源码锚点和历史证据。本轮以最终运行结果重新确认历史结论；两项费用目录测试属于费用科目主数据，不是费用流转状态测试。

## 要求

- R1 工位锚点：定位 CHECK 在夹具准备期提前拒绝的原因；按迁移时点构造有效前态，使回填断言实际执行；保留非法组织结构拒绝验证。
- R2 费用目录：对照系统模板与公司副本规则，修复不再成立的集合/数量断言或真实实现错误；验证内容、公司归属、复制与重复执行幂等，不仅断言数量大于零。
- R3 公司边界迁移：给出迁移前后字段级差异；验证引用正确改写，费用业务快照与无关字段不被错误修改，不得简单删掉快照断言。
- R4 证据：记录四项修复前签名、根因、修改点、修复后目标断言和相邻路径的结果。

## 验收标准

- [ ] A1（R1）：锚点回填场景及组织约束相邻场景真实 PostgreSQL PASS。
- [ ] A2（R2）：两个目录用例及模板/公司隔离/重复种子相邻场景 PASS，期望值有契约依据。
- [ ] A3（R3）：引用重写、快照不变和相邻公司边界场景 PASS，报告字段差异及原因。
- [ ] A4（R4）：四项用例无 SKIP，data 和 migration 两包完整真实库运行结束、无 panic 中断；目标两包无失败，新增问题按根因处理，范围外阻塞明确报告且本子任务不标完成。
- [ ] A5（R4）：research/verification.md 包含环境、SHA、命令、统计、证据；相关检查与 git diff --check 通过。

## 不在范围与约束

不重构生产财务链路，不改权限或组织语义来迁就测试，不并发 Schema.Create，不对开发库执行重置。只有证明产品错误后才修改业务/正式迁移；契约变更按生成流程同步调用方。不得以改造前也失败为通过理由。
