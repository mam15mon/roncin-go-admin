# 钉钉人员同步与待分配管理：产品方案

状态：规划已收敛，提交整体审阅；D1/D2/D3 已逐项确认，尚未批准实施。

## 核心流程

钉钉通讯录 → 系统管理员手动同步 → 无组织待分配 → 分配组织与角色并开通 → 员工扫码进入默认公司工作台。

钉钉维护人员基础资料，本系统只读；系统管理员维护业务组织、兼职组织、角色和默认工作台。公司管理员继续管理自身权限范围内的已分配人员。

## 页面与操作

```text
用户管理                           [同步钉钉人员]
最近同步：本地时间   新增 n 人 / 更新 n 人 / 失败 n 人

[待分配 n] [已开通] [离职/停用]
姓名/工号搜索      钉钉来源部门筛选      系统组织筛选

□ 姓名  钉钉来源部门  工号  系统组织  角色  状态  操作
□ 张三  海运事业部    001   未分配    —     待分配  [分配并开通]

选中 n 人                                  [批量分配并开通]
```

来源部门与本系统所属组织分列展示，钉钉调岗不会自动改变业务授权。钉钉技术 ID 放详情；手机号按权限脱敏，未获授权的资料不冒充已经同步。

批量一次设置同一组织和角色，成功者移出待分配，失败者展示原因并单独重试；需要多个组织兼职时使用现有单人维护能力。每个人的组织、角色和启用状态一起成功或失败。

## 员工与管理员看到的结果

| 场景 | 结果 |
| --- | --- |
| 未同步员工扫码 | 提示联系管理员同步开通，不创建申请 |
| 待分配员工扫码 | 提示尚未分配组织，不进入业务工作台 |
| 已开通员工扫码 | 进入有效默认公司工作台 |
| 钉钉修改姓名/资料后再次同步 | 本系统更新资料，保留组织和角色 |
| 已离职人员再次同步 | 保持离职；复职需管理员明确重新开通 |
| 本次通讯录未返回某人 | 不自动删除或认定离职 |
| 两人同时为同一员工开通 | 一方成功，另一方收到已处理提示，不能覆盖授权 |

## 旧功能与数据

钉钉邀请、二维码入职、自助注册审批和转派全部撤除。旧待审批人员准确迁入待分配，已开通人员与业务历史保留；旧邀请记录作为静态历史，不再参与开通。订单解锁等业务钉钉审批继续使用。本地管理员及企业微信入口按原有行为保留。
