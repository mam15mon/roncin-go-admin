# 钉钉人员同步与待分配管理

## 目标与授权范围

将用户管理调整为「钉钉同步人员 → 无组织待分配 → 管理员分配组织和角色 → 员工扫码使用」，减少手工录入和员工自行选择组织的负担。

用户于 2026-10-09 提出该方向，并明确要求规划、写入 Trellis 任务；已逐项确认 D1/D2/D3。用户已在最新整体方案呈现后明确回复“开始实施吧”，批准按本方案实施。实际钉钉权限与字段联调是实施阶段的环境核验项，不视为已经验证。

## 已确认事实

- 用户希望获取钉钉人员名单，先不放入组织，再由管理员分配组织。
- 现有钉钉集成支持扫码身份解析、单人通讯录手机号查询、邀请与注册审批；尚无全员通讯录同步。证据：`server/internal/data/dingtalk.go:20`、`:175`。
- 用户与组织成员关系分开存储，但当前用户列表依赖组织成员关系，完全无组织人员不会进入列表。证据：`server/internal/data/ent/schema/user.go:28`、`server/internal/data/ent/schema/membership.go:13`、`server/internal/data/admin_user.go:126`。
- 现有钉钉注册创建禁用用户，并附加系统管理组织成员资格；登录按钉钉 unionId 匹配。证据：`server/internal/data/auth.go:161`、`:180`、`:236`、`:251`。
- 当前用户页面以成员账号、注册审批、钉钉邀请组织导航，成员账号内按在职/离职划分。证据：`web/src/pages/admin/users.tsx:35`、`:241`。
- 已有组织范围、角色授权、多人跨组织成员关系、离职处理和会话撤销机制，应复用其当前业务边界。证据：`server/internal/biz/admin_user_membership.go:44`、`server/internal/data/admin_user.go:21`。
- 获取全员依赖钉钉应用的通讯录读取权限与授权范围；目前仅核实公开文档，尚未调用本企业接口验证全员范围、可返回字段及实际人数。

## 已确认产品决策

- **D1（2026-10-09）：统一钉钉员工开通入口。** 用户明确同意撤除现有钉钉邀请和自助注册审批，统一使用“同步人员 → 管理员分配开通”。员工扫码仅用于登录和展示当前开通状态，不再创建入职申请、自选组织或按手机号邀请自动激活。未同步人员提示联系管理员同步开通。
- D1 包含旧邀请页面、通用/定向邀请、注册确认、审批/转派入口及其专属接口和权限的收敛；订单解锁等业务钉钉审批不属于本次撤除范围。必要本地管理员登录保留，普通账号其他登录方式不因 D1 自动扩大修改范围。
- **D2（2026-10-09）：钉钉维护人员基础资料。** 用户明确同意钉钉同步人员的姓名、头像、来源部门，以及纳入同步的工号和联系方式统一以钉钉通讯录为准；本系统只读展示。业务组织、兼职组织、角色和默认工作台仍由本系统管理员维护。本地管理员账号资料继续由本系统维护。
- D2 同时约束后台资料编辑、分配开通和扫码资料更新：这些入口不能改写钉钉通讯录权威资料。现有姓名/邮箱本地编辑和扫码更新钉钉姓名/头像的行为必须同步调整。（证据：`server/internal/data/admin_user.go:234`、`server/internal/data/auth.go:582`、`web/src/pages/admin/components/users/UserFormModal.tsx:421`。）
- **D3（2026-10-09）：批量开通允许部分成功。** 用户同意每批分配相同组织和角色，逐人开通并报告；成功结果保留，失败人员单独处理、重试。每个人的组织、角色和账号开通必须一起成功或一起失败，多组织兼职沿用单人维护入口。

## 功能需求（提交整体审阅）

| 编号 | 可观察的行为 |
| --- | --- |
| R1 人员同步 | 系统管理员手动触发钉钉通讯录同步，看到执行状态、完成时间、新增/更新/失败数量及可处理的失败原因；普通组织管理员不能同步全员。 |
| R2 待分配 | 新人员进入独立“待分配”列表，无业务组织、无角色、无业务会话；不得混入离职列表，也不挂虚拟组织以便展示。 |
| R3 开通 | 管理员为待分配人员选择有效组织、该工作台可用角色和默认组织，成功后进入已开通列表；任一校验失败时该人员保持原状态。 |
| R4 批量处理 | 待分配列表支持勾选多人分配相同组织和角色；逐人原子处理，明确展示成功与失败名单，成功结果保留，重试只处理失败人员。（D3） |
| R5 登录 | 待分配人员扫码显示“尚未分配组织，请联系管理员”；已开通人员正常进入默认工作台；离职或停用账号保持不可登录；未同步人员提示联系管理员同步开通，不再进入注册申请。（D1） |
| R6 身份一致 | 重复同步按钉钉身份关联同一人员，不按姓名自动合并；遇到已存在账号的身份冲突时明确报告，由管理员处理。 |
| R7 资料与授权 | 钉钉同步人员的基础资料由钉钉通讯录维护，本系统只读；扫码及管理员编辑不能覆盖通讯录权威值。业务组织、角色和默认工作台由管理员维护；重复同步不重置这些授权，不重新启用已停用或离职账号。本地管理员资料仍可在本系统维护。（D2） |
| R8 管理范围 | 系统管理员在全局入口查看待分配人员并开通；组织管理员仅查看和管理授权组织范围内的已分配人员。具体分配权限沿用角色提权校验。 |
| R9 人员生命周期 | 待分配、已开通、停用/离职明确区分；组织移除与整个人员离职含义保持区分。同步缺失不直接判定离职或删除人员。 |
| R10 界面收敛 | 用户管理以人员列表和待分配工作为中心，提供同步与批量分配操作；撤除钉钉邀请和自助注册审批、转派及对应专属接口/权限，不保留另一套隐式开通路径。（D1） |

## 首期范围

- 当前已配置钉钉企业下、授权范围内的人员同步；需全员时先核验范围覆盖全企业。
- 姓名、钉钉身份、来源部门等分配所需资料；工号、手机号、邮箱仅按实际业务必要性和接口权限纳入，手机号不作为开通的必填前提。
- 管理员手动同步、同步结果摘要、待分配列表、单人/批量分配、明确登录提示、权限与审计。
- 已有钉钉账号复用身份；账号历史关联、订单责任人与财务记录保留。旧待审批账号按可证明的条件迁入待分配，原已开通、离职、本地/企业微信账号保持各自状态。
- 沿用现有离职业务动作及人工返聘需求，移除自助申请前置；管理员明确重新开通时重用原用户 ID，重新指定组织与角色。
- 一次性同步仓库内接口、前端、生成物、正式迁移、开发数据和规范，不增加旧接口兼容层。

## 不在首期范围

- 定时同步、钉钉事件实时回调、自动组织映射、自动授予角色。
- 将本系统组织和人员修改反向写回钉钉。
- 多个钉钉企业接入平台或通用身份源框架。
- 新增本地账号与钉钉账号手工绑定/自动合并平台；未绑定账号保持现有入口，不按姓名或手机号自动合并。
- 旧邀请历史记录的物理清理；功能入口撤除不扩大为清空既有历史。
- 自动离职、自动删除、自动复职；这些行为需要明确可靠的来源事件与业务规则后再设计。
- 订单解锁等业务钉钉审批机制改造。
- 数据库清空或重置；本任务未获得该授权。

## 验收标准

- [ ] AC1：授权范围完整时同步结果覆盖预期人员，多部门任职人员只出现一条；范围不足、分页失败或接口拒绝时不声称全员同步成功。（R1、R6）
- [ ] AC2：首次同步创建无组织、无角色的待分配人员；系统管理员能检索，普通组织管理员不可越权读取。（R2、R8）
- [ ] AC3：单人开通后组织、角色、默认工作台与登录结果一致；无效组织、越权角色、重复/并发开通不会产生部分授权或重复成员关系。（R3、R5）
- [ ] AC4：批量中 9 人成功、1 人失败时，9 人保持开通且仅失败人员待处理；结果包含对应人员与原因，对失败人员重试不覆盖已经成功人员的授权。（R4、D3）
- [ ] AC5：重复同步更新允许的来源资料，保持本地组织和角色；同名不同身份不合并，身份冲突可定位。（R6、R7）
- [ ] AC6：待分配、离职/停用、已开通及未同步人员扫码均有明确且正确的结果；未开通时不签发业务会话。（R5、R9）
- [ ] AC7：离职账号仍保留历史业务关联且既有会话失效；重复同步不复职；人员未返回不触发删除或离职。（R7、R9）
- [ ] AC8：旧邀请与自助注册审批、转派入口及专属接口/权限已移除，未同步人员不能通过旧邀请或扫码注册自动开通；按钮、路由和后端权限一致，业务钉钉审批仍正常。（R8、R10、D1）
- [ ] AC9：正式 SQL 迁移、Proto/OpenAPI/客户端、权限键、开发数据与规范一致；不手改生成物，不泄露 token、手机号或原始通讯录报文。
- [ ] AC10：钉钉同步人员的基础资料在列表、详情与分配表单只读，伪造写入请求也不能修改；再次扫码不以个人昵称覆盖通讯录姓名，同步更新基础资料不改本地组织/角色；本地管理员资料维护正常。（R7、D2）

## 范围收敛与实施前核验

D1/D2/D3 已确认，其他选择按最小改动保留现有业务：沿用离职与人工返聘、复用已有账号和成员关系、不新增没有明确用例的跨身份绑定平台。旧待审批人员的准确识别属于正式迁移设计，必须通过前态夹具与数据检查证明，不能推断所有系统管理成员都是占位账号。

本企业通讯录读取权限、实际全员范围及可选字段尚未实测。实施先核验；权限缺失时明确报告，允许用接口夹具验证本地逻辑，但不得据此宣称全员联调通过。事务、状态与任务设计选择见 design.md，整体方案需在实施前由用户审阅；本轮不执行数据库操作。
