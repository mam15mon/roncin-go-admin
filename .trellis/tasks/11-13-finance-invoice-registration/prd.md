# 发票分次登记与开票记录

## 目标与当前阶段

负责父任务 [整套财务模块](../11-13-order-fees-finance-workflow/prd.md) 的 R10/R12：围绕账单登记多张已有发票，明确发票→账单→费用分配、手工税额、开票进度及无需发票决定。

用户本轮要求接续实现并做完。已形成免票模型/接口/权限/历史及页面、发票列表筛选的待提交实现并完成定向验证；尚缺三层金额分配、多记录提交、直接修改边界及建账组合集成。剩余方案按 [design.md](./design.md)、[implement.md](./implement.md) 收敛后呈现最终审阅；不以部分实现宣称本任务完成。

## 已确认需求与验收

| 需求 | 可观察验收 |
| --- | --- |
| 以账单为主登记已有票据 | 账单详情可录入并继续添加多条发票，建账组内也可一并提交；每张记录号码、日期、类型、含税金额；独立发票台账可查询、导出和双向追溯。录入已有号码不等于在线开票，本期不接在线税务系统。 |
| 一票跨多账单 | 同公司、方向、结算对象、币种和本币，由财务明确填逐账单金额；合计等于发票本次登记额，各账单不超最新可开票余额。一张真实发票保留一个实体，不因多账单重复创建号码。 |
| 账单内逐费用分配 | 财务选择本次来源费用并逐项填写含税金额，逐费之和等于该账单分配；未选费用不增加进度，不超自身余额。非活动/别单/跨公司/重复费用均整次拒绝。 |
| 手工税额（2026-11-14） | 用户明确选择逐费用由财务填写税额；0≤税额≤本次含税额，未税额＝含税额−填写税额，不自动按来源税率重算或补尾差。不反写原费用税率、金额或提成税基；来源税率仍可追溯。金额精度复用当前项目契约，不从外部控件推断新服务端限制。 |
| 多记录原子提交与重试 | 一次弹窗可多张发票，任一行/账单/费用分配失败整次回滚；保留输入。重复请求不重复累计，同键不同号码/日期/税额/分配冲突。并发事务复核账单版本与逐费余额，不超开、不丢分配。 |
| 普通需票完成 | 足额登记且有效核销/对冲结清才完成；只票齐或只结清均不完成。开票/结算进度分别展示，账单、费用台账及筛选同源，部分发票不等于整张票齐。 |
| 无需发票 | 有独立权限的财务填写非空原因，记录人/时间/版本和撤销历史；标记不伪造发票号、税率或清偿。已有有效发票（含部分）禁止标记，免票状态禁止登记，锁内保证互斥；本期不支持部分免票。免票账单结清即可完成。 |
| 费用保护 | 首次成功登记、任何有效核销/对冲或免票，整账单禁止增删费用，允许后续继续登记；系统汇率不随航期改写。所有有效发票作废、核销/对冲全部撤销且免票撤销后恢复增删和后续自动更新资格，手工汇率保留；不解除订单人工审核锁。 |
| 作废/红冲 | 按原始发票分配释放余额及进度，保留历史，不按当前整账单重新分摊；两张只撤一张仍保护，末项撤销失败不得先解锁，撤销与新财务事实并发依最新状态。现有发票类型与号码唯一性沿用。 |
| 当前公司与权限 | 身份未就绪/非公司不查不提，来源须属于当前公司；创建、免票、修改、作废/红冲各自授权，不能借组合入口扩大范围。 |
| 筛选设置 | 本列表声明适用字段，偏好仅字段名按用户＋公司＋页面存本浏览器；移除清值并回首页/清选择，普通折叠保留条件。数据、完整合计、当前页导出共用官方已采纳快照；不含可移除公司或权限字段，存储失败明确提示。 |

## 创建边界与延期

零额/负数账单遵循账单任务已确认决定：本期只实现带符号判定，不开放创建、不允许负数费用、不改正数约束。负数真实更正场景另起任务；不能从外部前端金额控件允许0推断服务端可建零额发票。

不做在线税务平台、跨公司/混币种登记、自动分摊、自动邮件、历史双公式兼容或跨设备偏好同步。不清空或重建开发数据。

## 当前待决：直接修改

建议登记后只允许直接更正号码；日期、金额、税额或费用分配错误时作废/红冲后重新登记，保留历史与余额回退。已向用户提问；答复后写入最终方案，再完成余下阶段的实施确认。

## 技术事实与依赖

- `server/internal/biz/finance_invoice.go:127` 原输入只有账单ID/抬头/类型；`:358` 起按整张可开票金额取值，现有全额归集不能只改头金额冒充部分分配。
- `server/internal/data/finance_invoice.go` 已有订单→账单锁、版本、作废/红冲与活动关联；`finance_invoice_economic.go` 保留更正祖先与经济快照检查。
- 本任务依赖账单的免确认、锁序和费用维护；为账单F提供多记录登记输入及共享事务入口。核销无需先登记发票；建账组合任一步失败整组回滚，其他普通组独立。
- 正式新增schema/迁移、权限、Proto和客户端同步；不手改生成物。逐费分配的旧整额开发记录只经正式迁移补齐可确定来源，无法判定时显式报告，不在运行时兼容或重分摊。
