# 发票任务实施顺序

1. 补齐方案与当前差距，沿已确认范围继续；税额已确认由财务逐费用手填，直接修改/受控更正已于本轮确认，整体方案已获用户最终实施确认。
2. 先实现无需发票模型、迁移、独立权限、标记/撤销接口，接入保护谓词及账单进度/筛选。
3. 实现逐账单、逐费用金额快照及剩余额，创建提交锁内复核；复用现有金额精度并验证手工税额边界（不自动补尾差），号码/日期与分配一次提交。
4. 生成 API、Ent、权限键与前端客户端；生成器与其他代理串行协调。
5. 登记/详情界面接入分配、继续登记、免票及历史；发票列表统一筛选设置。
6. 复用用例向建账组合提供输入和事务入口，由账单任务负责逐组编排。
7. 实现后补针对性测试，真实库验证锁/余额/原子性；普通提交跑相关测试、类型和 diff 检查；最终全栈门禁。
