# 统一订单审核锁与费用账务回退

## 目标与用户价值

员工只理解一把订单审核锁；不同结算单位可分批建账，不等待整票费用录齐。普通编辑同时受订单审核锁及本笔账单占用约束；锁定后新增、修改、调减和作废经补审后才生效。

## 用户已确认的规则

- 用户已授权创建任务并进入规划，尚未授权实施。
- R1：订单锁定等同审核通过，统一由有权限的人执行“审核并锁定”，记录审核人员和时间。用户已明确取消应收结清触发的自动锁单；收款、建账、核销只更新相关财务事实，不产生订单审核锁。收敛订单锁与费用审核，避免叠加多把面向用户的锁。
- R2：订单未锁定、费用未创建账单且具备操作权限时，允许在订单费用录入页直接维护。费用在费用管理页选中并成功建账后，立即停止直接修改；草稿账单也属于已建账。
- R3：订单已锁定时不允许直接更改费用。新增、修改、调减和作废均提交申请，由锁定／审核人员补审；通过后才出现在正式费用明细中。待审、退回或撤回不改变原正式费用，也不能提前进入可建账费用。
- R4：所有已建账的原费用，无论订单是否锁定，修改、调减或作废前均须由有对应权限的人按实际依赖回退到“账单未建立”。用户已明确选择方案 A：未锁定订单回退后可直接编辑；锁定订单回退后仍保持锁定，提交变更补审，通过后才生效。新增费用可独立申请补审，不回退其他已建账费用。补审不再采用已建账原费冲回／替代的处理路径。
- R5：展示状态涵盖账单未建立、未核销未开票、已开票未核销、已核销未开票、已开票部分核销、部分核销未开票、已完成。中间状态按开票与核销两个进度组合，不能强制线性遍历所有分支。
- R6：操作／业务负责未建账费用维护及其授权范围内建账；财务负责开票、核销和相关回退，实际授权以权限清单为准，不按角色名称硬编码。
- R7：账务和已确认／已发提成的历史必须保留；合并面向用户的锁不等于允许覆盖财务事实。

## 初步验收标准

- [ ] AC1 / R1、R2：相同公司下覆盖订单锁定／未锁定 × 费用未建账／草稿占用／确认账单；前端与服务端普通编辑判定一致，删除及其他写入口无法绕过。
- [ ] AC2 / R2、R4：未锁定订单能先建 A 供应商账单、后录 B 供应商费用；取消草稿或按权限回退后只有正确费用恢复可编辑。
- [ ] AC3 / R3：新增、修改、调减、作废申请待审时原正式明细、汇总及建账候选不变化；补审通过一次生效，退回／撤回不生效。
- [ ] AC4 / R4、R6：开票、部分／全额核销与账单存在实际依赖时拒绝越级回退；锁定订单的原费用尚未回退到未建账时拒绝变更申请，批准时再次核验账单占用及费用版本。回退后订单仍锁定，原费用仍不可直接编辑；失败零部分写入，无权限或跨公司调用被拒。
- [ ] AC5 / R5：开票与核销组合在订单明细、费用管理及回退后显示一致，账单取消后恢复账单未建立，无硬编码串行中间态。
- [ ] AC6 / R1、R7：收款结清、建账、核销／对冲及删除最后一笔未建账费用不再自动锁单；人工“审核并锁定”记录真实审核人。统一审核锁不破坏单证历史、共享主单、账务清偿及提成差额；锁定／补审／建账／回退并发不产生绕过或部分写入。

## 范围边界

本期围绕统一审核锁、正常费用维护、补审及已有账务回退闭环。不得顺便实现通用审批引擎、第二套费用平台或自动代办所有财务回退。契约变化一次同步服务端、前端、生成物、权限和开发数据；不添加历史兼容分支，也不重置开发库。

## 待决产品规则

现有费用更正、账单取消、票据及核销回退、自动锁、审批资格和财务进度已核查，证据见 research/findings.md。已确认选择方案 A，先回退原账务再补审。已确认取消收款自动锁，统一人工“审核并锁定”。尚需收敛：补审资格是否限定原审核人员、原人员无法审批时的处理方式。待审期间其他费用建账、解锁／结案衔接在设计中明确，避免重现整票互相阻塞。未明确的产品决策不代用户选择。
