# 实施与验收计划

状态：planning，等待用户对 prd.md＋design.md 的最终审阅；本文件不是开始实现授权。

## 交付组织

保持一个任务，采用有序阶段，不拆可独立上线的子任务。原因是新增审批门禁会同时改变普通建账、锁后补录及提成执行，任一部分单独上线都可能留下旁路或阻断旧流程；各阶段单独验证和提交，全部完成后统一验收。

主会话负责范围、文档、提交、最终审阅及验收；批准后使用 trellis-implement / trellis-check。每个派发提示以 `Active task: .trellis/tasks/10-12-order-fee-approval` 开头并附所有权范围；共享仓库不得覆盖其他会话改动。公共契约与生成物由同一实现轮次串行维护，不能多个代理同时生成。

- [ ] 新权限 FinanceFeeReview，最小读依赖与角色配置；候选／实际审批使用同一真实 grant 规则，移除补录锁授权／bootstrap 旁路。

- [ ] 付款快照、调整执行方式与来源关联定义先随 Ent Schema 明确，CHECK／索引元数据齐全，不手改生成代码。
- [ ] Proto 定义审核、批量、预览、订单/台账筛选、补录影响、发放预览及错误原因；静态路径声明顺序正确。
- [ ] 生成正式迁移，包含有解释的预检而非强行数据修补；默认存量费用未提交，保留原账单和提成，历史实付不伪造。
- [ ] 生成 Go/API、权限键、前端客户端；实现 DTO/biz/data 最小联通，不留下编译失败的孤立提交。
- [ ] 实现后补充权限、状态机、decimal／指纹、Schema 元数据与正式迁移测试。禁止 TDD。

生成命令（对应源变化才运行）：

```bash

make -C server api
go -C server generate ./cmd/server
pnpm run generate:permission-keys

```

仓库没有现成的专用迁移生成脚本，不虚构 Atlas 命令；使用当前 Ent Schema diff 对正式迁移构造的隔离库生成 SQL，审阅后写入 server/migrations。不得在开发业务库运行自动建表或重建。必要的迁移生成辅助代码局限开发工具，不进入业务写路径。

阶段提交前运行受影响 Go 包定向测试、前端生成类型检查与 diff 检查；本阶段不得上线。

## 阶段 3：补录、提成冲减与发放闭环

所有权：order_fee_supplement、finance_commission、月度申请、调整、反核销／反对冲紧邻路径及相关测试。

- [ ] 原补录改为有效整票批准依据；仅审核冻结时也能补录。待审申请不生成费用，拒绝第二笔并行待审。
- [ ] 扩展补录预览：整票原／新利润、逐人逐提成影响、明确封顶及口径；指纹覆盖完整决策事实。
- [ ] 一次事务新增成本、新批准快照、CONFIRMED 冲减、申请终态、审计与通知任务；不再保留新补录 DRAFT 财务可忽略分支。
- [ ] 修正逐原提成的成本增量基线，排除已经存在其历史 FeeSnapshot 的旧补录成本；缺少可复算证据明确报错。
- [ ] 单笔／月度提成确认、发放、调整执行统一待审门禁，完整订单集合锁定后复核；沿用多订单父单及月申请整单粒度。
- [ ] 发放预览与登记保存实付快照，纳入调整 ID、版本、方向、金额，父提成与抵扣调整原子 PAID；独立扣回不能再次执行父单已抵扣调整。
- [ ] 新契约拒绝父提成未发先独立执行调整；父已发且有未执行增提时反核销／反对冲明确阻断，先按原支持动作处理增提。验证零额结清、负额拒绝、现金敞口证据不足失败。
- [ ] 区分累计权益净额与当次实付／历史实付；反核销、反对冲不能把未付款权益说成已付款追回；旧缺证据前态在迁移前明确处理，不靠运行期隐式回退。
- [ ] 补录有已确认冲减后不可直接撤销；无冲减且满足原专用撤销条件的删除须同步撤销整票批准、重新审核。
- [ ] 按 AC14–AC16 加入并发、回滚、连续补录、多员工、已发／未发、零额结清、重复执行及来源反转用例。

新审核／付款测试按功能独立文件，定向命令同步补入；每个重型组件测试文件≤10用例，超过20秒拆分。修改文件 Biome 检查通过 web 的 pnpm exec 命令按实际文件列表执行。没有构建配置／依赖／生产入口变更，不把 build 当固定步骤。

| 必测风险 | 通过标准 |
| --- | --- |
| 权限撤销／跨组织／拼接其他角色范围 | 在服务端拒绝，前端摘要也无泄漏 |
| 提交与编辑／批准与撤回／撤销与建账 | 真实 PostgreSQL 竞争只有合法的一方成功，无死锁无半成品 |
| 多次建账、取消账单 | 内容不变则批准仍有效，账单关联不误触发重新审核 |
| 批量审核混合失败 | 每票结果明确，成功项不可因重试重复记账／发通知 |
| 待审补录与提成发放 | 顺序线性化、金额预览过期拒绝，包含该票的整单阻断明确 |
| 补录A→计提→补录B | 各历史快照只计算后续成本增量 |
| 少发与独立扣回 | 明确执行身份，同一调整只执行一次，历史实付不动态变更 |
| 迁移历史事实不足 | 明确阻断／保留未知，不伪造金额批准，不删除数据 |
| UI 真实入口 | 筛选、状态、hover、批量、费用冻结、建账和付款均实际可用 |

## 提交与恢复

每个阶段只在编译和相关测试通过后形成可审阅提交。开发期发现问题通过修复提交处理，不 reset 他人工作。功能开始产生批准／付款记录后，不部署旧版二进制开放旧路径；数据库错误用前向修复，不删除新事件或已确认调整。若需真实库整理或操作超过现有授权，主会话交付具体记录和动作后再确认。
