# 实施与验证

1. 接通工作区页签状态及表单草稿身份。复用 formDraft、routeUtils、tabCloseGuard；验证当前工作区清单与草稿一同恢复，旧草稿与其他用户组织不参与关闭判断。
2. 将 TagsView 的单个与批量操作接入同一关闭生命周期。接通 useRouteLeaveGuard、工作区原生离开监听和切换组织、退出登录入口。确认后的写入失效与继续导航须在同一关闭动作中完成。
3. 接入 OrderFormTemplate 的新建和详情、HBL 与 AWB、客商详情、拆票和费用整表。逐一核查各表单编辑事件、初始化及显式清空、异步保存回调和并发基线。保留临时操作的现有防丢逻辑。检查其他整页编辑是否使用相同守卫。
4. 更新状态管理、组织切换和能力导航规范。调整现有断言普通切换会放弃的用例，补上后台页签与刷新、同页签不同编辑地址、关闭后迟到回写、提交和刷新并发等缺失场景。
5. 先使用 pnpm --dir web exec vitest run 运行修改涉及的布局、订单、运单、客商、拆票和费用目标测试，并运行修改文件的 Biome 检查及 git diff --check。再运行 pnpm run check:web，覆盖共享工作区改动。开发环境可用时用 Chrome 验证原生离开提示与刷新恢复。
6. 重点检查既有保护中的错误路径，包含组织切换失败、退出失败、保存 409、已落库但重读失败、以及新建请求结果未知时保留原幂等记录。
