# 作业待办明细与处理直达

## 目标与用户价值

员工从工作台知道「哪张订单、什么内容尚待处理」，直接进入该订单已有的办理入口，减少从总列表再次查找。用户选择友商借鉴建议第 1 项，并同意创建任务进入规划；用户已于 2026-10-26 授权修订规划、实施、review、合并、安全清理分支及推送。

## 背景与已确认事实

- 工作台已有未建账费用笔数、进行中异常件数，但费用链接只通往总费用页，异常没有下钻入口。证据：`web/src/pages/workbench/WorkbenchSideCards.tsx` 的 `TodosCard`。
- 协作关系来自 OrderPersonnel，限定当前用户、当前组织及可读的海运出口 SE / 空运出口 AE。证据：`server/internal/data/workbench.go:447`。
- 未建账指仍需记账、未被更正替代且没有有效账单关联；复用 `accountingOrderFeePredicate()` 和 `effectiveBillLinePredicate()`，未取消的草稿账单也占用费用。异常待办指 ACTIVE。证据：`server/internal/data/workbench.go:548`、`server/internal/data/fee_bill_association.go:13`。
- 异常已有查看、登记、解决、删除独立权限，现有面板却共用登记权限。详情传入的异常主数据选项为空，类型可能展示 UUID。证据：`web/src/pages/orders/detail.tsx:897`、`web/src/pages/orders/abnormal-case-panel.tsx:94`。

## 需求

### R1. 入口与分页明细

- 保留「我的作业待办」及两类数量，增加「查看明细」；打开侧边抽屉并选中对应类别，允许切换类别。
- 每行一笔费用或一件异常，同票多项分别列出，数量单位保持笔/件，不能称为订单票数。
- 服务端分页，默认每页 20 条、最大 200 条，展示总数；费用按创建时间、异常按标记时间从早到晚排列，再按主键稳定排序。
- 两类均为空时沿用首页隐藏卡片行为；已打开抽屉变空时显示空态。失败提供重试，不伪装为零条。

### R2. 字段与显示

- 公共字段：订单号、业务类型、客户名称。
- 未建账费用：应收/应付、费用名称、结算方、币种、金额、录入时间；显示订单审核锁、退关/结案状态与本费用的待补审阻塞原因。冲回费用按既有建账方向投影，不能误标原费用方向。
- 进行中异常：可读的异常类型名称、标记时间；已登记的停用类型仍显示名称；锁定、退关/结案造成的只读状态应有明确说明。
- 金额统一千分位两位小数，时间按本地时区分钟精度，不合计不同币种金额。

### R3. 办理直达与更新

- 费用进入 `/orders/{sea-export|air-export}/{orderId}/fees`，复用现有授权审核、建账流程；本期不要求自动选中某笔费用。
- 异常进入对应订单详情并自动打开异常面板；只有异常查看权限的人也能查看。
- 查看、登记、解决、删除按已有权限独立控制；订单业务锁、结案等写门禁继续生效，不因直达绕过。
- 待办表示尚未完成的业务事实，不等同于当前可写。退关/结案/锁定不直接隐藏仍需记账的费用或 ACTIVE 异常；待补审只阻止源费用建账，不影响无关费用。审核锁禁止普通费用修改，但不阻止符合现行规则的建账；只读或阻塞项目仍可进入原订单查看并了解处理条件。
- 返回工作台、再次打开明细或主动刷新时重取；已建账费用、已解决/移除异常不再出现在相应最新待办中。

### R4. 范围与一致性

- 本人真实协作 + 当前组织 + 对应业务订单读取权限为基础范围。逐笔费用待办必须具有该品类 `fee.read`；只有 `lock` 审核入口权限而没有 `fee.read` 时不展示费用待办、不返回数量或明细，原审核入口保持独立。异常待办要求该品类 `abnormal_case.read`；写操作仍分别要求原有写权限。
- 摘要与列表共享范围及谓词。没有某类读取权限时不展示该类入口，直接调用也不能泄露数量、内容或金额。
- 身份取会话，不接受改查同事/其他公司的参数；换组织首帧不展示旧明细，迟到请求不能覆盖新组织。
- 管理员也只统计本人协作订单；系统管理工作台不新增经营业务内容。
- 他人并发处理可能产生跨请求的短暂数量变化，通过刷新收敛，不建立历史快照。

## 验收标准

- [ ] AC1 / R1、R2：入口打开正确分类，字段完整、分页有效；同票两笔费用/两件异常分别显示两行和正确数量单位。
- [ ] AC2 / R3：SE、AE 费用落到对应订单费用页；异常自动展开正确订单面板，关闭后普通数据刷新不会重复弹出。
- [ ] AC3 / R3：异常只读、仅登记、仅解决、无删除及锁定组合符合独立权限；处理成功与失败均保留原有反馈。
- [ ] AC4 / R3、R4：有效草稿账单占用不算未建账，取消后仅仍需记账且未被替代的费用重新纳入；更正替代旧行与无需记账的冲回行不得计入，需记账的冲回行保持可见；异常解决/移除后从最新计数与列表消失。
- [ ] AC5 / R4：他人、其他组织、无业务读取或无费用/异常读取权限的数据不出现在摘要及明细，无法用请求参数扩大范围。
- [ ] AC6 / R1、R4：验证 page >= 1、1 <= pageSize <= 200；相同时间稳定跨页，空态/重试/切组织迟到响应隔离正确。
- [ ] AC7 / R2、R3：工作台及直达面板的异常类型可理解，金额/时间使用统一格式，不混加币种。
- [ ] AC9 / R2、R3：锁定、退关、结案、源费待补审及同票无关费用的待办纳入和状态说明符合现行门禁；锁不误阻正常建账，只有 lock 无 fee.read 者不泄露费用数量/金额。
- [ ] AC8：契约与生成物同步，定向验证、独立 review 及全栈门禁完成，不覆盖其他任务改动。

## 范围边界

本期只补齐现有可靠待办事实的明细与办理闭环。订舱/配舱/报关截止日自动预警、提醒规则、忽略/稍后提醒、手工待办、消息推送和费用模板留待后续；不新增通用任务平台、待办表、定时扫描或数据库迁移。

## 规划状态

2026-10-26 已按规划评审修订费用筛选口径、待办与处理能力区分及逐笔读取权限。用户已批准实施及后续审查、合并、安全清理分支和推送；在专属分支实施。
