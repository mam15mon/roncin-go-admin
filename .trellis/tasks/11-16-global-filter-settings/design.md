# 全站展示设置技术方案

## 变更边界

现有差距有三层：部分筛选没有设置入口，已有设置也只存本浏览器或当前表格实例，部分业务筛选缺少或现有输入不真正生效。本期以账号展示配置为统一入口，并按用户新增R8的海管家对照建议补齐必要查询；保留编辑表单及 ProTable 官方 request 数据流，不把偏好扩展为业务状态平台。

研究依据：[筛选区域](research/filter-inventory.md)、[表格维度与入口](research/column-inventory.md)、[服务端与身份](research/account-preferences.md)，以及新增[海管家字段观察](research/hgj-filter-evidence.md)与[业务筛选采纳方案](research/filter-adoption-proposal.md)。本系统仍为静态源码核查，海管家只验证字段入口，实施后另做查询实效及真实跨浏览器验收。

## 一、账号偏好契约与存储

- 新增个人展示偏好服务，GET `/api/v1/auth/me/display-preferences` 一次读取当前工作区配置快照，PUT／DELETE `/api/v1/auth/me/display-preferences/{kind}/{region_key}` 单独保存或恢复一个区域；kind 仅 FILTER／TABLE。该快照是本人少量配置聚合，不是业务分页列表。
- 请求显式携带预期用户／工作区身份作为等值前置条件；实际存储 user_id、organization_id 始终来自服务端登录主体，不允许调用方任选目标。当前请求作用域机制只能丢弃旧响应，不足以阻止旧队列在新 Cookie 下启动写入，必须同时销毁旧队列并在服务端校验身份。
- 用类型化 Proto 消息表达 filter／table 两类配置，禁止任意业务 JSON／敏感查询值。biz 持有纯 Go 结构和校验，service 仅转换；data 负责 Ent 转换和持久化。
- 新增 Ent `DisplayPreference`，唯一键为用户、工作区、配置类型、区域 key；JSON 字段承载已验证的结构化展示配置，更新原子覆盖该区域整份配置，其他区域互不影响。全部查询经 `Data.client(ctx)`。
- 个人偏好不是多人协作业务单据，不增加 version／expectedVersion 或悲观锁流程；并发依靠唯一索引和单条原子 upsert，最后成功提交生效。恢复默认删除对应区域记录；服务端不先读全量再覆盖其他配置。
- 接口仅认证本人，不新增业务授权权限码，不将个人设置挂在 FinanceCustomSetting 等公司业务配置上。参数需校验区域 key、字段标识集合、布局枚举、宽度和数量边界；用户字段名称由前端业务配置提供，服务端不接收业务字段值。
- 生成顺序为 Proto／Ent 源文件 → Go／OpenAPI／Ent 生成 → 正式 SQL 迁移审阅 → Web 客户端及必要 Proto 常量。迁移只新增偏好存储，不改业务数据。

## 二、前端统一异步保存源

- 新增中立 UI 能力 `web/src/components/ui/display-preferences/`，统一公开 Provider 和 hook；仅依赖认证上下文、生成客户端与 React Query，禁止 ui 反向导入 pages／features。
- 在 `OrganizationWorkspace` 现有按用户＋工作区重建的 QueryClient 边界内挂载 Provider，一次读取当前工作区展示配置快照，区域独立写入。Provider 持有写队列，不随设置面板或业务页关闭而销毁；工作区销毁时停止未发送队列及迟到反馈。
- 当前区域有较新本地操作时，迟到 GET／PUT 不能回滚最新展示；同一区域串行提交完整快照并合并尚未发送的连续操作。不同区域可并行。
- 各展示维度基于区域最新意图作局部更新，再生成完整快照；列显隐、调宽、密度及高级颜色不能各拿旧快照互相覆盖，也不能因单维度更新丢掉其他配置。
- 配置读取成功且身份匹配后才建立筛选恢复／表格偏好初始基线，避免先用默认挂载再清掉实际查询值。使用现有区域加载占位，不另造第二个全屏启动画面；失败显示可重试错误，不静默使用旧本地存储。
- 设置即时应用，服务端失败保留当前选择并明确未保存，可重试；重试始终提交当前区域最新意图，旧失败回调不能重发旧配置覆盖较新修改，也不能显示虚假的保存成功。恢复默认与普通写入走同一有序队列，避免旧响应复活配置。
- 仅把服务端成功结果当跨浏览器保存完成；进入工作区批量读取一次快照，区域切换复用工作区缓存，不逐区域重复 GET。浏览器刷新、重新登录或重建工作区时取得新快照，不建设轮询或两端实时同步。

## 三、筛选设置与布局

- 在现有 filter-settings 扩展 order、hidden、字段栅格跨度及收起数量；身份和保存复用统一 Provider。字段全集及默认值仍由业务区域显式声明，新增未知字段按当前业务默认加入，已退役字段不渲染。
- 面板沿用全站列设置的齿轮入口与大弹窗组织方式，提供勾选、拖拽及可访问的非拖拽移位操作、单项宽度选择、收起展示数量、恢复默认；不增加显式保存确认步骤。
- 单项宽度采用 24 栅格的 4／6／8／12／16／24，文案为 1/6、1/4、1/3、1/2、2/3、整行；避免像素布局跨屏失效。小屏按可用宽度自动换行，响应式临时布局不覆盖用户设置。
- 收起数量为正整数，允许按当前字段数显示全部；只有超过该数量才出现展开操作。字段被隐藏时仍保留其宽度／顺序选择，重新显示后恢复布局，但不恢复已移除条件的业务值。
- SearchFilterTemplate 的 grid／bar／custom、OrderListSearchFilter 以及 ProTable 官方搜索均消费同一展示配置。原生 ProTable 搜索优先通过列显隐／顺序／colSize／折叠协议适配，保留官方 request 调度；不能为接设置复制外部 data/loading 状态。
- 独立工具栏、候选表和权限矩阵搜索使用小型公共适配入口，业务区域保留参数转换及 onSearch 行为；嵌套表单不新增原生嵌套 form。
- 隐藏字段时同时更新控件 store、已提交查询、chip 和持久化页签查询恢复的 sanitize；范围字段完整移除并回第一页。经营台账按现行契约清选择；核销／建账等候选列表保留已经选定的业务来源和分配草稿，不能套用台账清选择规则。排序、宽度和收起数量只改变展示，不触发业务查询或清空输入。
- 提成申请管理和待执行冲减不再在 request 中用空值补默认状态。默认待审批／已确认仅在状态字段可见的首次初始化或「重置查询」时成为显式条件；隐藏后不注入，现有 optional status 契约支持不传，无需扩后端接口。「恢复默认布局」只调整展示，不填回已清除的业务值。报表默认日期等同类路径也按字段可见性初始化。
- 单字段区域也有统一入口，排序／折叠无实际作用时说明约束；必要条件标必显。全部可选字段隐藏后，设置、查询和重置仍可达。下拉候选搜索和业务编辑字段不作为个人可移除项。
- 提成方案抽屉的计提口径没有后端筛选参数，列设 search:false，仅保留展示和编辑；可配置筛选为名称、角色、状态、员工，不把原来无效的控件包装成新功能。

## 四、表头及其他已有表格展示维度

- 公共 useColumnSettings、订单费用专有存取和费用台账行配色都改消费统一账号偏好；移除本地存取来源，不保留兼容双读。应收／应付共享与品类隔离等现有 key 语义保持不变。
- 公共设置 hook 与 Responsive 表格之间显式传递稳定区域标识和受控偏好，列宽／密度不另建存储。为只有调宽能力的表格补稳定保存标识；模板及调用方显式声明稳定代码标识，不按中文标题、订单 ID 或数组位置生成区域 key。
- 列宽保存稳定叶子列 key 及用户实际选择的像素宽度；统一复合 dataIndex 的身份编码。调宽时测量的其他列和选择／展开辅助列仅作当次几何基线，不冒充主动偏好。
- 保留当前列宽 50–600px 范围、拖动和双击展开／还原交互；双击还原基线仍是业务默认，不是服务端加载的用户宽度。隐藏后再显示、排序后仍匹配原字段。
- 所有可选行密度使用官方 size/onSizeChange；费用台账高级七类行配色纳入相同表格偏好。恢复表格默认一并恢复该表的显隐、排序、冻结、列宽、密度及配套高级展示项；高级弹窗单独的「恢复默认颜色」只重置颜色，不清空其他表格设置。
- 结构列、必显列、分组表头、权限裁剪、窄屏临时解冻及全屏弹层挂载保持现有契约；订单审核完整核对表不应用个人显隐／冻结。

## 五、海管家对照后的业务筛选补齐（待本轮范围审阅）

完整默认／可选项及延期清单见 research/filter-adoption-proposal.md，候选A1–A5和B1–B13为推荐首批，尚未获用户确认。只补本系统已有模型和当前操作／对账用途，不照搬百项字段；人员扩岗、订单财务聚合、利润区间及历史账龄按C清单延期。

- 费用现有独立输入不再以多个值 `||` 合成一个keyword，订单号、分单、费用科目、发票号、收发简称、人员和船名航次各自AND；新增参数按Proto→service→biz→data实现，不能仅换控件。
- 订单权威航程、号码、代理、条款、异常／进度及箱号按采纳方案补齐；List和Export复用同一过滤内核。航空公司／航班用真实航空主单关联，船名航次用海运真实航程；共享箱按本票分配过滤。
- 财务补票面／核销／交易／确认日期及对象、币种和账户等明确维度；有效关联用EXISTS，不JOIN放大金额。费用核销准确命名为「关联账单核销日期」；票号＋票面日期匹配同张有效票据。
- 主数据国家参数下推服务端，国家大洲用现有小集合全量接口和客户端分页；不扩大pageSize或当前页本地过滤冒充完整结果。国家代码由现有国家候选提交，服务端校验ISO二字码形式，不增加存在性回退。
- 企业资源和提成方案的无效自动搜索关闭；提成订单号真实补查询，费用业务类型只列当前四种已上线业务。审计、本人提成及已有后端支持的对象／币种优先接UI。
- 不同字段AND，同一关联逻辑范围落在同一事件；布尔三态和optional存在性明确。日期为业务北京时间自然日；纯日期闭区间，timestamp起日≤值＜结束次日起点，不混用不同日期字段。
- 新过滤契约同步列表、total、筛选汇总、图表和已有导出。已有完整导出复用查询谓词，财务当前页／勾选导出继续消费采纳快照，不新增本来不存在的全量导出入口。利润新增主单号按订单存在性过滤后保持整票利润，不按部分费用截断重算；资金报表不因竞品账单视图而改变真实流水口径。

## 六、交付与风险

五子任务按 PRD 依赖顺序推进，每组通过针对性验证即提交；业务补齐可分域研究，但Proto／OpenAPI／Web客户端由指定所有者按组生成，不能并发覆盖。共享 Provider、异步恢复、编辑费用、响应式列宽和新增跨表筛选为重点风险：不能因设置响应重挂编辑表格、丢草稿、切换提交基线或放大金额。全站清单须记录接入及真实验证范围，静态索引不等于产品全量验收。

不迁移旧 localStorage；无服务端记录时使用当前业务默认，用户需重新设置一次。部署先应用新增表的正式迁移，再上线同时更新的 API 与客户端；不承诺跨版本兼容。故障修复／回退代码必须保留已写配置和所有业务数据，不以清库解决问题。
