# 研究：主数据、客商、企业资源、系统管理与工作台筛选缺口

- 研究问题：依据当前界面、后端契约和实际业务用途，哪些非订单、非财务主模块的筛选应保留、补充或延期？
- 范围：主数据八类维护页、客商列表、企业资源六类型、系统管理与工作台下钻；只写本研究，不修改产品或启动任务。
- 日期：2026-11-16（Asia/Shanghai）

## 证据与置信度

本轮读取已有海管家历史研究及主会话证据目录 `/home/vince/.local/share/rea/hgj/filters-01a1e359/` 的文件清单。审阅时目录只有海运出口初始／查询设置证据，历史财务研究也没有主数据、客商、企业资源、系统管理和本人工作台的具体筛选字段证据。

**因此本文不声称海管家有任何下列同名筛选。** 下述建议均来自本系统业务判断和现行源码。海管家只作为“常用／可选字段、查询设置、展开收起”的交互参考；主会话后续若补充对应模块证据，再单独比对，不能把推断升级为实测。

置信度标记：

- **代码高**：已对照页面声明、请求载荷、Proto 与服务端处理／仓储查询。
- **代码中**：已对照声明与契约，但未运行真实请求或全部边界。
- **价值判断**：这是本系统产品建议，尚待用户审阅；不是已批准的新字段。

## 建议结论

优先补齐真实有用且现有数据能支持的最小集合：

1. 全球港口、机场、航司、船公司增加**可选国家／地区**，各自服务端过滤；这些列表当前没有该请求参数，需要新契约。
2. 国家地区维护改用现有小集合全量接口，使现已声明的**大洲**过滤真正工作；不需要新实体或新的查询接口。
3. 本人提成明细增加**可选归属日期范围**，后端已完整支持，保持本人范围。
4. 系统审计可补**业务操作、对象类型**两项可选条件，复用现有后端能力；操作人候选权限与搜索未收敛，先延期。
5. 企业资源先消除**控件可填但请求不生效**的假筛选；状态其实已经支持，不要重复算新增。客商保留关键词＋档案状态及既有分类页签，本轮不凭竞品联想扩负责人、余额、信用等新过滤。

以上都是建议方案，不自动进入实施。每个新字段须与用户批准的 R8 规划一起审阅；“可选”表示可在查询设置中添加，默认不占首屏。

### 主数据分页、候选与规模约束

- 全球港口／机场等大集合仍服务端分页，`page >= 1`、`1 <= pageSize <= 200`；禁止前端循环翻页拼全量或按当前页做国家过滤。增加国家筛选时，列表查询与 Count 必须使用同一 country predicate，现有全目录启停统计仍明确标为全目录，不冒充筛选总计。
- 国家候选是小集合，可复用现有 `ListAllItems(kind=COUNTRY)` 一次加载完整字典后本地拼音搜索；服务端 `SearchOptions(kind=COUNTRY,keyword,page,pageSize)`（Proto:307；service/masterdata.go:189）也已支持关键字和分页，但固定只返回启用项。若维护旧国别数据必须选择停用国家，优先明确使用全量字典含停用项，而不是偷偷切换候选范围。
- 国家列表本身采用真正全量接口再客户端分页，符合小数据集维护规范；不是把 pageSize 改500或前端翻页绕过200。
- 服务器查询 country_code 前先 trim/uppercase 并校验现有ISO二字码形式；具体是否强制存在于国家字典需在设计明确，不创建新国家实体或静默纠正错误码。
- 国家字段只需利用已有列，不需要实体扩展；正式实现仍按 Proto→Go/OpenAPI→Web客户端更新。是否增加组合索引根据实际查询计划决定，不为假定规模提前建复杂索引体系。
