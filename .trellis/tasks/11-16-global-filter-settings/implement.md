# 全站展示设置实施与验收计划

## 当前阶段与启动条件

规划已包含完整需求、技术方案、研究和四个独立交付子任务；当前不执行产品修改。用户审阅最新完整方案后，启动第一个子任务；不得仅因 task.py create 已激活规划目录就跳过 start 门。

## 实施顺序

1. **账号展示偏好契约与服务端持久化**：类型化 Proto、本人／工作区校验、biz/data/Ent、唯一索引原子写、正式迁移与生成物。以隔离 PostgreSQL 验证身份、不同区域并发和恢复默认。
2. **表头与现有展示设置跨浏览器保存**：统一中立 Provider 和有序保存队列；公共 hook、费用专有偏好、列宽、密度、行配色全部接入；逐项补稳定区域 key。
3. **统一筛选设置与布局能力**：公共面板及布局模型；grid/bar/custom/ProTable/独立工具栏适配；先在既有财务区域验证完整显隐、排序、宽度、折叠及恢复。
4. **全站筛选设置接入与覆盖验收**：按 research/filter-inventory.md 分订单／主数据／管理客商资源／财务和工作台批次接入；每批核对查询、选择、统计与导出。
5. **父任务集成**：复核两个清单覆盖范围，跨浏览器真实验收与最终门禁，更新公共规范、提交并记录任务状态。发现遗漏回到所属子任务补齐，不降低全站要求。

父子关系不替代依赖。服务端与生成物有单一所有者；共享 UI 先完成后再并行分域适配，不能让多个实施者同时编辑公共入口。

## 子代理责任

实施默认派发 trellis-implement，检查派发 trellis-check，提示词以 Active task 开头并加载当前子任务上下文。明确文件所有权和其他会话改动；主会话协调、更新规范、审查生成物、分组提交及完成任务。原有订单费用文件有并行修改，触碰前读取最新 diff 并保留，不能整文件覆盖或提交无关改动。

部分完整规范超过原生注入的单文件32KB上限，task.py validate 会提示截断；不能把截断文本当作完整规范。派发时明确要求子代理按清单与研究锚点从源文件补读实际相关章节，尤其是状态管理和组件规范，不修改注入上限或跳过规则。

## 定向验证

- 服务端：实现后补用例，覆盖本人授权、工作区前置条件、不同用户隔离、非法结构／宽度、原子覆盖、并发首次创建、不同区域互不覆盖、恢复默认和正式迁移；禁止 TDD、禁止测试自动建表代替迁移。
- 前端 Provider：延迟读取、读取失败重试、连续修改有序保存、跨区域并行、保存失败／重试、DELETE 与 PUT 排序、卸载旧工作区、同公司切账号和迟到回包。
- 筛选：grid/bar/custom/Pro 官方搜索／单字段适配，必显项、移除条件和区间清值、折叠保留、未提交输入保护、页签查询恢复清洗、宽度和排序不触发查询。
- 表格：公共三类响应式表、费用专用、权限裁剪、分组／结构列、复合字段 key、隐藏重显、只保存主动宽度、业务默认双击还原、行密度、配色及恢复默认。
- 每批执行 `pnpm --dir web exec vitest run <受影响测试文件>` 和修改文件的 Biome；按类型影响执行 tsc。普通提交执行 `git diff --check`，不把全量门禁当每批固定步骤。

## 生成与集成门禁

- 按源文件执行 `make -C server api`、`go -C server generate ./...` 中实际受影响目标、`pnpm run generate:web-client`；只通过生成器更新生成物。新增权限码才执行权限键生成，本方案本人接口不计划新增业务权限码。
- 正式 SQL 迁移用 Ent 生成差异并审阅，独立 PostgreSQL 应用完整有序迁移验证；不清空／重建已有开发库。
- 全任务交付前执行 `pnpm run check:fast`，并验证生成客户端经开发代理访问新增本人接口；如实施实际影响构建配置、依赖或生产入口，再补 `pnpm run build` 并记录原因，不把构建当普通展示修改固定门禁。不将未执行的真实验证计作通过。

## 真实浏览器验收

1. 两个独立浏览器上下文、同账号同工作区：A 设置筛选五项及表头显隐／顺序／冻结／宽度／密度／配色，B 重新进入后逐项相同。
2. A 恢复默认，B 刷新后恢复业务默认；另账号和另工作区不受影响。
3. A/B 同区域并发保存，以最后成功提交结果为准；不同区域同时保存互不覆盖。断网或错误响应明确提示未保存，重试可成功。
4. 覆盖宽屏、390px、窄转宽和 Pro 全屏；实际几何验证列宽／冻结，查询按钮与设置入口始终可达。
5. 编辑费用时调整／加载展示设置及后台回包均不丢输入，不改变应收应付独立保存基线。
6. 分域至少验证所有机制类型，并对清单每个区域记录实际检查深度：源码接入、定向测试、浏览器操作分别标注，禁止把抽样当逐区域浏览器验收。

## 验收记录与完成条件

在父任务 research/ 保存区域矩阵、检查命令与结果、真实跨浏览器证据及剩余问题；不得记录凭据、Cookie、令牌或完整敏感载荷。全部 R1–R7 成立、独立 review 无阻塞、门禁通过、规范同步和提交完成后才归档。
