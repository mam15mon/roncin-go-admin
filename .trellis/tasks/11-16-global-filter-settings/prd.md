# 全站筛选与表头设置统一及跨浏览器保存

## 目标

全站所有筛选区域提供统一设置；筛选及表头的展示配置跟随账号保存，换浏览器登录后恢复，减少重复配置和模块间操作差异。

## 已确认需求

| 编号 | 需求 | 可观察验收 |
| --- | --- | --- |
| R1 | 全站所有包含筛选的区域都支持设置，不限财务 | 按[筛选盘点](research/filter-inventory.md)逐区域接入与验收，包含列表、主数据、报表、工作台、面板、抽屉和弹窗内独立列表的筛选；不只覆盖公共模板 |
| R2 | 筛选支持显隐、拖拽排序、单项宽度、收起时展示数量、恢复默认 | 在同一设置面板完成五项操作；重新进入后恢复；调整展示保留其他未提交输入，排序和宽度不改变生效查询条件 |
| R3 | 筛选配置跨浏览器保存 | 浏览器 A 保存后，浏览器 B 用同账号、同工作区重新进入相同区域能恢复；刷新及重新登录同样恢复 |
| R4 | 表头全部已有设置跨浏览器保存 | 列显隐、顺序、左右冻结、拖拽／双击列宽、行密度及费用台账高级行配色均保存；订单费用专有配置、无齿轮但已有调宽交互的表格也覆盖 |
| R5 | 按账号、工作区及业务区域身份隔离 | 同页面不同区域不串用；应收／应付及明确共用视图保留既有共享语义；切账号／工作区时不展示或写入旧作用域设置，服务端不能读取或修改他人的配置 |
| R6 | 筛选设置不破坏业务查询及表单 | 移除筛选项清除该字段及范围关联值并刷新，分页／勾选遵守现行规则；普通展开收起保留条件；查询、统计、图表和导出口径一致，迟到响应不得污染结果 |
| R7 | 保存与恢复结果明确 | 设置即时应用并自动保存，关闭面板不丢待保存配置；只有服务端成功才视为已保存，失败明确提示并可重试；恢复默认在另一浏览器也生效 |
| R8 | 参考海管家规划业务筛选项，核查缺少且应该补充的能力 | 逐业务区域记录海管家证据、本系统字段及前后端支持程度，形成保留、建议补充、延期和不适用清单；默认常用项与可选项分开，新增查询能力经方案审阅后再实施 |

R1 来自用户「所有的包含筛选的，都需要支持设置」；R3 来自「换浏览器，这个设置也保存」；R4 来自「表头也是，所有的设置也需要保存」；用户已确认 R2 的五项能力并要求开始。后续要求「参考hgj的筛选来，规划我们的筛选项，看看有没有缺少并且应该加的」，新增R8，替代上一版不新增业务筛选项的限制。

## 边界与验收口径

- 筛选区域指用于缩小一个列表／结果集的输入、选择、开关和日期控件；权限列表搜索、独立候选列表搜索也覆盖。业务编辑字段、下拉组件内部候选搜索、结构导航不作为可移除筛选。
- 个人配置只保存展示字段及布局，不保存查询词、日期值、业务数据、选择结果或表单草稿；全屏和刷新属于临时动作。换浏览器恢复以重新进入／刷新为验收，不要求两端实时推送。
- 公司工作区、权限范围及完成当前功能必需的条件不能被移除；必需项仍可参与允许的展示调整。结构列、分组表头和现有冻结约束不变。
- 本期补齐所有筛选设置，保存全部已有表头展示能力；不将所有无齿轮表格扩展为新增显隐／冻结入口。订单审核完整费用核对表继续固定全列，但已有调宽可保存。
- 展示偏好是本人维护的个人配置；同一区域两浏览器并发修改采用最后成功提交的整份配置。单浏览器按区域顺序保存，区域之间互不覆盖；不增加业务单据版本冲突交互。
- 设置首次无记录时使用当前业务默认；不读取、迁移、双写或回退到旧浏览器偏好。旧浏览器配置不会自动成为账号配置，本期开发环境按根规范不维持历史契约。

## 范围外与约束

仅将海管家对照后有当前业务价值的筛选补充建议纳入审阅，不机械把全部表头变成筛选、不为不存在的业务实体补模型。不建设通用查询平台、团队共享模板、批量代管他人设置或跨版本兼容；不恢复业务标签或独立公司选择。所有新契约按 Proto 生成，Schema 经 Ent 与正式迁移交付，禁止自动清空／重建现有数据库。保留其他会话已有未提交修改，特别是订单费用相关文件。
