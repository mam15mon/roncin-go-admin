# 产品需求文档 (PRD)：我的工作台与提成透出看板 (Workbench & Commission)

## 1. 目标与业务价值 (Goal & Value)

- **现状痛点**：
  1. 当前系统默认首页 `/welcome` 为纯静态的“账号信息与安全边界展示”，缺乏业务互动与日常操作粘性；
  2. 业务员无法直观掌握个人订单的提成核算与回款进度，缺乏即时正向激励，月末与财务对账成本高；
  3. 订单列表缺乏单票维度的财务与提成状态透出，业务与财务之间存在严重的认知壁垒与沟通鸿沟。
- **业务目标**：
  1. 将 `/welcome` 全面重构为**「我的工作台」**，实现基于登录角色的千人千面自适应（业务员 / 操作员 / 财务 / 管理员）；
  2. 建立以业务员为核心的**「提成晴雨表」与「回款催收看板」**，让业务员对个人收入透明可预期，利用潜在提成激励反哺催收，提升公司资金回款效率；
  3. 在全局**订单列表页**透出单票提成状态 Tag，打通业务执行与财务结算的端到端认知链路。

## 2. 核心业务原则与红线 (Core Principles & Guardrails)

### 2.1 系统职责边界与底薪隔离（系统根本不看基本工资）
1. **非 HR 薪酬人事系统**：
   - 本系统定位为 **Roncin 货代业务协同与结算系统 (TMS)**，非 HR 考勤薪酬人事系统，系统内**没有、也绝对无需维护**员工基本工资、岗位底薪、社保公积金或个税等字段；
2. **提成结算净额公式**：
   - 货代系统的提成模块**仅负责输出当期业务提成结算净额**：
     $$\text{当期系统应发提成} = \max(0, \text{当期新单提成} - \text{锁单补录冲减已确认金额})$$
   - 冲减只在浮动提成池内消化，单月提成输出下限为 0 元，绝对不产生负数发放，系统**绝无可能、绝无权限跨界倒扣员工的基本工资**；
   - 当期未扣完的冲减金额仅在系统内部挂账，顺延至下期新单提成继续抵扣。

### 2.2 提成一次性落袋原则
1. **正常提成一次性结算**：正常订单在满足计提条件并核发后，提成状态即处于终结状态；
2. **冲减审核弹性**：锁单后补录成本触发的提成冲减草稿（`DRAFT`），财务具有操作弹性——既可在锁内确认扣减，也可经特批走审批流程进行【忽略建议/豁免】。

### 2.3 财务核算与汇率核心风控铁律（事前强阻断原则）
1. **组织本位币终生不可变**：
   - 组织建立并设定本位币后，严禁任何形式的修改（杜绝历史汇率放大灾难）；
   - 前端本位币选择框强制置灰禁用，后端 `UpdateOrganization` 强校验拒绝变更。
2. **费用录入强阻断（废黜“静默继承上周旧汇率”）**：
   - 彻底废止技术端原有的“四级容灾/静默继承历史周（`INHERITED_LAST_WEEK`）”逻辑；
   - **外币费用发生日当周若未发布有效汇率，直接弹窗阻断报错，严禁录入费用**；
   - 严格落实“无汇率不录单、倒逼财务按时发布、责任明确不甩锅”的事前风控。
3. **汇率生命周期：彻底封板与使用锁定**：
   - **空白历史周允许补录**：若财务因休假等原因导致某历史周汇率空白，允许财务随时进行**补录新增（Create）**，补填空缺后该周单据即可正常录费；
   - **使用即死锁（一旦引用，永久只读）**：已发布的汇率只要被**任何一笔费用、账单或发票引用过**，该汇率行立刻永久锁定为只读状态，**禁止任何 Update 篡改**，防止出现“汇率表与单据明细前后矛盾”的审计灾难；
   - **未来周禁止预设**：`weekFrom > now` 的未来自然周禁止提前录入，防止汇率剧烈波动导致公司利润被侵蚀或亏损。
4. **汇率输错应急处理（救火通道规范）**：
   - **通道 A（零引用场景，引用数 = 0）**：若财务录错数值（如 7.1 误输为 71），在**尚未有任何单据引用**前，允许财务执行【停用/作废 (Disable)】，并重新创建一条正确的汇率行；
   - **通道 B（已被引用场景，引用数 > 0）**：**绝对严禁直接改写历史汇率行！** 必须走阳光下的业务纠偏流程——将错误汇率期间录入的几笔费用逐行作废重录，或通过红字冲销调整，保留全链路可审计操作痕迹，严禁暗改底层源头。
5. **费用明细收支方向（Direction）终生不可逆**：
   - 费用创建保存后，`RECEIVABLE`（应收）与 `PAYABLE`（应付）属性永久锁定，禁止更新反转；
   - 录错方向必须删除该行重录，杜绝毛利颠倒与科目挂错风险。

## 3. 功能需求 (Functional Requirements)

### 3.1 业务员视界：「我的工作台」

替换系统默认首页 `/welcome`，当具有业务员/销售角色的用户登录时展示：

#### 1. 提成晴雨表（三张核心激励卡）
- **【当前可领提成】**：
  - **判定标准**：订单客户应收已 100% 全额回款（核销完毕）、应收应付费用已录入完整无草稿、无待决争议；
  - **展示内容**：汇总个人当前可结算提成总额（如 `¥ 8,600.00`），支持查看对应订单清单并附快捷操作【申请计提】。
- **【在途提成看板（回款催收穿透利器）】**：
  - **判定标准**：订单已有正向毛利，但客户应收尚在账期内或未结清尾款；
  - **展示内容**：汇总个人在途潜在提成总额（如 `¥ 12,000.00`）；
  - **催款穿透**：逐票精确透视“当前卡在什么环节”，例如：*“订单 RC-2026-008 尚差客户 ¥3,000 尾款未回，收齐即可计提提成 ¥600.00”*，直接赋能业务员针对性催款。
- **【历史已发与调整明细】**：
  - **展示内容**：展示个人年度/月度累计已发放提成总额，以及锁单后补录成本产生的冲减扣除公示明细（扣减订单、扣减金额、对应审批来源）。

#### 2. 待办与风险拦截栏
- **待补齐费用订单**：新建后超过设定时限仍未录入应收/应付费用的订单提醒；
- **超期未回款预警**：已放单或已完成提单电放、但客户款项超过信用期未回款的风险预警。

#### 3. 我名下的近期订单快捷看板
- 呈现当前用户负责的最近 5~10 票海运出口单；
- 支持在卡片内直接快捷跳转录费、查看单证、追踪运输里程碑。

---

### 3.2 财务与管理视界：「管理工作台」

当具有财务人员（结算/出纳/会计）或管理人员角色登录时，工作台自适应为管理视角：

1. **待审批锁单补录**：
   - 集中展示全公司待审批的 `OrderFeeSupplementRequest`（`PENDING`）；
   - 展示订单号、补录费用项、金额、币种、补录原因、发起人；支持一键审批通过或驳回。
2. **待处理提成冲减建议**：
   - 集中展示锁单补录后系统自动生成的 `FinanceCommissionAdjustment`（`DRAFT`）；
   - 展示受影响员工、订单号、原提成单号、建议冲减金额；
   - 财务操作：支持【确认冲减】（计入抵扣）或【忽略建议】（特批豁免，必填原因）。
3. **待发放提成结算单**：
   - 按业务员汇总本期应发提成总表（新单提成 − 冲减已确认金额，下限为 0）；
   - 提供结算单据导出，支持线下打款后在系统内标记【已发放】。

---

### 3.3 订单列表透出单票提成状态 (Tag 体系)

在海运出口等业务订单列表页增加【提成状态】列，统一采用清晰的高识别度状态标签：

| 提成状态 Tag | 视觉规范 | 业务状态与触发条件 |
| :--- | :--- | :--- |
| **未计提** | 灰色 Tag (`default`) | 订单进行中，或客户应收尚未收齐结清，未达计提门槛 |
| **可计提** | 蓝色 Tag (`processing`) | 应收已全额结清且费用无草稿，已满足计提条件，等待提交或核算 |
| **已计提待发** | 青色 Tag (`cyan`) | 提成金额已核算锁定，已生成提成单，已纳入待发放总表 |
| **提成已发** | 绿色 Tag (`success`) | 该订单提成已完全结算并发放（PAID），业务闭环终结 |
| **待冲减** | 橙色 Tag (`warning`) | 锁单后发生了补录应付成本，系统已生成待财务确认的冲减草稿 |

## 4. 非功能性需求与规范 (NFRs & Standards)

1. **界面风格与布局标准**：
   - 严格遵循 `AGENTS.md`：全站 Fluid 满宽流式布局，背景统一使用 `#f5f7fa`，**严禁硬编码 maxWidth 1440 或外层水平居中容器**；
   - 统一纯白高密度卡片风格，卡片标题使用 `3px × 15px` 品牌蓝竖标（`#1677ff`），边框统一 `#f0f0f0`。
2. **数据隔离与权限防护**：
   - 业务员工作台接口强制限定 `employee_id = caller.UserID`，严禁通过修改入参查看其他业务员的提成与催款明细；
   - 财务/管理视界根据用户所在组织与 `system.finance.commission.read` / `system.order.fee.create` 细粒度权限严格校验。
3. **查询性能优化**：
   - 业务员在途提成与催收看板采用聚合查询或增量快照计算，单次工作台请求耗时控制在 200ms 以内，避免在大数据量订单下全表扫描。

## 5. 验收标准 (Acceptance Criteria)

- [ ] **业务员工作台**：
  - [ ] 登录业务员账号访问 `/` 或 `/welcome`，正确呈现「提成晴雨表」三大卡片；
  - [ ] 【当前可领提成】仅统计全额结清订单，数据准确且支持下钻；
  - [ ] 【在途提成】准确展示未结清订单及缺口催款金额，穿透信息完整；
  - [ ] 【累计已发与冲减明细】展示历史已发提成及锁后补录扣减明细；
  - [ ] 提成结算输出净额绝不为负数，绝无底薪扣减字段；
  - [ ] 业务员无法越权查看其他同事的提成与看板数据。
- [ ] **财务/管理工作台**：
  - [ ] 登录财务或管理员账号，自动自适应为管理视图；
  - [ ] 待审批补录、待处理冲减建议能实时聚合，支持快速审批与批量处理；
  - [ ] 提成应发表按员工汇总准确，冲减抵扣逻辑符合双层余额封顶。
- [ ] **订单列表透出**：
  - [ ] 订单列表正确展示【提成状态】列；
  - [ ] 未计提、可计提、已计提待发、提成已发、待冲减五种状态精准映射且与底层数据实时对齐。
- [ ] **财务风控铁律**：
  - [ ] 组织本币置灰禁用且后端强拒绝修改；
  - [ ] 当周无有效汇率时录费直接弹窗强阻断；
  - [ ] 引用过的汇率永久只读禁止任何更新；
  - [ ] 费用收支方向禁止编辑反转。
