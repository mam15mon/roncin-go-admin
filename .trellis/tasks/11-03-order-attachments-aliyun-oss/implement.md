# 实施与验证计划

## 开始条件
- PRD、设计、计划已完成，implement.jsonl/check.jsonl 含真实规范和调研入口。
- 向用户展示本次最终范围和延期项；收到后续明确批准后才能 task.py start 并派发实现。

## 实施顺序
1. 按 trellis-before-dev 加载专项规范，复核 git status，保留其他任务目录。
2. Trellis 实现子代理负责后端及契约：配置/API 源、官方 SDK 接入、授权核验、登记幂等、访问和删除路由；按边界同步生成物。
3. 后端契约确定后实现附件抽屉及上传、预览、下载。全部生成客户端由生成器产生，子代理不得相互覆盖。
4. 实现后补充针对性测试：正常流程、超限/空文件、无配置、权限/组织/订单绑定、过期/覆盖/对象不匹配、重复登记、业务锁、共享引用删除、企业图片删除相邻路径；前端覆盖成功、失败、上下文切换与预览释放。
5. 补充配置文档、规范导航与任务验收记录。未登记对象人工排查、真实云端验证限制明确记录。
6. Trellis 检查子代理审核完整差异并修复问题；主代理审阅、提交、收尾。

## 检查命令
- 开发阶段：受影响 Go 包定向测试、受影响 Vitest 文件（相对 web 路径）和修改文件 Biome；生成后前端 tsc。
- 提交前：相关测试、git diff --check；任何新增 Schema 需正式迁移验证，不执行数据库重置。
- 最终阶段：pnpm run check:fast（本次跨 API、配置和删除消费者，需全栈门禁）。仅依赖或生产入口变动确有构建风险时补 pnpm run build。
- OSS 实测须真实配置后执行：准备 → PUT → 登记 → 预览/下载 → 最后引用解除 → 后台 DELETE。无配置不得标记云端实测通过。

## 重点审查与回退点
- 订单范围与权限不能被对象键代替；登记必须有服务端授权与实际对象核验。
- 现有锁顺序及短事务保持，不在数据库事务中执行云请求。
- 删除路由不能误删企业图片或其他订单资产；未知前缀不能自动回退。
- 密钥、签名 URL、环境文件不得提交或写入日志。
- 每组可验证改动使用中文 Conventional Commit，整体通过门禁后归档任务。
