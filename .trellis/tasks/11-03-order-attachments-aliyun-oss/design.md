# 技术设计

## 边界与契约
在 order_attachment.proto 增加准备上传及获取附件访问链接接口，登记改为消费服务端上传授权。复用现有权限码和订单范围解析。配置在 conf/v1/conf.proto 增加订单 OSS 专属配置，变量前缀 ORDER_ATTACHMENT_OSS_，包括启用、地域、Endpoint、Bucket 和访问凭据；配置默认关闭，开启但缺项时启动失败。源文件修改后统一生成配置绑定、API/OpenAPI、前端客户端和 Wire 依赖，不手改生成物。

biz 定义订单附件存储接口和上传授权规则；data 使用阿里云官方 Go SDK V2 实现，service 只做转换与边界校验。企业图片保持现有 S3 接口。

## 上传与读取
1. 准备上传时验证订单范围、管理权限、可编辑状态和文件字段，服务端生成 orders/ 业务前缀下不可预测的对象键。
2. 签发约十分钟的 PUT 链接及需发送的请求头。上传授权同时绑定组织、订单、上传人、文档/文件属性、对象键和截止时间，使用服务端完整性保护，不能仅接受客户端传入任意 objectKey。可使用基于专属 OSS 凭据派生密钥的 HMAC 令牌；后端不记录完整令牌或签名 URL。
3. 直传只允许创建，不允许覆盖；签名绑定内容类型及校验信息。登记前 HEAD 核对大小、类型、组织及上传授权元数据。OSS 网络请求在数据库事务之外，最终登记在现有 WithTx 中再次锁订单并执行业务门禁，保持短事务。
4. 幂等键由上传授权生成，重试匹配同一内容返回已有结果，键相同但内容不同返回冲突。沿用资产/引用唯一索引，不新增多人编辑实体与版本字段。
5. 获取访问链接时通过 orderID + attachmentID 查询和组织校验，签发短期 GET 链接。下载保留原文件名；图片/PDF 可取回 Blob 后本地预览，关闭时释放 URL，避免依赖 OSS 默认域名的 inline 行为。不内联执行 HTML/SVG 等活动内容。

## 删除及一致性
沿用已有事务：锁订单 → 业务门禁 → 查引用 → 锁资产 → 删引用 → 无其他引用才登记删除任务、删资产；不扩大现有锁范围或新增锁模型。删除用例依赖最小删除接口，由明确的对象键前缀路由到订单 OSS 或企业图片 S3；未知前缀明确失败，不回退，任一存储开启时消费者可工作。失败继续走已有租约/重试。

## 前端
保留订单附件抽屉入口，使用 ProTable request/actionRef；上传表单使用 ModalForm.onFinish，文件选择与进度/失败状态就近管理，不改变跨模块边界。自动提取文件名、大小、类型和校验，技术字段不再要求手填。准备/登记/访问均走生成客户端，二进制直传只请求后端返回的签名 URL，不携带应用 Cookie。异步完成后核对当前订单和组织上下文，避免抽屉切换后串入其他订单。

## 迁移、运行与回滚
优先复用现有资产/引用表，不引入历史双轨。若实施发现必须新增持久化状态，先更新设计和正式迁移，不绕过 Ent。配置文档给出私有 Bucket、HTTPS 浏览器可达 Endpoint、最小 RAM 文件操作权限及准确 CORS 源/方法/请求头示例。没有凭据时用可控 OSS HTTP 测试替身验证签名、HEAD、GET 与 DELETE；真实云端验收单独标明未完成。回滚代码需成组包含源契约、生成物和调用方；关闭配置仅关闭存储访问，不删除数据库或云文件。
