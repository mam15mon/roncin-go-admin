# 公司初始管理员授权设计

## 身份和范围（D5/D8）

以 User.is_bootstrap_admin 定位唯一初始管理员，不按角色 code 或用户名识别。自动目标为系统管理及所有启用公司工作台，部门/组不重复建成员。公司管理员角色按所属公司创建、按 Manifest 过滤系统专属权限。

已有初始管理员时，bootstrap 配置用户名若与该账号冲突则明确失败，不把普通同名账号接管为初始管理员。首次创建仍需密码和展示名；补齐路径仅需要连接与身份定位所需配置，不要求或重新哈希用于首次创建的密码，不修改用户名/密码/姓名。

## 数据层复用

在 internal/data 保留 initializeCompanyAdministrator 的角色创建职责，新增本任务专用的“补齐初始管理员工作台成员及管理员绑定”能力；CLI 经 WithClientTx，业务仓储经 WithTx 使用同一事务内辅助方法。不引入通用 provision 平台。

已存在成员和绑定作为已满足；缺少成员先创建，缺少绑定只追加 administrator，不删除该成员其他角色。已停用角色/成员不视为缺失，不恢复、不改其权限配置。

## 公司创建与种子

创建 company 前在事务内确认唯一启用初始管理员并锁定，再建立公司、初始化角色和费用/单号配置、添加成员/绑定与审计。缺少初始管理员或账号停用时明确失败，整次公司创建不提交半套闭环。

默认公司种子入口同口径：首次 bootstrap 需调整执行顺序，先建立初始管理员身份再建默认公司，最后覆盖全部现有公司补齐。单独 seed-branches 也走明确的管理员初始化逻辑；已有公司种子不能只因编码存在就漏掉补齐验证。普通开发数据同步不扩大为普通用户自动加公司。保留 main 的 cee4bffb 规则：默认种子仅 BJ/CD，sync:dev 归属北京；本任务不会重新创建 SH/CQ，公司补齐遍历实际存在的启用公司，不硬编码种子名单。

## bootstrap 分支

| 前态 | 结果 |
| --- | --- |
| 无任何账号 | 正式迁移 → 复用/建立启用系统管理 → 创建唯一初始管理员 → 初始化角色/公司 → 加入有效工作台；同一事务完成账号和授权 |
| 已有唯一启用初始管理员 | 身份验证后幂等补齐，保留账号凭据与资料；普通员工不变 |
| 用户表非空但无初始管理员 | 明确报错，不新建第二身份、不转换普通账号 |
| 多个初始管理员或配置身份冲突 | 明确报错，本次不写授权 |
| 初始管理员停用、系统管理或其必要管理员资格被停用 | 全局前提失败，任何授权写入前终止，报告需人工恢复 |
| 公司停用 | 跳过该公司，报告，不启用 |
| 公司启用但管理员角色或原成员停用 | 跳过该公司授权，报告，不创建替代角色/成员绕过停用 |
| 公司角色/成员/绑定缺失 | 补建缺失项，不改其他角色与授权 |

补齐结果包含新增成员数、新增绑定数、已满足数、跳过公司及原因。出现跳过时明确“已完成可处理项，仍有跳过项”，不能写“全部公司授权成功”。数据库错误属于失败，整次可处理项事务回滚；跳过是预检后的明确计划，不通过吞业务异常继续提交。

## 事务与并发

已有账号分支与公司创建均先锁初始管理员 User，后锁所涉组织（多公司按 ID 排序），再按 ID 锁相关 Membership 和 Role；共同的初始管理员用户锁序列化这两条新增授权路径。新建公司本身不先锁既有公司后再等待用户，避免反向等待。

首次空账号 bootstrap 沿用系统管理组织锁及锁内用户表复核，账号/角色/成员建立在同一事务。若两个首次请求均尝试创建系统组织，唯一索引负责冲突，其中一个明确失败即可，不自动重试。种子被调用时要使用当前事务已创建的初始管理员，避免事务外查询不可见。

授权补齐以“事务内查到的有效公司集合”为本次目标；并发新公司创建也必须给同一初始管理员加成员，因此无须持有全表锁防止遗漏将来的公司。现有组织/成员/角色停用更新须受行锁保护，锁内复核后提交；用户标记不参与运行时准入旁路。

唯一约束覆盖组织内角色 code、用户组织成员、成员角色组合；驱动错误映射，不做忽略错误式幂等。所有成功授权审计同事务；CLI 审计标识命令来源及目标账号/公司，不打印密码或连接串。

## 迁移、规范和风险

沿用 is_bootstrap_admin 与现有唯一索引，不为这项功能增加版本字段或新角色模型。主组织删除迁移由前置子任务提供。替代 auth-session-org-switch 中“仅空账号可运行、不自动授公司”的条款，并调整原测试预期，保留组织隔离和系统权限过滤。

新增授权是用户明确的产品变更，不会自动给后来新增的其他系统管理员复制授权。回退代码不应顺带撤销真实成员关系；权限撤销需明确目标，保留审计，不猜测哪些已经被人工编辑。
