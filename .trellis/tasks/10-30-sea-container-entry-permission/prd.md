# 海运实际箱入口与共享箱权限错误修复

## 目标与授权

操作人员能从海运订单详情的「箱量与截关」直接找到实际箱维护入口；共享箱工作台准确区分加载失败、无权限和真实无数据，不以空列表误导用户。
2026-10-30 用户提供共享箱工作台双「无权执行此操作」截图，并同意创建任务，将权限报错、错误空态与实际箱入口一起纳入规划。本次仅创建规划，未开始实施。

## 背景与证据

- 「箱型箱量」绑定订单级 `containerRequests` 计划，实际独占箱由列表菜单的 ContainerDrawer 维护；详情 SeaExportDetailFeatures 目前只提供跨订单共享箱工作台，入口割裂。
- `web/src/pages/orders/components/drawers/SeaSharedContainerDrawer.tsx` 的 `loadContainers` / `loadCandidates` 在打开时各发一次请求。统一请求层消费失败后可能返回 undefined；两处 `resp?.data || []` 把失败解释为无数据，组件没有可见的错误状态及重试入口。截图双提示与这两个请求相吻合，但仍须通过请求记录确认。
- `server/api/order/v1/sea_cargo_allocation.proto` 两个读取接口均要求海运订单 `container.read`，创建要求 `container.create`。前端入口同样消费 canOrder('container.read')，不能据此直接认定前端缺权限门控。
- 后端 `server/internal/server/auth.go` 通过 requestOrder 优先读取 orderId 作为授权锚点；按具体操作权限范围查订单，再建立有效组织。`server/internal/data/sea_cargo_allocation.go` 的 ensureSharedAnchorExecution 要求活动链接属于请求航程。
- 尚未取得截图对应的实际请求、用户权限、订单公司和运行服务版本；鉴权拒绝的具体根因仍待技术复现，不得通过放宽权限、跨组织兜底或自动补授权来掩盖。

## 范围与需求

| 编号 | 优先级 | 要求 |
| --- | --- | --- |
| R1 | P1 | 复现两条共享箱查询的权限拒绝，核对路径、orderId、transportExecutionId、当前公司、订单公司、auth/me 权限与运行代码；定位后修正真实缺陷。合法无权场景保持拒绝。 |
| R2 | P1 | 为共享箱和候选订单分别管理 loading/error/success；403 展示明确权限提示，网络/5xx 展示失败及手动重试。只有有效成功响应且数据为空，才展示「暂无」与 0。 |
| R3 | P1 | 错误时不得展示误导性的正常创建空态；创建、修改、删除继续受权限、订单锁和公司写范围约束。单个请求失败不清除另一个区域已加载成功的数据或未保存分配草稿。 |
| R4 | P2 | 海运订单详情「箱量与截关」并列呈现「计划箱型箱量」和「实际装箱」入口。实际区明确普通独占箱与跨订单共享箱的用途，普通箱优先；复用现有箱维护能力，不另造表单。新建未保存时说明保存后维护实际箱，不强制先录实际箱。 |
| R5 | P2 | 详情维护实际箱后刷新对应实际箱数据/摘要；不能覆盖当前尚未保存的订单表单。初期摘要只展示已确认读取成功的数据；独占箱与共享箱不得重复计数，无数据失败不得显示零。若缺乏明确汇总口径，本期仅展示维护入口及独占箱摘要，共享箱另列，不混算总实际箱量。 |

## 验收标准

- AC1（R1）：提供可复现权限矩阵：同公司合法读可加载、无 container.read 拒绝、无创建权限不显示创建、其他公司/其他品类权限不越权、错误锚点/航程上下文被拒绝；截图问题的根因与修复证据记录到 research。
- AC2（R2）：共享箱查询 403、5xx、网络断开、失败被请求层消费为 undefined 均显示失败；不显示「暂无共享箱（0）」或正常空态创建按钮；手动重试成功后正确恢复。候选查询失败有独立反馈。
- AC3（R2/R3）：真实成功空数组正常显示空态；列表成功但候选失败时仍展示已读共享箱，不抹掉分配草稿；仅候选重试不重置人工分配；用户/订单/航程切换、关闭抽屉的迟到响应不污染新上下文。
- AC4（R4）：无需返回订单列表，便可从详情「箱量与截关」直接维护普通实际箱（箱型、箱号、封号、件重尺），并能辨认共享箱属于多票共箱；未保存的新建订单有清楚引导。
- AC5（R4/R5）：普通实际箱新增/编辑/删除后实际区域更新，未保存的订单字段保持；只读和审核锁维持既有规则；无权限不发不必要请求、不提供不可用入口。
- AC6（R4/R5）：计划保持独立，不被实际箱保存自动改写；1366×768 与 1920×1080 下入口可见、键盘可到达，错误提示和抽屉不遮挡操作。

## 排除与约束

- 不扩建箱务平台，不更改共享箱件重尺守恒、事务、版本和跨订单分配规则；不在本期增加计划/实际自动对账、差异报警或自动转换箱记录。
- 不擅自修改用户角色授权、清空数据或切换公司；复现只用受控测试环境/脱敏证据。
- 默认复用接口，不改 Schema 和生成物；若需契约更改，先记录真实必要性并按正式生成流程同步。
- 当前仓库存在其他进行中任务，实施前确认工作区和分支归属，只处理本任务文件。

## 技术待查项
