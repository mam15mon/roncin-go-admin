# 公司英文名称与 HBL 多公司支持

## 目标

管理员在公司档案中维护正式英文名称，各公司自签 HBL 使用真实签发公司的英文抬头输出，解除仅北京公司可用的限制。

## 背景与确认事实

- 用户明确要求支持其他公司，并同意增加公司英文名称；已批准创建任务和进入规划，尚待最终方案后的实现确认。
- 组织 Schema 当前只有名称、编码等字段，没有英文名称：`server/internal/data/ent/schema/organization.go:18`。
- 现有模板只允许自签且签发公司代码为 BJ：`server/internal/biz/sea_house_bill_print.go:13`；PDF 的公司英文名写死为北京：`web/src/pages/orders/hbl/pdf/HblPdfDocument.tsx:17`。
- 北京正式英文抬头已从用户提供的参考 PDF 确认。其他公司正式英文名没有可靠来源，不能推测翻译。
- 当前 HBL 已支持正文与印字保存、四版本输出、输入保护及完整续页；此次沿用该闭环。

## 需求

### R1 公司档案

- 在现有组织管理中的公司新建、编辑及详情增加「公司英文名称」，沿用组织管理权限和写入范围。
- 英文名称属于公司，系统节点、部门和团队不维护或继承该字段。
- 可空保存，允许管理员明确清空；去除首尾空白，最多 200 个字符，不允许内部换行或控制字符，不强制改写大小写。
- 现有公司的其他编辑不丢失英文名称。组织列表本地搜索可按英文名称匹配。

### R2 多公司 HBL

- 所有本公司签发的真实 HBL 可进入制作页，模板不再绑定 BJ 公司代码。
- PDF 的公司抬头、签发文字、固定条款中出现的公司名称及文件作者使用该 HBL 的真实签发公司英文名，不能取当前登录工作台或订单归属公司的名字代替。
- 未维护英文名时，制作页说明「签发公司尚未维护英文名称，请在公司档案中补齐后输出」；保留正文编辑/保存，预览、打印和下载不可执行。不以中文名、北京名称或自动翻译回退。
- 制单人员沿用订单读取权限获得所需抬头，无需增加组织管理读取权限。
- 继续复用 RONCIN 现有自签版式和 Logo，四种版本保持一致；较长英文抬头完整可读，不盖住其他内容。

### R3 基线与数据

- 公司英文名的变化纳入制作页既有前台 15 秒/回焦检查和生成前校验，保留用户输入、提示刷新，不自动推进制作基线。
- 英文名是公司主数据，此次生成使用明确读取的当前签发公司资料；不新建导出文件台账，也不回写已有 HBL 正文或不可变版本。
- 北京已有公司通过正式迁移补入已确认英文名，新环境默认北京公司种子同步该值。其他公司留空等待人工维护；默认种子不覆盖管理员修改或清空后的选择。
- 正式 Schema 增量迁移、API/Ent/OpenAPI/前端客户端源与生成物一起交付；不重置数据，不增加旧模板兼容分支。

## 验收标准

- [ ] AC1：公司英文名称可创建、编辑、清空和重新进入回显，长度/换行校验明确；部门/团队不出现该输入，直接请求也不能写入。
- [ ] AC2：北京已确认名称由迁移与新建默认种子补齐；成都及任意自签公司填入人工确认英文名后可输出，PDF 中无误用北京抬头。
- [ ] AC3：缺名时可编辑保存 HBL，但四版本输出均明确阻止；补齐后刷新恢复输出。
- [ ] AC4：HBL 签发公司与当前工作台/订单归属不同时，输出仍准确使用真实签发主体；不扩大组织权限。
- [ ] AC5：公司英文名外部变动触发持续提示并保留输入；刷新覆盖修改先确认，输出前拒绝过期抬头。
- [ ] AC6：四版本、锁定只读输出、长英文名、长正文续页及同一 Blob 预览下载打印经过实际 PDF/浏览器验证。
- [ ] AC7：定向测试、生成一致性、正式迁移验证、最终完整门禁和生产构建通过；review 后提交。

## 本期不包含

- 客户/代理等第三方签发模板、其他公司 Logo 上传或多品牌模板平台。
- 自动翻译或推测其他公司正式英文名称。
- 公司资料通用配置平台、组织新版本锁机制、打印文件台账或历史文件重现。
