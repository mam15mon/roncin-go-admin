# 技术设计

## 1 最小变更边界

补齐公司英文名称这一主数据字段及其真正消费端 HBL，保持现有组织管理、单证写入和 PDF 架构。唯一真相在 Organization，不在每份 HBL 的 PrintDetails 重复存一份公司名称。

## 2 契约和持久化

- Organization Ent 增加可空 `name_en`，最大 200 字符；AdminOrganization DO、创建/更新请求和响应追加 `name_en` / `nameEn`，不增加新接口或权限。
- biz 统一校验公司字段：去首尾空白、空表示清空、禁止内部换行/控制字符，非 company 的非空请求明确拒绝。保留原有 base_currency、组织层级和范围规则。
- data 沿原事务保存并审计 name_en，空值清列；列表、Get 及普通更新完整往返。组织关键词包含编码、中英文名和现有中文拼音键。
- 当前 HBL DTO 追加只读 `issuer_organization_name_en`；聚合查询及单票写后重读均依据真实 IssuerOrganizationID 投影，在 data 内完成，不跨层访问 Ent。
- 模板标识一次性由 `RONCIN_BEIJING` 改为 `RONCIN_SELF`，仅合法公司自签 HBL 返回；前后端和测试同步，不双认旧标识。
- 无新增 version、锁或事务；公司维护按低频主数据沿用已有机制，HBL 写入沿用原有并发和审核规则。

## 3 UI 和输出

- 现有公司创建/编辑模态表单添加可选 nameEn 输入，详情显示，组织列表本地搜索覆盖英文名；系统、部门、团队不增加该项。
- 区分「不可制作」与「暂不可输出」：无 HBL、作废、外部签发仍按原约束反馈；仅缺英文名不拦截编辑和保存，输出前明确提示补齐。
- HBL 页面通过单证 DTO 获取抬头，不使用 admin ListOrganizations，不增加管理权限，不让操作员临时改写公司抬头。
- HblPdfModel 增加必需签发英文名输入。页眉、作者、固定条款和签发区全部消费该值；字符支持检查也覆盖公司名，不能跳过现有缺字反馈。
- 共享 RONCIN Logo/现有四版本与 FlowTable。抬头按 200 字符边界设计有界换行和页眉空间，常规数据保持一页；长名称不能省略、覆盖或丢字。
- 资料指纹纳入模板标识、签发主体 ID 和英文名，沿原轮询及 verifyCurrent 检查；检测到主数据变化不能自动替换表单/输出基线。刷新经既有确认，再清理旧预览。
- 主数据名称更新只影响之后明确生成的文件；已下载的 PDF 和 HBL 不可变历史不修改。

## 4 迁移与初始化

先由 Ent 源生成增量 Schema SQL，再审阅正式迁移：仅新增组织列及必要检索键更新。北京补值使用 code=BJ 且 kind=company 的精确主体，采用已确认参考抬头；其他公司不补假名。

默认种子仅新建北京记录时设置 name_en，存在的记录始终保留管理员值，包括主动清空。北京正式迁移回填与种子来源文档记录参考 PDF，运行期不保留常量兜底。

禁止重置数据、并发 Schema.Create 或手工修补 Ent/API 生成物。正式迁移在独立 PostgreSQL Schema 验证完整迁移和已有数据升级。

## 5 验证与风险

- 最大风险是取错签发主体、名字出现在 PDF 多处但未改全、缺名与编辑状态耦合、名称变更未进检查指纹，以及长名称遮挡页眉；各项有针对性测试和实际渲染。
- 修改 proto → make api → go generate → 正式迁移生成/审阅 → generate:web-client，按源重跑确认差异稳定。
- 先定向后完整门禁；因涉及契约、Schema 和 PDF 页眉生产布局，最终 check:fast 与 build 必跑。
- 不引入兼容回退或第三方模板。若发现必须改变原有组织授权/事务边界，先报告问题，不以新增框架绕过。
