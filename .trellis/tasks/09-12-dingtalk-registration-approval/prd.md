# 钉钉注册审批与通知路由 PRD

## 1. Background & Scope

系统未开放注册，员工只能钉钉扫码进入。现状链条（已核实）：

1. 扫码 → 陌生身份 → 员工确认后账号落库为 **PENDING（禁用）**，无组织、无角色；
2. 之后**无任何通知**——持有用户管理权限的管理员只能翻用户页面人工发现挂起账号；
3. 审批是散的手工三步：启用账号 + 建 membership（凭肉眼判断归属）+ 派角色；
4. 通知基础设施齐全（后台任务队列 + 钉钉工作通知，"批准后通知本人"模板已有），唯独缺
   "新注册 → 通知审批人"半截。

分公司自治加人（成都的人加成都公司、总部零参与）需要打通：注册声明目标组织 →
按组织路由审批通知 → 一站式审批。

## 2. 身份与匹配键设计（已核实的技术事实）

- 扫码可得（`DingTalkIdentity`）：UnionID / 企业 UserID / 姓名 / 头像 / 邮箱（可空）/
  CorpID（强制本企业）；**OAuth 不返回手机号**。
- 系统已持有钉钉**企业通讯录 access token**（现用于 unionid→userid 转换），
  按手机号反查 userId（getbymobile）在既有能力范围内，无需新增授权。
- **数据归属原则**：邀请预存只有管理员决策字段（手机号 + 目标组织 + 初始角色 + 备注姓名）；
  账号身份（姓名/头像/unionId）以钉钉返回为准，预存姓名仅备注，避免双源打架。

## 3. Detailed Requirements

### 通道 A：邀请码（快路，推荐主用）

1. 分公司管理员（持目标组织的用户管理权限）预建邀请：**手机号** + 目标组织（默认本组织）+
   初始角色（默认最低权限角色）+ 备注姓名 + 有效期。
2. 员工扫码 → 换出企业 userId → 按手机号反查钉钉 userId（或反向按 userId 取通讯录手机号
   比对）→ 命中有效邀请 → **自动完成**：enable + membership + 初始角色 + 通知本人（复用
   `NewDingTalkUserAuthorizedNotification`）+ 通知邀请人"已激活"。
3. 邀请一次性消费；过期/已用不可复用；同手机号重复建邀请由唯一约束兜底（活跃邀请唯一）。
4. 扫码身份与邀请手机号对不上时**不自动放行**，落入通道 B。

### 通道 B：首扫认领（兜底慢路）

1. 无人邀请的扫码维持 PENDING，注册确认时**自选目标公司**（组织树下拉）。
2. 注册落库带目标组织 → 后台任务生成通知，**只发给目标组织持用户管理权限者**。
3. 审批页一站式"同意"= 启用 + 建 membership（目标组织）+ 初始角色 + 通知本人；"拒绝"留痕
   并通知本人；审批页展示钉钉姓名/头像供人工认领。
4. 总部兜底：开放式注册（无目标组织语义的存量 PENDING）通知总部管理员。

### 通知与安全

- 通知经既有后台任务 + 钉钉工作通知通道投递，失败重试语义沿用；审批提醒在注册后即时
  生成，不轮询。
- 邀请/审批全部写审计（谁邀的、谁批的、目标组织、时间）。
- 手机号仅用于匹配，展示时脱敏（138****1234）；不进入日志。

## 4. Acceptance Criteria

- [ ] 邀请链路：录手机号邀请 → 该手机号员工扫码 → 自动激活进目标组织带初始角色，
      本人收到通知，全程无人工审批；邀请消费后同手机号再扫不重复激活；
- [ ] 认领链路：无邀请扫码选公司 → 目标公司管理员收到通知 → 一键同意/拒绝，
      拒绝留痕并通知本人；
- [ ] 路由正确：成都的注册不通知总部（除非走总部兜底通道）；
- [ ] 手机号匹配不上不自动放行；邀请过期不可用；
- [ ] 既有钉钉登录/注册/会话回归全绿；
- [ ] `go -C server test ./...`（含集成）+ 前端相关定向测试通过。

## 5. Out of Scope

- 组织切换器（独立任务）；membership 管理界面重构；钉钉通讯录全量同步（按手机号反查
  的点查即可，不建同步）；HR 主数据系统对接。

## 6. 排期

- 默认排在 auth-org-switcher 之后串行；若分公司加人需求紧急，可插队提前（两者文件集
  基本不相交，插队无技术障碍）。
