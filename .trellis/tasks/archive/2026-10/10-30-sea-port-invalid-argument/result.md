# 修复记录

## 根因与范围

用户刷新后未编辑直接保存仍失败，实际请求的起运港和目的港引用同一有效港口。旧校验用 SQL IN 的唯一记录数量对比原始引用数量，误报 `ORDER_INVALID_ARGUMENT`；与前一任务的主单版本修复无关。

## 实现

- 港口、机场校验入口复用现有 `uniqueUUIDs`，按唯一 ID 集合计数，不改写原订单字段或输入切片。
- `biz` 定义港口/机场具体失效提示，沿用 `ORDER_INVALID_ARGUMENT` reason；缺失、停用和非 nil 零 UUID 仍拒绝。
- 不改变货物分类等业务禁止重复的校验，不放宽组织、权限、版本或事务规则。
- 数据库规范补充地点引用集合语义与回归要求。

## 验证与审查

- 单元回归覆盖 nil、单个、两个字段同 ID、不同 ID、四字段同 ID、混无效和零 UUID，验证原字段/切片不变。
- 专用一次性测试库执行正式 SQL 迁移与隔离 Schema 集成回归；覆盖 SE/AE 创建、刷新无改更新及缺失/停用引用原子拒绝，未修改开发业务数据。
- 初次真实迁移验证识别出测试 UN/LOCODE 夹具与国家代码不一致，按正式约束修正测试输入，没有改动 Schema 或业务规则。
- 空运主单已有起降机场必须不同的业务规则，真实 AE 流程保持合法起降、在其他字段重复；四字段同 ID 仅在引用集合校验层验证，不放宽航空规则。
- 最终定向在专用库运行：14 个单元叶子用例与 3 个共享地点 PostgreSQL 根测试通过，6 个 SE/AE 完整更新组合及缺失/停用原子拒绝全部通过，无 SKIP，7.16 秒（`/tmp/roncin-location-validation-final-targeted.log`）。
- 相邻组同样在专用库真实执行 `TestOrderCreateTransactionPostgres` 的 16 个子场景（含并发创建、版本冲突、共享主单）及 ToBiz/AllowedActions/Location 单测，全部通过，无 SKIP，3.06 秒。
- `biz` 的订单定向测试、`data/biz` vet、gofmt 和 diff 检查通过。
- 独立 review PASS，无遗留可操作问题；未通过改 Schema、放宽空运/货物分类业务约束或修改原订单数据来通过回归。
- 最终 `pnpm run check:server` exit 0：重复扫描、Go 分层检查、Proto lint、全后端测试、全后端 vet 及漏洞扫描通过（`/tmp/roncin-location-check-server.log`）。完整门禁未注入真实库环境，直接受影响及相邻数据库回归已在专用测试库单独真实运行，未把 SKIP 算作集成通过。
- 本次没有前端、契约、Schema、依赖或生产入口变更，未重跑无关的完整前端门禁或构建。
