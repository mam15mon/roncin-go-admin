# 技术设计

## 变更边界

差距位于海运表单候选与共享字段呈现：当前只回填候选标识，缺少明确的继承、差异采纳和只读来源。服务端已校验候选版本及冲突，共享更新按实际航次活动成员统一执行。

- 候选与表单：`templates/components/sea/SeaTransportSection.tsx` 及就近逻辑、`sea-template.tsx`、必要表单类型与只读字段组件。
- 更新入口与影响票：`components/drawers/SeaTransportExecutionUpdateModal.tsx`、`order-kinds/sea-export/SeaExportDetailFeatures.tsx` 及各自测试。
- 主会话维护任务、规范与提交；两个实施边界不互改对方文件。
- 不改 Proto、Ent、迁移、生成客户端和后端规则；发现现有契约不能完成本期时先报告证据，不静默扩展。

## 候选数据流

1. 船公司和主单号确定候选身份；防抖参数进入 React Query queryKey，身份变化立即隐藏旧结果。替换本次受影响的手写请求 Effect，表单同步仍可用 Effect。
2. 基于候选航程对照表单差异，服务端写入复验仍是权威。日期与保存载荷同口径使用本地日零点，不截取 ISO 字符串冒充日期换算。
3. 单航程自动选定，多航程明确选择。候选 ID、版本、航次 ID/版本仅在当前可关联、选定航程且差异解决后有效；直单占用、核对中或失败均不能误提交。
4. 空白字段带入；共享值缺失时不得将用户非空值当成继承成功、导致保存后丢失，应明确列出差异或提示先补全共享资料。覆盖非空不一致值必须由明确点击触发。
5. 清理旧候选标识和继承来源不清除单票资料，也不误删用户手填航程；换候选后保留输入重新比较。
6. 已采纳航程的共享字段只读，目的地继续可编辑。详情已有多票共用航程使用共享更新命令；单票详情既有更正能力保留。

## 界面语义

- 新建：“已找到主单 X，已有 N 票；本票保存后将加入，共 N+1 票”。未保存不称已关联。
- 详情：“共用主单 X，共 N 票”，不加一。
- 单航程展示业务摘要；多航程下拉明确船名、航次和日期，缺失值显示“未填写”。
- 资料缺失提供已有成员订单链接，新标签打开保留新建输入；已有订单权限控制真正更新能力。
- 未选船公司呈现待核对提示，其它独立错误继续由官方 Form 同时校验展示。

## 共享更新

船公司属于主单身份，不能通过共享航程更新修改，仍走既有更正/改配规则。复用现有预览/执行弹窗和 reassign 权限、业务锁、版本、幂等规则；详情顶部“更多操作”中的入口改名“修改共享航程”，共享区明确指向入口，不增加回调或全局事件。

影响范围严格来自预览 `memberOrderIds`；用生成客户端与 React Query 按这些 ID 读取订单号，不用同批列表推断实际航次全部成员。失败保留真实影响数量及对应 ID/失败提示，不把失败当空范围。

## 验证与回退

测试使用真实 Form 注册和独立 QueryClient，不为未注册候选字段增设生产不存在的隐藏项。重点覆盖回填不会循环查询、旧确认不沿用新主单、日期不偏移、单票资料保留及共享影响范围。无 Schema 变更，撤销时回退代码提交，不改演示业务数据。

## 后续项

共享 TE 更新后详情使用共享航程投影，列表部分搜索仍查询原始 Order 航程列，存在存量筛选口径风险。本期不改该查询链，后续需按实际筛选用例单独核对。

## 检查补充：MBL 与航程成员边界

正常页面创建、候选关联和拆票流程保持一个航程归属于一个 MBL，详情只读判断沿用当前摘要的 MBL 成员数。统一修改始终按服务端预览返回的实际航程成员执行和展示。当前摘要不提供独立的航程成员数，因此不能据此宣称支持任意跨 MBL 的共享航程编辑。

检查发现一个独立的存量服务端问题：改配的候选 MBL ID 与航程 ID 读取后未验证二者活动 Link 配对，直接构造不匹配请求可能打破正常页面的归属关系。普通保存的锁集合也按 MBL 成员处理。本期不改后端写入规则；后续应在改配预览和执行统一验证候选配对。若正式支持跨 MBL 共用航程，还需同步摘要成员数、只读判断和普通保存锁范围。
