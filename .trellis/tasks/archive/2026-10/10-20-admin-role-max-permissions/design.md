# 角色可授予权限候选设计

## 边界与数据流

保持完整权限字典 API 和页面不变。角色页读取当前认证上下文的 permissionCapabilities，将有效能力与字典求交后传入表单、权限树和矩阵。有效范围沿用 access 的 organization / organization_tree / all 口径，不以任意非空 scope 放行，不以 permissions、角色名或用户名回退。

后端 auth/me 已按工作台和启用角色投影有效能力，前端无需复制 Manifest 的工作台分类。提交仍由服务端实时防提权及工作台合法性校验兜底。

## 页面行为

全选读写、模块批量、单项操作和统计基于同一可授予候选，表单用简短中文说明范围。编辑保留既有 permissionKeys；遇到不可授予的既有项，明确提示并禁止提交，不在载入或提交时静默过滤。

复用认证工作区按身份重建的机制，并验证能力变化时重新派生候选。若触及字典请求，按规范迁移 React Query，不新增手写 useEffect 请求状态。

## 契约与风险

无 Proto、Schema、权限 Manifest 或生成客户端变更。修复现有 auth/me 的消费，不增加重复 API。重点防止编辑时静默撤权、缺能力误开放和工作台切换串用；业务库仅只读，集成验证仅使用专用库。回退代码不改实际授权数据。
