# 手机号账号登录与钉钉验证码自助重置密码

## 目标

将前端“管理员账号”入口调整为普通员工可用的账号登录。员工以钉钉提供的手机号作为登录账号，通过钉钉接收验证码，自助设置或重置密码，验证码发送间隔至少 60 秒。

## 已确认决定

- D1（2026-10-19）：用户回复“好的啊”，同意统一“账号登录”入口同时支持员工钉钉手机号和现有本地账号用户名；初始化管理员继续使用用户名密码。账号输入提示不再包含尚不支持的邮箱登录。
- D2（2026-10-19）：用户随后回复“好的”，确认统一“设置 / 忘记密码”入口；首次设置与找回使用相同流程；6 位数字验证码、5 分钟有效、累计错误 5 次后作废、重新发送使旧码失效，成功后退出该账号所有设备，返回登录页重新登录。
- 原始要求：验证码发到员工本人钉钉，两次发送至少间隔 60 秒。手机号取自钉钉资料。

## 现状核验

- 前端密码模式为“管理员账号”，输入提示为“用户名 / 邮箱”（`web/src/pages/user/login/index.tsx:156`、`:220`）；后端按用户名查询，并不支持邮箱登录（`server/internal/data/auth.go:27`）。
- 钉钉通讯录已有 `dingtalk_mobile`，目前为可选资料且没有唯一索引（`server/internal/data/ent/schema/user.go:57`、`:148`）。来源无手机号权限或响应无值时，成功同步会清空本地手机号快照；手机号缺失不阻断扫码（`.trellis/spec/server/backend/dingtalk-registration-approval.md:34`）。
- 已有手机号归一化、国内 11 位号码校验及脱敏工具（`server/internal/biz/dingtalk_mobile.go:12`）。
- 已有钉钉机器人单聊 `SendText`，按已绑定企业 UserID 发送（`server/internal/data/dingtalk.go:194`）；当前真实应用的验证码送达能力尚未联调。
- 管理员重置密码已有同事务修改密码、撤销全部未撤销会话和审计的行为，但要求目标具有用户名（`server/internal/data/admin_user.go:466`），不能直接套用为无用户名钉钉员工的自助接口。
- 现有密码工具要求至少 12 字节，管理员重置还先检查去首尾空白后的长度至少 12（`server/internal/security/password/password.go:25`、`server/internal/biz/admin_user.go:191`）；本任务沿用现有密码校验口径，不另行降低密码长度。
- 2026-10-13 的扫码任务原约定员工扫码、管理员使用密码；本次需求将其扩展为员工也可使用手机号密码，不改变组织授权与人员开通规则。已有任务文档足以核实这一决定，无须重复查阅原始对话。

## 需求范围

| 编号 | 需求与可见行为 |
| --- | --- |
| R1 | 默认仍展示钉钉扫码，次级入口改为“账号登录”，输入提示为“钉钉手机号 / 本地账号”；员工手机号和本地用户名均可登录。两种方式进入同一账号，沿用单工作台直接进入、多工作台明确选择的行为。（D1） |
| R2 | 手机号只来自钉钉通讯录，接受系统现有国内手机号归一化格式；不创建、合并或重绑用户，不以手机号覆盖 username。来源缺失、无效或号码重复时不能用该号码登录或找回；仍可扫码。不同用户的手机号与本地用户名重名时拒绝歧义输入，提示改用扫码或联系管理员，禁止逐账号尝试密码。 |
| R3 | 账号表单提供“设置 / 忘记密码”，输入钉钉手机号后请求验证码，验证码只发给已绑定企业 UserID；输入验证码、新密码与确认密码提交。首次无密码的钉钉员工也可完成流程，无须先补本地用户名。（D2） |
| R4 | 由服务端执行每个手机号至少 60 秒一次的发送限制，前端基于服务端时间显示倒计时；刷新、换浏览器、并发调用、重启服务不能绕过。另对来源 IP 的批量发送请求实施有界限流，不能用该接口批量骚扰员工。 |
| R5 | 采用 D2 确定的验证码有效期、错误次数、重发失效和一次性使用规则。手机号或钉钉身份在验证码申请后改变，旧验证码不能完成重置；发送失败或请求结果未知时明确提示，不能假报已送达。 |
| R6 | 新密码沿用现有校验规则；成功时密码写入、验证码消费、该账号全部会话撤销与审计必须一起成功。成功后返回账号登录，不自动建立会话。（D2） |
| R7 | 扫码、手机号密码和自助设置不能绕过未同步、待分配、停用、无有效工作台等既有准入。未绑定钉钉的本地账号不通过该入口找回，继续使用现有管理员管理能力。 |
| R8 | 验证码、密码和挑战令牌不得写入日志、审计及通用通知正文存储，手机号仅脱敏记录。公共发送响应不披露账号是否存在、启停状态、姓名、完整手机号或钉钉身份。契约与生成物、正式迁移、开发数据与规范同步交付。 |

## 验收标准

- AC1（R1、R2）：已启用员工用当前钉钉手机号与正确密码登录同一用户；本地管理员用户名登录正常；扫码和密码均正确处理单、多工作台及回跳。
- AC2（R2）：`+86`、`0086`、空白和连字符按现有工具归一化；空号、无效号、重复号码和跨用户用户名冲突均不误登录、不自动合并，不影响正常扫码。
- AC3（R3、R7）：已开通但没有 username/password 的员工收到本人钉钉验证码后可设置密码并以手机号登录；已有密码也能找回；没有手机号、未绑定钉钉的本地用户不被自动绑定。
- AC4（R4）：第 60 秒前不能重发，到达第 60 秒后允许；同时覆盖刷新、多个客户端、服务重启与并发请求只触发一次发送；同一 IP 大量不同号码请求被限流。
- AC5（R5）：验证码 6 位，5 分钟后失效；第 5 次输错后作废；重发后旧码失效；新手机号/新钉钉身份不能使用旧挑战；网络异常、消息失败和受理成功显示准确。
- AC6（R6）：同时提交正确验证码仅一次成功；成功后所有设备的旧会话均失效、新密码可登录、旧密码失败；密码写入、消费、撤会话或审计任一步失败均不出现部分提交。
- AC7（R7）：待分配、停用、无有效工作台用户不能通过新路径获得登录资格；验证码申请后再停用仍不能重置；现有组织选择、切换、管理员重置和通讯录同步相邻路径通过验证。
- AC8（R8）：未知、重复及不合格目标的公共发送响应不区分账号状态，不向任意外部 UserID 发送；日志及持久化敏感字段检查通过。接口错误有中文提示，不把消息受理称为实际送达。
- AC9（R8）：正式 SQL 在隔离 PostgreSQL Schema 验证冷启动及已有手机号回填，身份、组织授权和既有密码保持；所有生成物通过生成器更新，真实锁/并发测试实际执行，最终全栈门禁通过或明确报告环境阻塞。

## 范围外

- 短信、邮箱验证码或验证码直接登录；此次验证码只用于设置和找回密码。
- 自助注册、账号开通、手机号手动绑定/变更、按手机号合并账号。
- 改变扫码授权协议、公司角色及工作台授权、管理员初始化规则。
- 通用身份平台、Redis、通用验证码服务、新的后台通知调度平台及历史兼容分支。
- 自动清库、重建业务库、自动修改真实员工账号、未经指定收件人的实际钉钉消息测试。
