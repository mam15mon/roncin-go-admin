# 手机号登录与钉钉密码找回技术设计

## 1. 范围与边界

依据 `prd.md` 的 D1、D2 和 R1–R8。登录、首次设置与密码找回复用现有用户和成员关系，不产生新的身份。接口契约在 auth.proto，边界校验与 Cookie 操作在 service，业务规则和密码处理在 biz，Ent 查询、状态竞争和原子写入在 data；消息复用已有钉钉 `SendText` 适配器。`internal/server` 仅注册与中间件接入，不承担身份解析。

保持单任务，按契约/数据、后端闭环、前端、质量验收顺序实现；各阶段可提交，最终整体通过才算交付。实施由 Trellis 实现代理执行，检查代理独立核查；主会话负责范围协调、文档、提交和交付。

## 2. 手机号检索与登录身份

保留 `dingtalk_mobile` 来源快照；增加可空、敏感的 `dingtalk_mobile_normalized` 检索字段和普通索引，不建立手机号唯一约束。该字段是可重建的检索投影，不是独立身份。通讯录唯一生产写路径同时维护原始和归一化值；缺失、无授权或无效号码清空检索投影，不阻断其余资料同步。回填使用正式 SQL 并测试其与 `NormalizeDingTalkMobile` 的等价性，至少覆盖国内号、+86/0086、连字符、Unicode 空白、无效值和重复值。开发种子及所有其他实际写入方一次同步更新。无需把手机号暴露在 CurrentUser 响应。

不加唯一索引的原因：重复手机号属于不能凭号码确定目标的资料状态，不能让其阻断原有通讯录同步和扫码；按姓名或手机号合并违反既有身份规则。

登录输入沿用 LoginRequest.username 字段表达“账号”，修改注释与界面口径，不新增旧字段回退逻辑。按本地用户名规则生成 username 候选；合法国内手机号还将规范化号码作为本地用户名候选，并生成规范化手机号候选，避免 +86、空白等输入绕过数字用户名冲突。查询两类命中用户并按用户 ID 去重，在检查密码前确定结果：

- 无匹配：统一无效凭据。
- 同一用户两类命中：一个目标。
- 多用户或重复手机号：拒绝歧义，提示“账号信息存在冲突，请使用钉钉扫码或联系管理员”，不能用启停过滤来猜目标，也不能依次验证不同用户密码。
- 唯一目标：沿用密码校验、失败限流和工作台准入。最终建立会话的事务内再次核对用户可用状态、凭据快照与当前号码映射；重置或号码变化在先时，不得用事务外已验证的旧凭据建立新会话。

不自动设置 username 为手机号。支持手机号登录并不要求用户有 username；本地管理员仍用原有用户名。号码变化的生效时点是通讯录同步提交，不宣称能实时发现尚未同步的钉钉资料变更。失败登录审计只存域分隔 account_hash，不存原始输入；手机号等价格式共用失败限流桶，替换原失败审计直接写 username 的路径。

## 3. HTTP 契约草案

所有新增接口位于 AuthService，通过 access 注解标记 PUBLIC，使用现有统一信封和中文领域错误；无需新增业务权限码。请求不接受外部 userID/钉钉 UserID/组织 ID 作为重置目标。

| 方法与路径 | 输入 | 主要返回 |
| --- | --- | --- |
| POST `/api/v1/auth/login` | 现有 username、password、可选 organization_id | 现有 CurrentUser 与 organization_choices |
| POST `/api/v1/auth/password-reset/code` | mobile | 不透明 challenge_token、expires_at、resend_available_at、server_time |
| POST `/api/v1/auth/password-reset/confirm` | challenge_token、code、new_password | 成功信封，不签发新会话 |

上述 snake_case 为 Proto 字段，HTTP JSON 及生成客户端沿用 camelCase。挑战令牌为密码找回专用随机值，不能用作会话，不能放 URL。所有相关响应禁止缓存。发送失败与验证码错误返回可识别领域错误；429 包含可用于倒计时的重试时间，具体附加字段跟随仓库错误映射规则，不绕过统一请求客户端。

发送统一文案：“若该手机号对应已开通的钉钉账号，验证码将发送到本人钉钉。”未知、重复、未开通、停用、无有效工作台目标也返回同形状的不可使用挑战，且执行相同手机号冷却，不披露姓名、状态或目标 ID。全局钉钉未启用返回明确不可用提示；实际发送失败/超时返回“暂时无法发送验证码，请稍后重试或使用钉钉扫码”。不承诺消除网络时序侧信道，不为此建设异步认证平台。

密码输入校验沿用现有规则，确认密码只在前端比较；biz 复用 Argon2id Hash。验证码校验不会调用要求至少 12 字节的密码 Hash 来散列 6 位验证码。

## 4. 挑战状态与敏感数据

新增 Ent Schema `PasswordResetChallenge`（正式表名 `password_reset_challenges`），每个规范化手机号摘要最多保留一条当前状态，重发时替换。字段至少包括：

- ID、创建与更新时间；`mobile_key_hash` 唯一，使用固定域前缀与规范化手机号计算摘要，不存原始请求号码。
- `token_hash` 唯一、`code_hash` 敏感；可空 `user_id` 及钉钉 UserID/UnionID 快照用于绑定唯一目标，均不对外输出。
- `status`：PENDING、READY、FAILED、CONSUMED；`expires_at`、`resend_available_at`、`failed_attempts`。

规范手机号、挑战令牌均使用现有 crypto/rand 等标准库生成/摘要工具；验证码使用安全均匀的 6 位数字（保留前导零）。挑战令牌至少 32 随机字节，数据库只存其哈希；验证码摘要使用域分隔的 SHA-256(token + code)，令牌原文只返回发起浏览器，不进数据库、日志、审计或任务载荷。这样不能仅凭数据库中的摘要穷举 100 万个验证码。比较使用常量时间。不存在目标的挑战保留同样随机性和响应字段，但不得产生可消费的密码修改资格。

挑战是一次性状态机操作，按行锁加状态/令牌条件控制，不引入 expectedVersion 及人工编辑界面。唯一索引处理并发首次创建；使用 Ent 支持的冲突处理或在 data 内集中封装必要语句，不能吞数据库错误继续提交。CHECK 值集、尝试次数及生成元数据与正式迁移一致。

不在通用通知表保存验证码正文，不入后台任务，不增加自动重试。表按手机号复用，不存多代历史；来自任意号码的记录增长由 IP 限流约束，删除过期行的治理不扩展为本期通用任务。

## 5. 发送、冷却与结果

1. 边界验证/归一化手机号，按已有可信请求元数据取得 IP，拒绝格式错误。发送限流使用现有持久化桶机制，独立 `password-reset-send-ip` 前缀；每 IP 每 10 分钟最多 20 次发送申请（包含未知目标），与密码登录失败计数互不干扰。不将无效验证码请求累计为登录失败。
2. 查询唯一候选及有效工作台，事务内复核；已知用户按用户行锁先于挑战行锁的顺序操作。对 `mobile_key_hash` 对应行加锁或原子创建，取得挑战锁后以当前 UTC 时刻判断 DB 内的 `resend_available_at`，并基于该时刻建立新一代 60 秒冷却与 5 分钟有效期，不能沿用锁等待前的时刻。未到时返回 429；到期才允许覆盖 token/code，并将旧代立即作废。
3. 记录 PENDING，写下未来 60 秒冷却和 5 分钟到期时间；事务提交后才调用 SendText。绑定目标校验失败也执行同样冷却和不可使用挑战响应，不发送消息。服务器统一使用 UTC 时刻计算，前端只渲染相对秒数；客户端时钟不是门禁。
4. 消息内容只含业务名、用途、验证码、有效期与非本人操作可忽略提示。只使用已验证绑定的企业 UserID，不接收客户端提供的收件人，不群发。
5. API 受理后，在短事务中用 token_hash 条件把当前代 PENDING 改为 READY；状态确认前再次核对目标绑定。若已被新代替换、手机号改变或过期，不激活旧代。客户端只提示“请前往钉钉查看”，不称已送达。
6. 发送失败或超时把当前代标记 FAILED，清除可消费摘要，保留冷却；PENDING 因进程崩溃遗留也不能确认密码。外部消息可能已到达但状态未激活时，旧码不可用，60 秒后用户显式重发。发送调用必须有界超时，不在数据库事务内等待网络。

重发不依赖前端持有旧 token，同一手机号所有客户端共享冷却。前端丢失挑战或刷新后可以重新请求，服务器返回剩余冷却；不能绕过门禁。挑战令牌只保留在当前页面内存中，不把密码、验证码或 token 写入持久浏览器存储。

## 6. 消费、会话与并发

按 token_hash 查询最小快照得到目标，再进入 WithTx：需要锁的限流桶（若涉及）先按键排序，然后用户（多用户按 ID 排序）→ 相关组织/成员（按 ID 排序）→ 挑战 → 会话。避免反向“挑战锁等待用户锁”与既有用户→会话路径成环。状态回写只锁挑战且不再等待用户；验证失败计数在事务成功提交后由用例返回领域错误，不能返回事务回调错误导致计数回滚。

事务内必须复核：

- 取得所需行锁后以当前 UTC 时刻复核 token_hash 对应当前代且 READY，未消费、未过期、错误次数小于 5；发送激活同样遵守锁后时效判断。
- 当前用户启用、非待分配、有有效工作台；当前规范手机号仍匹配该 mobile_key_hash，钉钉 UserID/UnionID 与申请时相同。
- 当前手机号查询依然唯一；以当前读取/提交顺序判定同步变化与重置的先后，禁止缓存身份结果作为最终写入依据。
- 验证码正确；错误则增加 failed_attempts，第 5 次将挑战置 FAILED 并清摘要。未知/无资格 token 统一返回“验证码无效或已过期，请重新获取”。

正确时同事务：更新 password_hash → 标记 CONSUMED 并清摘要 → 撤销该 userID 全部未撤销会话 → 审计。任一步数据库失败整体回滚；两个正确请求由锁与状态串行，只允许一个成功。实现采用 biz 注入纯密码 Hash 回调，仓储仅在锁内完成状态、绑定、时效和正确验证码检查后调用，再写入结果。这样未知、错误、过期和用过的验证码不会触发 64MB Argon2id 计算，也无需新增预验证状态或第二套消费协议；代价是正确提交在事务内持有锁期间计算一次密码哈希，纳入并发测试。

已有管理员重置密码同样会撤会话，应同时废弃该用户当前找回挑战，防止旧验证码在管理员重置后再次覆盖新密码。仅补齐这一认证相邻规则，不扩大管理员重置权限、组织范围或改变用户名维护行为。

通讯录手机号投影或钉钉绑定变化时，在用户更新事务内主动废弃该用户未完成挑战，避免先改号再改回让旧验证码复活；消费仍须最终快照复核。若同步在消费后发生，消费按先发生处理。密码登录创建会话需复核最初验证的密码哈希仍为当前值，避免先验证旧密码、等待重置提交后再创建新会话。已有会话查询继续使用持久撤销状态，不新增另一套令牌。

## 7. 前端交互

修改现有登录卡片，不新增独立认证站点。保持扫码组件挂载/隐藏机制与组织选择行为，替换管理员限定文案及邮箱误导提示。统一请求客户端的公开认证豁免精确加入 code/confirm 两条路径，使残留工作台作用域不拦截找回；保留其他接口作用域 guard，不泛化放行所有 auth 路径。在账号模式放“设置 / 忘记密码”操作，以页面专属 ModalForm 实现手机号、验证码、新密码、确认密码；onFinish 返回 Promise，提交期间由组件接管状态。

发送按钮有独立请求 loading；倒计时按 resend_available_at 与 server_time 的差值计算单调截止时间，使用定时器仅更新展示，关闭清理。更换手机号立即清理当前 challenge/code 和旧异步响应；按请求序号和当前目标手机号比对响应，不能把上一个手机号挑战应用到新表单。关闭后不保留敏感字段。冷却及错误信息有可访问文案。

成功关闭重置表单、清除本页登录主体/待选择组织与相关用户缓存、清除当前站点会话 Cookie（由 service 清理，撤销仍是服务端权威）、进入账号模式，可保留刚操作的手机号帮助重新登录；密码及验证码必须清空。失败保留必要输入便于修正，不自动切换认证方式或自动发送。

## 8. 迁移、验证与回退

Ent Schema 是真相源，执行生成器更新实体及检查元数据，再提交正式 SQL，覆盖手机号投影回填和挑战表/索引/CHECK。不清空、不自动重建业务库；迁移在专用测试库按正式迁移链验证。Proto、Go 绑定、访问策略生成物、OpenAPI 和前端客户端按仓库生成顺序同步。

验收同时包括纯业务规则、真实 PostgreSQL 锁/一次性消费/回滚/迁移、HTTP Cookie 与公共接口规则、前端异步切换和倒计时，以及扫码/本地管理员/组织选择/目录同步相邻路径。最终执行 check:fast，因为此次跨认证、Schema 和生成契约；不是普通 UI 修改。

代码回退按本任务提交逆序回退，正式环境回退数据库须审阅迁移，不自动 DROP 列/表。真实钉钉验证依赖当前应用机器人权限及指定测试收件人；没有显式收件人时不实际发送消息，交付报告清楚区分 mock、API 受理和本人确认收到。资料获取受通讯录权限及同步时点限制，本地账号自助找回、非国内号码支持不在本期。
