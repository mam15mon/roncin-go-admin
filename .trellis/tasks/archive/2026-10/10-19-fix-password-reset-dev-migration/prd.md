# 修复开发环境验证码申请内部错误

## 目标与已证实根因

用户在设置/忘记密码点击发送验证码时看到“服务器内部错误”，已同意建立本修复任务。

2026-10-19 只读核验：当前开发数据库最新 revision 为 20261016100000_retire_role_data_scope；password_reset_challenges 表与 users.dingtalk_mobile_normalized 字段均不存在。后端 roncin-server 已热更新到新实现，进程由长期运行的 pnpm dev/air 管理。scripts/dev.mjs 仅在启动阶段执行 migrate:dev；air 监听 SQL 后只重建 Go，不自动执行迁移。因此这是未应用本期正式迁移的环境缺口，不添加业务自动建表或兼容分支。

## 最小修复边界

1. 审阅本期唯一待应用迁移，执行现有 pnpm run migrate:dev；保留业务数据、账号身份与密码，不清库，不额外同步开发种子。
2. 只读验证本期 revision、手机号检索列、验证码挑战表、索引/CHECK 均存在，采集不含个人数据的数量/摘要验证身份和密码不变。
3. 使用确认不对应本地身份的国内格式测试号码请求本地HTTP申请接口，验证码只产生不可消费挑战，不给真实员工发信；响应从500恢复为正常200（钉钉全局可用）或准确的业务错误。不得打印token、验证码、密码、连接串或员工手机号。
4. 独立检查核对根因、执行命令与验证证据；文档明确新迁移落地后长期运行的开发服务需要执行 migrate:dev（或重启pnpm dev），生产用 migrate:server。

## 验收

- 正式迁移成功且重复执行无待应用结构变化。
- user/organization/membership及密码hash统计摘要前后一致（只输出相等布尔值）。
- 申请接口无内部错误，公开响应不暴露目标状态；不实际发钉钉消息、不修改密码。
- 无产品代码、生成物或依赖的无关改动；只提交修复记录及必要运维规范提示。

## 范围外

自动清库、Schema.Create、业务缺表自动修复、自动重发、真实收件联调、改动air热更新机制和重建通用开发启动平台。
