# 独立复核重点

## 契约完整性

审查公共类型 → 默认冻结推导 → 偏好读取/解析 → Panel 修改 → 保存 → 应用列的完整链路，
再独立追踪费用专有默认值、等价比较、存取、归一化、orderColumnsByPreference 和工具栏。
旧 first/last 不再执行，不能遗漏仍引用旧类型的测试或消费者；结构 option 的冻结配置
不能在只接收普通字段 key 的偏好过滤阶段丢失。

## 顺序和身份

Panel 编号、区内 order、跨区变更与最终 columns 必须使用同一左/普通/右顺序。
特别检查前移/后移数组 splice 的目标位置、插入前/后、空区投放、搜索期间排序、
拖动取消、精确序号范围及隐藏列序号语义。字段身份来自稳定 key；结构列不能按中文猜测。

## 状态与边界

关闭/禁用/高级弹窗切换后拒绝过期回调；scope 变化当次渲染读取新偏好。
新列、未知 key、重复 key、左右冲突、必显、全隐藏、损坏存储和写入失败应有针对性证据。
只实现当前需求，不新增服务端偏好、通用平台、旧契约转换或不必要依赖。

## 几何与生命周期

主会话负责真实浏览器测量字段矩形、无内部滚动和横向多列冻结；复核不要用
happy-dom 或 CSS 字符串断言替代几何证据。检查公共表格未通过 key 重挂，
请求/分页/选择/列宽/未提交编辑不因设置丢失。保留窄容器临时解冻和宽度恢复。

## 验证分工

实施代理执行定向测试、修改文件 Biome 和 tsc。独立 check 审查整个变更并修复
确认问题，再执行对应最小复测。主会话跑真实浏览器及最终 check:web，避免并发
运行多套完整门禁造成资源争用。所有发现、修复和未决限制写入 check-report.md。
