# 技术设计

## 边界与入口

在现有 `components/ui/column-settings` 内改造。Entry 从 Popover 改为接近全屏的 Modal，高级设置仍独立管理生命周期。Panel 受控消费同一生效配置，调用方继续保存。

## 布局与拖动

CSS Grid 按行呈现编号条目，结合实际宽高、字段数量与可读最小条目尺寸选择列数；不再设置旧列表 maxHeight/overflowY。浏览器验收检查全部字段实际矩形和视口，不能只检查没有滚动条。

条目含手柄、全局序号、显隐、列名和紧凑冻结选择。显示左冻结、普通、右冻结边界和数量，各区域统一连续编号，区域间可投放且支持空区域。按字段 key 操作，不按搜索后的数组下标写回。精确移位通过目标序号提交。

优先延续原生拖动，补充拖动数据、插入前后判定、手柄与控件隔离、取消清理；若无法通过真实跨区拖动验证再评估工具，不预建平台或新增依赖。

## 冻结与唯一顺序

将 `ColumnFreezeValue` 从 `{ first, last }` 改为按稳定 key 描述的左右配置（如 `{ left: string[], right: string[] }`），字段只出现于一侧。order 管理区内相对顺序，按左/普通/右拼成唯一最终顺序；Panel 和列应用共用规则，避免 Antd/ProTable 重排造成编号不一致。

deriveColumnFreezeDefaults 保留原声明的全部默认 fixed；resolveColumnFreeze 校验新形状、重复及未知 key；applyColumnFreeze 统一应用冻结和必要重排，保留回调、类型及表格实例。无稳定 key 的结构列保持原声明的固定规则，不通过标题猜身份。

Hook 额外提供操作等结构列的冻结元数据，不将结构列注入普通自由排序列表。费用 option 使用既有稳定 key，同步费用专有默认值、比较、解析、存取、列应用和工具栏参数，移除首尾目标推导。

## 偏好与兼容性

沿用表格/用户/组织隔离的存储入口，写入新冻结结构；旧 first/last 不转换、不双读、不保留兼容分支。合法 order/hidden 仍按原规则解析，不删除或清空用户存储；无新冻结结构时使用业务默认字段冻结。保持默认隐藏、必显、权限和新增字段规则。

## 风险与回滚

- 公共类型与费用专有链路需一次同步，搜索所有导出消费者并跑完整前端门禁。
- 多列冻结可能占满窄表格，仍由 Responsive 临时解冻，宽度恢复后重新冻结。
- 与 ProTable start/end 转换保持一致，避免二次排序、序号锚点变化及内部 fixed 缓存覆盖。
- 桌面 40 字段可视性为硬验收；窄屏不能裁掉字段或过度缩小文字冒充全量展示。
- 功能作为原子组提交、回滚，不涉及数据库。
