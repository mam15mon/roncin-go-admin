## 2026-10-13 实施记录

已实现：

- `internal/data/bootstrap_administrator.go` 用唯一 `is_bootstrap_admin` 用户识别初始管理员，首次创建和重复补齐均在统一事务内完成；重复不哈希密码、不更新用户名/姓名。
- 按 User → 组织 ID → 成员 ID → 角色 ID 固定锁序预检。管理员角色首次读取直接采用 `FOR NO KEY UPDATE` 写互斥锁，避免共享锁再升级；它阻止业务角色停用/配置更新，并与权限目录同步插入关联所需的 FK `KEY SHARE` 相容。该锁不宣称串行化权限目录工具的所有关联写入。
- 系统工作台要求唯一且配置编码一致；初始账号停用/待分配、系统资格停用或管理员 `self` 数据范围失效使授权整次失败。停用公司/公司角色/公司成员及公司角色 `self` 范围保持原配置并明确跳过。
- 后台公司创建要求初始管理员的系统成员、有效管理员角色和绑定完整；缺失明确提示先 bootstrap 补齐。新公司、独立角色、初始管理员成员/绑定、默认配置及审计同事务，不为部门/组重复加入。
- 权限从 Manifest 及工作台允许范围取值；bootstrap 只同步目录并补处理项的管理员权限，不调用全局角色同步，不修改跳过角色配置。保留其他角色绑定，缺项追加，数据库/审计异常整次回滚。
- 默认种子仍仅 BJ/CD，遍历全部实际公司补齐。`CreateDefaultBranchCompanies` 返回摘要，CLI、sync:dev 和已有夹具一次性同步；sync:dev 必须先 bootstrap，不重造缺失系统资格，员工/经营数据仍属北京。
- 命令成功摘要区分新增公司/成员/绑定、已满足、跳过；逐公司打印跳过原因。CLI 审计使用初始管理员身份，后台创建审计保留请求真实操作人，并记录目标账号/公司。
