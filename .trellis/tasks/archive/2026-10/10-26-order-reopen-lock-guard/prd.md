# 反结案选填原因与审核锁校验

## 目标

反结案/重新激活订单的原因选填；订单已审核锁定时，必须先解锁后才能反结案。

## 需求与边界

- 反结案允许空原因，保留去首尾空白和最多 500 字约束。
- 已审核锁定订单不开放反结案；确认框打开后再发生锁定，也必须拦截提交。
- 服务端在订单行锁内再次校验审核锁，直接调用接口也不能绕过；失败不改变订单、版本、生命周期事件和审计。
- 未锁定订单可空原因反结案；锁定订单可完结、完结未锁可编辑及费用账单占用等现有规则保持。
- 本次复用既有业务锁错误、权限、版本和事务能力，不变更 Schema 或公开接口字段。

## 验收标准

- [x] 反结案空原因成功，超过 500 字仍拒绝。
- [x] 锁定时动作投影和前端入口不允许反结案；确认后锁定不提交。
- [x] 真实 PostgreSQL 验证锁内拒绝且零写入，解锁后可反结案。
- [x] 相关前后端测试、完整前后端门禁通过，规范同步并提交记录（前端高并发超时用例降低并发完整复跑通过，详见 verification.md）。
