# 空运出口表单 UI 对齐海运出口信息架构

## Goal

把空运出口新建/详情表单重组为海运出口的五卡片 + 小节竖标 + 可折叠备注信息架构，
字段不增不减，纯前端改动。

## 背景与问题

海运出口与空运出口共用 `new.tsx` / `detail.tsx` 页面骨架与 `OrderFormTemplate`
外壳，差异全部在表单模板层（`templates/sea-template.tsx` vs
`templates/air-template.tsx`）：

- 海运是五卡片架构（业务与客户 / 订舱与运输 / 货物与商业 / 提单信息 / 内部人员），
  卡片内有品牌蓝竖标小节分组（订舱与主单、航线与船期、箱量与截关），备注字段
  使用统一可折叠交互。
- 空运是四卡片平铺（业务与客户 / 航空运单与共同运输 / 本票货物 / 人员），
  第二卡把主单关联、航司机场、航班时刻、申报件重尺、主单备注、HAWB 全部
  平铺，无小节分组；备注是普通 textarea。

两个入口并排在同一菜单下，视觉体验割裂。

## Requirements

1. 空运出口新建与详情表单重组为与海运一致的信息架构（海运卡题为
   业务与客户 / 订舱与运输 / 货物与商业 / 提单信息 / 内部人员）：
   - 五个 SectionCard：业务与客户、订舱与运输、本票货物、分单信息、
     内部人员；卡片顺序与海运对齐（分单卡在货物卡之后、人员卡之前）。
   - 「订舱与运输」卡片内使用与海运同款的品牌蓝竖标小节分组（3px×14px
     竖标 + 13px 加粗标题），小节建议：主单与订舱、航线与班期、时刻与申报。
   - 备注字段（主单备注、操作备注）改为海运同款可折叠备注交互
     （`SeaCollapsibleNotesField`），操作备注作为卡片级折叠标题（与海运一致）。
   - 订舱号从「业务与客户」卡移到「订舱与运输」卡的主单小节（对齐海运
     `basic.booking` 的归属）。
2. 字段集合与表单值契约不变：不新增、不删除任何业务字段；create/update
   payload 结构不变；校验规则、必填项、hidden 字段、主单预选（masterId 查询
   参数）与共享主单 NEW/EXISTING 关联逻辑全部原样保留，只允许搬移位置。
3. 新建与详情的字段能力差异（`isDetail` 分支：编号时间仅新建可改、主单资料
   详情只读展示摘要、已签发分单修改原因仅详情展示）原样保留。
4. 航空共享主单工作台（`air-master.tsx`）的编辑弹窗视觉与行为不受影响。
5. 海运出口的视觉与测试行为零变化。
6. 纯前端改动（`web/` 内），不改 proto 契约、后端与生成物。

## 非目标（Out of Scope）

- 不为空运补贸易条款、合同号、货值、保险等商业字段（用户已确认）。
- 不把空运表单中未渲染的契约字段（bookingNotes / allocationNotes /
  tradeTerm / contractNo 等）新增到界面。
- 不动列表页、费用页、拆票页、共享主单工作台页面结构、详情页签扩展
  （本票重量与确认、本票分单历史）。
- 不做组件库层面的重构或 `Sea*` 前缀组件的批量改名。

## Acceptance Criteria

- [ ] 空运新建表单呈现五卡片，卡片标题与顺序为：业务与客户 / 订舱与运输 /
      本票货物 / 分单信息 / 内部人员；锚点导航按新标题展示。
- [ ] 空运详情表单呈现同样的五卡片结构（同一 `buildSections`，仅字段能力
      随 `isDetail` 变化）。
- [ ] 「订舱与运输」卡内出现与海运同款的小节竖标分组；主单备注与操作备注
      为可折叠备注（空内容收起、有内容展开）。
- [ ] 提交载荷与重组前完全一致（同输入同 payload），主单校验（模 7 校验、
      同号主单提示）不回归。
- [ ] 共享主单工作台编辑弹窗渲染与保存行为不变；其权限测试通过。
- [ ] 海运出口全部既有测试通过，视觉零变化。
- [ ] 新增空运模板结构布局测试（镜像 `sea-create-layout.test.tsx` 的断言
      方式）锁定五卡片与小节分组。
- [ ] `pnpm --dir web tsc`、改动文件 Biome、相关定向测试通过。
