# 共享运输段与本票最终目的港设计

## 业务关系与本期选择

一张操作票对应至多一张真实 HBL；多张操作票可通过活动 Link 共用一个 TE。共同段的起运港、卸货港、船名航次与船期只维护一份，每票独立保存最终目的港。本期不建设分单后续多段执行、另段承运人和另段单证关联。

用户明确要求常规开单简单、保留默认值：新票默认最终目的港等于所选共同段卸货港。有后续转运时才修改本票最终目的港。默认同港是前端录入便利，不是后端约束，也不是对所有分单的持续绑定。

## 现有能力与数据边界

- 复用 `Order.destination_location_id` 存每票最终目的港，复用 TE 的 `discharge_location_id` 存共同段卸货港；不新增同义字段、Schema 或迁移。
- SE 当前候选与校验以港口目录为准，本期只承诺最终目的港，不把现有选择器改名成任意交付地址。
- 共享候选与采纳仅含 origin/discharge/transit/vessel/ETD/ETA，不含每票 destination；维持这一边界。
- 共享 TE 更新只更新当前段和相关版本历史，不改每票独立目的港。Order 读投影从 TE 取共同段事实，独立目的地继续来自 Order。
- 当前 `SeaBillContent` 没有独立 POD/PlaceOfDelivery 路线字段，不为本任务增加第二套路线正文，也不把操作字段当成已签发单证内容静默回填。
- 一个 MBL 的候选 TE 列表表示可选择的运输执行，不代表有序的全程各运输段；不据此推断后续转运。

## 页面交互

- 保留现有纯白高密度五卡片模板，运输区明确分为「共同航程」和「本票目的地」。共同段显示起运港、卸货港、中转港、船名航次、ETD/ETA。
- 共同段 ETA 明确指预计到达共同段卸货港；不能把它展示成最终目的港预计到达时间。本期不新增最终到达时间字段。
- 本票字段标为「最终目的港」，默认以同港摘要显示与卸货港相同的地点；提供「更改」直接展开原选择器，普通业务不必操作。特殊票更改后保持可编辑，选择同一个港或清空同样属于明确人工状态；不加额外确认。
- 匹配已有主单时继续继承共同段。仅本票最终港可独立修改，共同段来源与共享范围清楚显示；不靠一整段技术说明让业务理解数据模型。
- 共同段缺项提示直接列出缺少哪些内容，提供现有维护入口的明确直达操作；保持现有权限、预览影响范围及显式确认，不让新票创建静默修改已存在共同段。
- 区分仅资料不齐与 ETD/ETA 缺失导致的必填阻断；没有维护权限时明确需由具备共同航程修改权限的人员补齐，不要求用户寻找不可见菜单。
- 已有详情上的共同航程维护尽量就近呈现现有操作入口，不复制新的写命令或权限真相；未授权时给出对应现有只读反馈。

## 默认值与草稿契约

| 场景 | 处理 |
| --- | --- |
| 新建首票，填写共同段卸货港 | 最终目的港处于默认状态时自动带入 |
| 新建分单，继承已有共同段 | 最终目的港默认取该段卸货港，不复制另一票人工不同的最终港 |
| 尚未手动改最终港，又更换共同段/卸货港 | 最终港继续按默认状态更新 |
| 最终港被人工改为其他港，或主动清空 | 视为手动状态，不被后续候选、卸货港、后台查询覆盖 |
| 客户预设等已明确提供独立目的地 | 保留明确预填值，不拿共同段默认覆写 |
| 恢复新建草稿 | 恢复该草稿的默认/手动语义；显式 null 表示已清空，不被当作未填 |
| 已有订单详情与保存后重置 | 原样采用已存目的港，不因挂载或共享段刷新补写/改写 |
| 主单身份/来源订单/组织切换 | 沿用现有隔离与草稿保护；旧候选迟到不得填当前票 |

默认状态可使用表单内仅前端元数据随草稿保存，不扩后端契约；不能使用「为空就填」无条件 Effect，也不能仅依赖不会随草稿恢复的内存 touched 状态。自动默认产生的是本票显式输入，组包继续提交 destinationLocationId，服务端不隐藏推断。

## 范围与风险

- 本期主要是前端默认值、名称/分组、共同段缺项与入口体验及针对性回归；现有后端独立目的地契约作为验收基础。
- 不自动修改其他票目的地、不强制最终目的港相同、不新增后续转船路线平台，不改已经签发的单证内容。
- 默认与人工值的归属要覆盖手动清空、恢复草稿、来源 A/B 切换、客户预填及显式重置。默认语义不应泄漏为接口字段。
- 用户没有授权数据库重置；不修改开发订单数据。若验证后端共享更新不覆盖目的地，使用正式迁移隔离测试库。
