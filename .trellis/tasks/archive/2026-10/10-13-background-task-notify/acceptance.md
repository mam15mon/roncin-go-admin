# 实施验收

## 实际交付与环境

用户已批准实施，分支 `codex/background-task-notify`。正式迁移安装两表通知触发器，
一个实例共享一条按 Schema、类别隔离的监听连接，四类 worker 使用通知与到期等待。
Wire 已通过仓库生成命令更新，后端能力导航及专项规范同步。
原有领取、租约、幂等和业务处理规则继续生效。

真实数据库验证使用 PostgreSQL 18.6，始终指向按精确名称创建的
`roncin_notify_verify_` 临时数据库，验证后销毁；未重置或注入用户开发数据。

## 性能观察

| 项目 | 实测结果 | 断言方式 |
| --- | --- | --- |

| 真实通知至开始领取 | 1.536916 ms | 专用监听已就绪后，以真实 pg_notify 提交唤醒，检测真实 worker 再次进入 ClaimAny |

正常即时任务唤醒与到期时延只针对消费者空闲、本机数据库连接正常的条件；外部
请求耗时和正在处理的长任务不属于 1 秒领取承诺。

## 功能与数据库验证

- 四类业务写入口和独立审批 inbox 真实提交唤醒；业务事务未提交及回滚不通知。
- 类别广播、同类别多个订阅者、重复信号合并、未知类别和 Schema 路由过滤。
- 可控时钟验证未来到期不需要新通知、59 秒不检查且 60 秒恢复；查询至等待间
  发信号仍保留，过去时间和查询异常退避，关闭订阅及取消解除等待。
- 最近调度时间覆盖终态排除、未来执行、RUNNING 租约、PROCESSING inbox；
  callbacks 关闭不读取 inbox。真实到期任务和 inbox 领取通过。
- 两实例均接收通知，同一任务并发领取恰好一个有效租约。
- 精确终止监听连接，在断线期间持久化任务；重新 LISTEN 后恢复广播及扫描。
- 最后退订后立即重订阅建立新监听，停止时解除订阅等待；断线后的停止无需
  等待重连计时器，旧连接无残留。
- 正式全链迁移冷启动、重复执行，以及正式前态升级后恰有两触发器和一条 revision。
- 四类消费者功能关闭时零订阅/零调度扫描；无消费者时监听不访问数据库。

实施代理最后一次真实 `TestBackgroundTaskScheduler*` 四个套件用时 9.691 秒，
全部 PASS、零 SKIP，临时库已销毁。独立审查新增用例结果见 `research/check.md`。

独立审查最终真实库执行：五组 scheduler 套件 **16.398 秒 PASS**，完整迁移链冷启动
**3.756 秒 PASS**，零 SKIP。新增真实两 Schema 隔离、调度字段变化/无关字段/相同值
UPDATE、FAILED 重试实际领取及 RUNNING 过期租约实际再领取（新 token、attempts）
断言。对应临时库已经销毁；数据库列表再次确认仅 `postgres` 与 `roncin_go_admin`。

## 门禁与限制

- `pnpm run check:server`：通过，包括 Go 分层、Proto lint、全量 Go 测试、vet、
  重复扫描器测试和可达漏洞检查。
- 改动相关 server/data 定向测试、vet、`git diff --check`：通过。
- 独立审查验证全部最终改动，最终结果见 `research/check.md`。
- 普通门禁未开启数据库测试环境；真实 PostgreSQL 用例另用专用库显式运行，
  不能把普通门禁的数据库 SKIP 当作真实库通过。
- 现有 CI 尚未配置 PostgreSQL service 和集成测试连接变量，真实数据库用例在
  常规 CI 会 SKIP；本次真实库证据来自本机独立临时库，不宣称 CI 已执行通知验证。
- race 未能运行：显式 `CGO_ENABLED=1` 后仍因系统无 `gcc/cc/clang` 编译失败。
  未安装额外系统依赖，已如实记录；常规并发及真实领取竞争通过。
- 本任务不涉及前端/Proto/生产入口打包，无需前端全量或构建。
- 最终代码冻结后再次运行 `pnpm run check:server`，退出码 0；Wire 重生成前后
  SHA-256 一致，确认生成幂等。

## 验证中发现并修复

- pgx 活连接配置的 `OnNotification` 绑定旧连接，复制给新连接导致消息进入旧缓冲，
  `WaitForNotification` 可返回 nil,nil。专用连接配置复制后清空回调并由新连接重新安装；
  修复前真实通知触发 panic，修复后完整真实空闲/通知验收通过，已写入专项规范。
- 监听先于 worker 停止时关闭信号 channel，等待器需要检查接收 `open` 并退出，
  避免关闭 channel 引发空转；已补回归。
- 自身失败状态更新或连续通知可能打断错误退避，造成无间隔重试。独立审查已修复为
  异常等待至少 1 秒，之后通知可打断较长退避；取消/关闭立即退出。可控时钟覆盖
  处理失败、查询错误、已到期不可领取三个场景，正常通知没有这个延迟门槛。

## 生效与运维

`pnpm dev` 会先执行正式迁移，再启动包含调度器的服务；首次升级建立触发器。
单实例最多新增一条专用监听连接。通知只含 Schema 和消费者类别，不含业务资料。
进程重启/监听重连主动扫描，空闲时保留 60 秒恢复检查。
若后续撤回数据库通知行为，使用正式后续迁移删除精确触发器与函数，不能重置库。
