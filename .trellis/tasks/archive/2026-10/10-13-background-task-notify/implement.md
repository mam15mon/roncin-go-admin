## 验证矩阵

| 场景 | 验证方式 |
| --- | --- |
| 提交/回滚与全写入口 | 独立 PostgreSQL，用业务仓储真实路径建任务；提交收到、回滚未收到，覆盖直接写表 |
| 通知就绪竞态 | 独立连接在 LISTEN 建立前后提交；在 worker 查询结束、开始等待之间发通知，不悬挂 |
| 通知合并及类别/Schema | 合并重复通知，四类独立接收；其他 Schema 或无关类别不导致错误消费 |
| 空闲查询频率 | worker fake clock/查询计数测 60 秒上界；真实空库观察 65 秒调度查询及无重复空闲日志 |
| 即刻唤醒 | 空闲 worker 提交到领取计时，正常本机 <=1 秒；不用短 sleep 推断行为 |
| 到期任务 | 可控时钟测试未来时间，不发新通知也领取；真实库延迟重试及过期租约/inbox 各一场景 |
| 断线恢复 | 终止真实 LISTEN 连接，期间写入；重连后 LISTEN+扫描恢复，断线与恢复日志一次状态转换 |
| 多实例竞争 | 两个独立调度监听/领取者竞争同一行，断言仅一个有效租约，维持现有最大尝试次数规则 |
| 功能禁用/取消 | 查询计数零、专用连接数量零（全部禁用）、阻塞等待及重连可取消、Stop 无协程泄漏 |
| 迁移 | 空 Schema 全链+旧正式前态升级，检查两个触发器存在、重复迁移不重复安装；不用 Schema.Create |

数据库测试必须显式 `RONCIN_INTEGRATION_DATABASE_SOURCE` 指向临时数据库，确认目标
结果 PASS 且零 SKIP。创建与销毁临时库由验证脚本负责，删除前识别精确库名。

## 验证命令

开发先运行：

```bash
go -C server test ./internal/server ./internal/biz ./internal/data ./internal/platform/migration -run '<受影响测试正则>' -count=1
go -C server vet ./internal/server ./internal/biz ./internal/data
# 注入专用临时数据库后跑真实通知/迁移/领取用例，检查 -v 日志无 SKIP。
git diff --check
```

最终运行 `pnpm run check:server`，本任务没有前端/Proto 契约变更，不固定运行
前端全量或生产构建。Wire 按仓库既有生成入口更新，生成差异须纳入同组审阅。
执行本地提交不要求先跑前后端全量，整体交付必须包含风险匹配门禁结果。

## 审查重点与回退点

- 触发器在当前 Schema 运行，不能通知其他测试 Schema；动态 payload 不拼接 SQL。
- 专用 LISTEN 连接不混用业务连接池/共享事务；现有仓储继续 Data.client(ctx)。
- 不把“通知收到”当“任务已执行”；不能丢广播、只唤醒一个类别或依赖启动顺序。
- 查询到期时间与 Claim 保持同谓词；不在过去时间上忙循环，不因通知重复增加 attempts。
- 替换 worker 等待必须同步修改邻近生命周期测试，启动/停止与功能开关回归。
- 只有现有任务的调度行为变化；如实现需改任务成功/重试规则，先返回设计审阅。

最终验收记录写 `acceptance.md`，包括实际查询频率、唤醒延迟、真实 PostgreSQL
场景、临时库清理、生成物及检查结果。
