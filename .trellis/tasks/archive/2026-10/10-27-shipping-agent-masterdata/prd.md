# 船代公共主数据与海运订单选择

## 目标
将已核实的 29 条船代候选资料纳入本系统后端主数据，供海运订单选择和显示；维护方式沿用既有公共主数据治理，系统管理工作台统一维护，各公司共享使用。

## 背景与确认事实
- 用户明确要求创建 Trellis 任务并开始，并征询统一维护的归属建议；本次方案建议沿用现有系统公共资料边界，所称“总公司”对应系统管理工作台，不新增公司上下级关系。
- 海管家 `GET https://anoingress.hgj.com/saas-support/data/item/1020` 返回 29 条记录，已与订单页面候选项逐条核对；数据只是候选字典，不代表完整行业名录。
- `.trellis/spec/server/backend/organization-shared-masterdata.md:5` 规定系统不存在集团；公共标准资料由系统管理维护，各公司共享读取。
- `server/internal/data/ent/schema/order.go:45` 已有 `shipping_agent_id`；`web/src/pages/orders/new.tsx:160` 当前错误复用供应商查询，`server/internal/data/order_sync.go:141` 当前按供应商校验，必须一次性切换数据语义。

## 本期要求
- 复用最薄的现有公共主数据机制，持久化船代中文名、英文名、唯一编码、启用状态和排序；不预建复杂行业实体平台。
- 系统管理身份且持有维护权限的用户可新增、修改和启停船代；公司工作台仅消费，不能修改公共资料。
- 提供主数据维护入口；小数据集采用全量接口与本地分页、搜索。选择器支持后端编码、中文、英文、别名（如存在）、拼音全拼和首字母搜索，不循环翻页拼接。
- 29 条静态初始资料保存于仓库，提供 `pnpm run sync:shipping-agents` 并接入 `pnpm run sync:all`，在正式迁移后幂等落库；保留来源标识，第三方 ID 只用于溯源，不冒充本系统 ID；不携带凭据或登录信息。
- 海运订单新建、编辑、详情统一引用船代主数据并显示名称；订舱代理和国外代理继续使用原本的公司经营档案。
- 新建订单、普通复制订单或主动更换船代时，只允许选择启用船代；原单编辑和拆票继承可保留原有停用船代引用，且仍能显示名称。现有供应商语义引用如实际存在，先明确检查和迁移，不删除、不清空、不做双读兼容。

## 验收标准
- [x] 新环境执行正式迁移及 `pnpm run sync:all` 后得到 29 条初始船代；单独执行 `pnpm run sync:shipping-agents` 可补齐，重复同步不新增、不覆盖管理员维护结果，也不自动停用已有记录。
- [x] 系统管理可维护，公司管理员即使具有同名权限也不能写入公共船代；各公司读取同一资料。
- [x] 维护列表支持新增、修改、启停、搜索及本地分页，沿用公共 UI 模板。
- [x] 海运订单可按中文/英文/编码/拼音查找船代，保存后新建、编辑与详情均显示一致名称。
- [x] 非船代 ID、缺失记录、停用新选择被拒绝；原单编辑与拆票继承可保留停用旧引用并显示名称；相邻订舱代理、国外代理路径不受影响。
- [x] 源契约、生成物、迁移与种子同步，风险匹配验证通过并提交 Git。

## 不在本期
公司独立船代库、联系人和结算账户、自动抓取或在线同步海管家、第三方系统数据库接入、供应商角色体系重构、删除或重置现有开发数据。

## 已完成研究与实施边界
- 复用 `MasterDataItem` 扩展 `shipping_agent`，复用既有通用维护权限，不另设公司私有库；技术设计和执行计划见 design.md、implement.md。
- 2026-10-27 只读核查开发库订单为 0，非空船代引用为 0；迁移遇到其他环境旧供应商引用必须显式拒绝，另行确认映射，不能猜配或清空。
- 正式 SQL 迁移只负责类型和约束；归档快照由离线同步命令写入数据库，运行时不访问第三方网站；有来源的内部导入码不代表官方行业编码。
