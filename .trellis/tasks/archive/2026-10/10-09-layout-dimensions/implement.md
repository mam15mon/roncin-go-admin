# 执行计划

## 实现顺序
1. 完成全站布局消费端检查，将证据保存在research；审阅PRD/design与范围。
2. 新增共享配置与CSS变量映射，接入主入口及ProLayout配置，保持默认值。
3. 替换全局壳布局的共享尺寸与派生偏移；仅修改有明确语义关系的值。
4. 同步公共模板吸顶/视口高度、导航宽度与正文预留、滚动定位默认值；核对真实页面消费端。
5. 实现完成后补充针对真实联动行为的验证，不编写CSS字符串镜像断言。
6. 按research清单运行受影响定向测试、修改文件Biome、LESS编译、tsc与diff check；检查代理审阅并修复。
7. Chromium验收默认桌面展开/折叠/滚动、移动及767/768/769边界；覆盖页头与参数页sticky及表单导航。再用替代配置证明组件数值、CSS尺寸和派生偏移一致后恢复默认。
8. 完整前端门禁 `pnpm run check:web` 一次；不涉及构建配置/生产入口机制更改则不额外生产构建，入口安装全局变量若带来生产风险则运行build:web。
9. 更新前端规范与验收工件，按根AGENTS授权提交任务变更、归档、记录日志。

## 计划门禁
- PRD/design/implement齐备。
- implement/check JSONL引用真实规范与research。
- 按trellis-brainstorm要求，在向用户呈现最终计划后等待后续明确批准，再start与派发实现。

## 检查原则
不把数字相同当语义相同；不推测页面局部高度公式；不更改调用方显式offset覆盖行为；不覆盖其他窗口改动；不将临时替代配置、截图、缓存或秘密提交。
