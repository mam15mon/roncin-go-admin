# 统一订单审核锁与费用账务回退

## 目标与用户价值

员工只理解一把订单审核锁；不同结算单位可分批建账，不等待整票费用录齐。普通编辑同时受订单审核锁及本笔账单占用约束，锁后新增、修改、调减和作废经补审后生效。

## 背景与确认决定

用户已授权任务规划，先后确认：补审覆盖新增／修改／调减／作废；已建账原费用先回退到未建账再补审（方案 A）；取消收款自动锁、统一人工审核并锁定；同公司有该订单审核权限的人均可补审（方案 A），无须原审核人本人操作。尚未批准实施。

当前普通费用写入叠加整票审批、业务锁、提成财务锁（`server/internal/data/order_fee.go:280`）；建账要求整票批准（`server/internal/data/order_fee_review.go:147`、`:514`）；七种财务进度和账务回退已有实现。完整证据、旧规则差异和复用入口见 research/findings.md。

## 需求

### R1：统一人工审核锁

- 页面只展示未审核／已审核（已锁定）这一套订单审核状态，统一“审核并锁定”动作，记录审核人、时间和审核内容依据。
- 取消收款结清自动锁；建账、核销、对冲或删除未建账费用不能自动生成审核事实。
- 普通费用编辑不再叠加独立费用审批冻结或提成财务锁。业务资料、单证仍受订单审核锁保护，保留不可变历史。
- 人工审核展示订单及费用摘要；授权范围内允许自审，沿用亏损说明要求。审核不要求收付款完成，也不成为建账前提。

### R2：普通费用维护与分批建账

- 在现有业务生命周期允许维护的前提下，订单未锁定、该费用未创建账单且有权限，才允许直接修改／删除；未锁定订单可按权限新增费用。
- 草稿账单即为有效占用；费用管理建账成功后，订单页立即禁改，服务端同步拒绝其他入口绕过。
- A 供应商先建账不妨碍 B 供应商继续录费。订单已锁定仍可对正式、未被变更申请占用的费用建账及后续结算。

### R3：统一补录／变更补审

- 锁定订单新增、修改、调减、作废均先提交申请。申请保存变更前后内容、原因及申请人；补审前原正式费用、正式利润汇总和账单内容不变。
- 同公司具有该订单品类审核权限的有效人员均可补审；原审核人和本次补审人分别留痕，人员／角色停用或撤权后不能继续审批。无管理员自动转交流程。
- 申请通过后一次生效，正式明细展示新结果；原内容保留在变更历史。退回／撤回不影响正式费用。补审不解锁订单。
- 复用当前同票一次一份待审变更的简单流程；待审变更的原费用暂不可建账，其余无关费用可以继续建账。新增申请的内容在批准前不进入建账候选。
- 审批预览展示利润及已有提成的影响，实际资金收付由财务按原流程办理。

### R4：已建账原费用先回退

- 无论订单是否锁定，修改／调减／作废已建账原费用前，均由有对应权限的人按实际依赖回退到“账单未建立”。
- 未锁定订单回退后可直接维护；锁定订单回退后仍只能申请变更补审。提交及批准均检查原费未被有效账单占用。
- 新增费用无须回退其他费用账单。补审不再提供对仍已建账原费直接生成冲回／替代账务的旁路。
- 复用整张账单取消、发票取消／红冲、反核销、取消／反对冲能力，显示实际阻断原因及关联单据。合并单据回退须明确展示涉及其他费用的影响；本期不增加单行拆账或一键自动回退。
- 回退保留历史；反核销不是实际退款，已确认／已发提成通过现有差额调整处理。

### R5：财务进度与权限

- 统一复用账单未建立、未核销未开票、已开票未核销、已核销未开票、已开票部分核销、部分核销未开票、已完成七种状态。
- 开票与核销是并行进度；展示、筛选沿用关联账单的实际开票及核销／对冲投影，不新增人工可改的费用状态字段。
- 操作／业务负责有权的费用维护和建账，财务负责有权的开票、核销及回退；全部按权限清单与公司范围判断，不按角色名硬编码。

### R6：解锁、结案与一致性

- 解锁属于撤销本轮审核，仍需现有解锁权限／授权流程。存在待审变更时先撤回或退回申请，再解锁，避免审批依据失效。
- 解锁不释放账单占用，不抹掉审计或提成事实。普通业务生命周期（结案、终止）规则继续适用，不把终止或结案伪装为另一把费用锁。
- 沿用结案后仍可办理受控补录／变更的现有能力；已有待审变更仍阻止执行结案。既有终止限制保留。
- 费用变化与提成重算／调整一致：保留已发历史，正确处理全额回退、部分来源回退以及未锁订单新增成本，不能移除财务锁后留下提成差异。
- 统一审核、费用维护、建账、回退和补审的并发冲突返回可重试错误；失败不发生部分业务写入。

## 验收标准

- [ ] AC1 / R1、R2：覆盖未锁／已锁 × 未建账／草稿占用／确认账单；前端能力与直接 API 判定一致，批量编辑、删除、复制及转移不绕过。
- [ ] AC2 / R2：未锁订单先建 A 供应商账单，再录 B 供应商费用；锁后正式费用继续建账、收付，待审某笔不阻塞无关费用建账。
- [ ] AC3 / R3：新增、替换、调减、作废分别验证待审不生效、批准一次生效、退回／撤回不生效；同公司另一合格人员可批，跨公司／品类无权／撤权不可批。
- [ ] AC4 / R4：未回退原账单时拒绝变更申请；回退后原订单仍锁定，补审通过才改。覆盖草稿发票、已开票、部分／全部核销、草稿／确认对冲及合并单据。
- [ ] AC5 / R5：七状态在费用管理、订单费用及筛选一致；账单取消后恢复未建账，非线性进度不允许越级伪改。
- [ ] AC6 / R1：收款结清、建账、核销／对冲和删除最后一笔未建账费用不再自动锁单；人工审核留存操作者及内容快照，单证历史保护有效。
- [ ] AC7 / R6：待审申请阻止解锁及结案；申请完成后按各动作原资格办理；已结案受控补录仍可用，解锁不能修改已建账原费。
- [ ] AC8 / R3、R6：补审／撤回、审核／编辑、建账／编辑、建账／变更申请、账务回退／补审和提成发放／变更竞争正确；失败全回滚，重复提交不重复生效。
- [ ] AC9 / R6：未锁新增成本、反核销后重建账、部分来源回退、已确认／已发提成、手工调整并存和连续更正净额一致，不重复冲减或重写支付历史。
- [ ] AC10：Proto、权限、迁移、生成客户端、种子及所有调用入口同步；真实 PostgreSQL 验证与全栈门禁通过，测试跳过不得冒充通过。

## 范围边界与交付

覆盖公共订单费用、订单列表／详情、费用管理和建账入口、补审、权限与必要提成联动，适用于既有六类订单的共享能力。此变更跨层耦合紧密，作为一个任务按可验证提交推进，统一集成验收；不创建可独立上线但实际互相依赖的子任务。

不建设通用审批引擎、逐行独立费用审核、自动代办财务回退或单笔拆分合并账单能力。正式账务和审计历史保留；不兼容旧行为，不重置开发库。迁移遇到无法归入新人工审核规则的旧自动锁或待审记录时，先报告具体影响，不伪造审批人或静默批准。
