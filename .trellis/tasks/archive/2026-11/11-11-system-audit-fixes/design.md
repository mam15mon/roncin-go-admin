# 六类缺陷修复总体设计

## 修复边界

父任务仅承担任务地图、公共规范、生成协调、集成验证、独立 review 与 Git 交付，产品代码分属六个子任务。具体设计以子任务 design.md 为准，不把其他未确认疑点并入本次。

## 核心决策

1. 客商身份使用角色专用写契约，从根源避免全量更新丢资料；复用已有权限、事务、行锁和角色行。
2. 资源覆盖是编辑行为，create-only 不能通过导入获得 update 能力；前后端同守边界。
3. non-optional bool 的零值由所属领域编辑映射处理，不能全局补值或混淆 optional/加载状态。
4. 流水在当前页面挂载期间按规范化意图复用幂等键，未知结果关闭重开仍保留对应关系；后端继续原回放及唯一索引。
5. 按已确认历史产品决策恢复信用额度本币口径（09-11-partner-terms-credit/prd.md §3/§5），结算币种独立；不发明换汇日期、不重算旧额度。
6. 空运地点查询使用同详情一致的主单关联权威事实，不批量回写冗余字段。

## 兼容、数据与风险

不维护旧客户端契约，仓库调用方和正式生成物一次同步。当前不预设 Schema 迁移；若出现必要变更必须补 Ent 与正式迁移。只允许独立测试库/测试 schema 验证；不清库、不自动改旧额度或恢复已丢失资料。已有错误币种配置需显式暴露并由用户确认本币金额后维护。

共享冲突：partner 写路径由 R1 先行再 R5；客商页面 R3/R5 串行；enterprise-resources 页 R2/R3 串行；所有生成命令由主协调者统一运行，避免不同代理竞争生成结果。

## 交付与回退

用户后续明确授权「执行计划，独立review，合并回主，安全删除分支，push」。在隔离工作分支完成代码、回归、独立审阅和全量门禁，再合并 main 并推送；删除分支前证明其提交均包含于 main。使用普通 merge/fast-forward 和安全 branch -d，不 force-push、不 reset。回退用 revert 指定提交，不回写业务数据。
