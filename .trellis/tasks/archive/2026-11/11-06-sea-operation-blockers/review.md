# 独立审查结论

审查范围：独立工作树 `codex/sea-operation-blockers` 相对 `632c9250` 的海运操作阻塞修复及收尾变更，包括已提交的分单快照、改配、拆票、种子同步与待提交的测试/文档。主会话负责最终标准门禁、提交、合并与推送。

## 发现与处理

- 已修复：拆票缺少真实的主动变动检查入口。最终页面在可见且聚焦时每 15 秒及恢复前台时检查拆票上下文，复用业务无关的 `usePageForeground`；检查结果不替换编辑基线。独立货物/箱写入不推进 Order.version，因此没有仅复用 GetOrder 检查；新增回归直接修改 cargo.version 而保持订单版本不变，验证提醒、旧件数与旧提交版本保留、后台停止及恢复检查。
- 已修复：开发种子未同步当前 HBL 快照。`seedNewSeaHouseBillVersions` 只归档 `sc.newOrderIDs` 的非 VOIDED 分单，重复同步不归档已有订单。原作废、模式切换和改单事件继续引用原不可变版本；审核种子仅支持 DIRECT，因此不改审核记录引用的分单快照。真实库检查当前快照身份、实体版本、主要正文与重复同步版本数不增加。新增时误用的 REPLACED 枚举已按实际 Schema 修正。
- 已修复：首轮门禁中的两个既有异步断言竞态。审查代理修正异常直达测试等待 Router replace 提交，以及海运详情扩展测试等待动作资格返回；没有改变生产行为。完整门禁失败栈与修复点一致，定向验证通过。
- 已修复：浏览器发现改配只切活动关联、未同步订单持久化投影。最终在原事务内从已校验目标航程同步船公司、船名航次、起运/卸货/中转港和 ETD/ETA，目标空值显式清除，保留本票最终目的港。新增投影首版 Clear 后 SetNillable 会生成重复 SQL 列赋值，初次仅测空值未检出；审查此前认为可链式覆盖的判断错误，已撤回。最终采用互斥 Set/Clear，并以真实库分别验证空值及三个独立港口、非空日期目标。
- 已修复：改配临时诊断输出全部移除；错误提示读取真实服务端业务报文。消息可见性测试中 HappyDOM 错配 antd 堆叠 CSS 的问题，通过仅将相关测试文件切换到已安装的 jsdom 解决，保留所有可见性断言和真实消息生命周期，没有改产品 CSS、增加固定等待或抑制检查规则。
