# 账单 A–E 独立审查记录

日期：2026-11-14。审查范围为免人工确认、进度/锁定投影、费用增删、普通逐组建账与 NETTING 整批原子、结算账户快建。依据任务 PRD、design 第 15 节、implement 及相关分层/事务/前端规范；保留主会话与其他代理同时开发的发票、核销改动。

## 本轮发现并修复

1. **更正来源重读后丢失**：`FinanceBill.CorrectionRequestID` 原先只在建账内存对象中赋值，持久映射不恢复。更正账单被重读后会误用普通费用候选与提交边界。现在账单映射从活动来源费用重建一致更正归属；详情/批次批量加载来源费用，增删以锁内活动行映射。新真实库回归验证候选与篡改提交均不能把普通费用混入更正账单，普通账单追加不受影响。
2. **历史停用行阻断普通账单编辑**：费用移除后，`FinanceBillUsecase.Update` 仍把详情中的全部历史行作为源费用、校验数量和行 ID 来源。已释放费用未建账或被删除后，后续编辑会报预览陈旧。现在仅在锁内使用当前活动行，历史快照不重算、不恢复关联。真实库验证“移除→删除原费→编辑账单”仍成功，历史金额不变。
3. **旧预览推进新会话步骤**：Query 数据按会话隔离，但初始化、下一步及失败组调整的异步完成回调仍直接 `setCurrent`。现在步骤变更也检查原会话序号，旧初始化预览不能把新费用选择页推进到空资料页。
4. **费用维护写入迟到回填及失败关闭确认**：旧单据组件卸载后 mutation Promise 仍可调用父 `onUpdated`；原生 Popconfirm 又把失败转换为完成关闭。现在复用 `useAsyncGuard` 保护写成功副作用，移除确认复用 `AsyncPopconfirm`，失败保留确认可重试。
5. **免票撤销 CHECK 的 NULL 漏口**：按主会话交接，撤销原因 NULL 时 PostgreSQL CHECK 表达式可能为 NULL 并通过。源 Schema、新迁移与重新生成的 Ent 注解增加 `revocation_reason IS NOT NULL`；真实库直接验证创建/更新缺原因均拒绝、原有效决定保留、完整撤销与新决定成功。

以上均为已有业务契约的局部补修，没有新增兼容分支、放开零额/负数创建或改写既有财务事实。
