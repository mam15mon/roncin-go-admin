# 全仓文档现状同步设计

## 边界与依据

本任务输出为文档更新及可追溯核查记录，所有业务实现、API、生成源、依赖和数据库保持不变。以当前 `.proto`、Ent Schema、实现代码、路由、package.json、Makefile 与 CLI 参数为事实来源；根 AGENTS.md 为协作约束。文档之间的矛盾必须追到实现后才能修正，不以时间新旧单独判定。

## 文档分层

1. 根 README、server/web README、docs 开发与配置说明：维护面向当前项目的能力、上手和运维入口。
2. `.trellis/spec/domain|server|web`：同步现行领域、边界与行为，不复制字段全集；已有生成文档仅通过生成器更新。
3. ADR：保留背景与动因，修正仍以现行规则表述的失效约束，补当前范围及权威导航。
4. PLAN 与 docs/plans：原交付和验收事实保留，补当前状态、退役或替代说明及现行规范入口。
5. 任务档案、会话日志、许可、通用 Trellis 模板：分类登记；历史记录和许可证原样保留，框架不自动升级。仓库项目化技能说明若直接冲突于当前命令及生成目录，可据实现纠正，并复核不会改变工具权限或工作流。

## 修改组织

先整理根目录与开发入口，再同步后端和前端专项规范，最后统一 ADR、旧计划状态与导航。研究和实施使用互不重叠的文件责任范围；写入阶段由 trellis-implement 承担，主会话整合跨层口径；独立 trellis-check 复核。

新增 `docs/README.md` 作为现行文档与历史计划的统一导航；入口链接指向已有权威文档，不再复制一套业务规则。全量路径清单与逐项证据保存在本任务 research 中，正式核查结果记录于本任务，避免把大批历史路径堆入用户上手页。

## 权衡与限制

- 不把归档计划全文改成当前状态，否则会抹去设计和验收的时间语义。
- 不声称文档永远自动最新；记录本次核查基线和维护入口。
- 外部系统、正式域名配置、真实数据库和端到端验收仅如实反映仓库证据，不补造已部署或已通过状态。
- 只读文档验证优先使用本地链接、路径、脚本存在性、生成目录一致性和 diff 检查；不运行迁移、数据同步、发消息或会写数据的验收命令。

## 回滚

按文档分组提交，若发现不实说明，仅纠正文案或回退本任务对应文档提交；不得重置用户工作或数据库。
