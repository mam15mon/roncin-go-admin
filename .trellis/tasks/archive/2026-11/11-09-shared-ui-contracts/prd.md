# 统一财务汇总数据流并修复公共展示契约

## 目标与用户价值
解决六类财务列表的汇总范围错误、跨币种混加和指标竞态，让用户看得懂“筛选结果”与“已选记录”的真实金额；统一路由标题来源，修复海运改配缺少阻断提示。按三个可独立验证的交付包分组实施，不建立通用报表或全量选择平台。

## 已确认事实与证据
- FinanceLedgerTemplate.tsx:392 将 currentData 当 allRows；底栏金额来自本页、记录数来自 total。FinanceSummaryBoard.tsx:101 只消费旧平铺汇总，正式 FeeLedgerSummary 已用 amountsByBaseCurrency。
- FinanceSummaryBoard.tsx:35-45 将不同本币金额相加并采用最后一个币种。流水/核销行使用 amount/baseAmount，对冲无 direction，现有费用模板不适用于这些实体。
- 六页 request 内直接更新指标；研究实验调用真实安装的 ProTable useFetchData，确定复现 A→B、B 先完成、A 后完成时表格保持 B 而指标被 A 覆盖，1 项实验通过。
- 正式列表契约只提供全量本币业务指标，没有严格按全部列表筛选的原币明细汇总；各页额外有效/已确认/已开票状态口径及准确文件锚点见 research/finance-summary.md。
- routeUtils.ts:141 手工标题表与集中路由脱节；航空共享主单、我的冲减来源存在错误解析。业务短名、SE/AE 标题和动态订单事件需保留，详见 research/title-and-reassignment.md。
- SeaOrderReassignmentModal.tsx:261 在成功预览省略 isValid=false 时漏掉阻断原因；SeaExportDetailFeatures.tsx:378 的弹窗门控与菜单不一致。matched 已在 queryFn 归一化，应排除；拆票未确认同类问题。

## 已确认的产品行为
1. 底栏单行切换：有勾选显示“已选 N 条”及金额，无勾选显示“筛选结果共 N 条”及完整金额，不同时铺两行。
2. 支持手动跨页勾选；翻页保留选择，表头全选仅作用于本页。修改已提交筛选条件或切换公司立即清空选择。用户已于本会话明确同意这两条规则。
3. 原币和本币分别按币种分组；缺折本币不能虚构为 0/CNY。各实体只显示有业务意义的金额，非费用不展示“利润”。
4. 顶部继续显示有效/已确认/已开票等业务指标，明确状态口径；统一跟随全部筛选。对冲也先应用完整列表筛选再统计已确认金额，筛选草稿时顶部已确认指标为零。
5. 全部筛选结果合计由服务端计算，不循环翻页。底栏明细合计包含列表筛选命中的行（包括筛选到的草稿、失效等审计行），不冒充顶部有效业绩。

## 需求与验收矩阵
| ID | 需求 | 验收 |
| --- | --- | --- |
| F1 | 六页正式列表返回 matchedSummary，原币/本币与完整筛选一致 | 大于一页且多币种、多本币时，无勾选底栏与服务端全部匹配行一致，翻页不变；空结果为真实零 |
| F2 | 领域金额映射正确 | 费用/账单/发票按各自行金额；收付/核销使用 amount/baseAmount；对冲展示抵销金额；发票缺折本币显示未折算信息，不跨币种相加 |

| F4 | 统一采纳快照 | A/B 乱序、失败或取消不覆盖新指标；表格、顶部、底栏及当前页导出保持同一被采纳结果，首次失败不伪装为成功零值 |

## 范围与边界
- 本期覆盖费用、账单、发票、收付、核销、对冲六页；路由标题与海运改配仅修复研究确认问题。
- 只扩展读取汇总契约，不修改财务写入、审核、核销、权限、事务、锁、版本或数据库 Schema。不做历史兼容，不重置开发数据。
- 不新增“一键勾选所有筛选记录”、跨刷新持久化选择、后台选择令牌、实时跨页重读或全站请求引擎；复用 AntD/ProTable 官方选择与采纳能力。
- 不顺带改变空运页签归组、动态顶栏单号、配置中心 query 页签命名或拆票业务。
