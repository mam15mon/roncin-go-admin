# 海运出口列表主分单可见性

## 目标
业务人员在逐票列表直接分辨订单编号、主单 MBL、分单 HBL，理解多票共享主单而非订单父子关系。

## 范围
- 仅海运出口增加清晰的主分单展示，靠近订单编号，保持一行一订单。
- 明确显示主单 MBL、分单 HBL 或直单；HOUSE 缺失号码显示未填写，未知结构不得判为直单。
- 主单展示服务端提供的关联订单票数；零、未返回的计数不得猜成一票，不从当前分页推算。
- 通用模板只消费稳定行模型，页面映射领域字段，不在模板解释 API DTO。
- 保留现有主单号筛选和个人列偏好；本次不新增树形分组、关联票弹窗、接口或自动请求。
- 空运、海运进口等其他订单列表展示保持原语义。

## 验收
- 同一主单关联不同订单和 HBL 时，各行明确显示订单号、相同 MBL 与各自 HBL。
- 直单显示直单，无 HBL；HOUSE 缺号、未知结构与未返回计数有准确展示。
- 不增加逐行详情请求，不从 shippingDocuments 猜测 SE 新单证真相；以 proto 定义的海运摘要为准。
- 覆盖真实 wire 缺省、显式零与非零计数、HOUSE/DIRECT/未知结构及其他订单类型隔离。
- 相关定向测试、类型检查及风险匹配前端门禁通过，变更单独提交。

## 变更边界与验证
行为缺口在 list-query.ts 行映射与 OrderListTemplate 主单列，预计调整模板类型、布局/样式和针对性用例。必要时增加页面专属展示适配。不改服务端契约及生成物，不改其他业务状态管理。使用定向 Vitest、修改文件 Biome、tsc，完成后运行 check:web。
