# Markdown 逐份补查与覆盖证据

## 目标

补齐上一轮不同文档核查深度不一致的问题，为每份 Markdown 建立可追溯状态、核查深度和依据；有确证遗漏则更新现行文档，帮助用户判断真实覆盖范围。

## 背景与确认事实

- 用户在上一轮更新 63 份文档后追问是否遗漏，并明确同意开始剩余文档逐份内容补查；随后确认创建 Trellis 任务。
- 本轮基线为 2aeaeeee，Git 跟踪 1,126 份 Markdown，共约 6.6 MB；其中含上一轮新任务研究和验收记录。
- 规划核查结论：跟踪MD中108份已核实无需修改、40份待修正、85份待确认、893份历史保留；额外267份中13份本地技能待修正。待确认包含后端尚需补核，不代表内容已通过。
- 用户原未跟踪目录 `.trellis/tasks/10-30-sea-order-page-layout/` 必须完整保留。
- 原 1,111 份文档盘点包含 1 份 TXT，不能继续称为 Markdown 总数。
- 已登记额外267份本地MD：47份忽略技能、1份用户未提交任务、219份备份/工具结果/内嵌产物。
- 初步确证遗漏包括月度提成申请的提交月与覆盖范围、失效权限键和问题模板、上游目录同步指令、工作区入口、CLI参数及配置层级，详见分域研究报告。

## 需求

1. 枚举基线所有 MD 及仓库内未跟踪/被忽略的项目技能 MD；对依赖、构建产物、外部软链接和用户私有资料明确范围边界，不把外部文件加入 Git。
2. 每份受查文件有独立记录，包含路径、分类、基线摘要、状态、检查深度、依据和限制；相同内容的模板可共享语义核对证据，但每条路径及角色差异仍登记。
3. 现行规范及开发说明对照源码、脚本、配置逐份查证；已修改文档仍需核对关联口径，不能仅看链接或标题就判为内容最新。
4. 历史任务和会话记录保留历史事实；每份检查其归档/时间语义及引用问题，历史业务矩阵未重跑就如实记录。模板说明必须适用于本仓库，不能因来自框架就豁免。
5. 使用「已核实无需修改／已修正／历史保留／待确认」结论并注明实际验证范围；发现来源外部或真实环境不明时不伪造通过。
6. 更新仅限 Markdown、核查数据与任务记录，不改业务代码、依赖、权限、运行配置、数据库或正式迁移。按可验证分组提交并独立复核。

## 验收标准

- 基线 1,126 份 MD 全部有一条可查状态记录，路径不重复、不遗漏，基线与本任务新增产物分开统计。
- 状态可追溯至真实证据，未全文语义验证的历史或工具文件不标「已核实最新」；现行项目文档不得因工作尚未做完就最终留在待确认，实施阶段必须补完语义核查；真正实现缺口、外部平台或负责人未知才保留待确认。
- 有源码依据的现行文档遗漏全部修正；不为增加修改文件数而机械改时间或重写历史。
- 校验 Markdown 链接/锚点、命令与源码路径、生成目录一致性、原用户文件摘要及 git diff --check；纯文档不执行写库、外部系统或业务端到端验证。
- 未确认或范围外内容明确列出，用户能从统一入口找到台账和结论。

## 范围外

- 保证未来改动后文档永久自动最新。
- 修改第三方许可、外部全局技能、依赖缓存、Trellis 安装包、用户未跟踪任务内容。
- 重写历史验收事实、清空数据库、升级框架或改变本项目工作流审批规则。
