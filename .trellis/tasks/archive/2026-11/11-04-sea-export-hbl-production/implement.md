## 4. 验证顺序

先小范围、后最终门禁，按实际文件名调整定向命令，不把带过滤参数的 `pnpm test` 当成定向测试。

1. `go -C server test -p 32 ./internal/biz ./internal/service ./internal/data -run '<受影响测试名>'`；涉及正式迁移的验证使用 `RONCIN_INTEGRATION_DATABASE_SOURCE` 和独立 Schema。
2. `pnpm --dir web exec vitest run <制作页及受影响测试文件>`、修改文件 Biome、`pnpm --dir web tsc`、`git diff --check`。
3. 独立渲染器检查普通单页、超长文本续页及四种标识；浏览器验证实际预览/下载/打印和组织切换。
4. `pnpm run check:fast`：跨层契约、生成物、历史和迁移风险需要完整门禁。
5. `pnpm run build`：新增生产依赖及字体/懒加载资源，检查开发代理和 Go 同域静态路径，以及 PDF 依赖未进入普通页面首屏。

单测试文件重型渲染不超过 10 项，耗时超过 20 秒按功能拆分；不为动画或请求写无意义帧等待。

## 风险和回退点

- 阶段 1：新印字字段遗漏普通保存/版本映射会丢资料，必须在进入页面阶段前验证。
- 阶段 3：字体静态化和分页必须实际看图；只提取到文字不能证明显示完整。
- 出错先修正源 Schema、契约、布局或依赖，再生成与验证；不手改生成物、不自动转旧模板。
- 迁移和数据不得为回退而自动删除；保持任务边界内的代码修复，需破坏性数据操作必须另获授权。
