# 技术设计

## 根因与分层
server/internal/server/jsoncodec.go:35-36 按 ProtoJSON 默认规则省略非 optional 标量零值。OpenAPI 的可选 TS 属性无法单独表达 Proto presence 与业务必填的差异。前端 mapper 将字段存在性等同业务有效性，重复逻辑导致局部修复无法传播；字段齐全的测试 mock 隐藏 wire 形态。

## 最小统一方案
保留当前服务端 wire 格式。主数据模块内扩展 masterDataMapper.ts，提取公共身份、来源、启停、排序、更新时间转换入口。船代/国家现有映射与船司/港口/航司/机场专用映射统一组合这个入口。领域专属代码、英文名、国家及扩展字段校验仍由对应适配器处理；不把港口/机场可选中文名改成必填。

公共 UI 模板消费转换后的稳定行模型，不承担 Proto 解码或具体 API 类型判断。现有复用范围在主数据页面模块内，不额外迁移 features；真正跨页面领域使用再提取公共 feature 入口。

非 optional enabled/sortOrder 缺失分别按 false/0 解读；协议与业务判断保留 optional 的存在性（已明确的纯展示空文本投影保持）；不可用全局 JSON 拦截器猜测字段，也不对所有 undefined 统一填零。来源与业务标识继续按现有业务约束验证，不把损坏响应吞成空数组。

## 防复发
1. AGENTS.md 明确 Proto 为真相源、presence 区分、响应转换归属及复用要求；类型安全 spec 替换仅限布尔比较的片面规则，导航登记 mapper。
2. 增加真实 codec 的零值及 optional presence 契约测试，前端用省略形态与显式零值覆盖公共 mapper、领域适配和页面展示。
3. 主数据范围加最薄的静态复用检查：指定适配器必须调用公共入口，禁止重新逐页定义 enabled/sortOrder 的缺失拒绝或默认值逻辑；复用现有 AST 基建且不全仓禁止 undefined 比较。具体断言在实施时以实际提取结果确定。

## 方案取舍与风险
统一启用 EmitDefaultValues 会改变所有接口 wire 字段集合，且仍不能替代业务必填校验及 optional 处理；EmitUnpopulated 还可能输出 null 等额外形态，范围更大。本期保留现有编码并收敛已发生重复的领域映射，成本更低。

公共映射改动影响国家页面，须包含相邻回归。不能拿完整 mock 代替真实省略形态。订单等领域审计发现的问题记录证据，不未经评审批量改业务状态、权限和提交行为。

## 数据与生成物
不涉及数据库、迁移、历史兼容或 Proto 字段调整；不手改生成客户端。若实施发现必须变更契约或额外业务行为，更新规划并重新评审。
