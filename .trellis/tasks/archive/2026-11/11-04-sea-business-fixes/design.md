# 技术设计

## 边界
缺口位于服务端 data 事务及前端创建载荷。沿用现有 biz 错误、订单业务内容门禁、候选版本、共享事务和不可变历史，不新增通用框架。默认无需 Schema 或 Proto 变化。

## R1
前端候选关联时省略 masterBillContent，独立新建仍提交。服务端候选关联禁止修改母单正文，显式业务错误而非静默忽略；检查调用方、测试夹具同步更新。新增票不改其他票的母单正文/版本/审核状态。候选已作废等相邻门禁如与本入口直接相关须校验并写回验收记录。

## R2/R4
改配预览、动作资格及 Execute 锁内检查本票是否存在任何共享箱分配。锁序与分配写入口对齐：订单行先锁，以同一行串行化新增分配。NEW 目标如船公司与规范化母单号相同，复用已锁原母单，调用现有创建运输执行 helper；其他 NEW 保留现有新母单分支。保留 HBL 迁移、版本、事件、幂等与费用行为。

## R3
共享箱 Update/Withdraw 写入前收集分配成员与锚点，按主键锁 Order，复用内容门禁；再锁共享箱并重验分配成员，集合变化冲突重试，禁止锁箱后补锁订单导致逆序。复用已有函数，避免另写门禁。版本检查和审计仍在同一事务。

## 验证与回滚
实现后补场景回归，优先隔离 PostgreSQL schema 上运行正式迁移。若无专用数据库，建立一次性本地测试实例而非碰开发业务数据。独立 reviewer 检查并发、分层、调用方及失败零写入。最终运行 check:fast。回滚为撤销本任务提交，不包含数据修复。
