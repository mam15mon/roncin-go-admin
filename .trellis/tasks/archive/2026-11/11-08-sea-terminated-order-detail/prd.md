# 修复完成退关后订单详情无法打开

## 目标
海运订单完成退关后，详情能立即显示已终止状态；刷新或重新进入仍能查看订单及保留单证。

## 已确认事实
- 用户实测订单 SE2026110600004：未退关→退关中→完成退关后仍显示退关中及变动提示；刷新报海运单证加载失败，接口 HTTP 400 / SEA_DOCUMENT_NO_ACTIVE_LINK，工作台已显示已终止。
- `server/internal/data/order_write_lifecycle.go:109` 在完成退关事务中结束活动 SE Link；结束原因固定为「订单退关」，保留 MBL/HBL，恢复不复活旧关联。
- `server/internal/data/sea_document.go:46` 的读取只查询 ACTIVE Link，正常终态因此被误判为异常。
- `web/src/pages/orders/use-order-detail-data.ts:100` 聚合订单和单证；单证失败使整包加载失败。
- `web/src/pages/orders/detail.tsx:1019` 状态操作后重读整包；失败时留存旧订单，变动检查继续提示。

## 需求与边界
1. R1：已终止订单按本次退关结束的关联读取保留单证；缺失或不一致的真实异常仍明确报错，禁止将任何单证错误吞掉当成功。
2. R2：完成退关后刷新正确展示终态；处理本次已成功操作的变动提示时必须保留未保存输入，不吸收真正的外部变动或擅自更新提交基线。
3. R3：保留单证只读；维持组织隔离、生命周期写入门禁及活动主单成员统计语义。
4. 范围限于单证读取、退关成功后的详情刷新及针对性回归；不改退关状态机、不恢复活动关联、不重置测试订单或数据库，不扩展恢复订单流程。

## 验收标准
- A1（R1/R2）：DIRECT、HOUSE 订单经真实完成退关路径后单证可读，重新进入详情不报加载失败，页面显示已终止。
- A2（R1）：有改配历史时不选中旧改配关联；非终止订单缺失活动关联仍报原错误，跨组织读取仍拒绝。
- A3（R3）：终态不提供单证写动作；HBL/MBL 写入继续被后端门禁拒绝，活动成员统计不含终止订单。
- A4（R2）：完成退关后刷新成功可同步状态；刷新失败保留输入并提示，订单切换期间的迟到结果不影响新订单，外部变更提示继续有效。
- A5：相关 Go 集成测试、前端定向测试及最终风险匹配门禁通过，记录未能执行的验证及原因。

## 实施授权
用户确认继续修复，并要求完成独立 review 后合并主分支、安全删除分支并推送。
