# 费用保存后审核快照同步：独立检查

日期：2026-11-14。范围为费用页保存后的审核投影同步及其输入保护；不改变服务端权限、并发版本、人工审核规则或公共接口。

## 发现与修复

1. 成功保存只刷新费用/关联账单和外部变动参考点，未刷新 `orders/lock-state`。订单审核区持有旧 `feeContentVersion`，与弹窗刚读取的全量费用快照不一致，真实浏览器因此不能立即锁定。实现者在既有 `refreshFeeBillTracking` 成功刷新入口调用稳定的 `refreshLockState`，并删除显式刷新的一次重复调用。
2. 独立检查发现该新增后台刷新会使 `feeWritesDisabled` 临时为真，旧 effect 因此会关闭已打开的费用、快捷费目或往来单位弹窗。若审核请求失败，真实 hook 返回 `state=null`，同样可能销毁另一侧草稿。已与实现者协同修复：临时加载或请求错误保留同身份弹窗及输入；仅明确失权或成功读到真实不可写状态时关闭。提交仍经过原 `getOrderBusinessWritePolicy` 和 `ensureFeeWriteAllowed`，不伪造成功或放行写入。

未新增弹窗参数、轮询或状态框架；独立主数据快捷创建继续执行自己的权限与公司门禁。

## 源码核对

- 整表/单行保存、删除、补审及建账后的相关刷新共用该入口；失败写入在成功副作用之前返回。
- `refreshLockState` 的订单身份与 React Query key 隔离保持不变；依赖稳定，不形成请求 Effect 循环。
- 不新增整页刷新、`reloadToken` 变化或另一侧表格重载；本人保存基线、未知结果键与原始 `expectedVersion` 不变。
- 订单/身份切换继续执行原重置逻辑。审核加载及失败时写入仍被关闭，错误场景提交返回 false 且订单 Add/Update API 未调用。
- 真实 Form 的已有行及新增行在 `feeWritesDisabled=true→false` 往返后保留输入、未保存提示与原提交版本。
