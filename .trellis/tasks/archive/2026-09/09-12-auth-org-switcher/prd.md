# 登录组织选择与应用内分公司切换器 PRD

## 1. Background & Scope

产品方向：各分公司独立运作（财务交易自理、基准集中），登录"海管家"后按账号成员资格
选择进入的组织——北京公司账号点北京公司进、成都公司账号点成都公司进，SaaS 式多租户
体验。

当前地基已具备八成：

- `membership` 表按 `(user_id, organization_id)` 唯一建模，**一个用户可属于多个组织**，
  带 `primary` 标志；
- 会话已绑定组织（登录取 `credential.PrimaryOrganizationID`）；
- 权限已按「用户 × 组织」解析（`ResolvePrincipal(userID, orgID)`）；
- 全部业务查询已按会话组织过滤。

缺的是：**组织由用户选择而非系统指定**、应用内切换、以及切换的成员资格校验。

## 2. Detailed Requirements

1. **登录组织选择**：
   - 登录成功响应携带用户全部**启用中**的成员资格组织列表（组织 ID/名称/编码、是否
     默认）；
   - 仅一个组织：前端直接进入（跳过选择页），行为与现状一致；
   - 多个组织：前端展示选择页，用户点选后以该组织建立会话；
   - 不选择时默认仍为 `primary` 组织（`primary` 语义不变）。
2. **会话按所选组织建立**：`CreateSession` 的组织取用户所选（未选为 primary），
   token/权限集/审计组织随之确定。
3. **应用内切换器**：
   - 顶栏提供组织切换入口，列出本人启用中的成员资格组织（当前组织标识）；
   - 切换 = 服务端**换发会话令牌**（新会话 + 旧令牌失效轮转）+ 前端重载状态与权限集；
   - 切换响应与登录响应同构（token + principal + 组织列表），前端复用登录后的初始化
     流程。
4. **安全红线**：只能切换进**本人启用中成员资格**且组织启用中的组织；非成员/已停用
   一律拒绝（403 语义），不做任何客户端信任；切换动作写审计（含目标组织）。
5. **总部集团视图不受影响**：TREE/ALL 数据范围角色保留跨组织查询能力；切换器只是让
   总部用户也能"下沉"进某分公司操作。
6. **并发会话**：允许同一用户在多浏览器/多组织各有会话；切换只轮转当前令牌，不吊销
   其他会话。

## 3. Acceptance Criteria

- [ ] 多组织用户登录看到组织选择页，单组织用户直进不出现选择页；
- [ ] 以所选组织建立会话后 `auth/me` 返回该组织的权限集与主组织身份；
- [ ] 应用内切换：令牌轮转（旧 token 失效）、权限集/菜单/数据随组织切换、页面状态
      重载；
- [ ] 切换到非本人成员资格组织 / 成员资格已停用 / 组织已停用：拒绝并有稳定错误；
- [ ] 切换写审计（操作者、来源组织、目标组织、时间）；
- [ ] 既有登录/会话/权限回归全绿；单组织用户行为与现状无差异。

## 4. Out of Scope

- 成员资格管理界面（既有 admin 用户/组织管理承担，本任务不改）；
- 角色与数据范围模型（现模型已够用，不动）；
- 集团并表/跨组织汇总报表（远期，另立）；
- 基准汇率/费用科目等行业级共享资产的归属调整（保持总部集中，见"交易自理、基准
  集中"决策）。
