# 财务全链路测试覆盖审计执行计划

## 1. 建立测试清单

- 枚举服务端、前端、Playwright 和验收脚本中的财务相关测试。
- 提取测试名、运行入口、数据库类型、是否依赖专用环境变量和默认质量门归属。
- 验证：每条清单包含文件锚点和证据等级 E1-E5。

## 2. 分阶段追踪证据

- 分别审计汇率、订单与费用、账单/开票、资金流水/核销、提成。
- 对金额、币种、日期、状态机、事务、并发、组织隔离、权限和审计建立矩阵。
- 验证：每个阶段同时列出已覆盖项和缺口，不以测试数量替代行为断言。

## 3. 追踪真实跨阶段链路

- 阅读 `acceptance:finance` 的三个组成部分，记录真实创建起点和最终断言终点。
- 检查 PostgreSQL 集成测试是否复用真实上游用例，或仅直接写入下游所需表。
- 检查 Playwright 是完成创建操作，还是只读取验收脚本预置的数据并验证页面。
- 验证：明确回答是否存在汇率配置到提成支付的一条连续自动化链路。

## 4. 核对最近运行证据

- 检查 Git/Trellis 归档、日志和当前命令配置，区分“测试文件存在”“默认质量门执行”
  和“专用 PostgreSQL/浏览器环境最近真实执行”。
- 在不修改数据的前提下运行安全的静态检查或默认测试；需要创建真实验收业务数据的
  命令只做配置审计，不在本只读任务中执行。
- 验证：所有通过结论标注运行日期/记录来源，默认跳过项不得误报为已执行。

## 5. 编写审计报告

- 写入 `research/audit-report.md`，按设计文档输出证据矩阵、断点、风险等级和补测路线。
- 风险分别标为：已证实生产缺陷、缺少自动化证据、超出功能测试能力的生产风险。
- 验证：报告直接回答用户问题，并避免绝对正确性表述。

## 6. 独立复核

- 交由独立 `trellis-check` 复核文件/测试锚点、证据等级和所有 P0/P1 判断。
- 重点挑战是否把直接写表夹具误称为跨阶段测试、是否把默认 Skip 误称为通过、是否
  忽略应付、多币种、权限或浏览器路径。
- 验证：P0/P1 误报和证据缺口清零；必要时修订报告后再检查。

## 7. 完成与提交

- 完成当前 PRD 验收框；执行 `task.py validate` 和 `git diff --check`。
- 评估是否有可推广的测试规范；有则走 `trellis-update-spec`，无则记录不更新理由。
- 以中文 Conventional Commit 提交审计报告和任务资料，然后执行 Trellis finish/archive。

## 风险文件与边界

- 允许修改：当前任务目录内的规划、研究和审计报告。
- 禁止修改：`server/`、`web/`、`scripts/`、迁移、配置、生成物和归档任务历史。
- 不运行：带 `--apply` 的验收脚本、任何指向开发或生产库的破坏性测试。
- 若发现需要真实环境才能判断的事项，报告为待执行验证，不自行扩大授权。
