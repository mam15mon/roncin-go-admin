# 海运出口端到端能力矩阵

- 审计日期：2026-09-05
- 产品定位：货代内部业务、操作、单证和财务管理平台
- 流程口径：人员判断步骤完成后在 UI 点击对应按钮，订单级流程状态是正式业务事实
- 明确不适用：船公司、海关、港区、单一窗口及 SI/VGM/AMS/ISF/ENS/ACI 等外部平台的一键提交与自动回执
- 证据口径：“已具备”必须同时有用户可达入口、后端强制规则或持久化约束，以及自动化测试或可复核的跨层证据；只有模型或规划的能力不得评为已具备。

## 一、结论总览

当前实现已经越过“订单表单原型”阶段，真实具备共享 MBL、多 HBL、DIRECT/HOUSE、FCL HOUSE 箱货守恒、拆票/改配、不可变单证版本、改单/作废/Switch、订单锁和订单费用到财务的主体骨架。

用户已确认“已放单”是当前流程终点，满足活动异常和费用门禁后允许人工结案；不要求实际开航/操作完成、逐张 Sea MBL/HBL 状态、复杂节点、自动分摊或系统内完整文件库。按这一边界，当前结论是：**海运出口可以正式使用**。仍有四项真实软件问题需要规避并修复，但它们不改变主体业务结论。

## 三、代表性场景核验

| 场景 | 关键步骤 | 结论 | 限制/失败行为 |
| --- | --- | --- | --- |
| FCL + DIRECT 单票 | 创建 SE+MBL → 标记 DIRECT → 录货物/实际箱 → MBL 汇总 → 人工流程/费用 | 已具备，可正式使用 | 放单由订单级按钮人工确认；不跟踪逐张单证状态 |
| FCL + HOUSE，多 HBL、多箱 | 创建 MBL/HBL → 录货/箱 → 货物-HBL-箱分配 → 确认守恒 → 汇总单证 | 核心最完整，可正式使用 | 箱/货物删除按钮缺版本参数，修复前不使用删除入口 |
| LCL + HOUSE | 创建 MBL/HBL → 录货 → 分配到 HBL，container 留空 → 确认 | 规则可表达，可按批准流程使用 | 无该组合统一浏览器 E2E，当前证据以领域与真 PG 为主 |
| BREAK_BULK + DIRECT/HOUSE | 禁止箱计划/VGM → 以件毛体和无箱分配维护单证 | 模型可表达，可按批准流程使用 | 缺代表性统一浏览器 E2E，首次真实业务建议人工复核 |
| 多票共享一张 MBL | 候选显式确认 → 共享航程/内容 → 成员锁重验 → 人工分摊后逐票录费 | 单证共享及录费后财务链已具备 | 系统不保存共享成本的分摊依据、版本或自动守恒过程 |
| 部分拆票/整票改配 | 上下文 → 预览 → 明确目标/归属 → 执行 → 历史 | 主要能力具备 | 拆票并发失败方错误码不稳定，完整 PG 质量门失败 |
| 锁定后改单/作废/Switch | 获取锁态 → 动作预览/执行 | 安全阻断已具备 | 解锁后仍受费用、账单、发票、核销、提成及箱货事实门禁 |
| 单票费用到核销/提成 | 录应收应付 → 确认 → 建账 → 发票/流水 → 核销 → 提成 | 已具备 | 仅适用于费用已正确直接归属订单；不解决共享成本分摊 |
| 外部渠道办结后的人工确认 | 外部办理 → 人员判断完成 → 点击订单流程按钮 → 必要时填备注/里程碑/异常 | 已具备，符合批准流程 | 系统只保存人工确认；关键文件由外部受控文件库保存，不声称自动验证或系统内完整文件能力 |

## 四、两个现存规划任务的关系

1. `09-02-sea-export-transport-document-model` 仍显示为 planning，但其六阶段中的共享 MBL、主分单内容、箱货分配、拆票/改配、单证版本/换单和订单锁已经由五个归档任务及后续通用锁任务真实落入代码。父规划中尚未落地的多航段和正常单证状态不属于当前批准范围，不影响正式使用结论。
2. `09-02-sea-export-finance-allocation` 确实仍未实施。当前 Schema 和 API 没有共享计费对象或版本化分摊记录；用户已批准线下人工计算并逐票录入，所以它是自动化增强任务，不是当前上线缺口。系统不得因此声称已经自动分摊或保存了分摊依据。

## 五、不适用能力

以下能力按用户已确认的产品边界统一标为“不适用”，不参与完成度评分：

- 从系统向船公司发送订舱、改单、取消订舱；
- 从系统向海关、单一窗口、港区、码头或堆场提交数据；
- SI、VGM、AMS、ISF、ENS、ACI 等一键外部申报；
- 自动接收外部平台受理号、错误码和状态回执。
- 实际开航、到港、交付、操作完成及相应结案门禁；
- 每张 Sea MBL/HBL 的独立确认、签发和放单流程；
- 复杂节点任务、SLA、自动提醒和完整异常工单；
- 共享费用自动分摊及其依据、版本和守恒记录；
- 系统内完整附件上传、预览、下载；关键文件由外部受控文件库保存。

当前系统以有权限人员点击订单级流程按钮作为正式人工确认，并保留订单人员、截止时间、备注、可选里程碑和异常门禁。上述不适用能力如果未来转为产品需求，需要重新审计和立项，不能直接沿用本次结论。
