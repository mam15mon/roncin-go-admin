# 海运出口业务完整度审计设计

## 1. 审计目标与边界

本任务不实现功能，而是回答当前系统作为“货代内部业务、操作、单证和财务管理平台”是否已经可以投入使用。船公司、海关、港区、堆场、单一窗口及目的国舱单平台的外部提交不在产品边界内；审计只验证系统内部能否支持操作协作、事实留痕和财务闭环。

审计同时区分三个概念：

- 技术存在：代码、接口或页面存在。
- 可达可用：用户能通过权限和页面完成合法操作，并得到明确结果。
- 业务闭环：上游事实能完整传到下游，状态、金额、数量和历史不会被普通编辑破坏。

只有同时满足可达可用和业务闭环的能力才评为“已具备”。

## 2. 证据优先级

每项结论按以下顺序取证：

1. 数据库约束、领域规则、事务与权限门禁；
2. API 契约、服务注册及前端真实调用链；
3. 自动化测试，尤其 PostgreSQL 集成测试和跨层测试；
4. 当前规格与已经归档的 Trellis 任务；
5. 仅有规划、注释或页面占位时，只能证明意图，不能证明已经具备。

证据冲突时以当前可执行代码为准；规划任务中尚未实现的内容不得计入完成度。

## 3. 能力矩阵

矩阵覆盖下列维度：

1. 接单与基础资料：客户、贸易条款、付款条款、服务类型、参与方、港口、船名航次、关键截止时间、箱型箱量和货物件重尺。
2. 运输与操作协同：订舱信息、FCL/LCL/BREAK_BULK、实际箱与封条、拖车/送仓/报关等责任和节点、附件、异常及终止/结案。
3. 单证：DIRECT/HOUSE、共享 MBL、一票多 HBL、多票共用 MBL、完整主分单内容、签发主体、版本和历史。
4. 箱货：订单货物、HBL、实际箱之间的定量分配及件数、重量、体积守恒。
5. 变更流程：拆票、整体改配、改单、作废、Switch B/L，以及相关预览、幂等、版本与财务门禁。
6. 财务：应收应付、币种与汇率、费用确认、共享成本分摊、账单、发票、核销、现金流、提成和利润可追溯性。
7. 风控与协作：订单锁、费用锁定效果、解锁审批、组织隔离、权限、审计日志、并发冲突和不可变快照。
8. 技术就绪度：迁移、生成物一致性、测试覆盖、构建检查和明显的未完成入口。

矩阵还要交叉核验以下代表性场景：

- FCL + DIRECT 单票；
- FCL + HOUSE，一票多 HBL 且多箱分配；
- LCL + HOUSE，不制造操作票级虚假箱；
- 多操作票共享 MBL；
- 部分拆票及整票改配；
- 锁定后改单、作废或 Switch；
- 订单费用到账单、发票和核销；
- 外部渠道办结后，在系统内部记录节点、附件和异常。

## 4. 分类与优先级

### 4.1 完成度

- 已具备：存在可达入口，后端强制关键规则，并有直接测试或可复核证据。
- 部分具备：主路径存在，但常见业务分支、前端入口、数据完整性或测试证据不完整。
- 缺失：没有实现，或者只有规划和占位而无法完成业务动作。
- 不适用：属于用户明确排除的外部提交边界，不参与完成度评分。

### 4.2 缺口优先级

- P0 上线阻断：核心场景不能完成，或存在可能造成订单、单证、箱货、金额、权限、历史事实错误的风险，且没有安全人工替代路径。
- P1 重要缺口：常见场景需线下补录、重复录入或跨页面绕行，但不会静默破坏核心事实；适合受限上线后尽快补齐。
- P2 后续增强：低频、高级或效率型能力，不影响声明范围内的核心业务闭环。

## 5. 上线结论

- 正式上线：声明范围内没有 P0，代表性核心场景闭环，关键规则有后端门禁及相应验证。
- 受限上线：限定业务范围后没有 P0，但仍存在需要明确操作规程或人工补充的 P1。
- 内部试用：核心场景仍有 P0，或当前证据只能证明技术组件存在，不能证明业务闭环。

结论必须写明适用的装载形态、单证结构、财务处理方式、人工操作边界及上线前置条件，不能只给一个百分比。

## 6. 输出物

- `research/current-capability-inventory.md`：当前代码、测试、规格与既有任务证据盘点。
- `research/capability-matrix.md`：端到端能力矩阵及代表性场景核验。
- `research/readiness-report.md`：最终结论、P0/P1/P2 缺口、上线边界和整改顺序。

本任务不修改产品代码。如报告建议整改，后续按独立且可验证的产品任务拆分，由用户另行确认优先级和实施授权。

## 7. 风险控制

- 规划文件不能作为功能完成证据，必须回到当前代码和测试。
- 通用附件或节点只能证明“有容器”，不能自动证明某一业务节点有稳定语义；需要核对数据约束、页面入口和角色操作路径。
- 单元测试通过不等于跨层闭环成立；关键结论优先寻找 PostgreSQL 集成测试或完整调用链。
- 审计不连接生产环境、不读取生产数据、不执行破坏性命令；测试只使用仓库既有隔离方式。
