# 海运出口共享费用分摊

## Goal

记录共享费用分摊不进入当前产品范围的业务决定，避免在没有真实业务案例和分摊依据时实现猜测性财务功能。

## Background

- 原计划假设一笔 MBL、航段、集装箱或 HBL 级供应商成本可能需要分摊到多票订单。
- 业务用户在 2026-09-06 确认，目前尚未遇到“一笔供应商总费用实际属于多票订单”的场景，也没有现行人工分摊规则。
- 当前费用直接录入所属订单即可满足业务；共享 MBL 或集装箱关系不自动产生共享费用。
- 在没有真实账单、责任人、分摊依据和调整流程时实现自动或人工分摊，会制造无法验证的单票成本和利润结果。

## Resolution

- 当前任务取消，不实现共享费用实体、分摊算法、分摊页面或财务下游集成。
- 现有订单级应收应付、账单、发票、核销、利润和提成逻辑保持不变。
- 未来首次出现真实共享费用时，以实际供应商账单和现行人工处理方式重新创建任务；优先评估“人工录入各订单承担金额、系统校验合计”的最小方案，不复用本任务中的假设性范围。

## Acceptance Criteria

- [x] 已确认当前没有真实共享费用案例或现行分摊规则。
- [x] 已明确当前费用继续按订单直接录入，共享 MBL/集装箱不自动触发分摊。
- [x] 已明确本任务不产生产品代码、Schema、API、页面或迁移。
- [x] 已明确未来只有在真实业务案例出现后才重新立项。

## Notes

- 归档状态表示取消决策已记录完成，不表示共享费用分摊功能已经实施。
