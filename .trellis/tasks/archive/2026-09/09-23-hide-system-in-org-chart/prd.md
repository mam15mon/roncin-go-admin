# 组织架构隐藏系统管理节点

## 目标

让组织架构只呈现实际经营组织（公司、部门、团队），避免把“系统管理”工作台误认为上级组织；保留系统管理工作台和现有权限能力。

## 已确认事实

- 前端 `web/src/pages/admin/organizations.tsx` 当前把组织列表接口返回的所有节点用于架构图、树表、节点统计和默认选中，因此系统管理节点会出现在组织架构中。
- 后端 `server/internal/biz/admin_organization.go` 定义系统管理、公司、部门、团队四种组织类型；公司可作为独立根节点创建，部门和团队分别挂在公司和部门下。

## 范围与要求

- 组织架构的拓扑图和“树表列表”（树形列表）均不展示系统管理节点，只展示公司、部门、团队；不能只处理默认打开的拓扑图。
- 组织架构页的节点数量、搜索结果、默认选中及详情信息与可见节点保持一致。
- 不修改组织列表接口、持久化数据、工作台切换、角色权限或其他页面对系统管理节点的使用。

## 验收标准

- [x] 接口同时返回系统管理、公司、部门、团队时，拓扑图与树形列表分别只显示实际经营组织，两个视图的节点数量都不包含系统管理。
- [x] 首次进入页面或刷新后，默认选中可见组织；搜索系统管理名称或编码不会使其出现在树表中。
- [x] 没有可见经营组织时，页面显示现有空状态且不展示系统管理节点的详情。
- [x] 组织创建、编辑入口仍按原有权限和组织层级规则工作，系统管理工作台入口及权限判断不变。

## 范围外

- 不删除或迁移系统管理组织数据，不改变后端组织层级和权限模型。
