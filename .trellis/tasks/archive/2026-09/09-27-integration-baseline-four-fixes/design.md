# 四项失败修复设计

## 定位与修复顺序

先在明确的隔离 PostgreSQL 测试目标逐项复现，收集实际失败签名；再读当前组织锚点、费用模板和公司边界规范，以测试要保护的契约为依据分类。实施范围主要是四个 integration_test.go 及其必要夹具，不能预设只改断言即可修好。

## 数据库与迁移

迁移用例按正式 SQL 文件重建被测迁移前态，再执行被测迁移，禁止在最新 schema 强塞不合法历史数据。保留现行 CHECK 和唯一索引。测试初始化与完整包运行顺序执行，避免 Ent 全局迁移表污染或共享测试库互相清理。

## 可诊断断言

工位锚点核对角色/工位归属；费用目录核对目标业务代码、模板与副本关联、组织范围和幂等性；公司边界迁移明确允许变化的引用列和必须保持的业务快照，逐字段报告差异。期望由正式迁移和现行契约推导，不能机械照抄实际输出。

## 风险与回退

如发现生产实现错误，最小范围修复并补相邻场景；需改契约、锁或业务边界时先更新规划。每组独立提交便于代码回退，数据库不靠删除开发数据回退。
