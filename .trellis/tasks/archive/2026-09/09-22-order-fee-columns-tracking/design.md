# 技术设计（待最终审阅）

## 1. 最小实现边界

本期使用已有费用与财务读取接口，不增加领域实体或持久业务字段。订单费用页负责录入及其列配置；财务状态遵守已有财务读取权限。全量证据见 `research/field-matrix.md`。

目标入口为 `web/src/pages/orders/fees.tsx` 与 `components/fees/OrderFeeTableTabs.tsx`。费用抽屉不新增配置入口；可共享必要字段格式，但不强制抽屉采用宽表。

## 2. 列定义与偏好

- 以页面专属的稳定列 key、中文标题、默认顺序、默认显隐、是否允许隐藏描述实际可用列。保留 EditableProTable 官方列状态机制，具体 props 以安装版本类型及本地文档核实。
- 优先使用 ProComponents 内建列设置与排序；若无法满足确定／取消和编辑期间禁用要求，增加仅该页使用的轻量受控设置窗。无需复制财务台账 153 字段配置器。
- 可选配置只来自本期真实列；不引入无契约的发票号、结算金额占位。
- 推荐本地偏好键按「订单费用场景 + 当前用户 ID + 当前组织 ID」隔离；应收／应付共享一个值，不按订单建无限个键。只存列 key、显隐、顺序，不存任何费用或身份秘密。
- 不直接调用财务 FeeLedgerPreference 接口：其权限、字段集、分页配色语义与唯一键都属于财务台账。
- 恢复默认显式删除当前场景偏好并恢复推荐列；存储失败需提示本次配置未持久保存，不虚报已保存。不设计跨版本兼容、迁移或静默修复分支。
- 配置数据只控制展示，不能参与构造 AddFee/UpdateFee 的金额与业务字段。编辑中禁用配置入口，提交仍使用现有行编辑模型与校验。

## 3. 费用展示数据

费用主数据继续经 `orderFeeServiceListFees` 与 EditableProTable request 获取；写入后通过 actionRef.reload 刷新。新增列读取已有 taxRate、taxAmount、netAmount、baseCurrencyAmount、baseCurrency、tags。

税额由 biz.calculateAmounts 精确计算。新增列不使用 Number 重算税额、总额或本币快照；遵循现有数字格式化工具。taxInclusive 标识用于准确解释输入单价。未保存新行的服务端派生税额在尚无可靠结果时显示待保存，不显示猜算结果；保存后展示后端值。

费用发生日是 YYYY-MM-DD 纯日期，不转成本地时刻。若显示时间戳则使用 formatDate；本期不引入创建人推断。

## 4. 财务读取与关联

1. 沿用 auth/me 生成的访问判断；仅具备 system.finance.fee.read 及当前上下文访问资格时启用订单维度财务查询。
2. 使用现有 `GetFeeLedgerOrderDetail`（`/api/v1/finance/fees/orders/{orderId}`），React Query 管理响应，query key 包含当前组织及订单。一次订单级请求得到两表关联信息，禁止每费用请求一次，也不循环台账分页。
3. 按费用 ID 将 FeeLedgerItem 的 billNo、financialProgress 叠加为只读展示投影；不可把财务响应替换为可编辑费用模型，也不能用于改写 version。
4. 前端只展示后端状态，不新写核销／对冲分类算法。现有服务端通过活动账单行、非取消账单、有效开票、有效核销及已确认对冲投影。
5. 现有活动费用唯一索引保证最多一个活动账单。历史作废与重新建账无需转为多活动账单列表。
6. 列名使用「关联账单财务进度」，提示该状态属于整张账单。同一账单多笔费用显示同一进度属于正常投影。
7. 现有响应只有账单号，没有账单 ID；本期账单号显示文本，追踪入口跳到已有 `/finance/fees/detail/:orderId`。不猜测账单详情 URL、不以号码冒充 ID。
8. 无权、加载中、失败、无关联分别保留明确状态；请求出错不能默认 UNBILLED。403 清除当前财务投影并提示权限变化，不用订单读权限尝试替代。
9. 所有影响关联的既有成功回调同时刷新费用 actionRef 与失效对应财务 query；从财务页返回按既有查询刷新约定读取最新值。不要用轮询或本地金额推断制造实时假象。

## 5. 复用与分层

- 业务标签通过 `components/business-tag` 现有组件展示。
- 财务进度的文字映射当前在财务页面私有文件中。订单页不得深引 pages/finance；若需要共用，抽取最小映射到 `features/finance/fee-progress/index.ts`，一次性同步原台账调用方并更新能力导航。不把 API 请求或页面状态放进通用 components/ui。
- 锁定解释复用 fees.tsx 的 business write policy 与 finance lock reason；不再写独立锁规则。
- 不复制整个财务列配置窗，不为本次增加通用用户偏好平台。

## 6. 验证、限制与回退

列偏好与金额展示走前端定向测试。共享财务进度映射变更同时验证原台账。无需服务端迁移或生成客户端；若实现时发现已有契约不能满足本期定义，先回规划评审，禁止手工补生成物。

当前工作区的行内汇率联动、默认值、订单状态和页面改版属于其他工作。执行前确认最新版本，按现有变更集适配，不覆盖或纳入本任务提交。

本地偏好不跨设备同步是本方案的明确限制。后续增加服务器偏好属于独立范围。

回退本期前端提交即可恢复原列与入口；本期不改费用金额、Schema、账单规则或锁状态。回退不清理其他页面偏好或开发数据。
