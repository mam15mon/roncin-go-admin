# 实施与验证计划

1. 收敛 self 决策，完成 PRD 与方案评审；配置 implement/check 上下文并启动任务。
2. 后端 implement agent：权限投影、范围解析及角色校验，修改 Proto 并执行正式生成流程；实现后补针对性测试。
3. 前端 implement agent：消费明确权限范围，修复 access 聚合判断、角色选项、订单页面门控，更新测试夹具与定向测试。源契约/生成物由后端负责，前端不手工改生成文件。
4. check agent 独立检查前后端矩阵、跨角色范围、总部/公司、self、无权限请求及补录审批入口。
5. 运行相关后端测试、前端定向 Vitest、类型检查和 git diff --check；修复后执行 pnpm run check:fast（跨层权限契约高风险）。
6. 更新规范，中文 Conventional Commit 提交可验证修改，记录任务进展并归档。

## 核心验证矩阵
- 权限 self + 无关权限 organization/all，不得合成组织/全局能力。
- 同权限多个角色取有效并集，不错误拒绝合法范围。
- 当前组织权限不得借其他权限的 all 范围开放全局管理。
- 公司/总部切换后能力与后端一致。
- self 不得通过直接 URL、订单 ID、子资源或财务接口扩大到组织资源。
- 新建/详情/费用针对具体 kind 校验，不只使用 Any 路由布尔值。
- 无 fee.read 的有效 lock 审批者可进入必要审批界面，但不获得费用编辑权限。

## 回滚与约束
不清库、不自动升权、不修改历史数据；生成物从源契约生成。若 self 实施范围改变，重写计划并确认。
