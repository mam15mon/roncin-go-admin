# 修复订单伙伴快捷新增验收缺口

## 背景

订单伙伴快捷新增已由提交 `b83c1be6` 落地，但复核发现实现、原 PRD 与真实后端约束之间仍有
偏差：完整只读状态没有随功能提交；组织切换存在被动 effect 窗口；弹窗保存期间仍可取消或
跳转；下拉底部入口缺少标准按钮语义；自动生成代码的冲突重试会对用户显式代码做无效重试；
费用面板的同源快捷新增仍会因角色未启用、税号规则不完整而被后端拒绝。原任务还缺少若干能
直接证明验收结论的测试，且全量前端门禁存在与本功能无关的过期面包屑断言。

本任务作为归档任务
`.trellis/tasks/archive/2026-09/09-08-order-partner-quick-add` 的验收修复，不重复开发功能，
只修复已确认缺口、补齐证据并使最终门禁结论可复现。

实施期间用户进一步明确授权：审核当前工作区中的表单草稿、页签关闭、品牌资源、菜单本地化
和 Linux 开发说明改动，修正后与本任务实现一起提交。因此原先仅为“用户 WIP”的文件不再按
无关改动排除，而是纳入本次最终质量门禁与提交范围。

## 目标

- 伙伴快捷新增严格服从订单的完整只读状态和当前组织边界。
- 快捷弹窗在请求期间只有一个确定状态，不允许重复提交、取消或跳转产生竞态。
- 下拉新增入口具备明确的开关控制和键盘可访问语义。
- 服务端仅对自动生成的伙伴代码执行有限冲突重试，显式代码冲突立即返回。
- 费用面板快捷新增遵守同一创建契约，能够实际创建客户或供应商伙伴。
- 用直接测试覆盖此前仅由代码阅读推断的验收项，并让最终 `check:web` 结果真实可信。
- 审核并完成当前工作区已有的订单表单草稿、页签关闭保护、后台品牌与本地开发说明改动。

## 已确认产品与契约决策

### D1. 保留服务端自动生成伙伴代码

`CreatePartnerRequest.code` 保持可选。调用方省略或传空代码时，由服务端生成
`P` 加 8 位大写字母数字代码；用户显式提供代码时保留原值。该行为是已落地契约，也是费用
面板“留空自动生成”既有文案的实际支撑，本任务不回滚为前端猜测或填写系统编号。

### D2. 保留客户/供应商税号业务规则

创建客户或供应商角色时，统一社会信用代码仍为必填并遵守既有 18 位格式及大写规范；国外
代理不要求税号。订单委托单位、订舱代理快捷弹窗因此保留税号字段，国外代理仍只填写公司
抬头。费用面板创建客户或供应商也必须执行同一规则。

### D3. 角色必须显式启用

所有快捷创建请求的角色项必须发送 `enabled: true`。不放宽后端“至少一个有效角色”的业务
校验，也不依赖布尔默认值。

## 需求

### R1. 完整只读状态一致

- 订单详情页只计算一份有效只读值：没有
  `ORDER_ALLOWED_ACTION_EDIT` 动作，或 `businessWritesDisabled` 为真时均为只读。
- 同一值同时传给 `OrderFormTemplate.readonly` 和模板分节使用的
  `TemplateProps.readonly`；伙伴快捷新增入口不得另行推导。
- 无订单编辑动作权限、业务锁单、无伙伴创建权限三种情况均不得显示或触发新增入口。
- 新建订单继续按可编辑状态工作，不改变其他订单字段的只读规则。

### R2. 组织切换与异步响应隔离

- 伙伴字段每次渲染时同步记录最新组织身份；不能只依赖渲染后的被动 effect 更新 ref。
- 搜索和创建请求在发起时捕获组织身份与请求序号，完成时同时核对最新组织和最新请求。
- 组织切换后立即关闭旧下拉与弹窗、清理旧组织本地新建选项并使在途请求失效。
- 旧组织迟到的搜索结果不得进入新组织候选项；旧组织迟到的创建成功不得设置伙伴字段、
  `customerCode`、本地选项或成功态。
- 组织未变化时，现有搜索、创建回填与按 ID 去重行为保持不变。

### R3. 下拉入口与弹窗并发控制

- 伙伴选择器使用受控 `open` / `onOpenChange`；点击新增入口时先显式关闭下拉，再打开弹窗。
- 下拉底部入口使用真实 Button，具备键盘焦点、Enter/Space 激活语义，并避免触发订单表单提交
  或选中候选项。
- 快捷弹窗保存开始后，保存、取消、右上角关闭、遮罩/ESC 关闭和“添加公司详情”均不可再次
  改变流程，直至请求成功或失败。
- 保存处理使用同步互斥门，防止 React 状态提交前的连续点击发起两次请求。
- 请求失败后恢复全部正常操作，保留输入并展示错误；成功后仍按既有逻辑重置并关闭。
- 未配置附加动作的 `QuickCreateModal` 调用保持既有按钮、重置与错误行为。

### R4. 自动编码冲突重试

- 只有调用方未提供代码、由服务端自动生成代码时，代码唯一冲突才重新生成并重试。
- 自动生成最多尝试 3 个候选代码；每次冲突后必须生成新候选，不能重复写入同一个候选。
- 调用方显式提供的代码发生冲突时立即返回既有代码冲突业务错误，仓储只调用一次。
- 随机源失败或非代码冲突错误立即返回，不自动重试，不改变错误分层与数据库唯一索引兜底。
- 不修改伙伴表结构、索引、权限、分页或其他创建校验。

### R5. 费用面板同源创建修复

- `QuickAddPartnerModal` 创建请求省略代码，由服务端自动生成；不得在前端生成业务代码。
- 所选客户/供应商角色逐项发送 `enabled: true`，继续支持原有多选角色能力。
- 因该弹窗只创建客户或供应商，统一社会信用代码改为必填，应用与伙伴完整档案一致的 18 位、
  去空白和大写规则。
- 创建成功、失败保留输入和父级回填行为保持不变；不把订单专属伙伴字段组件提升为公共组件，
  不合并两个业务表单。

### R6. 验收证据与门禁

- 补充页面或等价集成测试，直接证明完整只读值同时进入模板和分节，而非只断言组件收到某个
  手工传入的 `disabled`。
- 使用可控 deferred Promise 测试“组织已切换、旧请求后返回”的真实时序，分别覆盖搜索与
  创建迟到响应。
- 直接断言委托单位普通选择、快捷创建和清空时 `customerCode` 的同步与清空。
- 让远程搜索返回与本地新伙伴相同 ID，断言只保留一个选项且当前值继续显示名称而非裸 ID。
- 补充伙伴完整档案创建预填、查询参数变化和编辑模式忽略参数的页面级或等价边界测试。
- 补充公共弹窗在途请求期间的双击、取消和附加动作测试；补充费用面板使用真实
  `QuickCreateModal` 的集成测试。
- 补充服务端自动代码三次不同候选、显式代码冲突只调用一次、非冲突错误不重试测试。
- 修正 `orders-breadcrumbs.test.tsx` 中与当前页面规范不一致的旧断言，仅让测试与既有产品
  行为一致，不借机改页面面包屑。

### R7. 追加授权改动审核

- 订单表单修改后写入 `sessionStorage`，重新进入同一路径时恢复草稿；提交、重置或确认关闭
  页签后清理对应草稿。
- 草稿必须按用户和当前组织隔离；组织命名空间变化时重建表单，不得把旧组织 Form store 或
  草稿带入新组织。实时关闭 guard 与持久草稿任一为脏时都必须提示。
- 草稿反序列化应恢复订单表单中的日期、截止时间及 `*At` 时间字段，不把普通 ISO 文本按值
  形态误判为日期。
- 订单详情的首次初始值与草稿回填仅由 `OrderFormTemplate` 按订单/草稿上下文完成；锁单、解锁、
  锁状态同步或同订单后台加载不得覆盖当前未保存的 Form store。用户明确点击“刷新数据”时，才在
  当前加载成功后清草稿并使用最新服务端值重置表单。
- 菜单关闭翻译查找，品牌 Logo、favicon 与 PWA 图标使用本次提供资源；菜单头保留真实链接
  语义，不重复触发两次路由跳转。
- `HeaderDropdown` 使用 Ant Design 当前 `popupRender` 接口，同时保留旧调用方的兼容入口；
  本地开发说明与脚本提示统一描述 Ubuntu / Linux 环境。
- 海运贸易条款默认值只由新建订单页面的 `initialValues` 提供，分节字段不再重复声明默认值。

## 非目标

- 不回滚已发布的伙伴代码可选契约，不再变更 Proto、OpenAPI 或生成客户端。
- 不放宽客户/供应商税号规则，不为国外代理新增税号。
- 不新增伙伴角色、权限码、数据库字段、索引或迁移。
- 不为船代、空运订单或其他伙伴字段扩展快捷新增。
- 不重构伙伴完整档案或组织切换基础设施。
- 不通过排除目录、关闭规则或删除断言来掩盖 Biome、类型或测试问题。

## 风险与约束

- `detail.tsx`、`SeaBasicInfoSection.tsx` 与页签组件的原有 WIP 已由用户追加授权纳入；提交前
  必须审核完整数据流和测试证据，不能仅因“允许一起提交”而跳过定责。
- 服务端自动代码属于已落地跨层契约，本任务修正其算法和测试但不再次生成契约文件。
- 全量门禁此前的三个失败来自过期面包屑断言；只允许更新测试以匹配当前已确认页面规范。
  若出现新的产品代码失败，必须单独定责，不能扩大范围顺手修复。
