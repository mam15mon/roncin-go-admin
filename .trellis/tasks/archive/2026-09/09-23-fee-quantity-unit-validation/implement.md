# 实施与验证计划

## 阶段和执行边界

已获准并完成 task.py start，使用 Trellis 实现与检查子代理；主会话负责协调、规格更新、提交及收尾。跨层同一闭环不拆独立子任务。

## 步骤

1. **实施前核对**：检查 git status、子目录 AGENTS.md、后端公共主数据/数据库规范和前端规范；核对另一个费用种子任务的最新迁移，确认本任务迁移顺序。保留所有他人改动。
2. **Schema 与契约**：新增 Ent 属性和正式 SQL 迁移；按 design.md 初始映射回填；更新计费单位读写和订单费用候选 proto、领域对象及转换。
3. **生成同步**：依据 server/Makefile 与 go:generate 定义生成 Ent；make -C server api；pnpm run generate:web-client。审阅差异，禁止手工修补生成物。
4. **服务端闭环**：目录/单位读取传递属性，新增、复制、补录执行整数校验；更新仅在数量数值或单位改变时执行；检查已建账路径、权威版本、审批快照及并发一致性；同步 sync:dev 新建单位初值。
5. **前端闭环**：单位管理列表及二选一表单、新建箱型默认值、候选缓存刷新；费用弹窗、行内编辑、补录及其他可写入口统一校验，覆盖改费目默认单位、复制、批量保存及旧小数编辑基线。
6. **实现后定向验证**：补充并运行下方风险用例，禁止 TDD；使用真实正式迁移验证 Schema，不能通过 Schema.Create 替代迁移。
7. **质量审阅**：检查代理核对需求、权限、事务、映射/生成链及所有写入口，修复后只重复受影响检查。记录验证结果。
8. **交付**：更新公共主数据/费用校验规范；仅暂存本任务改动，分组 Conventional Commit；完成最终门禁后归档并记录会话。

## 定向验证矩阵

| 范围 | 必须覆盖 |
| --- | --- |
| 迁移 | 全新库、已有库、明确离散种子、未知单位默认、已有费用数量不变、种子迁移顺序 |
| 管理 | 新建普通默认小数、箱型自动带入整数、显式选择不被覆盖、编辑保留值、权限不扩大 |
| API | 属性读写往返、费用选项输出、非法小数错误、客户端伪造属性无效 |
| 数量 | 1、2.0000、4.4、0.5、0、负数、超过现有精度/上限 |
| 更新 | 数量未变只改备注/单价、数量改变、单位改变、改回原值、已建账字段限制、版本冲突 |
| 录入 | 弹窗、行内、复制新建、批量保存、补录、切换费用项目带入单位 |
| 配置变更 | 候选缓存刷新、旧表单提交兜底、sync:dev 不覆盖管理员配置、已提交补录审批不重解释 |

## 命令与验收

- Go 定向：go -C server test -p 32 ./internal/biz ./internal/data ./internal/service -run '<本次受影响用例模式>'；迁移集成用例按仓库环境运行，只用隔离测试库，不重置开发库。
- 前端定向：pnpm --dir web exec vitest run <实际受影响测试文件>，路径相对 web/，确认实际执行文件数；重型组件用例按职责拆分。
- 修改文件 Biome、pnpm --dir web tsc、git diff --check；后端按影响范围执行 vet。
- 全任务最终验收执行 pnpm run check:fast。本任务涉及 Schema、契约和多费用写入口，需全栈门禁；不需要固定执行生产构建。
- 无法执行的检查明确记录原因，不关闭规则或以 0 用例作为通过。
