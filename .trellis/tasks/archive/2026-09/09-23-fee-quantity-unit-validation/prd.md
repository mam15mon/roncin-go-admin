# 费用数量按计费单位校验

## 目标

系统预设常用单位的数量规则，管理员只需处理例外；费用录入自动遵守所选单位的规则，避免小数票数、箱数误录，同时允许正常重量、体积和时间小数计费。

## 背景与已确定决定

- 用户认可在计费单位档案配置规则，并要求按“常用单位预设好、管理员只处理例外”的方案编写计划。用户随后批准实施，已由实施与检查子代理完成。
- 实际单位是可维护的公共主数据，来自 billing_units 表全部启用记录，并非固定枚举（server/internal/data/order_fee.go:163；web/src/pages/orders/use-order-fee-options.ts:72）。
- 当前单位只含箱型标记，未含数量规则（server/internal/data/ent/schema/billing_unit.go:16）。管理员通过 BillingUnitsPanel 维护（web/src/pages/finance/fee-settings/components/BillingUnitsPanel.tsx:64）。
- 现有费用数量要求正数且最多 4 位小数，前后端尚未按单位校验（web/src/pages/orders/components/fees/FeeFormModal.tsx:253；OrderFeeTableTabs.tsx:767；server/internal/biz/order_fee.go:843）。
- 单位初始化来源包含正式迁移和开发种子（server/migrations/20260824080000_billing_unit_container_flag.sql:17；server/cmd/sync-dev/main.go:389），不能只参考开发示例。

## 需求

### R1 管理员维护

- 计费单位列表增加“数量规则”，显示“整数”或“允许小数”；新建、编辑提供两项选择，沿用已有系统管理权限。
- 新建普通单位默认允许小数。新建时勾选箱型单位，若数量规则尚未被管理员主动选择，则带入整数；管理员仍可调整。切换箱型不覆盖已主动选择的规则，编辑既有单位不自动重置规则。
- 名称或代码变化不改变数量规则。运行时以单位档案配置为准。

### R2 初始规则

| 系统已有单位类别 | 初始规则 |
| --- | --- |
| 票、份、套、车 | 整数 |
| 箱、具体箱型 | 整数 |
| 重量、体积、计费吨 | 允许小数 |
| 小时、天 | 允许小数 |

- 对系统已知单位一次初始化；自定义且语义不明的单位允许小数，留给管理员处理。
- 初始分类只在正式迁移及新增种子创建时赋值，后续同步不能覆盖管理员选择。

### R3 费用校验

- 普通新增、复制新增、行内新增、补录申请创建，按当前单位规则校验。
- 编辑已有费用时，数量数值或计费单位发生变化才追加当前整数规则校验；只改备注、日期、单价等其他字段，不因单位后来收紧而阻止保存。
- 整数单位拒绝 4.4、0.5；接受 1、2.0000。允许小数单位沿用正数、上限和最多 4 位小数规则。
- 单位切换或数量变化及时更新提示，提交再次校验，禁止自动取整改变金额。服务端以权威单位配置最终判定。
- 所有既有权限、锁定、已建账字段限制、版本及金额计算规则继续执行。

### R4 规则变更与已有费用

- 调整单位规则不改写已有费用，也不阻止查看、结算等不改变数量的既有流程。
- 补录申请创建时校验，已提交的不可变快照不因后来规则调整而重算或阻止审批；新建申请采用当前规则。
- 编辑费用比较数量的数值而非字符串，2 与 2.0000 视为未变化。与数量无关的修改不额外引入旧版本兼容分支。

## 验收标准

- AC1：管理员在列表可见规则，创建与编辑可设置；公司工作台权限不扩大。
- AC2：全新库与升级库的已知离散单位设为整数，重量/体积/时间单位允许小数，自定义未知单位保持允许小数。
- AC3：箱型新建默认合理，管理员主动选择及后续编辑不被自动覆盖；重复开发数据同步保留配置。
- AC4：普通弹窗、行内编辑、补录及直接 API 的整数/小数结果一致；切换单位后立即更新提示。
- AC5：数量未变的既有小数费用可以修改允许的其他字段；改变数量或单位则执行当前规则；禁止自动取整。
- AC6：普通新建、复制和补录没有绕过路径；已建账权限与版本冲突仍正确；已提交补录按原快照审批。
- AC7：正式迁移、契约源文件与生成物一致，验证结果有记录。

## 范围外

不增加单位自定义精度、复杂规则引擎、批量配置平台；不修改单价/金额/汇率精度；不重写历史费用、不清空数据库；不按名称实时猜测单位含义。
