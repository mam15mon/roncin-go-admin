# 简化海运出口主单签发方录入

## Goal

减少海运出口业务人员的重复录入：业务只填写必填的“船公司”和“MBL 主单号”，
系统自动以船公司维护 MBL 主单签发方，同时保留共享 MBL、拆票、改配、改单版本和
锁定快照所需的内部数据完整性。

## Background

- 用户确认海运出口新建订单时船公司必须填写，MBL 主单号通常已经取得并继续必填。
- 用户确认实际业务中没有出现过 MBL 主单签发方与船公司不同的订单。
- 当前新建和详情页额外要求选择“实际签发/承运主体”；拆票、改配还使用“发单人 /
  船代”，造成同一主体重复录入和概念混淆。
- 当前数据库、共享主单唯一索引、版本与锁定快照均使用 MBL
  `issuer_partner_id`。本需求只取消人工录入，不删除内部字段。
- HBL 签发方支持本公司、委托单位或其他合作伙伴，是独立业务事实，不属于本次调整。

## Requirements

### FR-1：订单新建与详情减负

- 海运出口的“船公司”保持原名称并改为必填，MBL 主单号继续必填。
- 删除新建页和详情编辑页的“实际签发/承运主体”输入控件，不增加隐藏的“签发方不同”入口。
- 创建和更新海运出口订单时，系统以当前船公司作为 MBL 主单签发方；前后端都不得允许
  新写入的 MBL 签发方与其权威运输执行船公司不一致。
- 详情页修改单成员 MBL 的船公司或主单号时，继续执行现有主单身份更正原因与下游事实
  保护；多订单共享 MBL 时，禁止从单票页面直接修改船公司或主单号。

### FR-2：共享 MBL 候选匹配

- 页面只让业务输入船公司和 MBL 主单号，候选匹配内部使用同一个船公司 ID 作为现有
  MBL 签发方身份与运输执行船公司。
- 保留现有共享 MBL 明确确认、候选版本、航程冲突检查和多成员保护，不因减负而静默合并。

### FR-3：拆票与整票改配

- 删除 MBL 目标中的“发单人 / 船代”或其他签发方人工输入。
- 新建目标 MBL 必须具备船公司，系统以该船公司同时维护运输执行 carrier 和 MBL issuer。
- 匹配已有目标 MBL 时，以候选 MBL 及其运输执行中的权威船公司为准，不要求业务重复回传签发方。

### FR-4：数据与契约边界

- 保留 MBL 数据库 `issuer_partner_id`、唯一索引、版本字段、锁定快照和查询响应字段；
  本阶段不为 UI 减负引入无必要的数据迁移。
- 写入契约可以暂时保留 `issuer_partner_id`，由前端从 carrier 派生并由后端强制校验或规范化；
  不以清理 Proto 字段为本次目标。
- HBL 的 `issuer_source`、`issuer_organization_id`、`issuer_partner_id` 及所有录入、唯一性、
  版本和改单逻辑保持不变。
- 实施前对现有开发数据库做只读审计，确认 SE 订单、运输执行 carrier 与 MBL issuer 的
  空值或不一致情况；发现异常只报告，不自动回填或静默纠正。

## Acceptance Criteria

- [x] AC-1：新建和详情编辑页中，海运出口“船公司”和“MBL 主单号”均必填，页面不再显示
  “实际签发/承运主体”或 MBL 签发方输入框。
- [x] AC-2：创建或更新 SE 订单后，订单 carrier、MBL 运输执行 carrier 与 MBL issuer 一致；
  缺少船公司或尝试提交不一致值时服务端明确拒绝或规范化为权威船公司。
- [x] AC-3：相同船公司和相同 MBL 主单号仍触发共享主单候选确认；航程冲突、候选版本和
  多成员限制保持有效。
- [x] AC-4：拆票和整票改配不再要求填写 MBL 发单人/签发方；新建目标 MBL 必须有船公司，
  保存后目标订单、运输执行和 MBL 使用同一船公司。
- [x] AC-5：MBL 单成员身份更正与共享 MBL 修改限制没有回归；HBL 签发方相关页面、契约和
  业务规则完全不受影响。
- [x] AC-6：现有数据只读审计结果已记录；未执行未获批准的数据修复或兼容分支。
- [x] AC-7：前后端针对性测试覆盖新建、详情、候选匹配、拆票、改配与 HBL 相邻路径；最终
  按风险执行一次完整质量门禁，生成物仅在源契约确有变化时重新生成。

## Out of Scope

- 不重命名“船公司”。
- 不移动整个 MBL/提单区块，不重构海运出口页面布局。
- 不支持 MBL 签发方与船公司不同的例外流程；实际出现业务案例后另行设计。
- 不删除 MBL 数据库字段、版本快照或历史响应字段。
- 不修改 HBL 签发主体规则。
- 不自动回填或清理现有数据。

## Key Decisions

- 拆票新建 MBL 默认带入来源主单的船公司，业务人员无需重复选择；确需换船公司时允许修改。
- 详情页继续允许在现有单成员、草稿和下游事实门禁范围内更换船公司，并将该变化视为 MBL
  身份更正；共享 MBL 不允许从单票页面修改。
- 已有数据先只读审计；本任务不默认生成自动回填、兼容分支或静默纠错。
