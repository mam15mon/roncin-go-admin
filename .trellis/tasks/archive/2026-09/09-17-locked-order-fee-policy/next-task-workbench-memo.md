## 1. 背景与核心价值

- **现状痛点**：当前系统默认首页 `/welcome` 为纯静态的“账号信息与安全边界展示”，缺乏业务互动与日常操作粘性；同时，业务员无法直观掌握个人订单的提成核算与回款进度，缺乏即时激励，月末对账成本高。
- **业务目标**：
  1. 将 `/welcome` 全面重构为**「我的工作台」**，实现按登录角色的千人千面（业务员 / 操作员 / 财务 / 管理员）；
  2. 建立以业务员为核心的**「提成晴雨表」与「回款催收看板」**，让业务员对个人收入透明可预期，反哺财务回款效率；
  3. 在全局**订单列表页**透出单票提成状态，打通业务与财务的认知壁垒。

## 2. 核心业务原则（红线与底线）

1. **系统职责边界与底薪隔离（系统根本不看基本工资）**：
   - 本系统为 **Roncin 货代业务协同与结算系统（TMS）**，非 HR 考勤薪酬人事系统，系统内**没有、也无需维护**员工基本工资、社保、个税等字段；
   - 货代系统的提成模块**仅负责输出当期业务提成结算净额**：`当期系统应发提成 = max(0, 当期新单提成 - 锁单补录冲减已确认金额)`；
   - 冲减只在浮动提成池内消化，单月提成输出下限为 0 元，绝对不产生负数发放，系统也绝无可能、绝无权限跨界去扣员工的基本工资；未扣完金额仅在系统内挂账顺延至下期新提成抵扣。
2. **提成一次性落袋原则**：
   - 正常订单在满足计提条件并核发后，提成即处于终结状态；
   - 锁单后补录成本触发的提成冲减草稿（`DRAFT`），财务具有审核弹性（可确认扣减，也可经审批特批【忽略建议/豁免】）。

## 3. 功能板块详细设计

### 3.1 业务员专属「我的工作台」板块

#### 模块 A：提成晴雨表（三张核心激励卡）
1. **【当前可领提成】**：
   - **判定条件**：客户应收已全额核销（100% 回款）、订单费用已完整录入、无待决争议。
   - **呈现**：汇总当前可结算总提成金额（如 `¥ 8,600`），附快捷操作【申请计提】。
2. **【在途提成看板（回款催收利器）】**：
   - **判定条件**：订单已有正向毛利，但客户应收尚在账期内或未结清尾款。
   - **呈现**：汇总在途潜在提成金额（如 `¥ 12,000`）；
   - **催款穿透**：每票展示“当前卡在什么环节”，例如：*“订单 RC-2026-008 尚差客户 ¥3,000 尾款未回，收齐即可计提提成 ¥600”*。
3. **【历史已发与调整明细】**：
   - 展示年度/月度累计已发提成，以及锁后补录成本产生的冲减扣除公示明细。

#### 模块 B：待办与风险拦截栏
- 待我补齐费用的订单（新建后未录费用的订单）；
- 超期未付款客户预警（已放单但超过信用期未回款）。

#### 模块 C：我名下的近期订单快捷看板
- 呈现当前用户负责的最近 5~10 票海运出口单；
- 支持直接在此快捷跳转录费、查看单证与流转状态。

---

### 3.2 财务与管理层视界（角色适配）

当财务或管理人员登录「我的工作台」时，自动切换为管理视角：
1. **待审批锁单补录**：展示全公司待审批的 `OrderFeeSupplementRequest` 列表，支持一键审批/驳回；
2. **待处理提成冲减建议**：展示锁单补录后系统自动生成的 `FinanceCommissionAdjustment`（`DRAFT`），财务可【确认冲减】或【忽略建议】；
3. **待发放提成结算单**：按业务员汇总本期应发提成总表，支持导出与线下发薪联动标记。

---

### 3.3 订单列表透出提成状态（Tag 体系）

在海运出口等订单列表增加【提成状态】列或标签：

| 状态标签 | 视觉建议 | 业务含义 |
| :--- | :--- | :--- |
| **未计提** | 灰色 Tag | 订单进行中，或客户应收尚未收齐，未达计提标准 |
| **可计提** | 蓝色 Tag | 应收已全额结清，满足计提条件，等待提交或核算 |
| **已计提待发** | 青色 Tag | 提成金额已核算锁定，已计入待发薪名单 |
| **提成已发** | 绿色 Tag | 该订单提成已完全结算并发放，生命周期闭环 |
| **待冲减** | 橙色 Tag | 锁单后发生了补录应付成本，存在待财务确认的冲减草稿 |

## 4. 财务核算与汇率核心风控铁律（事前强阻断原则）

1. **组织本位币终生不可变（已落地）**：
   - 组织建立并设定本位币后，严禁任何形式的修改（防止 7 倍历史汇率放大灾难）；
   - 前端本币选择框强制置灰禁用，后端 `UpdateOrganization` 强校验拒绝变更。
2. **费用录入强阻断（彻底废黜“静默继承上周旧汇率”）**：
   - 彻底废止技术端原有的“四级容灾/静默继承历史周（`INHERITED_LAST_WEEK`）”逻辑；
   - **外币费用发生日当周若未发布有效汇率，直接弹窗阻断报错，严禁录入费用**；
   - 严格落实“无汇率不录单、倒逼财务按时发布、责任明确不甩锅”的事前风控。
3. **汇率生命周期：彻底封板与使用锁定（做法二）**：
   - **空白周允许补录**：若财务因休假、生病导致某历史周汇率完全空白，允许财务随时进行**补录新增（Create）**，补填空缺后该周单据即可正常录费；
   - **使用即死锁（一旦引用，永久只读）**：已发布的汇率只要被**任何一笔费用、账单或发票引用过**，该汇率行立刻永久锁定为只读状态，**禁止任何 Update 篡改**，防止出现“汇率表与单据明细前后矛盾”的审计灾难；
   - **未来周禁止预设**：`weekFrom > now` 的未来自然周禁止提前录入，防止汇率剧烈波动导致公司利润被侵蚀或亏损。
4. **汇率输错应急处理（救火通道规范）**：
   - **通道 A（零引用场景，引用数 = 0）**：若财务手抖输入错误数值（如 7.1 误输为 71），在**尚未有任何费用/账单使用**该汇率前，允许财务执行【停用/作废（Disable）】，并重新创建一条正确的汇率行；
   - **通道 B（已被引用场景，引用数 > 0）**：**绝对严禁直接改写历史汇率行！** 必须走阳光下的业务纠偏流程——业务与财务协同将错误汇率期间录入的几笔费用逐行作废重录，或通过红字冲销调整，保留全链路可审计操作痕迹，严禁暗改底层源头。
5. **费用明细收支方向（Direction）终生不可逆**：
   - 费用创建保存后，`RECEIVABLE`（应收）与 `PAYABLE`（应付）属性永久锁定，禁止更新反转；
   - 录错方向必须删除该行重录，杜绝毛利颠倒与科目挂错风险。
