# 往来单位角色级黑名单

## Goal

让客户、供应商与国外代理角色分别具备黑名单能力，由后端阻止新增业务关联，同时不妨碍既有订单履约和历史债权债务结算。

## Requirements

- 将现有供应商专属黑名单扩展为客户、供应商、国外代理三个业务角色分别管理；保留 PartnerRole 存储位置。
- 同档案不同角色独立限制，散客不豁免；公司间不自动传播。
- 黑名单限制新增业务，不阻止历史查询及既有债权债务结算。
- 用户已确认：新建订单检查客户、订舱代理（供应商）、国外代理、船务代理（供应商）；草稿更新仅对相应字段新选入的单位执行黑名单拦截。原字段保留不变不因拉黑被禁止，移除可选关联仍允许。
- 管理弹窗明确选择档案已有的目标角色；默认角色跟随列表类别，展示对应黑名单状态，不能一次操作隐式拉黑其他角色。
- 加入和解除沿用既有规则：原因去除首尾空白后必须非空且不超过 500 字；解除后的原因保留在审计中。
- 同步 Proto、服务端、前端、生成客户端、审计和针对性验证；不保留供应商专属旧接口兼容分支。

## Acceptance Criteria

- [x] 三种角色均可独立加入/移出黑名单，纯客户无需具备供应商角色。
- [x] 黑名单原因与操作审计可追溯，无法通过移除再添加角色绕过限制。
- [x] 新建订单对客户、订舱代理（供应商）、国外代理、船务代理（供应商）执行后端强制校验，不仅依赖下拉过滤。
- [x] 已有订单、账单、收付款及核销不因拉黑被整体封锁。
- [x] 创建订单或草稿换入被拉黑单位返回包含角色含义的中文业务错误，并回滚事务；原关联不变与可选关联移除可正常保存。
- [x] 各列表可管理已有角色黑名单，显示状态，操作不会连带其他角色；具备既有黑名单权限才能操作。

## 已核实事实

- `server/api/partner/v1/partner.proto:63` 仅有 SetSupplierBlacklist；角色读模型已包含黑名单字段（227 行）。
- `server/internal/data/partner.go:324` 事务锁定档案后仅查供应商角色；697 行仅禁止移除已拉黑供应商角色。
- `server/internal/data/order_sync.go:133` 的订单角色引用校验只检查角色和档案启用，不检查 blacklisted。因此现有供应商黑名单不能视为已完成交易拦截。
- `web/src/pages/partners/index.tsx:543` 现有黑名单弹窗为供应商专属。

## 不在本期范围

- 集团全局黑名单、跨公司自动传播、档案级一键全角色封禁。
- 历史订单追加费用/采购拦截、自动终止订单、自动更改财务状态。
- 批量拉黑、自动风控规则、新权限体系或旧接口兼容。

## 技术约束与风险

- 复用现有 PartnerRole 字段及 business.partner.blacklist 权限；无预计 Schema 变更，保留既有供应商黑名单数据。
- 黑名单修改与订单引用校验须在事务中使用相容的锁，避免并发拉黑和开单之间的检查空窗；多个档案按主键固定顺序加锁。
- 通用档案/结算选择器不能全局隐藏黑名单单位，否则会误伤清欠与存量履约；本期保留候选可见，后端权威拦截。
