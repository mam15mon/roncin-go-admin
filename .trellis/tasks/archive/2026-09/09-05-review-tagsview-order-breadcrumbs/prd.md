# 联合审查 TagsView 与订单面包屑

## Goal

并行复核 TagsView 与订单面包屑的最终实现，确认两组修复分别满足原需求，并验证面包屑导航、页签复用和订单数据加载在组合使用时没有回归。

## Requirements

1. 审查已提交的 TagsView 修复，包括菜单稳定页签键、重定向入口、未知路径边界、最新地址、动态标题、右键操作和键盘操作。
2. 审查已提交的订单面包屑修复，包括列表、新建、详情、费用和拆票的层级、链接、主要返回入口、加载/空结果/无效类型状态。
3. 审查订单详情与费用页的数据加载隔离，确认订单 A 切换到订单 B 时不会展示、保留或提交 A 的数据，无效业务类型不会发起订单相关请求。
4. 联合验证点击 `/orders`、业务列表和订单号面包屑后，TagsView 继续复用正确菜单页签并保存最新地址。
5. 对照原归档任务、真实代码差异和测试，不以任务勾选项代替验证；只处理本轮审查确认的问题。
6. 两个领域由独立检查代理并行审查，主会话负责复核交界行为、合并发现并给出最终结论。
7. 修复费用页跨订单状态污染：订单 ID 变化时清空并关闭订单相关页面状态，账单工作台不得保留上一订单费用，迟到费用列表响应不得覆盖当前订单。
8. 修复详情页拆票/改配动作资格竞态：动作状态绑定订单 ID 和请求序号，订单变化或请求失败时不得继续展示上一订单动作状态。
9. 增加同一组件实例内 A→B 路由切换、逆序响应和失败响应测试，覆盖可见状态及财务提交入口。
