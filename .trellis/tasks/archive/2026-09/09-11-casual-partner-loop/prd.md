# 散客闭环：单次合作往来单位 PRD

## 1. 任务定位

货代业务中，单次合作客户（散客 / 一票客）与单次合作供应商（临时车队、零星堆场、临时吊车）是高频场景。现有快捷建档链路（仅录公司抬头 + 自动编码 + 税号选填）已经解决"建档不卡脖子"，但散客与正式客户在系统内没有任何区分，资金风险敞口无人看守：散客客户可能被误赋长期账期、垫资回款无提醒；向临时供应商出款时无收款账户约束，存在私户付款与错汇风险。

本任务补齐散客的最小风控闭环：**可标识、可区分、出款账户硬约束、散客账期零底线**。遵循"**风控充分预警、商业决策不强行锁死、强制只放在钱流出处**"原则：建档与录单环节零新增阻断门槛，唯一的刚性拦截是对外出款无收款账户。

**范围边界**：散客客户的应收账期底线（默认 0 + 预警）**在本任务内以症状级最小实现交付**——直接按 `is_casual` 硬编码，不建通用机制；正式客户的应收账期主档带出、信用额度管控（含双模自定义设置）由后续任务 `09-11-partner-terms-credit` 承接，该任务可整体顺延而不影响散客底线。

优先级：**P2（上线交付窗口内交付；非正确性阻断项，但缺失会在上线首月产生付款合规敞口）**。

## 2. 当前代码事实与问题边界

- 快捷新增（订单基本信息的 `PartnerQuickAddSelect`、费用的 `QuickAddPartnerModal`）仅录公司抬头；后端在编码为空时自动生成 `P+8` 位随机码；统一社会信用代码已改为选填（commit 656388cb）。散客建档无障碍，但产生的档案与正式客户无法区分。
- 伙伴批量导入入口已存在（`ImportPartners`，含 `create_only` / `upsert` 模式），当前无散客维度。
- 费用侧快捷建档弹窗（`QuickAddPartnerModal`）的客商类型为多选，可同时勾选「客户」与「供应商」；订单侧快捷建档（`PartnerQuickAddSelect`）则由触发字段上下文静默写入单一角色，两处交互契约不一致。
- 现金流创建（`finance_cashflow.go`）强制要求我方账户与付款方式，**对方账户（`CounterpartyAccount`）为选填**；向临时供应商出款时无收款账户约束。
- 伙伴列表与选择器没有散客维度的展示与筛选。
- 建账走 `PreviewBatch` / 批量建账流程，账单组在预览阶段成型，可在该处注入散客默认账期；账单 / 财务 UI 重构已合入 main（PR #1），无在途冲突。

## 3. 已确定的产品决策

- **散客标识为伙伴级属性**（`is_casual`），不按角色拆分：同一往来单位即使同时具备客户与供应商角色，也只有一个散客标识。
- **快捷新增默认散客**：弹窗提供「单次合作」复选框，默认勾选、允许取消。理由：把正式客户误标为散客的代价（补一次编辑）远小于散客漏标，且「新客户首单现结」符合货代信用惯例；显式勾选框允许 OP 快捷录入长期客户时取消。
- **正式入口不默认散客**：伙伴主档新建表单由维护者显式选择。批量导入默认均为正式伙伴（`is_casual = false`）。
- **转正 = 编辑档案**：取消散客标识并按需补齐税号、开票抬头、结算规则即可，不建专门转正功能或提醒。
- **快捷建档角色由上下文决定，不做多选**：订单侧维持现状（按触发字段写入单一角色）；费用侧弹窗改为单选，由调用方按当前费用方向预选（应收→客户、应付→供应商，方向未选默认客户），用户可切换为另一角色。理由：同时勾选双角色属于主档级维护决策，且误勾供应商角色会使散客在付款时触发「对方收款账户必填」刚性拦截；「同行互为客商换方向检索不到」的重复建档顾虑，后续在选择器做同名提示或追加角色引导解决，不在快捷弹窗预勾多角色。
- **账户约束作用于出款方向且维持绝对刚性**：向散客供应商创建付款方向现金流（`Payable`）时，对方收款账户必填，缺失时服务端直接拒绝，返回稳定业务错误 `ErrFinanceCashflowCasualSupplierAccountRequired`。对外支出真金白银无账户属于重大合规隐患，必须保留刚性拦截。
- **散客账期底线为症状级硬编码，不建通用机制**：建账预览（`PreviewBatch`）对散客客户的账单组直接返回默认账期 0（到期日 = 账单日），前端修改为大于 0 天时黄色预警、不阻断。不新增结算规则"默认账期天数"字段、不做正式客户带出——那是 `09-11-partner-terms-credit` 的治本范围；散客"不读规则、恒为 0"的行为在其后保持不变。
- **选择器采用契约字段传递**：选择器选项数据暴露 `is_casual` 字段，由前端动态渲染 `[散客]` 标签，不把散客文本硬拼进 `label`，避免污染单证与合同名称。

## 4. 功能需求与验收标准

### 4.1 散客标识与建档

- 伙伴实体新增 `is_casual` 布尔属性，默认 `false`，经 Ent Schema 迁移落库，契约（proto / OpenAPI / 前端生成物）同步。
- 快捷新增弹窗展示「单次合作」复选框，默认勾选、可取消，创建请求携带该标识。
- 费用侧快捷建档弹窗（`QuickAddPartnerModal`）的客商类型由多选改为单选：新增 `defaultRole` 入参，由调用方按当前费用方向预选（应收→客户、应付→供应商；方向未选默认客户），用户可切换为另一角色；与订单侧「上下文决定角色」契约对齐。
- 伙伴主档表单与详情页可查看、修改该标识，详情页展示散客 Tag。

验收：快捷新增默认产生散客档案，取消勾选产生正式档案；费用侧弹窗只能选择单一角色且按费用方向预选正确；主档可双向切换标识；批量导入默认正式；存量数据迁移后默认为正式伙伴。

### 4.2 散客供应商出款账户必填

- 创建付款方向现金流（`Direction == Payable`）时，若结算对方为散客：对方收款账户必填，缺失时服务端返回稳定业务错误 `ErrFinanceCashflowCasualSupplierAccountRequired`。
- 前端在散客供应商的付款录入中将对方账户标记为必填项并做前置表单校验。

验收：散客供应商无对方账户的付款被服务端坚决拒绝；正式供应商付款与所有收款方向流水不受影响。

### 4.3 散客客户应收账期底线（默认 0 + 预警）

- 建账预览（`PreviewBatch`）对散客客户的账单组返回 `is_casual` 与默认账期天数 0；前端默认回填 0 并联动到期日 = 账单日。
- 财务修改为大于 0 天时，输入框旁呈现醒目黄色预警（"该客户为单次合作散客，建议现结；当前已设置 X 天账期，请注意资金回款风险"），允许正常提交，服务端不拦截。

验收：散客客户建账默认账期 0、到期日 = 账单日；改大时出现预警且可正常提交；正式客户建账行为与现状完全一致。

### 4.4 列表与选择器区分

- 客户 / 供应商列表支持按散客筛选，行内展示散客 Tag。
- 伙伴选择器（订单、费用等处的检索下拉）选项契约携带 `is_casual`，候选项为散客时前端渲染「散客」标签。

验收：列表筛选与 Tag 正确；选择器标注仅在候选为散客时出现；非散客展示无变化；选中值不包含多余前缀。

## 5. 非目标

- 不做正式客户的应收账期主档带出、信用额度双模管控与建账工作台信用预警——由 `09-11-partner-terms-credit` 承接并可整体顺延；散客账期底线已在本任务交付，顺延不留敞口。
- 不建信用额度占用 / 释放 / 超限拦截的任何形态（拦截属上述后续任务的可选模式）。
- 不做放单 / 电放拦截（分单 RELEASED 流程与放货记录的钩子已存在，属后续独立任务）。
- 不建转正提醒、按票数统计、客户 360 画像、供应商红黑榜。
- 不建客户类型枚举（企业 / 个人 / 境外由 USCC 可选、发票抬头形态、散客标识等属性隐式表达）。
- 不做对账单、境外账户 SWIFT/IBAN 字段细化、双语 PDF、邮件抄送通道。
- 不改动开票抬头（`InvoiceProfilesPanel`）的税号必填口径。
