# 修复订单缓存复用与组织切换隔离

## Goal

完成“优化新建订单页面主数据加载体验”任务的 Review 闭环：同一组织重复进入新建页时不因空关键字联想绕过地点首批缓存；组织切换后任何旧组织搜索结果或错误状态都不能出现在当前页面；恢复严格的浏览器网络请求验收。

## Background

- 原任务位于 `.trellis/tasks/archive/2026-09/09-06-optimize-order-create-loading/`，核心约束包括组织隔离、会话级缓存复用、关键字远程联想和浏览器请求计数验收。
- 修复提交 `5455b305` 已处理主加载状态隔离、详情页无组织错误和缓存 Promise 竞态，但复审仍发现三个缺口：
  1. `useOrderCreateOptions.searchLocations` 在空关键字时仍调用后端；海运表单四个地点下拉挂载会各发一次港口请求，真实 Playwright 验收得到第二次进入新增港口请求数为 4。
  2. 列表资源中的客户、港口、地点和承运人远程搜索即使在组织切换后丢弃了部分本地状态写入，仍可能把旧组织候选项作为 Promise 返回值交给下拉组件。
  3. 新建页和详情页的失败状态没有绑定请求所属组织；组织 A 失败后切到组织 B，Effect 清理前的一次渲染仍可能展示 A 的错误。

## Requirements

### FR-1：空关键字复用当前组织地点首批缓存

- 新建页和详情页的地点搜索收到空值、空字符串或仅空白关键字时，不调用地点远程查询接口，直接返回当前组织、当前业务类别已经加载的 `locationOptions`。
- 只有非空关键字才调用现有服务端联想接口，继续满足服务端关键字过滤约定，不限制真实搜索结果为首批 50 条。
- 缓存尚未就绪、当前组织缺失或已切换到其他组织时，空关键字搜索返回空数组，不得回退到旧组织候选项。

### FR-2：远程搜索结果按组织身份隔离

- 订单列表资源中的客户、港口、地点、承运人和人员搜索在发起请求前捕获当前 `organizationId`。
- 当前组织缺失时不得发起组织级搜索请求，直接返回空数组。
- 请求完成后必须同时校验捕获的组织与当前活动组织；不一致时返回空数组，且不得更新 Hook 或调用方可见状态。
- 客户和港口搜索保留现有当前组织下的映射/首批数据合并行为；组织校验必须同时保护内部 state 和 Promise 返回值。

### FR-3：错误状态绑定请求身份

- 新建页主数据错误至少绑定组织 ID 与当前订单业务配置；只有错误身份与当前页面身份一致时才向页面暴露。
- 详情页加载错误至少绑定组织 ID 与订单 ID；只有错误身份与当前详情身份一致时才向页面暴露。
- 从失败的组织 A 切换到组织 B 后，第一次渲染即进入 B 的加载态，不得等待 Effect 执行后才移除 A 的错误。
- 缺少有效组织的明确错误行为保持不变。

### FR-4：针对性测试与浏览器验收

- 单元测试覆盖空关键字复用、非空关键字继续远程查询、组织切换后搜索 Promise 返回空数组，以及失败组织切换后的即时错误隔离。
- 保留 Playwright 对第二次进入新建页港口新增请求数为 0 的严格断言，不通过放宽计数或忽略空关键字请求规避问题。
- 最终执行全量前端测试、TypeScript、Biome/lint、`git diff --check` 和目标 Playwright 用例。

## Acceptance Criteria

- [ ] AC-1：同一组织首次进入海运新建页后，经 SPA 返回列表并再次进入时，`master-data/options`、港口首批、机场首批、币种和人员候选项的新增请求数均为 0。
- [ ] AC-2：海运表单四个地点下拉挂载时不会以空关键字额外触发港口或地区查询；输入非空关键字仍调用服务端并返回匹配候选项。
- [ ] AC-3：组织 A 发起客户、港口、地点、承运人或人员搜索后切换到组织 B，A 的迟到 Promise 对调用方返回 `[]`，且不会写入 B 的 Hook state。
- [ ] AC-4：组织 A 的新建页加载失败后切换到 B，B 的首次渲染不包含 A 的错误并处于加载态；详情页同一订单 ID 下的组织切换同样成立。
- [ ] AC-5：缺少当前组织时仍展示明确错误，不发起组织级主数据或搜索请求。
- [ ] AC-6：目标定向测试、全量 Vitest、TypeScript、前端静态检查、`git diff --check` 和 `order-create-loading.e2e.ts` 全部通过。

## Out of Scope

- 不修改后端接口、Protobuf、数据库 Schema 或生成客户端。
- 不改变有真实关键字时的服务端联想行为、分页上限或候选项展示格式。
- 不重构订单列表、表单模板或 TagsView 的整体状态架构。
- 不放宽原任务的缓存复用、组织隔离或 E2E 请求计数标准。
