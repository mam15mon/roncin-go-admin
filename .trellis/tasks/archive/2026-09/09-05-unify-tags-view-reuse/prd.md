# 统一全站 TagsView 页面复用规则

## Goal

将 TagsView 从“每个完整 URL 都新建页签”改为“每个菜单入口只有一个工作页签”。业务人员从菜单列表进入新建、详情、编辑、费用录入、拆票等内部页面时，当前菜单页签继续承载新页面，不再产生一串重复页签。

## Background

- 当前 `TagsView.tsx` 直接以 `location.pathname` 同时作为页签 `key` 和页面地址，因此列表、详情、新建、费用等不同路径会被识别为不同页签。
- 当前路由中已经存在多类菜单内部子页面：
  - 订单：`/orders/:kind/new`、`/orders/:kind/:id`、`/orders/:kind/:id/fees`、海运出口拆票；
  - 客商：客户、供应商、国外代理各自的新建与详情；
  - 费用：集运费用明细下的单票费用详情。
- 参数设置、主数据、系统管理、企业资源配置等主要通过同一路径的查询参数或页面内标签切换，目前不会因页面内标签产生多个 TagsView 页签。
- 订单详情和费用录入会在数据加载后通过 `roncin:update-tab-title` 更新动态标题；统一页签身份后需要同步调整事件匹配逻辑，避免旧完整路径与新稳定页签键不一致。
- 现有另一个任务正在修改海运出口配舱信息相关文件。本任务只修改全局 TagsView、路由解析辅助逻辑及其测试，不覆盖该任务的代码。

## Requirements

1. **菜单入口是唯一页签身份**
   - 工作台继续为固定且不可关闭的页签。
   - 每个侧边栏或顶部菜单中的实际业务入口拥有独立页签。
   - 同一菜单入口下的列表、新建、详情、编辑、费用录入、拆票等页面共用一个稳定页签键。

2. **页签记录该菜单最后访问的位置**
   - 在同一菜单内部跳转时更新已有页签的目标地址，不新增页签。
   - 切换到其他菜单页签后再切回来，应返回该菜单最后访问的内部页面。
   - 回到菜单列表时，同一页签的目标地址同步恢复为列表地址。

3. **覆盖当前全站内部子路由**
   - 同一订单业务类型下的新建、详情、费用录入和拆票复用该订单类型的列表页签。
   - 客户、供应商、国外代理各自的新建和详情复用各自的列表页签；三个客商入口仍是三个独立页签。
   - 集运费用详情复用“集运费用明细”页签。
   - 从一个菜单的页面跳转到另一个菜单所属页面时，使用目标菜单自己的页签，不错误覆盖来源菜单页签。

4. **直接访问与刷新可恢复**
   - 浏览器直接访问或刷新内部页面时，应按其所属菜单建立一个页签，而不是把内部 URL 当成新的独立页签。
   - 未命中已知复用规则的独立页面仍按自身路径建立页签，避免未知路由被错误归组。

5. **交互完整性**
   - 关闭当前页签、关闭其他、关闭左侧、关闭右侧、重新加载、点击切换等现有操作继续正确工作。
   - 登录、注册与认证回调页继续不进入 TagsView。
   - 页签图标按稳定菜单身份判断，不因当前停留在详情路径而改变模块归属。
   - 查询参数应保留在页签最后访问地址中，重新点击该页签时不丢失页面内标签状态。
   - 页签标题跟随当前内部页面变化：列表显示列表标题，新建显示新建标题，详情和费用页在数据加载后继续显示包含真实业务编号的动态标题；标题变化不得改变页签身份或增加页签。

6. **集中维护与可扩展性**
   - 页签归属规则集中定义和测试，不在各业务页面逐个增加临时关闭页签或替换页签事件。
   - 后续新增带内部子页面的菜单入口时，可以在单一位置增加归属规则。

## Acceptance Criteria

- [x] 从“海运出口”进入新建订单，不新增 TagsView 页签。
- [x] 从“海运出口”进入订单详情、费用录入或拆票，不新增 TagsView 页签。
- [x] 从订单内部页面返回海运出口列表，仍只有原来的海运出口页签。
- [x] 同一订单类型连续打开不同订单详情，仍只有一个该类型页签，并指向最后打开的订单。
- [x] 客户、供应商、国外代理的新建与详情分别复用各自列表页签，且三类入口互不合并。
- [x] 集运费用详情复用“集运费用明细”页签。
- [x] 跨菜单跳转时目标菜单拥有独立页签；例如从费用详情查看业务订单时，保留费用页签并打开或复用对应订单页签。
- [x] 直接打开内部 URL 时只建立工作台和所属菜单页签，刷新后行为一致。
- [x] 切换到其他菜单再切回来，恢复该菜单最后访问的内部 URL（包括查询参数）。
- [x] 同一页签内切换列表、新建、详情和费用页面时，标题同步反映当前页面；订单详情与费用页仍能显示真实订单号。
- [x] 现有页签关闭、左右批量关闭、关闭其他、重新加载和键盘激活行为均通过测试。
- [x] 未命中归属规则的页面不会被错误合并。
- [x] `pnpm --dir web tsc`、TagsView 相关测试及前端格式/静态检查通过。

## Out of Scope

- 不为路由页面增加组件级缓存，不承诺未写入 URL 的表格临时筛选、滚动位置或未保存表单内容在卸载后自动恢复。
- 不改变侧边栏、顶部菜单、TagsView 的视觉样式和权限规则。
- 不修改服务端接口、数据库或生成代码。
- 不把不同菜单入口合并为一个页签。
