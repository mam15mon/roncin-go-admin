# 订单面包屑现状审计

## 当前页面矩阵

| 页面 | 当前导航 | 主要问题 |
| --- | --- | --- |
| 列表 | 路由自动生成 `订单管理 > 海运出口` | 层级正确，但来源与内部页面不同 |
| 新建 | `返回列表 / 订单管理 / 海运出口订单 / 新建订单 / 新建海运出口订单` | 当前页重复、业务名不一致 |
| 详情 | `海运出口订单 > 海运出口订单详情 (订单号)` | 缺“订单管理”，订单号不是稳定层级，无统一返回按钮 |
| 费用 | `返回订单详情 / 海运出口订单 > 订单号 > 费用录入`，右侧另有回详情按钮 | 手写样式、返回入口重复、业务类型不可返回列表 |
| 拆票 | `返回订单详情 / 海运出口 > 订单号详情 > 拆票工作台 / 海运出口拆票工作台 订单号` | 当前页与订单号重复 |

## 实现来源

- 列表：`routes.ts` 的 route name + `OrderListTemplate` 中未关闭自动面包屑的 `PageContainer`。
- 新建、拆票：各自向 `PageHeaderShell` 传入手写 breadcrumbs。
- 详情：`OrderDetailHeader` 向 `DocumentDetailLayout` 传入另一种 breadcrumbs。
- 费用：`fees.tsx` 自己渲染 Button、Span 和 `<a onClick>`。
- 全局顶部标题与 TagsView 标题另由 `routeUtils.ts` 计算，不是订单页面面包屑来源。

## 公共组件问题

- `PageHeaderShell` 会在每个 breadcrumbs 项后渲染分隔符，再输出 title。调用方把当前页
  同时放进 breadcrumbs 和 title 时就会重复。
- `PageHeaderShellProps` 已声明 `href`，组件却只识别 `onClick`；因此无法使用标准链接。
- `DocumentDetailLayout` 当前只有订单详情使用，其自带面包屑与公共页头形成两套视觉。

## 异常状态问题

- 详情和费用加载中或未找到订单时在正常页头之前直接返回，导航上下文消失。
- 新建对未知 kind 显示 404；详情和费用却使用海运出口配置兜底，错误 URL 会被误标为
  海运出口。

## 设计输入

- `PageHeaderShell` 是项目规范指定的整页表单/详情公共页头，应成为订单内部页唯一外观。
- 订单详情的动作按钮较多，需要继续放在页头下方可横向滚动的操作工具栏，不能全部塞入
  `PageHeaderShell.extra`。
- 费用页右侧刷新属于当前页操作，应保留；“回到订单详情”与左侧主要返回重复，应移除。
- 拆票底部取消属于表单动作，保留不影响顶部导航唯一性。
