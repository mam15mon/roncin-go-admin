# 统一订单页面面包屑导航

## Goal

统一订单列表、新建、详情、费用录入和拆票页面的位置导航，让业务人员在任何订单页面都能明确知道当前所属业务、订单和功能，并通过一致的入口返回上级页面。

## Background

- 订单列表使用路由自动面包屑，新建与拆票使用 `PageHeaderShell`，详情使用 `DocumentDetailLayout`，费用页又手写一套导航栏，当前至少存在四套展示来源。
- 同一业务在不同页面混用“海运出口”“海运出口订单”“海运出口订单列表”等名称。
- 新建页同时显示“新建订单”和“新建海运出口订单”，拆票页同时显示“拆票工作台”和“海运出口拆票工作台”，当前页含义重复。
- 费用页同屏存在多个“返回订单详情”入口，却无法从面包屑直接返回列表。
- 详情和费用页对未知订单类型静默回退为海运出口，可能产生错误业务归属提示。

## Requirements

1. **统一业务层级**
   - 订单页面统一遵循 `订单管理 > 业务类型 > 订单号 > 当前功能`。
   - 按页面省略不存在的层级：列表止于业务类型，新建不显示订单号，详情止于订单号。
   - 业务类型层统一使用菜单名称“海运出口”，不再在面包屑中混用“海运出口订单”或“海运出口订单列表”。

2. **各页面目标结构**
   - 列表：`订单管理 > 海运出口`。
   - 新建：`订单管理 > 海运出口 > 新建订单`。
   - 详情：`订单管理 > 海运出口 > SE订单号`。
   - 费用：`订单管理 > 海运出口 > SE订单号 > 费用录入`。
   - 拆票：`订单管理 > 海运出口 > SE订单号 > 拆票`。

3. **统一点击与返回规则**
   - 当前页面不可点击，所有真实上级页面可点击。
   - 新建与详情的主要返回按钮返回业务类型列表。
   - 费用与拆票的主要返回按钮返回订单详情。
   - 每个页面只保留一个主要返回按钮；删除费用页右侧重复的“回到订单详情”。
   - 拆票底部“取消返回”作为表单取消动作保留，不视为重复面包屑入口。
   - 面包屑上级项使用真实链接语义，支持浏览器复制链接、Ctrl/Command 点击和中键打开。

4. **统一页面头部**
   - 新建、详情、费用和拆票统一通过订单专属公共页头构建面包屑、当前标题和返回行为。
   - 当前页只展示一次：公共页头的 `breadcrumbs` 只承载上级层级，`title` 承载当前页面。
   - 详情页现有业务操作工具栏、锁定状态和状态流转区域保持原功能，不因页头统一而丢失。
   - 费用页保留刷新、锁定提示和费用摘要，但移除手写导航栏。

5. **加载、空结果与无效路由**
   - 详情和费用在加载中或订单不存在时仍保留所属业务的公共页头和返回路径。
   - 订单号尚未加载时可暂用路由 ID，加载成功后显示真实订单号。
   - 新建、详情和费用统一校验业务类型；无效类型明确显示错误页面，不得静默当成海运出口。

6. **范围与兼容**
   - 当前只统一订单模块，不顺带改造客商、财务台账详情等其他模块。
   - 不改变订单业务流程、权限、接口、数据库、表单内容和 TagsView 规则。
   - 不改变列表、新建、详情、费用和拆票的业务操作结果。

## Acceptance Criteria

- [x] 列表、新建、详情、费用、拆票分别按约定层级展示，且当前页面名称不重复。
- [x] 面包屑统一使用“订单管理”和菜单名“海运出口”，不再混用三种业务名称。
- [x] 详情、费用和拆票中的订单号位置一致；费用与拆票可通过订单号返回详情。
- [x] 新建与详情只有一个主要“返回列表”入口；费用与拆票只有一个主要“返回订单详情”入口。
- [x] 费用页右侧重复“回到订单详情”按钮移除；订单基础信息中的订单编号不再承担重复的主要导航入口。
- [x] 拆票底部“取消返回”继续可用。
- [x] 上级面包屑使用真实链接，当前页不可点击。
- [x] 详情与费用的加载中、订单不存在状态仍显示正确业务归属和返回入口。
- [x] 未知订单类型不会显示为海运出口，统一进入明确错误状态。
- [x] 订单详情操作按钮、订单锁状态、费用刷新与拆票刷新等原功能保持可用。
- [x] 面包屑公共组件、页面接入和异常状态均有针对性测试。
- [x] `pnpm --dir web tsc`、相关前端测试、Biome 检查和 `git diff --check` 通过。

## Out of Scope

- TagsView 页签归属和复用规则。
- 页面数据缓存、筛选条件或滚动位置恢复。
- 订单以外模块的面包屑改造。
- 服务端、接口契约、权限和数据库变更。
