# 订单表单伙伴字段快捷新增

## 目标与用户价值

海运出口订单的新建页和详情页中，「委托单位 / 订舱代理 / 国外代理」三个伙伴选择器
支持在不离开订单表单的情况下快捷创建伙伴：用户从下拉底部进入只填写公司抬头的弹窗，
保存后立即选中新伙伴；需要录入完整档案时，可携带已填公司抬头进入对应角色的新建页面。

该能力缩短订单录入路径，同时保持伙伴创建权限、订单只读状态和既有伙伴档案流程不变。

## 已确认事实与字段映射

- 三个字段当前都在 `SeaBasicInfoSection` 中，并通过服务端关键字检索按角色过滤的 Partner；
  海运新建页和详情页共用该模板。
- `partnerServiceCreatePartner` 已支持只提交 `legalName + roles` 的最小创建请求，本任务不需
  修改后端契约。
- `canCreatePartners` 是既有伙伴创建权限，三个伙伴新建路由也使用该权限。
- 订单详情页的有效只读状态同时包含“没有订单编辑动作权限”和“锁单等业务写入关闭”；快捷
  新增必须使用这一完整状态，不能只判断锁单状态。
- `partner-detail` 已按路径识别伙伴角色，但创建模式尚未读取 `legalName` 查询参数。

| 表单字段 | 页面名称 | 伙伴角色 | 枚举值 | 完整档案新建路由 |
| --- | --- | --- | --- | --- |
| `customerId` | 委托单位 | `CUSTOMER` | `1` | `/partners/customers/create` |
| `bookingAgentId` | 订舱代理 | `SUPPLIER` | `2` | `/partners/suppliers/create` |
| `foreignAgentId` | 国外代理 | `FOREIGN_AGENT` | `3` | `/partners/foreign-agents/create` |

## 需求

### R1. 伙伴字段与现有行为

- 为上述三个字段复用同一个订单专属伙伴快捷新增字段组件；组件按配置接收字段名、显示名称、
  角色、完整档案路由、检索函数及字段变更回调。
- 保留既有字段规则：委托单位必填，订舱代理和国外代理选填，三者继续支持远程关键字检索和
  清空。
- 委托单位通过正常选择或快捷创建回填时，继续同步 `customerCode`；新伙伴没有代码时清空该
  派生字段，禁止残留上一个委托单位的代码。
- 详情页传给字段组件的 `readonly` 必须与 `OrderFormTemplate` 实际使用的有效只读值一致：
  没有订单编辑动作权限或因锁单等原因关闭业务写入时均视为只读。

### R2. 下拉底部新增入口

- 三个字段的下拉菜单底部通过 Ant Design v6 的 `popupRender` 渲染固定操作行，内容为蓝色
  加号图标和「新增 委托单位 / 新增 订舱代理 / 新增 国外代理」。
- 仅当用户具有 `canCreatePartners` 且订单表单可编辑时显示入口；任一条件不满足时不渲染，
  也不得留下其他可触发快捷创建的路径。
- 点击入口只关闭当前下拉并打开对应快捷新增弹窗，不触发订单表单提交或字段校验。
- 快捷弹窗、创建响应和本地新建选项必须绑定发起时的当前组织；组织切换后清理旧交互状态，
  迟到的旧组织响应不得回填到新组织的订单表单。

### R3. 快捷新增弹窗与创建

- 弹窗垂直居中，标题为「新增 委托单位 / 新增 订舱代理 / 新增 国外代理」，保留右上角关闭
  按钮。
- 表单仅包含一个必填的「公司抬头」单行文本字段；去除首尾空白后提交，最大长度 200 字符。
- 底部按「添加公司详情 / 取消 / 保存」提供三个动作：
  - 取消：重置快捷表单并关闭弹窗，不修改订单字段；
  - 保存：校验公司抬头，调用 `partnerServiceCreatePartner`，只提交规范化后的 `legalName`
    与当前字段对应的单一角色；
  - 添加公司详情：不触发快捷表单校验或保存，按 R4 跳转完整档案页面。
- 创建响应必须包含伙伴 ID 才算成功。成功后关闭弹窗、把新伙伴写入当前订单字段，并将新伙伴
  选项合并到该字段本地选项中；后续远程搜索刷新不得让当前值退化为只显示 ID。
- 本地新建选项与远程结果按伙伴 ID 去重，不重复显示同一伙伴。
- 请求失败或响应缺少伙伴 ID 时显示错误、保持弹窗打开并保留用户输入；不自动重试、不静默
  创建其他角色，也不修改订单字段。

### R4. 进入完整伙伴档案

- 点击「添加公司详情」时读取当前公司抬头并去除首尾空白：非空则使用标准查询参数编码，以
  `legalName` 携带到当前角色的新建路由；空白则直接进入新建路由，不携带该参数。
- `partner-detail` 只在创建模式读取并预填 `legalName`；编辑现有伙伴时必须忽略该查询参数，
  不得覆盖已加载的公司抬头。
- 创建页面在同一组件实例中切换路径或查询参数时，应使用当前地址重新建立创建默认值，不能
  残留上一条地址的预填公司抬头。
- 跳转离开订单页不创建伙伴、不保存订单，也不增加自动返回或草稿恢复逻辑。

### R5. 公共组件兼容

- 通过扩展 `QuickCreateModal` 实现可选附加底部动作和可选垂直居中能力；附加动作可以读取
  当前表单实例，但点击时不触发表单校验或 `onSubmit`。
- 未传新增属性的现有调用继续保留当前标题、宽度、按钮文案、按钮顺序、表单重置和错误展示
  行为。
- 费用面板 `QuickAddPartnerModal` 的字段、角色选择、请求载荷与成功回填行为均不改动。

## 非目标

- 不修改后端契约、权限清单、伙伴搜索接口或数据库。
- 快捷弹窗不支持客商代码、统一社会信用代码、多角色、联系人、结算规则等完整档案字段。
- 不为船代 `shippingAgentId` 或空运订单字段增加快捷创建。
- 不改造费用面板的 `QuickAddPartnerModal`，不合并两种业务表单。
- 不增加订单草稿自动保存、离开页面确认、跳转后的自动返回或旧数据兼容分支。

## 实施偏离记录（后端现实约束，均已核实）

PRD「已确认事实」中「partnerServiceCreatePartner 已支持只提交 legalName + roles」不成立，
实测被后端三道校验拦截，据此产生三处偏离：

1. **客商代码服务端自动生成**（跨层小契约变更，突破本 PRD 非目标）：proto
   `CreatePartnerRequest.code` 去掉 REQUIRED 改 optional；biz 创建时留空生成
   `P` + 8 位大写字母数字（crypto/rand），冲突由 `partner_org_code_key` 唯一索引兜底并重试
   （最多 3 次）。顺带使费用面板快捷新建「留空自动生成」的既有占位承诺首次变为可行。
2. **委托单位/订舱代理弹窗增加必填的纳税人识别号**（18 位统一社会信用代码，normalize
   自动大写）：后端 2026-08-22「拆分企业资源角色与入口」特性规定客户/供应商角色必须提供
   税号，属有意业务规则不可放宽；国外代理豁免，保持仅公司抬头单字段。
3. **角色载荷需 `enabled: true`**：后端 normalizePartnerRoles 要求至少一个启用角色，
   省略 enabled 默认 false 会被判无效。

费用面板 `QuickAddPartnerModal` 存在同源问题（空 code、税号未按角色必填、角色缺
enabled），按 PRD 非目标未在本任务改造，建议后续单独修复。

另：`detail.tsx` 的 readonly 完整判定修复（effectiveReadonly）已实现但因与并行进行的
表单草稿 WIP 交织于同一文件，未随本任务提交，待该特性提交时一并入库。
