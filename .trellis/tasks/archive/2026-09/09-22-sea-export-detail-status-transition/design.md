# 海运出口详情页直接流转状态技术设计

## 1. 边界与目标

本次调整海运出口订单详情交互，修正服务端“流转后不可编辑”的重复草稿门禁，并统一新建与
详情的五卡片信息架构；不新增 API 字段，不修改数据库 Schema、主流程迁移边或权限码。主流程、
退关和结案统一在“订单状态”卡片操作。详情接口已经返回以下权威字段：

- `flowStatus`：当前主流程状态；
- `allowedTargetFlowStatuses`：当前合法的下一状态集合；
- `terminationStatus` / `closureStatus`：退关和结案当前状态；
- `allowedActions`：经过权限、组织范围和当前状态裁剪的订单动作；
- `version`：提交时使用的乐观锁版本。

前端只消费这些字段，不根据当前状态自行推导下一状态，确保“已配舱”同时允许“拖车已安排”
和“已截单”等分支与服务端始终一致。

服务端订单内容编辑资格统一为：

```text
具有订单 update 权限与可写组织范围
  ∧ termination_status = ACTIVE
  ∧ closure_status = OPEN
  ∧ locked_at IS NULL
```

主流程状态不参与内容编辑资格裁剪。`orderAllowedActions` 对满足生命周期条件的订单投影 `EDIT`；
`UpdateDraft` 在 `ForUpdate` 后继续执行 `ensureOrderBusinessEditable` 与版本比对，但不再额外要求
`flow_status = DRAFT`。这样前端仍只消费服务端动作，不复制编辑规则，后端写入也保留权威门禁。

## 2. 组件职责

### 2.1 `OrderStatusSection`

状态分节继续负责流程展示，并新增最薄的交互输入：

- 当前订单；
- 是否允许发起主流程写入；
- 禁用原因；
- `onTransition(targetStatus)` 主流程回调；
- 由详情页按允许动作注入的退关与结案回调。

组件使用 `allowedTargetFlowStatuses` 建立可点击集合：

- 已完成节点：蓝色完成态，只展示；
- 服务端允许的目标节点：渲染为 Ant Design `Button`，具备键盘聚焦、明确 hover/focus
  和 `aria-label="流转到<状态>"`；
- 其余未来节点：灰色只读展示；
- 合法目标因锁状态、工作台或同步失败被前端写门禁关闭时：保持目标提示但禁用，并展示统一
  `businessWriteBlockedReason`。

组件不请求接口、不维护服务端状态、不读取权限系统，也不自行判断状态迁移边。

退关和结案徽标改为状态动作入口：

| 当前维度状态 | 展示 | 允许动作与交互 |
| --- | --- | --- |
| `ACTIVE` | 未退关 | 有 `START_TERMINATION` 时点击发起退关 |
| `TERMINATING` | 退关中 | 下拉选择“完成退关”或“取消退关” |
| `TERMINATED` | 已退关 | 有 `CANCEL_TERMINATION` 时点击恢复订单 |
| `OPEN` | 未完结 | 有 `CLOSE` 时点击完结；否则禁用并提示当前暂不可完结 |
| `CLOSED` | 已完结 | 有 `REOPEN` 时点击反结案 |

单一动作使用按钮式徽标直接打开既有确认框；`TERMINATING` 存在两个动作，使用 Ant Design
`Dropdown` 呈现明确选择，避免一次点击猜测用户意图。所有按钮保留键盘语义与可见焦点。
完结与反结案确认均要求填写原因，对齐 Proto `REQUIRED` 和 Biz 非空校验；不再显示“完结原因
选填”的错误提示。

### 2.2 详情页编排

`detail.tsx` 负责把既有事实组合为流转资格：

```text
服务端 allowedActions 含 TRANSITION_FLOW
  ∧ 当前工作台可操作订单所属公司
  ∧ 统一业务写策略未关闭（锁状态已加载且未锁定）
  ∧ 目标存在于 allowedTargetFlowStatuses
```

点击目标后由详情页调用新的主流程确认辅助函数。确认框固定当前和目标状态，可填写可选原因，
不提供目标状态下拉框。页面以 ref 保证确认框单实例；`afterClose` 释放该门禁。

详情页同时把现有 `confirmOrderTermination` / `confirmOrderClosure` 回调注入状态分节。状态分节
只显示页面按 `allowedActions` 和工作台范围授权后的动作，不自行复制生命周期状态机。提交前门禁
按动作种类分开：

- 主流程推进、发起退关：复核当前工作台与统一业务锁策略；
- 完成退关、取消退关、恢复订单：只复核当前工作台和最新允许动作，不因业务锁阻断；
- 完结、反结案：只复核当前工作台和最新允许动作，不因业务锁阻断，结案 readiness 仍由服务端
  在事务内权威校验。

该区分对齐 `.trellis/spec/server/backend/order-lock-and-document-version.md`，并修正现有页头把全部
生命周期动作统一套用 `businessWritesDisabled` 的前端误拦截。

确认提交使用当前响应中的 `id`、`version` 与目标状态调用生成客户端
`orderServiceTransitionOrderStatus`。`onOk` 返回 Promise，让 Ant Design 自动管理确认按钮
loading。成功后：

1. 显示“状态已流转至……”提示；
2. 并行刷新订单详情和锁状态；
3. 最新详情响应驱动流程条重绘和版本更新。

请求失败时不修改本地订单状态；统一请求层呈现服务端错误，且必须显式识别请求层消费错误后
返回的空响应，禁止误报成功。并发旧版本继续由服务端返回 `ORDER_STATUS_CONFLICT`。

### 2.3 确认辅助函数

在现有 `order-detail-transitions.tsx` 中加入 `confirmOrderFlow`，与退关、结案确认保持同一
`App.useApp()` 上下文。它只负责：

- 校验订单 ID、版本和目标状态；
- 渲染当前/目标状态及可选原因；
- 调用生成客户端；
- 成功提示与完成回调。

它不拥有权限或锁状态判断；调用前和 `onOk` 提交前均由页面门禁复核，避免弹窗打开后锁状态
变化仍继续提交。

## 3. 旧入口收口

状态动作统一收口到详情状态卡：

- 删除 `OrderListTemplate` 的 `onTransitionStatus` 属性和“更多 → 流转状态”菜单项；
- 删除 `list.tsx` 中 `TransitionModal` ref、回调和挂载；
- 删除不再使用的 `components/modals/TransitionModal.tsx`。
- 删除 `OrderDetailHeader` 中发起/完成/取消退关、完结、反结案按钮及对应 props；费用、锁单、
  保存等非状态动作保持原位。

里程碑、单证、费用等其他操作不变。详情页状态卡成为主流程、退关和结案的统一入口。

## 4. 新建与详情的统一五卡片

### 4.1 单一分节构建器

`getSeaTemplateSections(props)` 不再按 `props.isDetail` 返回两套区块。它始终按以下稳定 key 与
标题返回相同五卡片；复用现有字段组件和相同 Form name，不复制表单定义：

| key | 标题 | 主要组件来源 |
| --- | --- | --- |
| `businessCustomer` | 业务与客户 | `getSeaBaseInfoFields` 的订单身份、委托客户、服务与业务编号 |
| `bookingTransport` | 订舱与运输 | 订舱与主单、航线与船期、箱量与截关三组小标题；订舱/配舱备注就近显示，操作备注在底部平级区域 |
| `cargoCommercial` | 货物与商业 | 货物品类/危险品、贸易/合约/货值/保费、接单与货好信息、货描/特殊要求和委托件重尺 |
| `seaDocument` | 提单信息 | 单一页签组件：MBL 正文，HOUSE 模式增加 HBL 身份与正文；详情保留单证版本动作 |
| `internalPersonnel` | 内部人员 | `buildSeaPersonnelSection` 的人员字段，不容纳备注 |

`isDetail` 只影响字段能力，不影响信息架构：订单编号时间只在新建可改；详情按服务端动作和业务
锁变为只读；主单/分单历史、改单、独立保存及模式切换动作只在已落库订单显示。所有字段继续
使用当前 form name 和 payload adapter，不改请求字段或数据含义。
详情专属动作放卡片操作区或页签工具栏，允许动作区因生命周期不同而变化，共享字段位置保持一致。

### 4.2 页内折叠与单证页签

“订舱与运输”按“订舱与主单、航线与船期、箱量与截关”三组编排，使用小标题与间距，不套子卡片。
订舱备注在第一组补充说明中，配舱备注在第三组补充说明中，操作备注在卡片末尾平级的“操作补充”。
空备注初始折叠、有备注初始展开并完整可读，沿用输入框直接编辑；收起有内容的区域时标记“有备注”。
初始数据或恢复草稿到达后确定初始展开态；同单普通重绘尊重用户选择，切换订单重置展开态，校验
错误可强制展开。关闭区域保留 Form store，不能卸载必需校验规则。货物品类和危险品一起进入
第三张核心卡片，保持危险品条件校验。

详情现有 `SeaDocumentSectionComponent` 已有 MBL/HBL 页签与单一状态所有者，保留现有请求、Form
回填与版本动作；新建模式复用其相同页签交互，但不触发已落库订单的详情请求或版本操作，直接
消费现有 `SeaBillContentFormFields` 与 `HouseBillIdentityFields`。提单模式继续在订舱/主单小节
选择，页签依 `seaDocumentStructure` 切换：DIRECT 只有 MBL，HOUSE 同时显示 MBL/HBL 标签，
一次仅展示一个正文，适用的隐藏页签字段仍注册校验；切换页签或模式须保留 Form store 内其他
页签的已填内容，DIRECT 的 HBL 不参与校验或 payload。详情改变模式的
动作保持既有授权与确认，不增设新的服务端请求。

该方案不拆成两张独立单证卡片，也不为视觉重组新建通用请求层；原有单证更新接口、共享 MBL
门禁、数据隔离和独立保存动作保持原样。

复用 `web/src/components/ui/order-template/OrderFormTemplate.tsx` 的 `handleFinishFailed` 链路，
按当前模式和页面字段顺序确定首个错误，先通知 SE 区块切换页签/展开备注，待字段可见后再调用
表单滚动与聚焦能力。按需提供最小回调，不让通用模板导入 SE 页面。必须覆盖 HOUSE 下从未访问
HBL 页签的校验；仅保存 Form 值不等于校验已注册，不可把这两件事混为一谈。

### 4.3 详情专属区块

详情页面最终顺序固定为：

```text
订单状态
→ 五张核心卡片
→ 关联与记录〔操作记录｜同批订单｜拆票与改配记录〕
```

SE 详情把类型扩展贡献的同批订单、拆票/改配记录与通用审计内容组合为一个页签卡，默认操作记录；
复用内容组件，不保留三张外层卡或重复标题，不影响其他订单类型的现有后置区块。原审计长标题改为
“操作记录”，保留拆票/改配“查看全部”抽屉。不得通过匹配中文标题决定组件身份。

数量只从现有数据所有者向上暴露可选值，不重复请求。已核对：`SameBatchOrdersSection.tsx` 持有
去重并排除当前单后的结果；`SeaOrderChangeHistorySection` 在
`components/drawers/SeaOrderChangeHistoryDrawer.tsx` 以 `pageSize: 5` 请求预览，需取响应 total。
数字未知时省略，只有确定空结果时显示 0；保留当前刷新语义，不为角标新建统计接口或全面改造懒加载。
新建页不渲染详情专属区块；两页主要操作均留在页头。

### 4.4 创建成功跳转

`new.tsx` 必须保留创建响应并校验 `response?.data?.id`：

```text
POST 创建订单
  → 有 data.id：轮换幂等键 → 成功提示 → 跳转 /orders/{kind}/{id}
  → 空响应/缺 id：保留当前幂等键和表单 → 显式失败提示 → 不跳转
  → 请求异常：保留当前幂等键和表单 → 统一错误提示 → 不跳转
```

沿用同一个幂等键重试可安全取回已创建订单，避免服务端已落库但响应丢失时重复建单。页头继续
只提供“创建订单 / 取消”，不增加底部提交入口。

## 5. 数据流

```text
GET 订单详情
  → 三维当前状态 + allowedActions + allowedTargetFlowStatuses + version
  → OrderStatusSection 标出可点击节点/徽标
  → 用户点击主流程目标或生命周期动作
  → 对应确认框（主流程固定目标；退关/结案沿用既有原因规则）
  → 调用既有 status / termination / closure 接口
  → 成功提示
  → 刷新订单详情 + 锁状态
  → 新状态、新 version、新合法目标重新渲染
```

## 6. 异常与并发

| 场景 | 行为 |
| --- | --- |
| 无 `TRANSITION_FLOW` 动作 | 所有节点只读，不出现写入口 |
| 非订单所属公司工作台 | 所有写动作禁用，提示切换工作台 |
| 锁状态加载中、失败或缺失 | 主流程和发起退关失败关闭；其他生命周期动作不依赖锁状态快照 |
| 订单已锁定 | 主流程和发起退关禁用；其他生命周期动作按允许动作继续开放 |
| 退关中、已退关或已结案 | 服务端不给合法目标，流程条只读 |
| 已配舱有两个合法目标 | 两个节点均可点击，前端不裁剪 |
| 未退关 | 有发起动作时点击徽标进入退关确认 |
| 退关中 | 点击徽标打开“完成 / 取消”动作菜单 |
| 已退关 | 有恢复动作时点击徽标进入恢复确认 |
| 未完结但无 `CLOSE` | 徽标禁用并提示当前暂不可完结，不发送请求 |
| 已完结 | 有 `REOPEN` 时点击徽标进入反结案确认 |
| 完结/反结案原因为空 | 确认框内提示必填，不发送请求 |
| 确认框已打开 | 后续节点点击不再打开第二个确认框 |
| 提交期间重复确认 | Promise loading 阻止重复提交 |
| 版本冲突或服务端门禁变化 | 保留服务端错误，不乐观修改本地状态 |
| 成功后的详情刷新失败 | 已落库结果不改判失败；详情查询进入既有错误/重试状态 |
| 创建响应缺少订单 ID | 不提示成功、不跳转、不轮换幂等键，保留表单供同键重试 |
| 新建选择 DIRECT | 提单卡仅显示 MBL 页签，不挂载 HBL 正文；当前编辑内容仍保留在 Form store |
| 新建或详情选择 HOUSE | 提单卡出现 MBL/HBL 页签，两页共享字段与栅格，一次展示一个正文 |
| 切换页签或折叠说明 | 只改变可见性，不清空表单数据，重新展开后正常回显 |
| 单证详情查询失败 | 提单卡展示既有错误和重试状态，不以空数据覆盖表单 |

## 7. 兼容与回滚

- 不兼容保留列表与页头旧入口；本次一次性删除，避免同一状态动作存在两套交互。
- 无数据迁移、权限生成或 API 字段变更；如仅调整 Proto 注释，生成物必须按正式流程同步。
- 核心区块 key 和标题一次性统一，不保留旧的两套布局兼容分支。
- 如需回滚，只需恢复前端状态分节、列表菜单及旧弹窗文件，不涉及业务数据回滚。
