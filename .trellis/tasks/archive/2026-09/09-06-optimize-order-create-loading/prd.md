# 优化新建订单页面主数据加载体验

## Goal

彻底解决新建订单页面长时间卡在“正在加载业务模板与主数据...”大转盘遮罩的问题，通过“组织隔离的会话级主数据与人员选项缓存”、“海空运按需模式拉取”与“分节骨架占位体验”，消除同一组织下的重复数据请求，缩减海运冷启动请求组，并在加载期呈现与真实表单一致的高密度分节骨架屏，显著提升订单开单体验。

## Background

- 用户在访问新建订单页面（`/orders/sea-export/new`）时反馈一直卡在“正在加载业务模板与主数据...”。
- 经全链路排查分析发现：
  1. **全屏硬阻塞遮罩**：`OrderFormTemplate` 在 `loading=true` 时直接渲染全屏居中卡片 `Spin`，未展示任何页面骨架或表单结构，数据全部就绪前用户只能面对大转盘等待。
  2. **首屏 5 个接口并发短板效应**：`useOrderCreateOptions` 通过 `Promise.all` 强绑定拉取 `master-data/options`（101 项字典）、`ports`（港口前 50 条）、`airports`（机场前 50 条）、`currencies`（币种列表）、`order-personnel-options`（人员选项 200 条），且海运订单无差别拉取了空运机场接口。
  3. **缺乏组织隔离的会话级缓存**：主数据字典、港口/机场首批数据与人员候选项无前端内存缓存，多次进出新建页、列表页或详情页都会重复发起全套重度 HTTP 请求，在高负载下叠加鉴权与数据库争用，导致动辄数秒甚至十余秒等待。
  4. **组织边界安全约束**：后端主数据与人员选项均强依赖登录主体的 `principal.Organization.ID`。前端切换组织仅更新 `initialState` 而不刷新页面，因此缓存必须以 `organizationId` 严格隔离，严防跨组织数据泄露。
  5. **组织切换存在在途请求竞态**：仅按 `organizationId` 划分缓存不能阻止旧组织请求在切换后晚到并覆盖新组织页面状态；订单新建、详情和列表加载都必须丢弃已经过期的异步结果。

## Requirements

- **FR-1: 建立按组织严格隔离的会话级内存缓存机制**
  - 在独立共享模块 `web/src/utils/order-options-cache.ts` 中提供统一的主数据与地点首批数据缓存函数，避免全局登出组件反向依赖订单页面模块；`web/src/pages/orders/common.ts` 只负责消费缓存结果并派生订单表单候选项：
    - `getMasterDataOptions(organizationId: string)`：以 `organizationId` 为键缓存主数据字典 Promise；
    - `getCachedPorts(organizationId: string)`：以 `organizationId` 为键缓存首批港口 Promise；
    - `getCachedAirports(organizationId: string)`：以 `organizationId` 为键缓存首批机场 Promise；
    - `getOrderPersonnelOptions(organizationId: string, businessType: number)`：以 `${organizationId}:${businessType}` 为键缓存人员候选项 Promise；
  - **并发与失败保护**：
    - 同一组织同一 key 的多个并发调用共享同一个在途 Promise；
    - 请求失败（Promise reject）时必须立即从缓存 Map 中移除，不得保留失败态；用户重试时必须重新向服务端发起请求；
    - 使用组织级缓存的页面 Hook 必须把 `organizationId` 纳入加载依赖，并通过请求序号、Effect cleanup 或等价机制丢弃过期结果；组织 A 的请求即使在切换到组织 B 后才返回，也不得更新当前页面状态；
    - `organizationId` 缺失时不得发起组织级数据请求或静默返回成功的空数据；当前用户状态已就绪但没有有效组织时，页面必须展示明确错误。
  - **清理机制**：
    - 导出 `clearOrderMasterDataCache(organizationId?: string)`：传入组织 ID 时仅失效该组织的主数据、地点与人员缓存；省略参数时清理所有组织缓存，供单测 `beforeEach`、登出或明确的全局刷新使用；
    - 普通组织切换不清空其他组织的缓存，依靠组织键和过期请求保护实现隔离；切回此前访问过的组织时允许复用该组织自己的会话缓存；
    - 退出登录成功后必须调用无参数 `clearOrderMasterDataCache()`，再清理当前用户状态并跳转登录页，确保模块缓存不会跨登录会话残留；
    - 用户主动重试主数据加载时先失效当前组织缓存，保证 API 成功但业务校验未通过的缓存也能重新向服务端获取。
- **FR-2: 区分海运与空运模式，按需精准加载**
  - 重构 `fetchOrderMasterData(organizationId: string, category?: 'sea' | 'air')`：
    - 当 `category === 'sea'` 时，仅加载港口，彻底剔除空运机场接口（`masterDataServiceListAirports`）；
    - 当 `category === 'air'` 时，仅加载机场，彻底剔除港口接口（`masterDataServiceListPorts`）；
    - 未指定 `category` 时兼容拉取两者；
  - 订单新建页（`useOrderCreateOptions`）、详情页（`useOrderDetailData`）及列表资源加载（`list-resources.ts`）均复用该逻辑并传入当前 `category` 与 `organizationId`。
- **FR-3: 优化加载占位体验（分节骨架占位与失败恢复）**
  - 改造 `OrderFormTemplate` 中的 `loading` 渲染：
    - 采用与真实表单高度契合的纯白高密度分节骨架屏（业务委托卡片骨架 + 配舱运输卡片骨架）替代居中单卡片大 Spin，保留 `loadingTip` 说明文案，消除视觉跳动与卡死误解；
  - **失败重试机制**：
    - 当关键主数据加载失败时，新建页展示明确的错误状态与“重新加载”重试按钮，不得直接离开加载态渲染可提交但主数据缺失的空白表单；
    - 点击“重新加载”时先失效当前组织缓存，再重新执行加载，使网络失败和成功响应后的必需主数据校验失败均可恢复。
- **FR-4: 保证订单表单初始值与业务行为 100% 准确**
  - 优先按稳定业务码 `GENERAL` 匹配默认货物类别（`cargoCategoryIds`），当存在启用的 `GENERAL` 时自动选中，兼顾代码稳定性；
  - 推荐海运服务项（`serviceTypeIds`）继续按业务模式与代码稳定计算；
  - 地点联想输入（`searchLocations`）继续按关键字请求后端，不受首批 50 条本地缓存限制。

## Non-Requirements

- 不修改后端 Protobuf 契约、服务端业务逻辑或数据库 Schema。
- 除退出登录流程增加订单会话缓存清理外，不影响订单模块（新建、详情、列表）以外的其他系统模块。
- 不做异步细粒度字段级渐进填充（避免扩大为大表单可编辑状态机重构），保持分节骨架屏占位到数据就绪的原子切换。
- 不引入 TTL、持久化缓存或主数据 CRUD 的实时广播失效机制；普通会话内按组织复用缓存，明确重试、登出与全局刷新时按上述规则失效。

## Acceptance Criteria

- [ ] **AC-1: 按需加载精准性**：海运新建页（`/orders/sea-export/new`）、详情页与列表页不触发机场首批接口（`/api/v1/master-data/airports`）；空运模式不触发港口接口；未指定类别时保持双加载兼容。
- [ ] **AC-2: 会话级无重复请求**：同一组织、同一 SPA 会话内，多次进入新建页，或在订单列表与新建页之间切换时，主数据字典、对应地点首批数据、币种及人员候选项均不再发起重复的网络请求。
- [ ] **AC-3: 组织与会话隔离安全性**：每个组织首次访问时分别加载自己的数据，切换组织不得读取或展示其他组织的缓存；组织 A 请求未完成时切换到组织 B，即使 A 最后返回，页面仍只能展示 B 的数据；切回此前访问过的组织时允许复用该组织自己的缓存；退出登录后所有订单会话缓存清空，后续重新登录不得复用上一登录会话的缓存。
- [ ] **AC-4: 并发共享与失败重试**：同组织并发请求共享同一个在途 Promise；底层接口失败时自动移出缓存；成功响应未通过必需主数据校验时，点击重试会先失效当前组织缓存并重新调用服务端接口。
- [ ] **AC-5: 分节骨架与错误恢复**：冷启动阶段展示与表单布局一致的分节骨架屏与 `loadingTip`；主数据加载失败或当前用户缺少有效组织时展示明确的错误状态与重试入口，不渲染可提交的空表单。
- [ ] **AC-6: 默认值业务码对齐**：主数据中存在启用的 `GENERAL` 货物类别时，加载完成后 `cargoCategoryIds` 自动选中；推荐海运服务项正确选中，表单提交校验无回归。
- [ ] **AC-7: 远程联想无短路**：地点联想输入（`searchLocations`）继续向服务端发起关键字查询，候选项不受首批列表缓存截断。
- [ ] **AC-8: 针对性单测与质量门禁**：新增针对按类别加载、组织与登录会话隔离、组织切换在途请求竞态、并发去重、失败释放与重试、无有效组织、默认普货、列表缓存复用、错误状态及骨架占位的测试用例；全量 Vitest、TypeScript 与前端静态检查全部通过。
- [ ] **AC-9: 浏览器网络请求验收**：自动化访问海运新建页时不发出机场首批请求；同一组织第二次进入新建页时，主数据字典、港口首批数据、币种及人员候选项的新增网络请求数均为 0。
