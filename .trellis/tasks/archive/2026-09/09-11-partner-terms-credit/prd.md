# 应收账期与信用额度消费 PRD

## 1. 任务定位

结算规则模型（含信用额度字段）在服务端没有任何消费方，账期由财务逐单手工录入，主档上的信用约定与实际录账完全脱节；散客客户可能被误赋长期账期。

本任务让伙伴主档成为账期的真相源并首次被消费：**正式客户的账期规则带出（散客"默认账期恒为 0"的底线已由散客任务交付，本任务保持该行为不变）、信用额度双模管控、建账工作台信用预警**。遵循"**风控充分预警、商业决策不强行锁死、强制只放在钱流出处与管理层明确启用的干预规则上**"原则。

**任务依赖（启动前置，全部满足后才可开始实施）**：
1. `09-11-casual-partner-loop` 已交付并归档（本任务消费其 `is_casual` 字段、选择器契约与散客账期底线行为）；
2. 09-10 加固任务（`system-contradictions-and-safety-hardening`）已收尾——本任务的未核销余额聚合必须复用其修复后的核销 / 对冲分摊口径，**不得另写一套余额算法**；
3. 在途账单 / 现金流 / 伙伴 UI 改动已合入 main（PR #1，此条已满足）。

优先级：**P2（若上线窗口紧张，可顺延至上线后首个迭代，由散客任务先行覆盖底线风险）**。

## 2. 当前代码事实与问题边界

- 结算规则模型（`PartnerSettlementRule`，按角色挂靠）含 `StatementMode`、`SettlementMethod`（票结 / 周结 / 月结 / 45 天 / prepaid 等对账节奏）、`SettlementDay`、`SettlementCycleDays`、`CreditLimitMinor` / `CreditCurrency` 等字段，在服务端**没有任何消费方**；模型中**没有**"信用账期天数"字段——`SettlementMethod` 表达的是对账节奏，不等于账单日 + N 天的信用账期。
- 账单的账期天数与到期日由财务在创建账单时按账单组手工录入；账单仓储已具备 `OnlyUnsettled` 谓词与折本币未核销金额（`unverified_base_amount`，09-10 修复口径），可支撑按伙伴聚合未核销余额。
- 自定义设置基础设施已存在（`finance_custom_setting` 实体与既有汇率自定义设置同源），管控策略开关有现成挂载点。
- 建账工作台已有 `PreviewBatch` / 批量建账流程，可在预览阶段注入默认账期与超额信息。
- 订单 / 费用写入路径（委托客户 `CustomerID`、应收费用结算单位 `SettlementPartyID`）可直接挂接干预校验。
- 对账单功能尚为占位页（`settlement-placeholder.tsx`），与本任务无关。

## 3. 已确定的产品决策

- **账期真相源 = 角色级结算规则新增"默认账期天数"**（可空整数，0~3650 天）：
  - 应收账单创建时，按账单对方的**客户角色激活结算规则**带出默认账期天数，到期日 = 账单日 + N 天，财务可调整；
  - **散客客户不读规则**，默认账期恒为 0（该底线已由散客任务以硬编码交付，本任务保持该行为不变）；
  - 散客客户若被调整为大于 0 天账期，前端呈现醒目黄色预警（"该客户为单次合作散客，建议现结；当前已设置 X 天账期，请注意资金回款风险"），**允许正常提交，服务端不拦截**——硬拒绝会激励操作者摘掉散客标识再录账期，反而破坏标识真实性；事后可通过"散客 + 账期 > 0"联查审计；
  - 正式客户无规则或规则未填默认账期时，维持现有手工录入行为，不强制补齐；
  - 本期只做"账单日 + N 天"的线性到期日，月结 / 周结等对齐结算日的节奏型推算不做。
- **信用额度支持「自定义设置」双模管控（仅提醒 vs 直接干预）**：
  - 在「系统设置 -> 自定义设置」中新增**往来单位信用额度管控策略**配置，提供组织级开关：**「往来户超信用额度后是否可以选择」**（默认 **开启**，允许选择 = 仅提醒模式）；
  - **开启开关（默认，仅提醒模式）**：应收账单建账或选择往来单位时，若该客户超额，仅前端呈现黄色醒目预警（展示未核销本币金额 vs 信用额度），**允许正常选择和提交入账，服务端不阻断**；
  - **关闭开关（直接干预模式）**：
    - 当往来户「应收未核销本币金额」大于主档设置的「信用额度（本币）」时：
      - 前端选择器（订单委托客户选择、费用结算单位选择等）中该超额客户置灰禁用（`disabled`）并标注 Tag `[已超信用额度]`，**无法选择该往来户**；
      - 服务端在订单创建/修改、费用录入时对超额客户执行刚性校验拒绝，返回稳定业务错误 `ErrPartnerCreditLimitExceeded`，杜绝绕过前端强行提交；
  - **超额判定口径（统一折本币）**：
    - 额度真相源：客户角色的激活结算规则中的 `CreditLimitMinor`（主档录入的本币信用额度）；
    - 未核销金额：聚合当前组织下该客户所有已确认（`CONFIRMED`）且未结清（`Unsettled`）的应收账单折本币未核销总额（`SUM(unverified_base_amount)`）；
    - 当且仅当 `设置了信用额度 > 0` 且 `未核销本币总额 > 信用额度` 时判定为超额；散客与未设额度（NULL/0）的客户不触发超额判定。
  - **并发口径**：写入路径的干预拦截为**尽力而为**（校验时点查询余额，不做串行化加锁）；并发窗口内多笔单据同时过检导致的事后超额，以超额预警与事后报表校正，不为拦截上重锁。
- **选择器采用契约字段传递**：选择器选项数据暴露 `credit_exceeded` 字段（`is_casual` 由散客任务先行提供），由前端动态渲染 `[已超信用额度]` 标签，不把标签文本硬拼进 `label`。

### 3.1 待定设计决策（design 阶段必须定稿，不得带进实施）

1. **默认账期回填位置**：纯前端预填，还是服务端在请求未填账期时兜底注入（推荐服务端兜底——默认值注入不是拦截，不违反"不锁死"，且能覆盖 API 直录路径）；
2. **账单编辑场景**：账单创建后的编辑是否同样触发散客账期预警与超额预警（需按账单状态机核实可编辑范围后定稿）。

## 4. 功能需求与验收标准

### 4.1 应收账期：正式客户主档带出（散客底线已由散客任务交付）

- 结算规则新增可空"默认账期天数"字段，主档表单可维护；契约同步。
- 财务创建应收账单时：
  - 对方为正式客户且其客户角色激活规则填有默认账期：账期天数默认回填该值，到期日 = 账单日 + N 天，可调整；
  - 对方为正式客户且无规则或未填：维持现有手工录入行为；
  - 对方为散客客户：维持散客任务交付的"默认 0 + 改大黄色预警、不拦截"行为不变，本任务不改写。

验收：正式客户按规则带出默认账期、可调整；无规则客户行为与现状一致；散客行为与散客任务交付版本一致；到期日与账期天数联动正确。

### 4.2 信用额度管控自定义设置（仅提醒 vs 直接干预）

- 自定义设置模型与接口扩展：
  - 新增**信用额度管控策略**（`CreditLimitControlPolicy`），包含组织级开关 `allow_selection_when_credit_exceeded`（默认 `true`：允许选择 / 仅提醒模式；关闭时为直接干预拦截模式）；
  - 维护接口支持读取与更新该设置（受权限管控）。
- 直接干预逻辑：
  - 当开关关闭时，对于设置了信用额度的客户，若其「折本币未核销应收总额 > 折本币信用额度」：
    - 前端所有客户选择器（订单委托客户、费用结算单位等）中该客户标为禁用（`disabled: true`），显示 `[已超信用额度]` Tag，无法被选中；
    - 服务端在订单保存、费用录入等写入入口校验：若处于直接干预模式且选择了超额客户，返回稳定业务错误 `ErrPartnerCreditLimitExceeded` 拒绝入库。

验收：开启开关时（默认），超额客户允许正常选择并继续录单/建账；关闭开关时，超额客户在下拉中不可被选，且服务端接口坚决阻断；未超额或未设额度的客户不受任何影响。

### 4.3 建账工作台信用额度预警展示

- 财务在批量建账工作台生成预览时：
  - 若对方客户角色设有额度且存在未核销余额：前端展示"未核销应收余额 vs 额度"的比对；
  - 超限时呈现黄色醒目预警 Alert（展示当前余额、本单金额与约定额度）；
  - 建账提交环节不设阻断拦截，确保财务在核对后仍能正常入账。

验收：超额时预警出现且信息准确；不超额或未设额度时无预警；建账提交行为不受阻断。

### 4.4 选择器超额标注与禁用

- 伙伴选择器选项契约携带 `credit_exceeded`：
  - 超额候选在开启直接干预时渲染「已超信用额度」标签并置灰禁用；
  - 选中项的展示文本保持干净，不污染单据或合同字符串。

验收：标注与禁用状态仅在对应条件下生效；正常伙伴展示无变化。

## 5. 非目标

- 不建复杂的信用额度事前占用、暂扣、释放的状态流引擎（以账单确认后的未核销金额作为信用消耗真相源）。
- 不做月结 / 周结等对齐结算日的节奏型到期日推算与对账单生成（对账单现为占位页，属后续专项）。
- 不做实时汇率换算：超额判定只使用账单既有折本币字段，不做查询时点换算。
- 不做放单 / 电放拦截（分单 RELEASED 流程与放货记录的钩子已存在，属后续独立任务）。
- 不在服务端对应收账单账期做硬性报错阻断（保持商业与运营弹性，以预警提醒为主）。
- 不建转正提醒、按票数统计、客户 360 画像、供应商红黑榜。
- 不改动开票抬头（`InvoiceProfilesPanel`）的税号必填口径。
