# 诊断手机端打开系统白屏

## Goal

定位手机浏览器打开 Roncin 货代后台时出现白屏的具体原因，区分访问地址、静态资源、接口登录、浏览器兼容和窄屏 UI 初始化问题，并给出有证据的最小修复方案。

## Background

- 用户反馈电脑端可以使用，但手机打开出现白屏。
- 当前本地 Go 服务监听 `8000`，前端开发服务监听 `8001`。
- 此前面包屑与 TagsView 修改已提交并推送，桌面组件测试通过。
- 尚未取得手机型号、浏览器类型、访问 URL 和白屏截图，因此不能先假定是某一种手机兼容问题。

## Confirmed Evidence

- `http://127.0.0.1:8000/user/login` 在 Chromium 的 iPhone 13 与 Pixel 7 视口下均能渲染、登录并进入 `/welcome`，无控制台错误或失败请求。
- 生产入口首次加载约传输 2.9 MB JavaScript；普通模拟设备约 1.9 秒出现登录表单，4 倍 CPU 降速约 7.1 秒，登录后主界面约 9.3 秒可见。加载阶段的浅色骨架容易被误认为白屏，但最终可以完成渲染。
- `http://127.0.0.1:8001/user/login` 可稳定复现真正白屏：`#root` 为空，浏览器连续报告 `SyntaxError: Unexpected token '<'`。
- 8001 开发服务器对 `/umi.js`、`/scripts/loading.js` 和 UtooPack 异步脚本均返回 `200 text/html`，即 JavaScript 请求被 SPA HTML 回退错误接管；浏览器无法执行入口代码。
- 8001 的 UtooPack 开发进程自前一日持续运行并占用 `.turbopack/lock`，新进程提示已有缓存锁。当前证据指向失效的开发进程/缓存状态，而非面包屑或窄屏 CSS。
- 当前 `browserslist` 为 `defaults`，生成包仍包含箭头函数和可选链；若用户使用老旧 iOS/Android WebView，仍需根据真实浏览器版本评估兼容范围，但现代移动端 Chromium 不能复现兼容性白屏。

## Requirements

1. 检查手机访问地址是否指向手机自身的 `localhost/127.0.0.1`，以及服务是否监听可被局域网或公网访问的地址。
2. 检查入口 HTML、JavaScript/CSS 静态资源及 API 代理/同域路径在手机访问方式下是否可达。
3. 使用真实浏览器的手机视口复现登录页和登录后主界面，收集控制台错误、页面错误、失败请求和最终 DOM。
4. 检查窄屏布局相关的 TagsView、侧边栏、响应式 Hook 和浏览器兼容构建配置。
5. 诊断阶段不创建、修改或删除业务订单，不输出本地登录凭据、Cookie 或令牌。

## Acceptance Criteria

- [ ] 明确用户手机实际访问地址、浏览器环境和白屏发生阶段。
- [ ] 至少在一个真实浏览器手机视口下验证登录页和登录后主界面。
- [ ] 对白屏给出可复现证据，或明确证明当前代码无法复现并列出仍缺少的现场证据。
- [ ] 失败资源、控制台异常、接口错误与 UI 初始化路径均完成核对。
- [ ] 若确认代码缺陷，给出最小修复范围和回归验证方案；未经用户批准不进入实现。

## Out of Scope

- 不借诊断顺便重做全站移动端布局。
- 不修改服务端业务规则、订单数据或权限模型。
- 不记录、展示或提交任何真实密码、Cookie、令牌和敏感请求报文。

## Open Questions

- 用户手机实际访问的是 `:8000` 生产入口还是已确认损坏的 `:8001` 开发入口；该答案决定是直接重启开发服务/清理缓存，还是继续针对实际手机浏览器和现场地址排查。
