# 费用状态移除审阅收尾

## 目标与范围

修复提交 `b895aa3e` 的两项实现遗漏，补齐自动锁定验收证据。关联原任务：`.trellis/tasks/archive/2026-09/09-26-fee-hard-delete/`。不重新设计费用模型，不恢复费用状态。

## 审阅发现与需求

### R1（P2）：迁移禁止遗留待处理冲减建议

证据：`server/migrations/20260926100000_order_fee_status_hard_delete.sql:32` 的守卫允许 DRAFT 调整，随后只删除费用。审阅在专用库临时表执行原 SQL，得到 `remaining_fees=0 / remaining_adjustment=DRAFT`，已回滚。

已作废补录费用关联任何未取消调整，或者调整曾确认/支付时，迁移必须明确失败且整体回滚；不自动取消、删除调整或修改金融历史。只有关联调整均已取消且从未确认/支付，或无关联调整时，才允许归档审计并删除费用。申请和历史调整保留。

补充真实补录关联夹具及异常矩阵。明确已应用开发库不自动重放历史迁移；先核对旧迁移是否留下孤立待处理调整，异常单独报告，不自动修复。

### R2（P2）：普通删除审计补全快照

证据：`server/internal/data/order_fee.go:718`、`:904`，单条/批量删除仅保存代码、方向、金额、币种、版本，缺少结算单位和费用名称快照。

在删除事务内保存费用科目名称、结算单位 ID 与名称，沿用既有金额、币种、方向、版本及原因；费用名称取该费用保存的名称，不能事后用目录名称代替。单条/批量一致，任何审计写入失败必须回滚删除。不得用事务外旧快照替代锁内费用事实。

### R3（P2）：自动锁定验收必须执行到目标断言

证据：原任务 `research/baseline-failure-registry.md:101` 声称剩余失败与验收无重叠，但 `TestAutoOrderLock_SettlementTriggerPostgres/核销用例创建生效后自动触发锁定` 在汇率组织解析处提前失败。本次修改过自动锁定的未建账谓词，因此该失败会遮蔽相邻验收路径。

检查夹具的公司组织与本币配置，按真实业务模型修正；禁止关闭校验、弱化断言或统一补账单掩盖问题。真实 PostgreSQL 上核销触发锁定场景执行到锁定结果断言；同时验证未建账费用仍阻止锁定，删除最后一笔未建账费用后的重评行为符合现有资格规则。

验收记录区分本轮实际 PASS、SKIP、存量失败与未覆盖项，不再用「基线同样失败」证明业务路径已验证。原任务归档保留，本任务记录更正及前后对照。

## 不在范围内

- 其它费用目录、工位锚点、公司边界迁移存量失败的全量治理。
- 新增状态框架、改动提成政策、取消金融调整的通用自动修复。
- 清空/重建开发库、自动清理异常历史数据、重写原任务历史记录。

## 验收标准

- [ ] A1/R1：关联 DRAFT、CONFIRMED、PAID 或曾确认/支付的调整时拒绝迁移；费用、调整、申请、审计和列结构无部分变更。
- [ ] A2/R1：仅有关联 CANCELLED 且无确认/支付历史时迁移成功，申请/调整/历史账单快照保留；无关联调整、普通费用及空库路径正常。
- [ ] A3/R1：记录历史迁移修订策略、已应用环境行为和只读影响核查结果；不声称校验和重录会重跑 DML，不自动处置异常。
- [ ] A4/R2：单条、批量硬删除后的审计含完整费用名称与结算单位快照；原因/金额/币种/版本保留，事务原子性不变。
- [ ] A5/R3：原失败自动锁定用例实际 PASS，无 SKIP，并覆盖未建账阻断及删除后重评；记录实际执行的子用例。
- [ ] A6：相关测试与 diff 检查通过，最终风险匹配门禁通过；完整集成若有其它失败，逐项列明，不报告全绿。
