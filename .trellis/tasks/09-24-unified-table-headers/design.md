# 表头设置统一设计（评审草案）

## 视觉与交互结构

采用一套白底、细边框、高密度的设置弹窗；标准版建议宽 640px，增强版建议宽 960px，均受视口宽度约束。统一标题「列设置」，标题旁展示已显示／可配置列数；中部独立滚动；底部左侧恢复默认，右侧取消、保存。尺寸为设计建议，实施时由浏览器验收确认。

```text
列设置                         已显示 18 / 32
[搜索列名……]                   全部／已显示／已隐藏
[拖动] [✓] 业务单号   [必显]          ↑ ↓
[拖动] [✓] 客户名称                  ↑ ↓
[拖动] [ ] 备注                      ↑ ↓
────────────────────────────────────────
恢复默认                             取消  保存
```

标准版使用上述结构。增强版共用同一字段行组件，增加「列配置／高级设置」页签；高级设置承载现有分页、默认排序与行配色，避免把所有选项混在一个长弹窗。列计数由当前有效元数据计算，不硬编码 153。字段技术标识不作为默认展示内容。

显隐、排序和恢复默认均操作草稿；搜索中禁用拖拽和上下移并展示说明。恢复默认的范围为该弹窗管理的配置，并在按钮提示中说明；高级页保留单独的配色重置。固定列能力仅在已有业务支持时展示，不能凭空添加左右固定或把必显等同于禁止排序。

## 边界与复用

- 公共设置 UI 放入 `web/src/components/ui/`，从公共 index 导出；接收字段元数据、当前配置、默认配置及保存回调，维护弹窗草稿，不导入 pages/features 或特定 API。
- 财务 API 与业务字段适配由 `pages/finance/fees` 所属调用方承接；现有公共弹窗直接依赖 settlementService 的耦合在迁移时收敛。
- 订单费用继续使用其领域字段定义、权限与本地存储逻辑，适配公共 UI，避免另造一套显隐规则。
- 普通 ProTable 经受控列状态接入统一设置入口；实现前查询当前安装版本的正式 API，确认关闭原生入口和接管顺序／固定状态的能力，不依赖覆盖第三方弹层内部 DOM。
- 无持久化的内置设置保持原保存范围；UI 提示配置生效范围。财务保留现有服务端偏好，订单费用保留浏览器作用域，不为统一外观建设新的持久化平台。
- 配置变更继续使用原有 ProTable request/actionRef；不接管业务数据加载，不修改服务端契约或生成物。

## 风险与取舍

1. ProTable 默认启用的入口可能漏盘，需同时扫描封装模板、直接引用及透传 options 的调用方。
2. 现有财务「恢复系统默认」会立即请求服务端，统一方案改成草稿重置＋保存，需要明确回归取消语义。
3. 可见列、完整顺序、固定列及权限字段并非同一集合，适配层必须以稳定字段 key 映射，不能用当前渲染序号。
4. 财务宽表数量大，采用滚动列表与搜索；暂不引入虚拟列表依赖，实际测量出现瓶颈再评估。
5. 此文为提案；PRD 的无入口表格范围问题确认后补齐迁移清单，不启动实现。

## 迁移与回退

先公共组件，再订单费用／财务试点，最后所有已有入口；每组迁移运行相关验证并单独提交。无数据迁移，旧公共弹窗无调用后移除；不保留双套设置入口。必要回退按提交恢复 UI 与适配层。
