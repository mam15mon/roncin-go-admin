# 前端控件与排版一致性审查（订单与财务）

## 目标

让订单与财务页面“像一个人做的”：同一语义的控件形态、交互行为与排版口径一致，
业务人员换页面不需要重新学习。本任务分两段：先用 REA 真实浏览器逐页审查产出
差异清单交用户过目；用户圈定修复项后再改代码、补规范并复验。

## 背景与已确认事实

- 用户确认第一轮范围为订单与财务；客商、主数据、系统管理、工作台留第二轮。
- 已有任务 `archive/2026-11/11-16-order-pages-usability` 处理的是四类订单的功能布局
  （运输/货物/单证就近办理），本任务只管控件形态与排版一致性，不改其功能归属。
- 退役集运/跨境检查时已发现（REA，liming，1440×1000），作为清单初始条目：
  - F1 二选一单证模式形态不一：海运「提单模式」为按钮组，空运「航空单证模式」为
    单选圆点；同一海运表单「托运类型」又是单选圆点。
  - F2 海运出口列表「船公司」列过窄，表头与内容截断（仅露 “MS”“EV”）。
  - F3 海运出口列表顶部按钮行与表格之间仅一排设置图标，留大块空白。
  - F4 费用明细筛选控件过窄，占位提示截断为「输入订单…」「全部财…」「输入名…」。
  - F5 订单「业务与客户」卡片第二行稀疏（海运新建 3/6 列，空运新建 1/6 列）。
- 现有规范 `.trellis/spec/web/frontend/component-guidelines.md` 未约定
  “按钮组 vs 单选圆点”等同语义控件选型；代码中 `optionType/Segmented` 约 18 处、
  `Radio.Group` 约 22 处并存。

## 范围

订单（`web/config/routes.ts`）：

- 四类列表 `/orders/{sea-export,sea-import,air-export,air-import}`
- 四类新建 `/orders/:kind/new` 与详情 `/orders/:kind/:id`（含主分单页签、常用弹窗/抽屉）
- 费用录入 `/orders/:kind/:id/fees`、海运出口拆票、HBL 制作（SE/SI）、
  AWB 制作（AE/AI 主单与分单）、航空共享主单工作台

财务（`/finance/*`）：费用明细与费用详情、账单、开票、收付、核销、对冲、提成、
利润分析图、利润报表、实际收付款报表、账龄表、汇率、费用设置。

## 需求

- R1 审查维度：
  - 同语义控件选型（单选/二选一/多选/日期与日期区间/金额与币种/备注/联想下拉/开关）
  - 必填标记、校验提示位置与文案
  - 禁用与只读展示（详情只读值用标签/文本还是禁用控件）
  - 截断、省略与 tooltip
  - 栅格行列排布、空位与对齐
  - 页头/吸底/卡片右上操作按钮的位置、顺序与主次
  - 列表工具栏、筛选区、列宽、操作列
  - 空态与加载态、时间/金额格式（对照 AGENTS.md 时间与金额规范）
- R2 产出差异清单：按“维度 → 页面”组织，每条含截图、代码定位、建议统一口径、
  优先级（P1 影响理解或操作 / P2 明显不一致 / P3 细节）。
- R3 清单交用户过目，用户圈定修复批次后才改代码；本任务内修复用户批准的批次，
  未批准项记入清单作为后续任务候选。
- R4 新确定的统一口径写入 `.trellis/spec/web/frontend/`（以 component-guidelines.md 为主）。
- R5 修复后用 REA 复验对应页面并按风险运行定向测试、`pnpm --dir web tsc` 与
  `pnpm run check:web`。

## 验收标准

- AC1（R1/R2）：范围内每个页面都有截图并被逐维度检查，清单每条有截图与代码定位。
- AC2（R3）：用户已明确批准修复批次；未批准项保留在清单中。
- AC3（R5）：批准的修复项在 REA 截图中消除，相邻页面无新布局回归；检查命令通过或
  记录无法运行的原因。
- AC4（R4）：新统一口径已写入前端规范。

## 不在范围

- 客商、主数据、系统管理、工作台、登录页（第二轮）。
- 后端契约、业务规则、权限与字段归属变更。
- 视觉风格重设计（配色、品牌、布局骨架沿用现有规范）。
