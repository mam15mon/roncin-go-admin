# 实施计划

## 阶段 A：审查（不改代码）

1. 确认开发服务与种子数据就绪（8001 可访问，`sync:dev` 数据存在），确定财务可用账号。
2. 编写 REA 场景：订单四类列表 / 新建 / 详情（各页签与常用抽屉）、费用录入、拆票、
   HBL、AWB、航空共享主单；财务 15 页。1440 与 1280 两档视口。
3. 逐页逐维度对照判定基准，结合源码定位，写 `research/audit-findings.md`
   （维度 → 页面，含截图名、文件:行、建议口径、优先级）。
4. 汇总给用户：P1/P2/P3 条目数、需要用户裁决的口径选项、关键截图。
   **停在此处，等待用户圈定修复批次。**

## 阶段 B：修复（仅用户批准项）

5. 按批次修改，优先公共组件/模板；同步更新受影响的定向测试。
6. 每批完成：定向 vitest、修改文件 Biome、`git diff --check`，按类型影响跑
   `pnpm --dir web tsc`；REA 复验对应页面与受影响相邻页面；提交一次 Conventional Commit。
7. 统一口径写入 `.trellis/spec/web/frontend/component-guidelines.md`（及相关规范）。

## 收尾

8. `pnpm run check:web`（公共模板改动属跨领域风险，必要时 `check:fast`）。
9. 清单中未批准项标注为后续候选；归档任务、记录日志。

## 回滚点

- 每批修复独立提交，可按批 revert；公共模板改动单独成批。
