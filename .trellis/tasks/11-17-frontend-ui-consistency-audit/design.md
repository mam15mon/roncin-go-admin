# 设计：审查方法与修复边界

## 审查方法

- 工具：REA `rea-local-browser capture-browser-scenario --format json`，
  `browser.mode=launch` + `/usr/bin/google-chrome-stable`，前端 `http://127.0.0.1:8001`；
  不连接 19322 上用户的海管家浏览器。
- 账号：`pnpm run sync:dev` 种子用户（liming 覆盖订单；财务页若权限不足换种子财务账号）；
  密码经 `secrets` 环境变量注入，不写入场景文件与清单。
- 视口：主检查 1440×1000；列表与筛选区另取 1280×800 检查截断与换行；
  详情长页用滚动后分段截图。
- 数据：使用种子订单（海运出口 SE2609xxxx、共享 MAWB `78112345675` 等）进入详情、
  费用录入、单证制作；页面无种子数据的状态（如空态）记为“未覆盖”。
- 证据存放：截图在会话 scratchpad，清单文件 `research/audit-findings.md` 记录
  截图名、页面、代码定位；关键截图随清单发给用户，不提交 PNG 进仓库。

## 判定基准（优先级从高到低）

1. AGENTS.md 与 `.trellis/spec/web/frontend/` 已有明文规则（时间、金额、模板组件、
   ProTable 范式、占位与禁用色等）——违反即为差异。
2. 同语义在多数页面已采用的形态——少数派为差异，建议向多数口径收敛。
3. 无明文且无多数时，列出候选口径由用户在清单评审时决定，并在 R4 写入规范。

## 修复边界

- 优先改公共组件/模板（`@/components/ui`、订单模板、`MasterDataTemplate`、
  列表模板）一处生效，避免逐页打补丁；公共组件改动需检查全部使用方。
- 不改字段 name、表单载荷、接口契约与权限判断；只调整展示形态、布局与文案。
- 列宽与截断优先用列定义的 `width/ellipsis` 与模板既有列偏好能力，不新增布局系统。

## 风险

- 公共模板改动会波及第二轮范围的页面：修复时一并 REA 截图抽查受影响页面。
- 控件形态变化影响既有测试的 role 查询（如 radio ↔ button）：同步更新定向测试。
