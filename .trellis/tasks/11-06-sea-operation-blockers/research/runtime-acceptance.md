# 运行时验收与边界

## 环境

本次使用独立工作树与专用 PostgreSQL 测试库，通过正式迁移建立 Schema。隔离服务监听 8010，真实 API 前端监听 8013；合成 API 路由回归使用 8011。原开发业务订单和数据库未重置或自动回填。会话 Cookie、连接串和请求凭据仅保留在仓库外临时文件，不进入 Git。

## 已确认根因

- R1：拆票守恒读取实际货物明细；委托量和实际箱不能替代它。新增缺失提示、权限入口和显式刷新基线，保留既有分配输入。
- R2：复合布局中的母单输入没有直接绑定 Form.Item；日期未使用 RFC3339；旧预览与新输入/会话未可靠隔离。另通过真实候选改配发现 Execute 只切活动 Link，不同步订单船公司和航程投影，使接口出现新船公司 ID 与旧名称；已在原事务同步目标投影并验证目标空字段清除。Axios 错误须解析后端业务报文。
- R3：普通创建/保存 HBL 缺不可变当前快照，预览曾放行但执行要求 currentVersionId；新 DRAFT_SAVE 来源补齐生命周期，预览也验证当前基线。

## 真实 API 浏览器已验证

- 正式创建 HOUSE 并保存，执行 HOUSE→DIRECT，确认模式变为 DIRECT 且原 HBL 有作废历史。
- 拆票缺实际货物→打开现有货物抽屉录入→显式刷新上下文→分配 6/4 件、60/40 kg、3/2 m³→执行成功→返回详情；原票保留 6 件/60 kg/3 m³。
- NEW 改配在真实浏览器执行成功，订单/HBL 版本推进且运输执行切换；候选改配及同票连续链路最终结果另见改配验收报告。
- 真实接口路径未捕获原先「页面暂时无法打开」错误页；存在既有 useForm、showCount、受控输入切换控制台警告，未据此推断错误页根因。

## 合成 API、真实路由回归

`web/tests/e2e/sea-operation-stability.e2e.ts` 保留真实路由、完整订单表单和 SeaDocumentSection，只在 API 边界合成响应。

1560×1000 桌面视口下三项全部通过（约 1.3 分钟）：

1. 三次拆票进入/返回、浏览器前进后退、迟到订单或单证响应，详情完整且无写入。
2. 连续保存、分批重读与再次进入详情，已保存字段不丢失且下一次写入使用新版本。
3. 保存成功后单证读取 503，恢复时仅重读，不重复保存。

pageerror、严重 React 渲染错误、未声明 API 请求均为 0。默认 1280×720 的菜单点击曾受头像浮层/菜单重排影响而超时；未出现原错误页，不将该点击问题当成原缺陷已定位。持久用例显式固定本次已验收桌面视口。

R4 的结论限于「补充稳定性回归并通过」，不能声称原偶发错误页已修复；再现时仍需现场错误栈与触发顺序。
