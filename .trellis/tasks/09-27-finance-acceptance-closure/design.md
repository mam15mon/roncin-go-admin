# 总体处理设计

## 边界

采用两个独立子任务：历史测试治理和真实链路验收。前者恢复底层回归保护，后者验证运行时交互。父任务只负责跨任务证据汇总，不用任何一类测试代替另一类。

## 数据与环境

真实 PostgreSQL 集成验证使用明确指定的专用测试目标，先检查测试建库/建 schema 和清理行为。HTTP 与浏览器复用现有一次性验收编排，使用正式 SQL 迁移、隔离角色和唯一测试数据。现有编排是否适配当前组织、费用和提成契约必须在执行中核验，不能把历史成功视为当前成功。

## 证据设计

两子任务各自生成 research/verification.md；父任务最终创建 research/closure-report.md，列出子任务提交、运行覆盖、失败签名变化和限制。脚本成功、浏览器成功、人工验收分别记录。目录编号和关联 ID 串联同一业务，允许只读 API 复核持久化，但关键页面操作必须真实执行。

## 变更与风险

优先修夹具、断言与脚本漂移；若证明是产品或迁移错误，按真实契约修复并补相邻验证。不得修改约束来迁就夹具，不得把实际输出当成期望值直接粘贴。新增缺陷若改变业务范围，先更新子任务规划。
