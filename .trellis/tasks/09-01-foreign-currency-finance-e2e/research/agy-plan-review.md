# Agy 独立规划审查结论

## 采用的发现

- 非 CNY 本位币是触发提成 `DERIVED` CNY 倒数派生的必要条件，CNY 本位币下的外币
  业务链不能替代该证据。
- 汇率 `effectiveFrom/effectiveTo` 必须使用带时区、精确到秒且无纳秒的 RFC 3339；
  本任务固定使用 Asia/Shanghai 当日零点。
- 汇率 `toCurrency` 必须等于当前组织本位币；EUR→USD 与 CNY→USD 配置只能在 USD
  环境创建。
- 一次性环境需要统一编排迁移、bootstrap、健康检查、验收和 `finally` 清理，并在
  结束后验证数据库、角色与子进程零残留。
- 所有关联费用必须进入允许提成计算的状态，不能遗留草稿费用造成假失败。

## 未采用的建议及原因

- Agy 建议在同一数据库创建 USD 子组织，并直接写数据库预置角色。由于新组织确实不会
  自动获得默认角色，这种纯 API 切换会 403；但本任务采用两个隔离数据库，临时库 B
  可在无业务数据时直接通过 Admin API 修改 bootstrap 总公司本位币，不需要数据库
  夹具或跨组织切换。
- Agy 建议把 CNY 外币链、USD 提成链、支付、调整和反核销全部合成一个大型脚本。
  本任务只补“系统汇率到 CNY 快照”的最小连续证据；`MarkPaid`、调整支付和反核销
  保留为独立后续任务，避免掩盖外币口径失败原因。
- Agy 建议只做 CNY 本位币 USD 业务，再另做 USD 本位币 USD 业务。当前设计改用一个
  USD 本位币、EUR 业务币的外币链，同时覆盖五类系统汇率、汇兑损益和 DERIVED CNY
  快照，证据更连续且少一套重复业务夹具。

## 实施提醒

- 实施阶段继续使用 `gemini-3.7-flash-high`，但 Agy 不得执行任何 Git 操作。
- 编排器不能用自动回退或宽泛删除兜底；清理目标必须由固定前缀和当前连接信息共同
  确认。
