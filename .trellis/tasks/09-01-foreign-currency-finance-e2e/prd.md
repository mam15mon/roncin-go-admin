# 补齐外币财务全链路验收

## Goal

在与开发库完全隔离的一次性 PostgreSQL 环境中，先固化当前 CNY 财务验收基线，再
补齐一条使用系统汇率的真实外币应收连续 API 链路，证明汇率配置、订单费用、账单、
开票、资金流水、核销及提成 CNY 快照之间的币种、金额、汇率来源和业务 ID 能够连续
传递。

## Requirements

### 1. 固化现有 CNY 基线

- 使用全新一次性 PostgreSQL 数据库执行迁移、初始化管理员、启动真实 Go 服务与
  Web 测试服务，完整运行现有 `pnpm run acceptance:finance`。
- 验收数据必须由脚本显式创建，不能依赖开发库中已有客户、订单或财务记录；现有
  应收脚本在 `--apply` 模式下创建本轮专用客户。
- 在现有 CNY 提成链路中补充 CNY 快照断言：汇率为 `1.00000000`、来源为
  `BASE_CURRENCY`，提成本位币金额与 CNY 金额一致。
- PostgreSQL 集成测试必须显式注入一次性数据库连接执行；报告必须区分真实 PASS
  与未配置环境导致的 SKIP，且顶层用例必须 PASS > 0、FAIL == 0、SKIP == 0（任何顶层 SKIP 均视为失败）。
- 外币验收所有日历日期（today）必须显式基于 Asia/Shanghai 时区生成，避免 00:00–08:00 跨日偏差。
- 一次性编排器必须对所有被追踪子命令（包括后台长驻服务与 runCommand 子命令）在 Unix 下分配独立进程组并在退出/中断时完整终止；支持 SIGINT/SIGTERM/SIGHUP 信号安全清理，通过单一串行清理所有权消除与阶段 finally 的竞态，并通过 `--self-test-lifecycle` 提供可验证的生命周期与信号中断清理自测。

### 2. 补齐真实外币应收链路

- 使用第二个全新一次性 PostgreSQL 数据库。初始化后、创建任何业务数据前，通过
  真实管理 API 把当前组织本位币设为 USD；不得在已有财务数据的组织上变更本位币。
- 通过真实汇率 API 设置时间标准，并创建六条数值刻意不同的系统汇率：
  `BASE_CURRENCY/BILL/INVOICE/SETTLEMENT/WRITE_OFF` 的 EUR→USD 汇率，以及
  `WRITE_OFF` 的 CNY→USD 汇率。
- 从同一张订单的 EUR 应收费用开始，依次创建并确认 EUR 账单、登记并开具发票、
  创建并确认 EUR 收款、执行 EUR 核销、预览并创建 10% 提成。各阶段必须使用同一组
  订单、费用、账单、资金流水和核销 ID，不得用彼此无关的夹具拼接结果。
- 费用、账单、开票、收款和核销请求不得提交手工汇率或汇率覆盖值；响应必须逐层
  断言对应的系统汇率、`SYSTEM` 来源、汇率日期和汇率配置 ID。
- 核销必须断言账单本币分摊、资金流水本币分摊、核销本币金额及应收汇兑损益。
- 提成预览与创建结果必须断言 USD 本位币提成、`DERIVED` CNY 汇率来源、CNY→USD
  配置 ID、倒数八位精度及 CNY 提成金额；创建后通过详情接口重读持久化快照。

### 3. 隔离与结果证据

- 两套验收数据库与角色都使用本任务专用且可校验的名称；任何创建、清理或连接失败
  都必须让验收失败，禁止回退到 `.env.local`、开发库或默认连接。
- 验收过程不得输出数据库密码、Cookie、令牌或完整敏感响应。
- 记录提交哈希、运行配置摘要、命令、PASS/SKIP 数量和关键业务编号；结束后停止本轮
  启动的进程，并确认两个数据库及其角色已删除。
- 若验收暴露生产业务缺陷，停止当前测试任务并单独规划修复；不得为了让脚本通过而
  静默改变生产财务口径或增加兜底。

## Acceptance Criteria

- [x] 一次性 CNY 数据库中，显式注入 PostgreSQL 连接后的服务端集成测试真实执行，
  零 SKIP、零 FAIL 且至少一条顶层 PASS。
- [x] 一次性 CNY 数据库中，迁移、管理员初始化、后端、Web 及
  `pnpm run acceptance:finance` 全部通过，且不依赖预存客户或业务数据。
- [x] 现有 CNY 提成链路断言 `BASE_CURRENCY/1.00000000` 快照及本位币/CNY金额一致。
- [x] 一次性 USD 数据库中，通过 API 完成 EUR→USD 五类系统汇率与 CNY→USD
  WRITE_OFF 汇率配置，业务日期与 effectiveFrom 严格基于 Asia/Shanghai。
- [x] 同一外币业务链的费用、账单、发票、资金流水和核销都返回预期汇率、来源、日期、
  配置 ID、本币金额及连续业务 ID。
- [x] 外币核销精确断言账单本币分摊 `48.00000000`、资金流水本币分摊
  `50.00000000`、核销本币金额 `52.00000000` 和应收汇兑收益 `2.00000000`。
- [x] 提成预览与创建精确断言已实现收入 `44.00000000` USD（基于账单明细保留的费用原始本位币快照 110 USD × 40%）、USD 提成 `4.40000000`、CNY 派生汇率
  `7.14285714`、CNY 提成 `31.42857142`、来源 `DERIVED` 及 CNY→USD 配置 ID；
  明确区分账单头核销分摊 `48.00000000` 与费用快照提成已实现收入 `44.00000000`；详情重读结果一致。
- [x] 一次性编排器通过 `--self-test-lifecycle` 完成 only-role 正常清理 (1A)、only-role 故障注入 (1B)、父建子接管 SIGTERM 信号中断 (2)、父流程异常故障注入 (3)、就绪超时故障注入 (4)、进程组直接清理故障注入 (5)、runCommand 进程组安全防护双故障注入 (6A/6B) 及 stage 阶段双错误保留故障注入 (7) 共八项自测，所有自测均有直接证据并验证退出后无子进程/数据库/角色残留，活跃追踪进程集合归零。
- [x] `git diff --check`、相关 Node 语法检查、`go -C server test ./...`、
  `go -C server vet ./...` 与既有前端类型检查通过。
- [x] 独立 `trellis-check` 无 P0/P1，验收报告已记录真实执行结果，且两套临时数据库、
  角色和本轮进程均已清理。

## Out of Scope

- 提成 `MarkPaid` 状态流转；该缺口继续作为独立后续任务处理。
- 应付方向的外币连续链路、低权限/跨组织负向验收和 CI 自动创建 PostgreSQL 服务。
- 修改生产汇率、财务或提成计算口径；本任务原则上只修改验收脚本、命令和任务证据。
- 为验收脚本新增自动回退、旧数据兼容或使用开发数据库的便利分支。
