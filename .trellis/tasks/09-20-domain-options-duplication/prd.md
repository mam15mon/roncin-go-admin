# 候选能力领域化与重复逻辑发现

## 目标
承接 AI 友好架构的延期项：候选能力按业务归属提供公开入口，保持缓存正确性；建立覆盖前后端手写业务源码的可重复运行的疑似重复报告，为后续人工审查提供依据。

## 已确认背景
旧任务已归档。options 聚合了多个领域的请求、信用控制与通用类型；订单缓存被订单页面、组织切换和退出登录共同使用。现有架构检查器已限制通用层反向引用领域。取证与风险见 research/findings.md。

## 需求
- R1：订单候选缓存、往来单位搜索、船公司搜索、币种候选与信用干预按所属领域提供公开入口，所有调用方、mock 和类型同步更新；删除旧聚合文件，无兼容转导出。
- R2：保持现有请求参数、首批分页、标签、信用控制和缓存刷新语义；保持组织及业务类型隔离、在途复用、按组织/全量清理。修复币种旧失败清除新缓存引用的竞态。
- R3：通用候选类型只保留通用字段，业务字段在领域类型或局部真实需要处定义；不引入通用缓存框架，不迁移到新状态管理方案。
- R4：提供一条 pnpm 命令扫描前端 TS/TSX/JS/JSX 与后端 Go 手写源码，输出函数级相同/规范化结构的疑似重复组及文件位置、符号、依据、覆盖统计。默认排除测试、生成物、依赖与构建产物；手写 Ent schema 仍可参与。不同语言分别比较，不声称证明业务等价。
- R5：重复报告可读且可供程序消费，顺序稳定；疑似重复不阻断 CI，不自动重构；解析失败/扫描失败必须非零退出并明确报告。检测器测试接入既有检查链。
- R6：实际运行一次扫描，对高优先候选抽样审阅并记录复用建议或合理重复理由；更新能力导航与扫描说明。

## 验收标准
- AC1（R1/R3）：产品与测试无旧 options/cache 导入；架构检查零违规；领域入口可发现；通用候选类型无信用或散客字段。
- AC2（R2）：四类订单缓存的复用/隔离/失败/清理验证通过；币种强刷后旧失败不清掉新缓存，失败重试和启停刷新正常；组织切换/退出、订单创建/详情、财务调用回归通过。
- AC3（R4/R5）：TS 与 Go 均有可识别的相同函数、局部改名函数样例；存在关键字面量/操作符/外部调用差异的样例不会被标成完全一致；短函数阈值、生成物/测试排除、解析失败、稳定 JSON/文本输出均可验证。
- AC4（R6）：实仓报告记录扫描文件和函数数量、排除规则、限制与至少前十组候选的审查（不足十组则全审）。报告不等于自动合并清单。
- AC5：针对性测试、diff 检查、check:architecture 和完整 check:web 通过；Go 扫描辅助工具单测通过，无后端业务/接口/数据修改。

## 范围外
不自动合并全仓重复实现；不做跨语言业务等价证明、任意代码片段或全部配置文件检测；不外提所有页面逻辑；不更改业务权限、API、数据库或前端交互。缓存重写为 React Query、全局缓存注册平台不在本期。

## 状态
用户已批准创建任务与规划。设计与执行计划形成后展示最终摘要，待后续明确批准才进入实施。
