# 加入其他组织支持多选

## 目标

单个已开通用户一次加入多个组织，角色选填。承接父任务 R4/R7。

## 事实

admin.proto:281 接收一个 organization_id；admin_role.go:397 允许空角色；不同公司角色 ID 不共用。现有单项创建锁定用户并校验范围/角色、写入成员/绑定/审计；待分配人员仍必须走开通流程。

## 需求

- 所属组织支持多选，候选遵守管理范围，角色可空。
- 每个组织分别校验角色归属与授权，不把跨公司角色直接复制给所有组织。
- 已加入、停用关系、无效组织有明确处理；重复操作不覆盖已有正常授权。
- 成功后刷新列表，后续逐条编辑；不引入主要组织开关。
- 设计明确批量接口，避免前端循环单项接口产生不可解释的部分成功。

## 待确认

1. 多选后按组织逐项选填角色，或先加入后逐条分配；建议前者保留一次完成能力，后者界面更简单。
2. 单人多组织失败建议全成全败；原任务多人开通部分成功不决定此处行为。

## 验收

- [ ] 同公司多个部门、跨两个公司及角色全空均可加入。
- [ ] 各组织角色正确绑定，越权组织/跨公司角色被拒绝。
- [ ] 失败结果符合确认后的原子性，不展示虚假全部成功。
- [ ] 重复点击、并发加入、提交前组织停用有针对性验证。
- [ ] 单项编辑、停用/移除和会话撤销正确。

## 范围与依赖

不扩展多人×多组织矩阵，不改待分配批量开通语义。待主要组织契约稳定后实施，事务范围在设计审阅时明确。
