# 加入其他组织支持多选

## 目标

单个已开通用户一次加入多个组织，角色选填。承接父任务 R4/R7。

## 事实

admin.proto:281 接收一个 organization_id；admin_role.go:397 允许空角色；不同公司角色 ID 不共用。现有单项创建锁定用户并校验范围/角色、写入成员/绑定/审计；待分配人员仍必须走开通流程。

## 需求

- 所属组织支持多选，候选遵守管理范围，角色可空。
- **D6（2026-10-13 已确认）：多选后每个组织单独一行选填角色，最后一次保存。** 用户明确回复“可以”；全部留空或仅部分组织选择角色均可提交，不强制先加入再逐条编辑。
- **D7（2026-10-13 已确认）：全部成功才保存。** 任一项校验或写入失败，本批新增成员和角色绑定全部撤销，已有授权不变；提示具体失败项，保留所选组织与角色供调整后重试。
- 每个组织分别校验角色归属与授权，不把跨公司角色直接复制给所有组织。
- 已加入、停用关系、无效组织有明确处理；重复操作不覆盖已有正常授权。
- 成功后刷新列表，后续逐条编辑；不引入主要组织开关。
- 设计明确批量接口，避免前端循环单项接口产生不可解释的部分成功。

## 验收

- [ ] 同公司多个部门、跨两个公司及角色全空均可加入。
- [ ] 多选后各组织有独立角色行；部分选角色、部分留空一次保存成功，不串用其他组织的选项和已选角色（D6）。
- [ ] 各组织角色正确绑定，越权组织/跨公司角色被拒绝。
- [ ] 任一项失败时整批成员与角色绑定不落库，已有授权不变；提示原因且表单不关闭、不丢失已选组织与角色（D7）。
- [ ] 三个组织中一个提交时已停用，以及部分写入后出错，两类场景均验证整批回滚；调整失败项后可重新提交成功。
- [ ] 重复点击、并发加入、提交前组织停用有针对性验证。
- [ ] 单项编辑、停用/移除和会话撤销正确。

## 范围与依赖

不扩展多人×多组织矩阵，不改待分配批量开通语义。待主要组织契约稳定后实施；D7 已确定事务业务范围为单人本批全部成员关系和角色绑定，具体锁序、审计及仓储实现见已审阅的 design.md。用户已于 2026-10-13 回复“开始”，批准整体实施。
