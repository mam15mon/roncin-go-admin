# 共享主单批次自动关联与分单强制排重

## 背景

- 业务已确认一票一分口径（2026-09，见 `sea-export-document-contract.md`）：所有分单
  独立建订单、独立建账单；「一主多分」由多张操作票共享同一 `SeaMasterBill` 承载。
- 现状差距：
  1. 新建订单命中同船公司+同主单号的已有 MBL 时，服务端返回
     `SEA_MASTER_BILL_CONFIRMATION_REQUIRED`（409），要求业务员人工确认候选后才
     关联——业务要求命中即自动关联，无感入批；
  2. 新建时 HBL 可空、可选直单（DIRECT）——业务要求一旦命中已有批次（该 MBL 已是
     一主多分状态），本票强制分单模式（HOUSE）且 HBL 分单号必填；
  3. 分单号唯一性目前靠数据库唯一索引「组织 + 签发主体 + 规范化分单号」全局排重，
     同签发主体重号已被物理阻止；缺口是**同一主单批次内、不同签发主体**（如一票
     本公司签、一票客户签）出现同号时不拦截，且无即时提示。

## 需求

- R1 主单自动关联：新建页录入「船公司 + 主单号」后（失焦/防抖）自动调用候选查询；
  命中则前端把候选 ID + 版本作为确认参数自动带入保存请求（契约已有该确认参数，
  预期零契约变更），并展示「已自动关联共享主单批次（当前 N 票）」提示；服务端
  事务内复验逻辑照旧兜底，候选状态并发变化仍返回 409。
- R0（UX 基线，2026-09-16 确认）：单证模式默认 DIRECT。现状模式选择器必填无默认
  （不选报「请选择 HOUSE 或 DIRECT」），改为默认勾选 DIRECT——HBL 分单内容区块
  默认不渲染，选择器保留、手动切 HOUSE 照旧；提交显式 DIRECT 合法，
  `UNDETERMINED` 不再由新建表单产生（仅剩历史数据与 API 路径）。
- R2 强制 HOUSE + HBL 必填：命中已有批次（该 MBL 下存在其他活动成员票）时——
  - 前端：单证模式锁 HOUSE（DIRECT 选项置灰并说明原因），HBL 分单号必填校验阻断；
  - 服务端：创建与普通整单更新路径同规则校验——确认关联到已有其他活动成员票的
    MBL 时，单证结构必须为 HOUSE 且分单号非空，违反返回明确业务错误。
- R3 同批次分单排重：
  - 即时提示：录入分单号失焦时与该 MBL 下兄弟票的活动分单号比对，重复立即提示；
  - 保存阻断：服务端在创建/模式切换事务内对该 MBL 下所有活动成员票的 HBL 规范化
    分单号跨签发主体排重，重复返回明确业务错误（提示冲突的分单号）。

## 非目标

- 不改共享 MBL 既有模型（候选查询、事务内复验、加锁顺序、共享航程字段锁定）；
- 不改一票一分契约与账单口径（分单独立建订单、独立建账单维持现状）；
- 未命中已有主单的新建流程维持现状（直单/分单可选、HBL 可空）。

## 开放问题（规划期确认）

- Q1 直单成员并存：若批次中已有 DIRECT 成员票（第一票直单挂主单），第二票自动
  关联强制 HOUSE 后，主单下「直单成员 + 分单成员」并存是否允许？还是 DIRECT
  成员也要求补出分单？（问业务）
- Q2 作废分单号复用：排重范围是否仅限活动 HBL？已作废（VOIDED）分单的号是否
  允许同批次复用？（初步倾向：仅活动 HBL 排重，需业务确认）
- Q3 兄弟票分单号查询的契约形态：扩展 `sea-master-bill-candidate` 响应携带批次内
  活动分单号列表，还是新增轻量接口？（涉及 proto 变更与前端客户端再生成）
- Q4 批次成员后续退出：命中批次建票后，该票 HOUSE→DIRECT 模式切换是否允许？
  （若允许，批次可能回到仅剩一张票的状态；需与 R2 的强制语义自洽）

## 验收标准

- A1 未命中场景回归：新建不命中候选时，现有流程（直单/分单可选、HBL 可空）行为
  与改造前一致，现有集成测试与前端测试保持通过。
- A2 自动关联：命中候选的新建请求携带确认参数直接成功，订单挂到既有 MBL 批次；
  候选在保存前被并发占用/变更时仍 409，前端提示刷新重试。
- A3 强制校验：命中批次时创建为 DIRECT、或 HOUSE 但分单号为空 → 服务端业务错误；
  前端同场景无法提交（模式锁死 + 必填校验）。
- A4 批次排重：同 MBL 批次内跨签发主体重复分单号 → 服务端阻断并提示冲突分单号；
  前端失焦即时提示；同签发主体重复仍由既有唯一索引兜底（409 `SEA_HOUSE_BILL_EXISTS`）。
- A5 服务端定向集成测试 + 前端定向 vitest 通过；若涉 proto 变更，生成物同提交。

## 约束

- 服务端校验为底线，前端锁死仅为体验层；两者规则必须同源同口径。
- 共享 MBL 的加锁顺序、唯一索引、并发复验契约不变
  （`.trellis/spec/server/backend/sea-export-document-contract.md`）。
- 若 Q3 选扩展候选响应，契约变更按仓库流程：proto → 生成 → 前端客户端同提交。
