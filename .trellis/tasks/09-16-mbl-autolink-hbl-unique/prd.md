# 共享主单批次自动关联与分单批次排重

## 背景

- 业务已确认一票一分口径（2026-09，见 `sea-export-document-contract.md`）：所有分单
  独立建订单、独立建账单；「一主多分」由多张操作票共享同一 `SeaMasterBill` 承载。
- 业务补充确认两条规则（2026-09-16）：
  1. **共享主单全员分单制，直单禁止被自动加拼**——共享批次内所有成员必须是
     HOUSE；直单订单独占其主单，auto-link 不得把新票加进含直单成员的批次；
  2. **作废分单号绝对禁止复用，一号一案**——批次内排重覆盖含作废在内的全部分单。
- 现状差距：
  1. 命中同船公司+同主单号的已有 MBL 时，服务端返回
     `SEA_MASTER_BILL_CONFIRMATION_REQUIRED`（409）要求人工确认——业务要求命中
     即自动关联，无感入批；
  2. 新建模式选择器必填无默认（不选报「请选择 HOUSE 或 DIRECT」），HBL 可空——
     全员分单制下应为默认 HOUSE、分单号必填；
  3. 分单号唯一性现状是「组织 + 签发主体 + 规范化分单号」**全局**唯一索引：
     同签发主体跨 shipment 重号被禁——但外部主体（`CUSTOMER_PARTNER` 等）的号是
     外部编的，跨 shipment 合法复用会被误挡；同时同批次内**跨签发主体**重号不拦。

## 需求

- R0（UX 基线，2026-09-16 修订）：单证模式默认 HOUSE、HBL 分单号必填。全员分单制
  下拼柜是常态且分单号为货代自编（录单时即已确定），默认直单会系统性产出独占
  主单的直单票、阻断后续拼批。直单降级为少数场景的显式选择（整柜直出），选择直单
  即独占该主单；`UNDETERMINED` 不再由新建表单产生（仅剩历史数据与 API 路径）。
- R1 主单自动关联：新建页录入「船公司 + 主单号」后（失焦/防抖）自动调用候选查询；
  命中则前端把候选 ID + 版本作为确认参数自动带入保存请求（契约已有该确认参数，
  预期零契约变更），并展示「已自动关联共享主单批次（当前 N 票）」提示；服务端
  事务内复验逻辑照旧兜底，候选状态并发变化仍返回 409。
- R2 直单禁拼与强制校验：
  - 命中全 HOUSE 批次：本票强制 HOUSE、分单号必填（前端锁模式 + 服务端创建与
    普通整单更新路径同规则校验）；
  - 命中含直单成员的批次：auto-link 阻断，返回明确业务错误提示「该主单已被直单
    订单占用，如需拼单请先将其转为分单」；
  - 批次成员在还有其他活动成员时，不得经模式切换转 DIRECT（否则全员分单制被绕过）；
    批次仅剩自己时允许转直单。
- R3 批次内分单排重（2026-09-16 口径确认）：
  - **范围 = 同一主单批次内**（跨签发主体、含作废分单，一号一案）；**跨批次允许
    重号**——外部主体分单号合法复用不再被全局索引误挡；
  - 落地：撤销现有两个部分唯一索引（组织+自有签发主体+号、组织+外部签发主体+号），
    新增 `(master_bill_id, normalized_house_no)` 唯一索引（不过滤状态，作废行天然
    覆盖）；迁移前 fail-fast 检查存量同批次跨主体重号，存在即报错终止交人工确认；
  - 即时提示：录入分单号失焦时与该批次内兄弟票分单号比对（含作废），重复立即提示；
  - 保存阻断：服务端在创建/模式切换事务内预查给出含冲突分单号的友好报错，唯一
    索引作最终兜底。

## 非目标

- 不改共享 MBL 既有模型（候选查询、事务内复验、加锁顺序、共享航程字段锁定）；
- 不改一票一分契约与账单口径（分单独立建订单、独立建账单维持现状）。

## 验收标准

- A1 默认与回归：新建默认 HOUSE、分单号必填；显式选直单照常可建（独占主单）；
  现有集成测试与前端测试按新口径更新后全部通过。
- A2 自动关联：命中候选的新建请求携带确认参数直接成功，订单挂到既有批次；候选
  被并发占用/变更时仍 409，前端提示刷新重试。
- A3 直单禁拼：命中含直单成员的批次 → 创建被阻断并提示占用订单；批次还有其他
  活动成员时该成员模式切换转 DIRECT 被阻断；仅剩自己时允许。
- A4 批次排重：同批次跨签发主体重号（含与作废分单重号）→ 服务端阻断并提示冲突
  分单号，前端失焦即时提示；**跨批次同号保存成功**（全局唯一索引已撤销）；
  迁移对存量违规 fail-fast。
- A5 服务端定向集成测试 + 前端定向 vitest 通过；Q3 涉 proto 变更时生成物同提交；
  `sea-export-document-contract.md` 的唯一索引与单证结构描述同步更新。

## 约束

- 服务端校验为底线，前端锁死仅为体验层；两者规则必须同源同口径。
- 共享 MBL 的加锁顺序、事务内复验契约不变
  （`.trellis/spec/server/backend/sea-export-document-contract.md`）。
- 唯一索引变更为正式 Ent Schema 迁移，生成、审阅、随代码提交；Q3 涉契约变更按
  仓库流程：proto → 生成 → 前端客户端同提交。
