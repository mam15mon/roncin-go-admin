# 技术方案

## 行为差异与归属

现状是 Query 主流程与手工查询/模块缓存并存。目标是在原页面或所属 feature 接入当前工作区客户端，让 Query 管理远端数据生命周期；草稿仍归表单，列表 request/onLoad 仍归框架。文件锚点统一见 research/source-audit.md。

本任务直接拥有公共能力和消费方的契约同步，按单个集成任务分批验证提交，不保留中间兼容分支。

## 查询身份

- 沿用工厂的 retry/focus/reconnect 策略，业务消费 useQueryClient，不导入公开单例。
- 各领域就近定义前缀，键为 `[域, 资源, 参数对象]`，包含实际依赖的组织、业务类型、实体、父级、关键词、分页与必要会话身份。
- 弹窗/链式依赖用 enabled；分页按语义用 keepPreviousData，换实体/会话不得桥接旧内容。
- 防抖只更新进入 key 的参数。回填 Effect 可保留，但不直接请求；仅初始化或用户确认刷新采纳，不随背景成功自动回填。
- 加载更多使用 useInfiniteQuery 或明确分页 Query；删除手工远端请求序号。写入会话、编辑修订及幂等保护继续保留。

## 公共候选与缓存

RemoteSearchSelect 留在通用层，不导入业务 feature；请求回调用 ref 持有，资源键与父依赖显式表达。若需扩展公开参数，同组更新 SearchFilterTemplate 类型和全部调用方，不增加匿名全局缓存或旧协议回退。

PartnerQuickAddSelect 以关键词 Query 取远端候选，渲染侧合并新建和已选项，保留创建的组织/会话保护。

订单 options 保留薄的纯取数/映射入口，删除模块 Map 和 clear 协议；同步登录、退出、组织切换、新建及重试调用方。货币删除模块 Promise 和 forceRefresh 参数，启停后失效真实消费前缀。跨页面去重只放在当前 QueryClient，原生 ProForm request 可调用纯函数。外层已用 Query 的聚合不得再命中第二层结果缓存。

## 编辑、汇率与命令

详情以选中 ID 驱动 Query，关闭/换记录/刷新不再靠 token。账单信用/余额、币种和账户分别按真实依赖查询，后台候选刷新不改人工选择。

BillEditModal 复用 useBillChangeNotice，探测与编辑快照分离。保存期间 ownWritePending，成功关闭保持到关闭，失败恢复；确认刷新且完整读取成功才更新表单及提交基线。

两种汇率入口按订单/方向/币种及会话或行身份查询。金额纯计算、手工值和系统参考值分离，保留当前同文件增加的「改回系统汇率」。

自动随完整输入变化的只读预览用 Query；显式按钮、产生 previewToken 或属于命令步骤的预检用 mutation；按需只读带入可用当前客户端 fetchQuery。保留载荷/指纹绑定、修订检查及未知结果同键重试，不自动后台执行命令。

## 响应和提示

先验证信封存在、成功状态及列表类型再解包，合法成功空 repeated 仍为空列表。必填校验留在领域映射入口，不全局盲补 data。修改 ensureListResponse 前检查所有调用方，选最薄方案。

错误沿用 meta 静默或中文文案；就地错误同时 skipErrorHandler + silent。交 Query 管理的取消应进入 Query 生命周期，避免请求层误报取消。写响应守卫仍是成功副作用前提。

## 范围、并行与回滚

主体为清单 31 个查询文件、2 个缓存、7 个命令补充入口，必要调用方、测试、公开类型和规范同组同步。认证初始化、后端和生成客户端不在范围。

费用表格、费用页、补录和汇率 Hook 正在并行修改。写前重新读差异，不恢复已删除的 FeeFormModal；主会话整合重叠文件和暂存差异。无法安全分离时保留源改动并报告，不覆盖、不重置。

按验证后的提交回滚，只回退本任务变化。若实际需要后端新契约、全站公共变动 Hook 或扩展产品行为，先更新方案再复核。
