# 全站服务端状态迁移与请求生命周期收敛

## 目标

将已盘点的服务端状态统一交给 React Query v5 和框架原生请求协议管理，消除手工查询、独立缓存与失败响应处理差异，保持业务交互、人工输入和提交基线正确。

## 背景与范围依据

- 用户要求全站盘点后明确提出「一起帮我改了吧」，并同意创建任务继续规划。
- 初始证据涉及 31 个查询消费文件、2 个模块缓存、7 个命令式预览/带入补充入口；逐文件锚点见 [research/source-audit.md](./research/source-audit.md)。静态盘点不等同于行为回归。
- 已有工作区独立 QueryClient、官方列表采纳快照与多数变动检查，应直接复用。
- 当前存在其他会话的费用与服务端改动，初始清单见 [research/worktree-baseline.md](./research/worktree-baseline.md)，实施和提交前重新核对。

## 需求

### R1：公共候选与缓存生命周期

覆盖 RemoteSearchSelect、PartnerQuickAddSelect、订单列表资源与订单/货币缓存。关键词和实际依赖共同决定查询身份，旧关键词、旧实体与旧工作区结果不覆盖当前候选；已选与快捷创建的名称保活。缓存失效后能读取新数据，认证业务不再并存模块级 Map/Promise 结果缓存。缺身份/权限或未开放运输类型保持零经营请求。

### R2：全部业务查询迁移

完成清单内订单、财务、客商、企业资源、管理及主数据迁移，同步调用方与测试。覆盖详情、候选、策略、历史、分页、加载更多及轮询。官方 ProTable/ProForm 请求继续按框架协议运行，全量主数据与本地分页保持原语义。后台重查不卸载已有表单、不覆盖人工输入、不推进旧稿版本；失败不能冒充合法空结果。

### R3：费用汇率与命令预览

表单与行内汇率按订单、方向、币种等依赖查询，保留手工覆盖、改回系统汇率及数量金额预览。补充清单的提成、共享航程、海运抬头带入、空运影响、牌价抓取和导入预检采用适合其语义的 Query/mutation 生命周期。显式命令不因背景重查自动执行；过期预览不可提交，结果未知时保留原提交意图。

### R4：账单基本信息编辑变动检查

覆盖 BillEditModal：已有账单编辑在前台每 15 秒及回焦检查，隐藏/关闭/身份未就绪时停止。外部变化持续提示「这个账单已经发生变动，请重新刷新。」，保留输入与提交基线。未保存刷新须确认；取消/失败保留，成功才接受完整新快照。本人保存的写入在途和采纳响应后两个窗口均不误报；提交仍做服务端 expectedVersion 校验。

### R5：失败响应和错误展示

修复清单及 useMasterDataCrud 中 undefined 进入 unwrapList/unwrapPage 的路径。区分成功且省略空 repeated、失败响应、非法类型和业务必填缺失，遵循 ProtoJSON 零值存在性。静默、固定/动态错误及就地重试保持明确且无重复通知。写入仅真实成功才清输入、关闭、导航或刷新，后台读失败不推翻已落库结果。

### R6：验证与交付

实现后补针对性回归，完成类型、架构与完整前端门禁；同步状态管理、Hook 约定和能力导航的旧缓存描述。每组验证通过后以中文 Conventional Commit 提交，仅包含本任务差异，保留原有改动及暂存状态。

## 验收条件

- [ ] AC1（R1、R2）：原始清单逐项记录处置结果，无未说明的手工查询竞态链、刷新 token 或模块结果缓存。
- [ ] AC2（R1、R2）：关键词乱序、父依赖/实体变化、关闭重开、工作区 A→B→A、身份缺失均不串数据，已选名称保留。
- [ ] AC3（R2、R3）：历史分页、写后失效正确；背景重查/失败不覆盖表单、费用行或提交基线。
- [ ] AC4（R3）：手工汇率/改回系统汇率/换币种/缺 ETD 或 ETA，以及预览失败、过期、关闭重开与幂等重试符合原契约。
- [ ] AC5（R4）：账单停留/回焦检查、隐藏停止、真实变化、本人保存两个窗口、输入保留和刷新取消/成功/失败均有验证。
- [ ] AC6（R5）：覆盖 undefined、success:false、合法空 repeated、非法类型和缺必填字段，无 data TypeError 或重复提示。
- [ ] AC7（R6）：定向测试、git diff --check、TypeScript、架构与 check:web 通过；未执行的真实环境验收如实记录。
- [ ] AC8（R6）：文档与实现/验证一致，用户其他工作及暂存状态保留，完成分组提交。

## 不在范围

不调整后端契约、数据库、权限模型和登录身份初始化；不重写官方表格协议，不引入通用变动检查平台、实时通知、KeepAlive、自动保存、历史兼容或新依赖。写入身份代际、dirty revision、保存版本、幂等键等必要保护不按名称批量删除。

## 规划状态

需求和技术边界已收敛，设计、执行计划与代理上下文随任务提供。实施等待用户对最终规划摘要的后续明确批准。
