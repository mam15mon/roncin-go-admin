# 财务四类报表：最小交付设计

状态：方案待主会话向用户呈现；本文件不授权实施。源码证据见 [report-source-map.md](research/report-source-map.md)，需求见 [prd.md](prd.md)。

## 1. 边界与已确认口径

首版提供利润分析图、利润报表、实际收付款报表、当前账龄表四个独立入口。利润图与利润表使用一个服务端过滤/聚合内核；图、表、合计、导出共用业务事实和筛选。只读派生查询，不新增报表表、数据回填或定时任务。

主会话已传达用户选择：利润按出口 ETD／进口 ETA，含未建账当前有效费用，含税/不含税并列；实际收付款按流水日期剔除撤销；账龄按到期日分五档，首版仅当前余额，历史截止余额延期。

本期不把提成已实现利润或汇兑损益并入经营费用利润，不从收付款倒推经营收入。用户若以后要求现金制利润，须另定收入/成本分配规则，不通过改本报表名称混入。

## 2. 指标与金额精度

### 2.1 利润共同来源

经营费用集合复用 `currentOrderFeePredicate` / `biz.IsCurrentFee`：正常 INCREASE 且未被后续更正替代。未建账、已建账、已开票、未收付等状态不改变是否纳入。补审待处理载荷尚未成为正式费用，不计；批准后的有效替换叶子计入。反向 DECREASE 清偿行及已替代历史叶子不重复计入。

每费用：

- 含税原币 = `fee.total_amount`；未税原币 = `fee.net_amount`。
- 含税本币 = 已保存 `fee.base_currency_amount`。
- 未税本币 = `fee.BaseCurrencyNetAmount()`，即含税本币 × 原币未税 ÷ 原币含税，逐行银行家舍入到 8 位；零分母按领域函数返回 0。
- 含税利润 = 含税应收 − 含税应付；未税利润 = 未税应收 − 未税应付。方向用费用原 `direction`，不是反向清偿方向。

聚合先逐费用应用领域公式，再求和。数据库侧实现等价半偶舍入表达式并与领域函数表格测试对照，不用 PostgreSQL 默认 `ROUND` 冒充 `RoundBank`。不得整批先四舍五入到 2 位再合计。

原币统计按币种分组、本币统计按本币分组，禁止跨币种相加。单订单如出现多个本币，不猜测 CNY，表按「订单＋本币」行展示；筛选结果订单数按 distinct order_id 统计，金额行数另计。金额响应一律 decimal 字符串 8 位，UI 两位，CSV 两位无千分位，比例保留有效精度。

样例：某订单费用应收 10,600、未税 10,000，应付 6,360、未税 6,000，均为 CNY，则两类利润分别 4,240 和 4,000；建账/开票/部分核销不会改变这组经营指标。若费用更正为应付 5,300、未税 5,000，当前利润为 5,300/5,000，旧 6,360 与反向清偿行不再另加。

### 2.2 实际收付款

固定来源 `finance_cashflows.status=CONFIRMED`，按 `transaction_date` 查询，包含尚未核销的真实预收预付。收款、付款各自求和，净额 = 收款 − 付款；原币与本币分别分组，折本币用流水 `base_amount` 快照，不实时取汇率。

DRAFT 不代表实际发生；CANCELLED 排除。反核销恢复流水可用余额但实际收付金额不减少；再次核销也不增加。对冲没有现金，不计入实际收付。样例：已确认收款 1,000，已核销 600 后反核销，报表始终收款 1,000；只有流水本身取消后不再计入。

### 2.3 账龄

固定来源有效正常账单，零余额不列；余额 = 账单总额 − 有效核销分配 − 有效对冲分配。沿账单读取谓词的 active 及父单状态事实，不按发票号/免票状态推断清偿，不计草稿对冲；账单取消后排除。

当前业务日由服务端 `ExchangeRateBusinessLocation()` 产生，一次读取固定 `as_of_date`。不接收调用方任意历史日期。

| 条件 | 分段 |
| --- | --- |
| due_date >= as_of_date | 未到期（包含到期当天） |
| 日差 1–30 | 1–30 天 |
| 日差 31–60 | 31–60 天 |
| 日差 61–90 | 61–90 天 |
| 日差 >= 91 | 90 天以上 |
| due_date 未设置 | 独立“未设置到期日”异常余额/数量，不能静默归未到期或回退其他日期 |

每张账单余额完整落入且只落入一个桶；应收/应付分别展示。折本币余额 = 原币当前余额 × 账单 exchange_rate，8 位半偶舍入，与账单信用汇总等价。保留带符号，不擅自 max(0)；现有创建约束仍只允许正额，本任务不放开负数账单入口。

## 3. 日期、维度与缺失数据

利润按 `trade_direction` 选 ETD/ETA，转换业务时区自然日；SQL 复用 `writeOrderTransportTimeExpression` 的 AE 权威主单日期，不用可能陈旧的订单空运投影。未知方向/无效非空日期属于契约错误，显式失败；未设置日期可作为未归期行展示，不回退创建时间。未设日期在未筛日期时进入“未设置业务日期”图表桶，指定日期范围时不属于该区间并返回同其他筛选下的缺日期数量提醒。

初版维度：

- 利润：业务日期区间、业务类型、订单客户、销售/操作/客服岗位人员、订单关键词；列表每订单＋本币一行，图表固定按月展示全部匹配数据。岗位筛选用 `order_personnel` 现行岗位，与订单列表同口径，不把提成归属当当前操作岗位。无人员值时不限制该岗位；人员 EXISTS 子查询不能 join 成倍放大费用。
- 收付款：流水日期区间、方向、结算单位、币种、支付方式、本方账户、流水/银行参考号关键词。一流水一行，不伪造多账单分摊后的订单或人员利润。
- 账龄：方向、结算单位、币种、分段、账单关键词。一账单一行，返回账单总额、有效清偿额、余额及到期日。多订单账单不按关联订单重复整张余额。

日期区间双端均含所选自然日，实际查询为业务时区起日含、末日次日不含。UI 初次明确显示当前自然月的日期条件（利润与流水），可清除或修改；后端不隐藏追加默认日期。账龄只显示本次当前日期。

## 4. API、权限与分层

新增 `system.finance.report.read`（Manifest 名称建议“查看财务报表”），组织范围与当前公司经营工作区一致；建议不依赖费用维护、账单维护、流水维护权限。前端新 `canReadFinanceReports` 纳入财务目录可见条件，四路由共用。候选、列表、导出同一权限，拥有报表权限不自动获其他实体详情/修改权，跳转详情仍按既有权限展示。

建议在既有 `settlement.proto` 添加三个只读列表及三个同筛选导出 RPC：

| RPC | 最小职责 |
| --- | --- |
| `ListProfitReport` | 分页订单行、完整匹配合计、按月序列、订单数/费用数/缺日期数，同一读取快照 |
| `ListCashflowReport` | 分页已确认流水、完整筛选收款/付款/净额，按原币/本币分组 |
| `ListAgingReport` | 当前分页账单余额、五段及未设日期合计、`as_of_date` |
| `ExportProfitReport` / `ExportCashflowReport` / `ExportAgingReport` | 规范化相同筛选，不接受 page，返回扁平导出 DTO 或约定的 CSV；本期沿已有提成路径返回 DTO，由前端 CSV 序列化 |

列表 `page >= 1`，pageSize 默认 20，最大 200；复用公共分页校验。导出服务端在同一读快照先计数，单次最大 10,000 行，超限显式提示缩小筛选；这是导出接口自身契约，不是循环列表绕过 200 上限。筛选类型/查询构造与列表共用，导出使用同一聚合事实。导出失败不生成部分文件。

公司 ID 来自认证当前公司并由服务端强制校验请求/权限范围，组织未就绪/系统管理工作区不请求。RPC 中保留 organization_id 时必须与当前公司相同，不接受前端换公司参数替代工作区。

候选若旧接口要求其他模块权限，新增两个报表只读薄 RPC（结算单位、人员）并复用 data 既有 keyword/拼音检索与公司人员范围，不要求给报表读用户加订单/客商维护权限。分页最大 200；候选用于展示选择，列表最终范围仍在服务端校验。

分层落点：

- biz `finance_report.go`/`finance_report_types.go`：筛选/分页/日期/导出上限、纯金额与分桶规则、仓储接口。
- data `finance_report_profit.go`、`finance_report_cashflow.go`、`finance_report_aging.go`：Ent/参数化 SQL 聚合、权威日期、同源过滤及读取快照；不在 service 查库。
- service `settlement_report.go`：鉴权组织、DTO 与领域转换；注入接入既有 provider/wire，不让页面拼 host。

## 5. 聚合性能与一致性

每次列表在 `withReadSnapshot` 里执行分页前基查询、完整计数/汇总/图表、分页行读取；所有查询复用同一规范化 predicate/CTE。订单人员用 EXISTS；核销与对冲各先按 bill_id 聚合再关联，禁止两明细表直接 join 相乘。利润先按 fee/order 聚合再 join 展示，不将全量 Ent 业务树加载到 Go。

不新增缓存、物化视图或预聚合表。只有 EXPLAIN 和实际测试显示已有 company/status/date/关联索引不足时，才同步 Ent Schema 添加必要索引与正式迁移；不提前拍脑袋建宽索引。图表序列按完整月份返回（含零月份），不能从当前表页绘制。

列表、汇总、图在一次响应中是同一快照。用户稍后发起导出时使用同筛选的新一致快照，返回 `generated_at/as_of_date`；不宣称与几分钟前页面数值逐字相同，不为快照固定建设持久报表任务。

## 6. 前端布局与数据流

四条路由建议 `/finance/reports/profit-analysis`、`/finance/reports/profit`、`/finance/reports/cashflows`、`/finance/reports/aging`，标题和重定向只来自 routes.ts。页面统一 PageContainer 全宽，分节 SectionCard，筛选设置沿 useFilterSettings 的用户＋公司＋页面本地偏好。

利润图和利润表可同属 `pages/finance/reports` 目录，公共查询/映射就近复用，避免为单模块创建跨域平台。表格走 ProTable request；合计和月序列经官方 onLoad 已采纳快照同步更新。利润分析页同样用一次已采纳报表结果呈现图和可读表，迟到/失败请求不能推进图表/顶部合计。

局部 SVG 分组柱图展示月度含税/未税利润，负利润横跨零轴；币种切换显式选择本币桶，不能把多币种序列相加。附金额/月份可读数据表、键盘可达提示；无数据、未设日期、查询失败分开。当前 package.json 无图表库，首版不新增依赖、不建通用图形框架。

导出读取已提交并采纳的筛选，不读仍未提交的 Form 值；复用 csvAmount/serializeCsv、CSV BOM/CRLF/公式防护。金额显示和时间显示沿公共工具，版本及原始 UTC 不展示给业务人员。

## 7. 验收与延期

正式 PostgreSQL 验证当前费用/更正链、不同税率和汇率、未建账、订单多人、AE 权威日期跨时区、多笔核销/对冲、撤销、未核销流水及账龄边界。一次读取中并发提交财务动作时，行/合计/图不跨快照；下一次请求反映新事实。

明确延期：历史截止账龄、已实现利润/现金制利润、汇兑损益纳入经营利润、跨公司合并、自定义透视、异步导出/订阅、持久报表快照。现有批准口径足以推进本期最薄闭环；没有必须在实施前再问用户的技术选型。辅助缺日期桶、固定月图及候选权限边界随本方案统一审阅即可。
