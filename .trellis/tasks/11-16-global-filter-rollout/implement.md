# 全站筛选设置接入与覆盖验收实施计划

## 启动条件

统一筛选布局子任务完成并交付签名后实施，依赖前两个子任务的账号保存链路。

须先取得对最新父任务完整方案的审阅批准，再 task.py start 本子任务。

## 步骤

1. 实施前据最新代码复核F01–F33，形成每个实际身份实例的覆盖矩阵，并登记研究后新增区域。
2. 分批接入：订单与共享箱→主数据→管理/客商/资源→财务次级面板及工作台；不同域可派不重叠所有者，公共组件只交原子任务所有者调整。
3. 每批实现后补触发与相邻路径验证，运行定向vitest、Biome、按类型影响tsc及diff check，通过后提交。
4. 浏览器检查代表机制和所有特殊条件清理场景，逐区域记录源码/定向测试/浏览器各自深度。
5. 回交父任务完整矩阵和问题清单，父任务统一跨浏览器链路、独立review及check:fast，不把未测试标记通过。

## 完成门

验收结果与未验证限制写入本子任务 research/，所有权和生成物清晰，独立 trellis-check 无阻塞后交付父任务。父最终门禁见[集成计划](../11-16-global-filter-settings/implement.md)。
