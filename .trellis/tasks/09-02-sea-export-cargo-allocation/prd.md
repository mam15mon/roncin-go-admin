# 海运出口箱货分配

## Goal

让操作员在一张海运出口操作票内，把真实货物数量分配到一张或多张 HBL，并在有
实际箱号时进一步分配到集装箱；系统阻止超分和错误归属，同时不要求用户在订舱
早期伪造尚未掌握的装箱数据。

## Background

- 阶段 2 已建立 `UNDETERMINED / DIRECT / HOUSE`、共享 MBL、真实多 HBL 及每张
  HBL 的独立提单显示件重尺。
- 当前 `OrderCargoItem` 保存货物行的件数、毛重、体积和可选净重；三项主数量均
  为正数。
- 当前 `OrderContainerRequest` 只表示订舱阶段的箱型箱量计划，不是实际箱，也
  不能作为装货分配目标。
- 当前 `OrderContainer` 表示已知箱号的实际箱，只保存毛重、体积，没有件数；其
  旧 `shipping_document_id` 指向非海运新模型，阶段 3 必须消除 SE 对该旧关系的
  依赖。
- 已确认一个操作票可以有多张 HBL、一只实际箱可以承载多张 HBL、一张 HBL 也可
  覆盖多只实际箱；不能为了维持伪造的 1:1 关系强迫用户拆操作票。

## Requirements

- 依赖 `09-02-sea-export-document-content` 已完成、检查并提交。
- 分配必须以操作票真实 `OrderCargoItem` 为数量来源，以当前活动 MBL 下的真实
  `SeaHouseBill` 为单证归属；可选关联同一操作票的实际 `OrderContainer`。
- 一条分配至少保存件数、毛重、体积；同一货物行可以拆到多个 HBL/实际箱，支持
  一箱多 HBL 和一张 HBL 多箱。
- `OrderContainerRequest` 只用于计划箱型箱量，禁止作为实际分配目标。
- 任一分配引用的订单、货物行、HBL、实际箱必须属于同一组织、同一操作票和当前
  活动 MBL；旧 HBL、旧 MBL 或其他订单的数据必须被拒绝。
- 数量必须为有限正值；件数为整数。任何保存都禁止单个货物行或实际箱被超分。
- 分配聚合采用 `DRAFT / CONFIRMED`：
  - `DRAFT` 允许只分配一部分，便于 HBL、货物和箱号按实际作业顺序逐步补齐；
  - `CONFIRMED` 要求每条订单货物在件数、毛重、体积三个维度完整分配到当前
    HBL，且每张当前 HBL 至少取得一条真实分配；
  - FCL 确认时实际箱必须齐全，每条分配必须落到实际箱，并按每只箱的件数、毛重、
    体积完整守恒；LCL/散杂不创建操作票级虚假箱，确认只做货物到 HBL 守恒；
  - 确认后禁止普通修改货物、实际箱、HBL 集合和分配；调整前必须显式撤回确认。
- 确认和撤回必须携带分配聚合预期版本并写业务审计；阶段 5 的单证确认/签发事实
  建立后，撤回还需受其正交状态门禁约束，本阶段不伪造尚不存在的外部状态。
- HBL 提单内容中的件重尺是可编辑的单证显示快照，不作为分配真相，也不随分配
  静默改写；确认分配时由用户明确决定是否把汇总值写入对应 HBL 内容。
- DIRECT 不创建 HBL 分配；主单内容从操作票货物和运输事实明确生成，不制造虚拟分单。
- 分配增删改必须使用预期版本、固定锁序和同事务业务审计；审计或守恒校验失败时
  完整回滚。
- 本阶段不实施拆票、改配或财务费用重分摊。

## Acceptance Criteria

- [ ] 一箱可分配给至少两张 HBL，一张 HBL 可覆盖至少两个箱。
- [ ] 一个货物行可定量分配到多个 HBL/箱；跨组织、跨订单、旧 MBL 引用被拒绝。
- [ ] 负数、NaN/Inf、非整数件数和任一维度超分被拒绝，失败无部分写入。
- [ ] 订舱计划箱量与实际箱明确分开；没有实际箱号时不创建虚假箱记录。
- [ ] HBL 提单显示件重尺不会被普通分配保存静默覆盖。
- [ ] 草稿可部分分配但不可超分；HOUSE 确认时所有货物和 HBL 完整守恒。
- [ ] FCL 确认时所有分配落到真实箱并按箱守恒；LCL/散杂不生成虚假箱号。
- [ ] 确认后普通货物、实际箱、HBL 和分配修改被阻止；显式撤回后恢复编辑。
- [ ] 并发修改使用版本与固定锁顺序，失败完整回滚。
- [ ] DIRECT、HOUSE 和订单货物既有链路回归通过。

## Out of Scope

- 拆票、整体改配、甩柜、Switch B/L、费用重分摊和已签发单证版本切换。
- 根据订舱箱型数量自动生成虚拟箱号。
- 把 HBL 显示件重尺当作货物分配的唯一数据源。

## Open Question

### Q1：确认分配时如何处理 HBL 显示件重尺（待确认）

阶段 2 允许人工维护 HBL 的提单显示件重尺；阶段 3 分配会计算每张 HBL 的内部
汇总。需要确定确认动作是否同时把内部汇总写进 HBL 内容，还是只展示差异并由
用户另行明确填入。禁止在普通分配保存时静默覆盖。
