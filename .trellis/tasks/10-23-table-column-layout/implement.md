# 实施计划

## 阶段入口

- [x] 用户同意创建任务，明确布局自行判断，要求一次看到全部字段。
- [x] 检查公共入口、类型、冻结、偏好、Hook、Responsive 规范和费用专有调用。
- [x] PRD 按目标、事实、需求、验收及范围外收敛，无阻塞问题。
- [ ] 展示最终摘要并获得后续明确批准；批准前不执行 task.py start，不改产品代码。

## 实施顺序

1. 批准后激活任务，加载 Phase 2 和前端技能，派发 trellis-implement 子代理负责公共列设置与费用适配。主会话负责协调、规范、提交和收尾。
2. 更新逐字段冻结契约、唯一最终顺序和纯函数，同步公共/费用专有偏好的全部消费者，不添加首尾兼容分支。
3. 实现大面板、自适应 Grid、完整编号、插入提示、跨区与空区拖动、精确移位，保留搜索/显隐/默认/高级设置。
4. 实现后更新针对性测试，覆盖冻结/重排/偏好/生命周期/费用链路，不采用 TDD。
5. 独立派发 trellis-check 对照 PRD 和全调用链检查并修正确认缺陷，完成真实浏览器验收。
6. 同步 column-settings.md、必要导航及公共导出说明，清除旧首尾语义。
7. 完成门禁、diff 检查，提交功能组，按 finish-work 记录与归档。

## 验证

- 开发：修改文件 Biome；定向 `pnpm --dir web exec vitest run <相对 web 的测试文件>`。
- 定向覆盖 column-settings 的纯函数、偏好、Panel、Entry、Hook，Responsive 三类表格冻结，费用偏好/冻结/工具栏及相邻显隐排序路径。
- `pnpm --dir web tsc` 检查公共契约所有调用方。
- 浏览器在 1366×768、1440×900、1920×1080 检查费用 19 个普通字段和 40 字段集合的实际矩形、无内部滚动、跨行/跨区/空区拖动、精确移位和默认恢复；横向滚动验证双侧多列固定，390px 和窄→宽验证访问及冻结恢复。
- 最终 `pnpm run check:web`：全局公共状态契约和费用专有偏好属于前端高影响改动，需要完整前端门禁；后端未改动，不扩展后端门禁或无关构建。
- 提交前 `git diff --check`，核对无秘密、缓存、生成物手改和无关更改。

## 重点审查与回滚

公共类型、冻结、偏好、Hook、Entry/Panel 及费用专有适配属于一个原子功能组。不能通过关闭规则、重挂表格或吞掉错误绕过 scope、编辑、结构锚点或 Responsive 缺陷。
