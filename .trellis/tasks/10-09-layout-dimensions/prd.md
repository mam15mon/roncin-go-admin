# 统一全站布局尺寸配置与样式变量

## 目标
用户已批准使用一份 TypeScript 布局尺寸配置，供组件配置与 CSS 变量共同消费，并要求全站有同类联动关系的布局均采用该方式。以后调整侧栏、顶部栏、页签等尺寸时只修改一处，不产生错位。

## 范围
全站布局壳与公共页面模板中的共享尺寸及派生偏移，包括侧栏展开/折叠宽度、顶部栏高度、页签高度、吸顶页头偏移、内容区间距、公共页面区块外间距，以及公共表单导航宽度/正文避让、侧栏底部操作区/菜单预留、吸底栏几何参数和公共布局层级。

## 已确认消费端
- ProLayout 默认配置、AppLayout、global.less和main入口。
- PageHeaderShell与ParameterSettingTemplate吸顶84；FinanceLedgerTemplate视口高度减48。
- OrderFormTemplate与partner-detail的表单导航预留164，FormAnchorNav宽140。
- formErrorUtils与FormAnchorNav滚动默认偏移及测量后间隙；保持当前默认与调用方覆盖行为。

## 约束
- 当前尺寸与视觉行为保持一致；不同职责即使数值相同也不得绑成一个变量。
- 不改变业务数据、权限、接口、页面结构或交互，不做全站装饰性数值替换。已有theme.ts中的控件/表格/卡片主题参数继续由主题管理；现有媒体查询断点及页面专属图形高度保留。
- 使用最小配置与CSS变量桥接机制，不建设主题编辑器、用户偏好或通用尺寸平台。
- 契合组件依赖边界，通用层不依赖 pages/features；保留既有header修复。

## 验收标准
- 联动布局尺寸存在唯一真相源，ProLayout配置、全局样式和公共模板派生偏移一致。
- 调整侧栏/顶部栏/页签/内容边距配置，关联消费端随之变化；无需分别修改组件与CSS。
- 默认配置下桌面展开/折叠/滚动、移动端及767/768/769px边界的布局保持一致；吸顶页头接在页签下方。
- 检查全站同类硬编码并记录纳入与未纳入范围的理由。
- 相关验证、完整前端门禁与git diff --check通过，更新规范并提交归档。
