# 海运订单整页统一保存

## 目标与用户价值
用户填写海运订单资料、主单正文和本票分单后，只点击整页「保存」一次。无需理解主单、分单各自保存入口；失败时不丢输入，也不出现一部分成功、一部分失败。

## 背景与已确认事实
- 用户明确要求操作尽可能简单，并批准按上述范围创建任务、进入规划；实施须等待最终方案批准。
- 当前详情保存入口在 `web/src/pages/orders/detail.tsx:414`；海运更新适配器 `web/src/pages/orders/order-kinds/sea-export/form-adapter.ts:385` 没有将独立单证字段完整纳入整单保存。
- `server/internal/biz/sea_document.go:214` 与 `server/internal/data/order_write_sea_document.go:142` 明确禁止整单更新分单。现有订单更新在 `server/internal/data/order_write_draft.go:181` 使用统一事务，具备扩展基础。
- 独立分单更新同时递增 HBL 和 Link 版本（`server/internal/data/sea_document.go:221`）；不能仅接收 HBL 响应便认为保存基线已完整更新。

## 需求
### R1 单一保存入口
- 海运新建继续一次创建；详情将订单普通资料、主单正文、本票分单号码/签发方/正文纳入现有整页保存。
- 移除主单、分单页签内的独立保存按钮和引导用户到另一页签保存的文字。
- 保留底部吸底保存入口；已有顶部同一动作可复用同一提交链路，不新增第二种保存语义。

### R2 全部成功或全部失败
- 一次用户保存仅发起一个聚合写请求，所有业务写入与审计在同一事务内完成。
- 只提交发生变化的单证部分，未修改共享主单时不触发共享主单写入或无关版本校验。
- 继续校验订单、主单、活动关联、分单各自的身份与版本，不能替用户自动重试覆盖冲突。
- 保留同主单内分单号唯一、跨主单允许重号、同组织范围、锁定/终态以及共享主单成员门禁。

### R3 清晰的保存反馈与草稿保护
- 校验失败定位到实际字段，必要时切换页签/展开区块；保留全部输入。
- 保存过程中显示统一加载状态，防止重复提交；提交期间暂停表单编辑，避免成功回填覆盖在途新增输入。
- 保存成功后更新订单与单证完整基线，下一次保存无需手动刷新；分单保存后的 Link 版本必须同步。
- 写入失败或结果未知时保留输入和未保存标记。已确认写入成功但刷新失败时明确提示“已保存，最新数据读取失败”，提供重试读取，不能误报未保存或再次重复写入。
- 页面离开草稿、组织切换隔离、详情身份切换的迟到响应保护保持有效。

## 范围边界
- 本次是海运订单普通编辑表单统一保存；费用、账单、审核锁、放货、附件及其他独立业务工作流不并入本事务。
- HOUSE/DIRECT 模式切换、改单、作废、改配仍走现有专用业务动作与确认流程。
- 共享主单仍为多票共享实体，不复制为订单私有数据；不修改其他票分单。
- 不新增自动保存、历史兼容层、数据库清空或数据重建；不扩展为空运或其他品类统一保存重构。

## 验收标准
| 编号 | 对应需求 | 可观察结果 |
| --- | --- | --- |
| A1 | R1/R2 | 同时修改订单资料、MBL 正文与 HBL 后点击一次保存，重进页面三部分均为新值；没有独立主/分单保存入口。 |
| A2 | R2 | 分别构造订单/MBL/Link/HBL 冲突、分单重号、签发方无效，整组写入及审计无部分落库。 |
| A3 | R2 | 仅改订单资料或 HBL 时不触发未修改 MBL 的写入；DIRECT 不受隐藏 HBL 必填限制。 |
| A4 | R2 | 锁定、终态、跨组织和共享成员锁定继续阻断对应写入；不能经整单保存切模式或创建/替换另一票 HBL。 |
| A5 | R3 | 失败时所有输入保留，错误定位可见；连续两次保存使用最新订单、MBL、Link、HBL 版本。 |
| A6 | R3 | 重复点击/网络结果未知重试不重复递增版本；保存后刷新失败明确说明已保存，重试读取恢复可编辑状态。 |
| A7 | R1/R3 | 原新建、草稿恢复、切换订单/组织和常规详情字段编辑无回归。 |

## 风险与延后项
- 聚合保存涉及共享主单锁顺序和已有幂等语义，必须用真实 PostgreSQL 事务验证回滚；仅组件 Mock 测试不足。
- 不治理本任务之外的全量测试偶发失败；若门禁遇到无关失败，记录文件、结果和定向复跑证据。
