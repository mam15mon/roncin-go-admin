# 订单费用录入与财务账单流程优化

## 目标与阶段

减少订单费用逐行操作，明确汇率、税率及利润口径，打通费用台账、建账、账单费用维护与开票入口。
本次用户要求创建 Trellis 任务；当前为需求规划，尚未批准实施，不修改产品代码。

## 需求与验收标准

| 编号 | 需求 | 可观察验收标准 |
| --- | --- | --- |
| R1 | 费用录入取汇率：出口 CASE 按 ETD，进口 CASE 按 ETA | 应收、应付均按订单进出口方向采用对应日期查询汇率：出口 ETD、进口 ETA，再分别取应收汇率与应付汇率；覆盖不同日期汇率不同的场景，不能默认按录入当天取值。沿用缺日期显式报错、不默认回退的约束；日期变更处理待确认。 |
| R2 | 应收、应付始终打开编辑，各自标题右侧提供整表保存，取消逐行编辑与保存 | 在当前有权编辑且业务允许的费用上直接输入，分别保存应收表和应付表；校验失败及并发冲突保留输入，不得因常开编辑绕过锁定、已建账等限制。整表原子保存为建议，待确认。 |
| R3 | 税率可以按权限更改 | 财务权限分组新增准确名称「订单费用税率更改权限」；有权人员可修改允许编辑费用的税率，无权人员不能修改，服务端也拒绝越权请求；权限源与生成物同步更新。 |
| R4 | 应收、应付、毛利看板展示含税和不含税两种口径 | 两种口径均能查看且明确标注，金额与费用税额一致；布局采用同时展示还是切换待确认，避免不同币种未经折算相加。 |
| R5 | 重新规划费用录入表头列宽 | 应收、应付统一规划列宽，名称、金额、税率与操作可读可操作；窄屏允许合理横向滚动，容器遵循全宽规范。具体列宽在设计阶段形成可审阅方案。 |
| R6 | 排查费用明细台账主单号不显示 | 对有主单关联的订单显示正确主单号，无主单时明确为空；沿来源、服务端投影、DTO 映射与列渲染定位，覆盖相关海运/空运路径。尚未确定根因。 |
| R7 | 筛选区提供类似表头的设置，用户自主增加或删除筛选项 | 用户可在设置中选择显示的筛选字段；这里的增加/删除指筛选项展示配置，不删除业务数据。隐藏已生效筛选的处理、偏好保存范围及适用页面待确认。 |
| R8 | 费用批量转账单页面的结算账户支持快速添加 | 参考订单客户快速添加交互，在建账过程中创建结算账户并可选用；关联正确结算对象与当前公司，遵循已有账户创建权限。不得丢失建账配置。 |
| R9 | 账单无需人工确认；录入发票号时锁定费用明细 | 创建账单后直接进入对账流程，无需点击确认；尚未录入发票号、未发生付款核销且未发生对冲时，允许有权限人员增加、移除账单费用明细并重算金额；成功保存发票号、发生付款核销或对冲，任一条件满足后整张账单禁止增删费用，部分开票、部分核销或部分对冲也不能绕过。触发业务操作与锁定须原子完成，前后端统一拦截，并发中的费用调整不得越过锁定。移除是否仅解除关联仍待确认。 |
| R10 | 调整账单列表状态并在账单页面录入发票号 | 用户已确认采用「开票进度＋核销进度」分别展示，允许同时表达部分开票与部分核销，不强行合并为五个互斥状态；综合「已完成」判定仍待确认；账单内支持分次录入多张发票，每张记录发票号、日期、本次对应账单的金额，按累计金额计算开票进度，沿用发票权限与业务关联；第一张发票成功保存即锁定整张账单费用明细，仍允许补录后续发票。不能只改文案造成状态与真实业务不符。 |

## 已确认决策

- 2026-11-13：用户确认一张账单可分次登记多张发票，记录号码、日期、本次对应账单金额，累计计算开票进度；首次登记后禁止增删费用，但可以继续登记后续发票。

- 2026-11-13：用户确认应收、应付统一使用「出口按 ETD、进口按 ETA」的日期基准，分别取应收/应付方向汇率。

- 2026-11-13：用户确认，即使未录入发票号，发生付款核销或对冲也立即禁止增删账单费用明细。不能仅以发票号为空判断可编辑。

- 2026-11-13：用户明确取消人工「确认账单」步骤。实际流程为创建账单 → 对账人员核对 → 无问题后人工发邮件给财务付款 → 财务在账单中录入发票号 → 禁止增加和删除账单费用明细。邮件是既有线下协作背景，本任务不包含自动发送邮件。
- 费用明细锁定由发票号录入成功、付款核销或对冲任一条件触发；不采用上一轮建议的「仅草稿可改，已确认先回退」交互。发票号更正、撤销后的解锁规则仍需设计，不能直接假定清空号码就自动解锁。

- 2026-11-13：用户回复「跟着你的建议走先」，接受上一轮提出的开票进度与核销进度分别展示方案。本次确认针对该展示建议，其余待确认项尚未决策。

## 已核对事实与定位

- `server/internal/biz/finance_invoice.go:127`：现有创建发票输入接收账单 ID、开票资料与类型，没有本次指定开票金额字段；`:365` 起按账单总额或可开票余额形成关联金额。因此不能仅凭现有号码录入界面认定支持一账单多次指定金额的部分开票；此次已确认需支持指定金额分次登记，后续设计须同步完善发票关联与金额分配契约。

- `server/internal/biz/order_fee.go:455`：现有费用汇率预览统一按 ETD 所在自然周取值，应收取 `ar_rate`、应付取 `ap_rate`；不是已经按进出口方向区分 ETD/ETA。
- `server/internal/biz/order_fee.go:473`、`:523`：日期缺失显式报错，手工覆盖也先校验日期，并受汇率权限及收支币种集合条件约束；本次不默认放宽。
- `server/internal/biz/order_fee.go:339`：更新费用且未手工指定汇率、币种与收支方向未变时保留原汇率快照；用户尚未要求日期变化自动重算已保存费用。

- `server/internal/biz/finance_bill.go:255`：当前普通账单更新仅允许草稿，且检查 `ExpectedVersion`；事务内再次检查状态与版本。现有更新流程从原账单行取得费用 ID，不能据此认定已支持用户选增/移除费用。这是待改的现状，不是新流程的产品约束。
- `server/internal/biz/finance_invoice.go:342`、`server/internal/data/finance_verification.go:253`：现有开票与核销依赖账单 CONFIRMED 状态。取消人工确认需要统一调整建账、编辑、开票、核销及相关权限/生成契约，不能只隐藏确认按钮；内部状态实现待技术设计。
- `server/internal/data/finance_bill_write.go:390`：账单取消依赖检查会提示取消/红冲发票、反核销、取消/反转对冲；新流程不得隐式撤销这些事实。
- `web/src/features/finance/bill-status/index.ts:10`：当前账单状态元信息围绕 DRAFT、CONFIRMED、CANCELLED；用户提出的开票/核销进度不能未经设计直接替换状态机。
- `web/src/pages/finance/fees/components/feeLedgerColumns.tsx:109`：已有「主单号」列，绑定 `masterNo`，空值渲染 `-`；尚需追查数据来源，不能认定只是缺列。
- `web/src/features/finance/bill-creation/BillGroupCard.tsx:158`：建账分组已有结算账户选择入口。
- `web/src/pages/finance/bills/components/BillEditModal.tsx:225`：账单编辑也有结算账户字段，后续核对复用范围。
- `.trellis/spec/domain/glossary.md` 与 `architecture-map.md`：已建账（含草稿）的费用已被占用，账务回退受发票、核销、对冲依赖影响；新的账单增删费用流程须与这些约束一致。

## 范围与约束

- 覆盖订单费用录入、费用台账、费用批量建账、账单列表/详情/编辑及必要的服务端契约和权限。
- 不扩展为税务平台或通用筛选平台，不恢复业务标签，不擅自改变账单汇率日期规则。
- 不自动重算历史已保存费用或改写已发生开票、核销事实；是否需要重取汇率由明确需求决定。
- 保持当前公司工作区边界、服务端权限、事务原子性与并发版本校验；生成物通过生成器更新。
- 本次任务创建仅提交规划文档；产品实现后按风险补测试，禁止 TDD。

## 待确认的产品决策

1. 已确认开票、核销进度分别展示；「已完成」是否要求开票与核销两者都完成，以及对冲、无需开票等情况的完成口径仍待确认。
2. 已确认取消人工确认步骤，录入发票号后禁止增删费用。未录发票号但已发生付款核销或对冲也禁止增删，已确认。新增费用是否仅选择已有未建账费用，删除是否仅移除账单关联？发票更正或撤销后如何处理锁定？
3. 已确认应收、应付都适用出口 ETD／进口 ETA。日期改变后已有费用是否主动重取汇率？现有缺日期报错、手工汇率权限约束继续保留，未提出放宽需求。
4. 应收/应付各自整表保存是否要求全部成功或全部失败？含税/不含税看板采用并列还是切换？
5. 自定义筛选应用于费用台账还是同时覆盖账单等页面？隐藏生效条件是否清除，用户偏好是否跨设备保存？

## 开票与锁定的重点验收场景

- 以同币种、需全额开票的正常账单 10,000.00 为例：首次登记 3,000.00 后显示部分开票，费用明细立即禁止增删；补录另一张 7,000.00 后累计为 10,000.00，显示已开票。
- 首张发票保存失败不视为录入成功，不得留下孤立的发票关联或锁定结果；保存成功后其他用户持有旧页面发起增删，服务端仍拒绝。
- 未录发票但已有部分付款核销或对冲时，同样禁止增删费用。开票与核销两项进度各自真实显示，互不覆盖。
- 费用明细已锁定不阻止授权人员补录后续发票；两人并发登记时按服务端最新金额与版本校验，避免重复累计或丢失登记。
