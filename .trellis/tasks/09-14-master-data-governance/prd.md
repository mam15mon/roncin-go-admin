# 货代系统主数据多组织治理与存储重构方案 (PRD)

## 1. 背景与目标

当前系统在主数据多组织治理中存在技术债务：依赖 `organization_id` 挂载"总部组织"来模拟全局数据，导致治理语义全部依赖运行时的 `resolveHeadquartersOrganizationID` 递归解析（逐行查库向上爬组织树，每次列表查询都执行），且 `(organization_id, code)` 唯一索引无法真正保证全球通用码的唯一性。

**本次重构核心目标：**
将"业务治理边界"完全物化为"数据库存储结构（可空性与唯一索引）"。让数据归属、唯一性、查询范围、维护权限、API 契约与前端交互这六层逻辑，全部由底层的"存储三型（A/B/C 型）"直接推导，彻底废除隐式规则与运行时组织树遍历。

## 2. 核心架构：存储三型定义

任何一个实体，其治理模式直接对应其存储结构。彻底剥离"数据属于总部"的误导性认知，明确界定为"数据治理层级"。

| 存储类型 | 治理语义 | `organization_id` | 读取/可见性 | 写入权限拦截 |
|---|---|---|---|---|
| **A 型（全局型）** | 客观事实/全球标准，只有一份真相，无组织归属 | **不存在该字段** | 所有人同等可见，业务码全局唯一 `UNIQUE(code)` | `RequireGlobalMasterDataWrite(ctx)` |
| **B 型（基线+本地）** | 集团统一定义 + 本地真实差异化补充 | **可空** | NULL=集团基线（全网可见）；OrgID=本组织行（仅本组织可见） | NULL 行：`RequireBaselineWrite(ctx)`；Org 行：本组织权限 |
| **C 型（组织私有）** | 纯粹的组织内部业务资产 | **必填** | 本组织隔离（或遵循既有共享机制） | 本组织权限 |

## 3. 实体归型与改造明细

### R1. A 型改造（彻底剥离组织维度）

**目标实体**：Currency（已是 A 型，保持）、AdministrativeRegion（已是 A 型，保持）、Country、Region、ContainerType、ServiceType（服务类型/费用大类）、AbnormalCase（以上为 master_data_items 整表去组织维度）、**Airline、ShippingLine 及集装箱前缀（强制收口，取消本地让位，转为纯 A 型，彻底关闭分公司创建入口）**、BillingUnit（计费单位，客观通用单位）。

**改造动作**：

- 数据库彻底删除 `organization_id` 列，业务码（SCAC、IATA、ISO、民政码）建立全局唯一索引。
- 仓储层**绝对禁止**传入 `organization_id` 作为过滤条件，禁止依赖组织树函数。
- **双轨收敛盘点**：`master_data_items` 的 currency kind 与全局 `Currency` 表双轨、region kind 与全局 `AdministrativeRegion` 表疑似双轨——改造前先盘点各 kind 的实际消费方，冗余 kind 收敛到全局表，消费方一次性切换。
- TaxableService（货物或应税劳务名称）不进 A 型：**归 C 型**，随组织税务主体（开票口径），放开归属组织自维护（待确认 §8.1）。
- EnterpriseResource（企业资源库：常用收发通抬头、地址簿、业务标签、品名、唛头）：**归 C 型**，物理结构保持 `organization_id NOT NULL` 不可变外键，维持现状零改造，纯组织私有隔离。

### R2. B 型改造（按部分唯一索引约束）

**目标实体**：Port、Airport、FeeSetting（费用科目）。

**改造动作**：

- **唯一索引重构（Partial Unique Index）**：
  - 基线约束：`UNIQUE(code) WHERE organization_id IS NULL`
  - 本地约束：`UNIQUE(organization_id, code) WHERE organization_id IS NOT NULL`
  - 各表的业务键按实际字段展开（费用 `fee_code`、港口 `un_locode`），design.md 逐表给出 DDL。
- **航司/船司强制收口**：归入 R1 A 型执行（见上）。
- **费用科目（FeeSetting）**：
  - 总部建立 NULL 行公共科目；分公司可建 org 行本地明细科目，但**必须挂载** A 型 `ServiceType`（费用大类，合并报表底座）。
  - 允许分公司建立与总部同 Code 的本地科目，实行"本组织优先"覆盖。
  - **引用校验同步放宽**：本地科目对计费单位（A 型）、税务名称（C 型）、服务类型（A 型）的引用，接受"全局有效行或本组织有效行"，替换现有"仅总部行"的校验。

### R3. 汇率实战化重构（ExchangeRateSetting：周汇率 + 应收/应付点差 + 中国银行一键同步）

彻底纠偏“依赖专职总部财务人工维护全盘基准汇率”的失真假设，按**真实货代财税实战口径**重构汇率治理体系：

1. **目标币种物化为「本币（Base Currency）」**：
   - 汇率的本质是“各外币折算成本公司的核算本币”；
   - 深圳分公司本币为 CNY，香港分公司本币为 HKD，新加坡分公司本币为 SGD；
   - 各核算组织独立维护外币折算本位币的兑换规则，`to_currency` 默认为本组织 `base_currency`。

2. **支持货代「应收汇率」与「应付汇率」双轨买卖点差（消除单一汇率技术债务）**：
   - **现状技术债务与成因**：现有数据库与契约中仅维护单一 `rate`（单一基准折算价），历史上甚至在 Proto 中将 `receivable_rate` 与 `payable_rate` 粗暴标记为 `reserved` 废弃。这导致系统无法支持货代行业最核心的“外汇买卖点差汇差收益”，财务无法对客户和供应商实行不同的折算口径。
   - **买卖双汇率字段与业务口径对照表**：
     | 字段名 | 对应中行牌价（/100） | 业务结算用途 | 货代实战逻辑与收益机制 |
     |---|---|---|---|
     | **`ar_rate`（应收汇率）** | **现汇卖出价** | 客户账单（AR）外币折算本币收款 | 银行卖外币给我们的价格较高（如 6.7272）。向客户收取外币账单折本币时使用高汇率，确保多收本币，锁定汇兑收益。 |
     | **`ap_rate`（应付汇率）** | **现汇买入价** | 供应商账单（AP）外币折算本币付款 | 银行向我们买外币的价格较低（如 6.6990）。向船司/供应商支付外币账单折本币时使用低汇率，压低本币支出成本。 |
     | **`rate`（基准汇率）** | **中行折算价** | 内部综合审计与报表基准 | 官方权威中间折算价，作为财务合规、税局审计与集团统计基线。 |
   - **业务收益与费用联动机制**：
     - **汇差收益公式**：单票外汇业务的汇差收益直接体现为 `外币金额 × (ar_rate - ap_rate)`，合法赚取外汇买卖点差利润；
     - **费用录入自动匹配**：录入应收费用（AR）时，系统自动匹配并默认带出业务日期对应自然周的 `ar_rate`；录入应付费用（AP）时，自动匹配并带出 `ap_rate`；
     - **快照固化与就地覆盖**：费用录入成功后将生效汇率打快照落库（`order_fees.exchange_rate`），支持财务/操作现场手工覆盖，存盘后不受后续周汇率更替影响；
   - **契约与界面呈现升级**：
     - 解除 Proto 中的 `reserved` 限制，正式定义 `ar_rate` 与 `ap_rate` 字段；
     - `/finance/exchange-rates` 列表与导入模板将原有的单一「折本币汇率」升级为 **「应收汇率（现汇卖出价）」** 与 **「应付汇率（现汇买入价）」** 双列展示。

3. **按自然周滚动生效与防卡死容灾机制（周汇率工业级闭环）**：
   - **标准自然周管理**：汇率生效周期默认按标准自然周（周一 00:00:00 至周日 23:59:59）闭环管理，贴合主流船公司（COSCO/Maersk 等）与货代行业周结算惯例；
   - **跨周预设机制（提前排定下周汇率）**：
     - 同步弹窗支持选择目标生效周期：默认为【本周（周一至周日）】，亦可切换为【预设下周（下周一至下周日）】；
     - 赋能财务在周五下班前或周末提前排定并发布下周汇率，彻底消除“周一早晨 08:30 码头/报关开单已启动、而财务尚未上班”导致的时间差真空；
   - **漏配容灾与三级缓冲机制（彻底杜绝业务阻断卡死）**：
     - **一级缓冲（自动继承上周）**：若周一财务因故（请假/开会）未及时同步，开单折算时系统**严禁直接抛错阻断保存**，自动向前回溯并顺延沿用最近一个有效自然周的汇率；来源快照标记为 `INHERITED_LAST_WEEK`，前端表单展示黄色提示 Tag「暂沿用上周汇率」，确保单据正常流转放行；
     - **二级缓冲（就地手工覆盖）**：允许业务员或财务在单据费用行直接手工填入汇率（标记为 `MANUAL`），先行放行单据与报关；
     - **三级通知（财务待办督办）**：系统若检测到周一 10:00 分公司仍未同步当周汇率，自动向财务角色推送一条轻量待办提醒；
   - **同周二次同步幂等更新（Upsert 与快照隔离）**：
     - 面对国际外汇突发剧烈波动（如央行调息/地缘事件），支持财务在周中随时重新同步并刷新本周汇率；
     - 系统执行幂等 Upsert，弹窗友好提示「检测到本周已发布汇率，本次确认将覆盖更新本周配置」，严禁报唯一键冲突；
     - **严格快照隔离（保护历史账目）**：汇率刷新仅对后续新增或修改的未锁定费用生效；历史已录入存盘、已确认账单的费用快照（`order_fees.exchange_rate`）绝对冻结，绝不发生不可控的逆向篡改。

4. **官方/市场外汇牌价一键自动抓取体系（覆盖 CNY 与非 CNY 本币组织）**：
   - **自动化数据源架构与防盗链处理**：
     - **组织本币为 CNY（国内分公司，如深圳、宁波、上海）**：
       - **主数据源（高效 JSON）**：调用新浪财经中行专线外汇接口（`https://vip.stock.finance.sina.com.cn/forex/api/openapi.php/ForexService.getBankForex`），服务端自动携带 `Referer: https://finance.sina.com.cn` 突破防盗链；直接筛选 `bank: "boc"`（中国银行）获取 `xh_buy_price`（现汇买入价）与 `xh_sell_price`（现汇卖出价）。该接口直接吐出清洗规范的 JSON，且数值已按 1 外币折合本币单价归一化（免除除以 100 换算），毫秒级响应，0 元完全免费；
       - **官方兜底源（HTML 页面）**：直连中国银行官方公开外汇牌价页面（`https://www.boc.cn/sourcedb/whpj/`），HTML 解析 `<table id="priceTable">` 兜底，按报价基准除以 100 换算。
     - **组织本币为非 CNY（境外分公司，如香港 HKD、新加坡 SGD、美国 USD 等）**：
       - **国际外汇直盘抓取（首选）**：系统根据当前组织的 `base_currency`（如 HKD）与各常用外币，自动向外汇行情接口请求直盘行情（如 `fx_s{from}{to}`，例如 `fx_susdhkd`、`fx_seurhkd`、`fx_susdsgd`，同样携带 Referer）；直接提取国际现汇市场实时 Ask（卖出价）预填为 `ar_rate`，Bid（买入价）预填为 `ap_rate`；
       - **中行交叉盘算法（备选/集团联动）**：若境外分公司要求与境内集团保持同源，系统自动基于中行牌价进行交叉折算预填：
         $$\text{Rate}_{\text{外币}\to\text{本币}} = \frac{\text{Rate}_{\text{外币}\to\text{CNY}}}{\text{Rate}_{\text{本币}\to\text{CNY}}}$$
   - **一键同步交互（非静默落库，弹窗核对与微调）**：
     - 在汇率管理界面提供同步按钮：本币为 CNY 时显示 **「从中国银行同步周汇率」**，本币为非 CNY 时显示 **「一键同步周汇率」**；
     - 弹窗内置周切换控件（【本周】与【预设下周】），点击后系统自动抓取对应行情并换算为选定周的起止时间区间；
     - 弹窗呈现预览表格，清晰标明数据来源（如「中国银行官方牌价」或「国际直盘行情」），展示各币种的抓取建议值（`ar_rate`、`ap_rate`、`rate`）；
     - **微调机制设计意图与业务必要性（为什么允许财务就地微调）**：
       1. **商业主动加点（风险缓冲储备）**：中行牌价是金融市场公开基准，货代向客户报价或开账单时，财务常在官方卖出价基础上主动上浮加点（如中行卖出价 6.7272 上浮至 6.7500），以覆盖单周内汇率波动风险并锁定汇兑服务利润；
       2. **业务报价取整习惯**：银行牌价多为 4~8 位小数（如 6.7272），开单与客户对账习惯四舍五入或取整（如 6.73、7.85），便于商务核算；
       3. **协议汇率与管理层周策略**：对于大客户约定的季度锁定汇率，或美联储议息等极端行情下管理层周一早会统一的锁汇指令，财务需现场拍板校正；
       4. **防呆闭环与财务责任终审（核心原则）**：严禁机器全自动静默强制落库。机器负责解决 99% 的查网页、打字和算起止周的繁琐重复工作；财务专员负责最后 1% 的专业核验。财务在预览界面点击「确认发布」代表最终审定并对生效数据负责，彻底阻断外部接口偶发抖动对业务账目的误伤；
     - 财务快速核对或手动微调点差后一键入库生效，全网各分公司每周 10 秒免维护。

5. **跨组织协同结算务实化（原币对账）**：
   - 分公司之间协同往来款对账（如深圳委托香港代收海运费），系统直接按**单据原币（如 USD）**进行跨组织对账，严禁系统强行跨组织二次折算引入人为汇差死账。
   - 现有 `ResolveBaseRate`（总部基线折算，提成 CNY 口径）随之退役，跨组织提成与往来按原币记账；各组织本币管理口径如需折算，用本组织汇率自行处理。

6. **存储归型**：`exchange_rate_settings` 保持 **B 型**（`organization_id` 可空）——org 行为各核算组织自维护的周汇率行；NULL 基线行由总部维护，作为新组织未同步时的**公共兜底**；DERIVED 交叉套算收窄为「仅从 NULL 基线行派生」的兜底路径。唯一键按周窗口生效（`from_currency, to_currency, effective_from`，`effective_from` 即当周周一）；`rate` 列扩展为 `ar_rate`/`ap_rate` 双轨（基准价列保留，字段映射见第 4 条）。

## 4. 技术与查询标准规范

### 4.1 B 型统一读取范式（Shadowing，两种形态）

废除各业务模块自行发明的 Fallback 逻辑，在仓储层抽象统一的 B 型查询构造器。规则：同码数据，本组织无条件覆盖总部基线。**两种形态都必须提供**：

- **单码解析形态**（选择器定值等点查）：

```sql
WHERE code = ? AND (organization_id = ? OR organization_id IS NULL)
ORDER BY CASE WHEN organization_id = ? THEN 0 ELSE 1 END
LIMIT 1
```

- **列表去重形态**（港口列表、费用选择器等分页列表）：基线行被同码本地行覆盖时必须整行不可见，采用 `NOT EXISTS` 反连接谓词下推到 SQL，保证分页计数、排序与去重结果一致（沿承现有 `writeIndustryLocalCodePrecedence` 的形态，仅去掉组织树解析）。**禁止**在分页列表中使用 `ORDER BY + LIMIT 1` 形态。

### 4.2 权限拦截器更替

全面废弃 `requireHeadquarters`，替换为语义精确的鉴权，**两者都必须校验：权限码 + 当前组织身份**（仅持有权限码不够——分支上下文的管理员不得写全局/基线行）：

- `RequireGlobalMasterDataWrite(ctx)`：A 型实体写入拦截，要求当前组织 `kind == headquarters` 且持有对应全局治理权限码。
- `RequireBaselineWrite(ctx)`：B 型实体操作 `organization_id IS NULL` 记录时拦截，要求同上。

组织身份判定来自组织树根节点的 `kind`（一次性、写在路径上），不再进入任何读路径。

### 4.3 组织身份前端契约（API 暴露）

`auth/me` 的 Organization 新增 `kind` 枚举字段。**存储层已存在该字段**（`organization.go:20`：`headquarters | company | department | team`，Immutable），本项工作是契约暴露而非新建存储，无需回填；proto 枚举必须映射既有四个值，不引入存储中不存在的 `BRANCH`：

```protobuf
enum OrganizationKind {
  ORGANIZATION_KIND_UNSPECIFIED = 0;
  ORGANIZATION_KIND_HEADQUARTERS = 1;
  ORGANIZATION_KIND_COMPANY = 2;
  ORGANIZATION_KIND_DEPARTMENT = 3;
  ORGANIZATION_KIND_TEAM = 4;
}
```

前端交互（依 `kind` 判定，复用 access 权限体系，不硬编码第二套规则）：

- A 型页签（币种/国家/区划/箱型/服务类型/计费单位/航司/船司）：非总部组织只读，提示「由总部统一维护与共享」，隐藏写按钮。
- B 型页签（港口/机场/费用）：隐藏基线行（NULL 行）编辑按钮，保留"新增本地行"；基线行对非总部禁用编辑。
- 汇率页（`/finance/exchange-rates`，B 型）：所有组织维护本组织周汇率行；总部 NULL 兜底基线行只读展示；同步入口对全部组织开放，按钮文案按本币动态显示（CNY 本币「从中国银行同步周汇率」/非 CNY 本币「一键同步周汇率」）。
- 总部视角（`HEADQUARTERS`）全部入口正常。

## 5. 数据迁移与上线策略

- **航司/船司本地行迁移（Fail-fast 策略）**：禁止自动静默合并或硬删除分公司历史创建的数据。迁移脚本按全球 Code 匹配：与总部完全一致的自动清理；存在事实冲突或无匹配的，生成冲突报告（Conflict Report）阻断迁移，经人工授权/决策后方可清理。开发数据任何清理/重置须先取得用户明确授权。
- **基线行转换**：Port/Airport/FeeSetting/ExchangeRateSetting 的总部行 `organization_id` 置 NULL，一次性迁移，走正式 Ent 迁移流程。
- **汇率结构重建**：`exchange_rate_settings` 扩展 `ar_rate`/`ap_rate` 并按自然周窗口重建存量行（开发库存量任意区间行清理重建，已授权）；`order_fees`/`finance_bill_lines` 的汇率快照字段随新结构迁移（单 `rate` → 按费用方向落 ar/ap + 来源枚举扩展，`DERIVED`/`BASE_CURRENCY` 退役值清理）。
- **种子同步（sync:all）**：写 A 型表与 B 型 NULL 行，彻底摆脱对特定总部组织 ID 的依赖。
- master_data_items 双轨 kind 收敛随 R1 一次性完成，消费方同步切换，不留双读。

## 6. 验收标准

1. **存储与代码约束**：所有 A 型表 `organization_id` 物理列已消除；A 型实体 Repository 无任何组织相关引用或查询参数；主数据读路径无组织树递归解析；C 型实体（企业资源库 EnterpriseResource、税务服务 TaxableService）严格保持组织隔离。
2. **唯一性验证**：B 型表中可成功插入两条同 Code 记录（一条 NULL、一条特定 org），但两条 NULL 同 Code 被数据库物理拒绝；A 型表同 Code 第二条插入被拒并映射为业务错误。
3. **解析穿透测试**：
   - 费用选择器与港口列表：正确显示本地行与基线行，同 Code 时仅展示本地行（被覆盖的基线行不可见），分页计数与去重一致。
   - 汇率周区间与点差匹配：按业务日期正确命中对应自然周（周一至周日）的生效记录；应收费用折算使用 `ar_rate`，应付费用折算使用 `ap_rate`；录入费用时快照落库，修改汇率后历史费用快照不变；支持费用行手工覆盖汇率。
   - 跨周预设与幂等覆盖：支持在当周提前发布下周汇率（下周一自然生效）；同周内二次同步执行幂等覆盖更新，不抛出唯一键冲突，且历史已冻结的费用快照完全不受干扰。
   - 漏配容灾回溯继承：当周未配置汇率时，录入费用自动顺延继承上周已生效汇率，快照标记为 `INHERITED_LAST_WEEK` 且前端展示黄色提示 Tag，开单与订舱流程不被卡死抛错。
   - 汇率数据源同步：调用同步服务能够准确拉取牌价（国内分公司拉取中行现汇买卖价，境外分公司拉取国际直盘或中行交叉盘），自动按所选周计算起止时间区间，弹窗预览微调后可一键批量入库生效。
   - 非 CNY 本币组织同步：本币 SGD/HKD 等组织同步时，支持国际直盘直查或由人民币牌价交叉换算预填，预览表标注换算路径，微调后可入库。
   - 跨组织往来结算：跨组织协同账单直接按单据原币（如 USD）对账，不强行实施多币种二次折算；`ResolveBaseRate` 已退役，跨组织提成/往来单据按原币记账。
4. **前端契约咬合**：`kind == COMPANY` 等非总部用户登录后，A 型页签只读并显示「由总部统一维护与共享」；B 型页面隐藏基线行编辑、保留新增本地行；总部视角全部入口正常；拦截器对分支上下文持权限用户写入 A 型/NULL 行返回 403。

## 8. 已决事项（原待确认问题）

1. **TaxableService 归 C 型**（已决）：随组织税务主体放开自维护。依据：分公司是独立法人/注册地税务主体（中国 6% 增值税、新加坡 9% GST、免税项目名称各异），税务名称与税率强依附本地财税合规，总部统一反而导致各地开票无合规名称。`organization_id` 必填，纯组织隔离。
2. **企业资源库（EnterpriseResource）归 C 型**（已决）：常用收发通抬头、地址簿、业务标签、品名、唛头等完全归属各分公司私有客户资源与日常操作资产，保持 `organization_id NOT NULL` 不可变外键，维持现状零改造。
3. **服务类型就地改名**（已决）：kind `service_type` → `charge_category`，表/代码/契约/文案同步更名，前端统一「费用大类」。依据：货代语境 Service Type 已绑定业务模式（FCL/LCL/AIR），且现有种子的 19 个值（订舱、拖车、报关、熏蒸、仓储等）内容本就是费用大类，名实不符是误传参数类 Bug 的温床；未上线窗口改名成本最低。
4. **汇率实战化改造与中国银行自动抓取（已决）**：彻底破除“总部专职财务人工维护全盘基准汇率”的失真假设。各核算分公司面向自身核算本币维护外币汇率，按自然周（周一至周日）生效；引入 `ar_rate`（现汇卖出价）与 `ap_rate`（现汇买入价）支持货代汇差收益；提供「从中国银行同步本周汇率」按钮一键抓取 BOC 官方牌价与自动算周区间，支持财务微调确认，10秒内完成维护；跨组织协同结算基于单据原币核对，杜绝折算死账。
5. **迁移冲突处置授权**（已决）：开发阶段，Fail-fast 冲突报告由实施方按报告处置开发数据，无需逐条回询。
