# 账单到期日固定：补费用不顺延、不重估汇率

> 父任务：`11-18-payment-terms-due-date`。本子任务不依赖 `11-18-customer-payment-terms`，可以先做。

## 问题（2026-11-18 已对照代码核实）

1. `server/internal/biz/finance_bill_fees.go` 的 `UpdateFees` 在刷新回调里执行以下操作：
   - `bill.BillDate = uc.businessDate()`：把账单日期改成当天；
   - 有账期时，按新的账单日期重算 `DueDate`，到期日因此被顺延；
   - 调用 `applyBillExchangeRate`：按新日期重新取汇率，`ExchangeRateDate` 也跟着改，
     原有费用行的本币金额被重新折算。
2. 前端文案把这个行为写成了规则：建账卡片（`BillGroupCard.tsx`）和编辑弹窗（`BillEditModal.tsx`）
   的「创建日期」提示都写着「未开票时增减费用会更新创建日期」。编辑弹窗又写着
   「账单币种和汇率已固定，不能修改」，两处说法自相矛盾。
3. 建账和编辑页面只能填「账期（天）」，不能直接指定到期日；到期日只是一行灰色小字。
   后端其实已经支持直接传 `due_date`（`CreateBillBatchGroupInput.due_date`、`UpdateBill.due_date`）。
4. 编辑弹窗提交时不带 `dueDate`。如果账单原本是「指定到期日、无账期」，保存一次编辑，
   服务端会按「无账期、无到期日」把到期日清空（`normalizedFinanceBillDueDate(billDate, nil, nil)`）。

## 需求

### R1 增减费用不改日期、不改汇率
- 增减费用时，账单日期（`bill_date`）、到期日（`due_date`）、账期（`payment_terms_days`）、
  账单汇率、汇率来源、汇率日期和汇率设置 ID 全部保持原值。
- 新增费用行与保留费用行统一按原账单汇率折算本币，末行吸收尾差（沿用现有
  `RecomputeFinanceBillAmounts` 口径）；预计开票金额照常随原币合计重算。
- 增减费用的其余规则不变：锁序、锁定事实拒绝、最后一笔不可移除、版本号、审计、提成经济重算。
- 删除只为旧行为存在的错误 `FINANCE_BILL_DUE_DATE_BEFORE_CREATION`。账单日期不再变化，
  这个错误不可能再出现。

### R2 建账时由财务确认一个到期结果
- 每张待建账单卡片突出显示到期结果，替代原来那行灰色小字：
  - 有账期：`2026-12-18 到期 · 账期 30 天`；
  - 账期为 0：`当天到期 · 现结`；
  - 既没有账期也没有指定日期：`未约定到期日`。
- 默认按客户约定带出账期（沿用现有 `default_payment_terms_days`），财务不用改任何东西。
- 需要例外时，点「调整到期日」，在两种方式里选一种：
  - **按账期天数：** 输入 N 天，到期日 = 账单日期 + N；
  - **指定日期：** 用日期选择器选一个不早于账单日期的日期，提交时只带 `dueDate`、不带 `paymentTermsDays`。
- 散客应收账单保持现有「建议现结」黄色提示，以及账期大于 0 时的预警，不做拦截。

### R3 编辑账单时同样可以调整到期日，且不再误清空
- 编辑弹窗显示同样的到期结果和「调整到期日」，支持上述两种方式。
- 提交时必须如实带上当前的到期设置：按天数时带 `paymentTermsDays`；
  指定日期时带 `dueDate`。不能出现「打开编辑弹窗、什么都不改、保存后到期日被清空」。
- 可编辑范围以服务端规则为准，不在前端另立规则：
  - 账单有发票、核销或对冲（受保护）时，账期天数不能改。账期为空、到期日为指定日期时，
    仍可修改到期日（服务端 `financeBillProtectedFieldsUnchanged` 本来就允许）。
  - 账期天数与到期日同时存在时，必须满足「到期日 = 账单日期 + 天数」（`validFinanceBillTerms`）。

### R4 文案与提示统一
- 「创建日期」的提示改为：「建账时由系统记录，之后不再变化」。
- 增减费用入口（`BillFeeMaintenance`）补一句：「增减费用不会改变到期日和账单汇率」。
- 编辑弹窗里「账单币种和汇率已固定，不能修改」的说法保留，现在它和实际行为一致了。
