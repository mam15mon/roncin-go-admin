# 统一财务汇总数据流并修复公共展示契约

## 目标
修复公共数据流造成的全量金额口径错误、指标错配、路由标题漂移和海运改配无效原因不显示。按财务、导航、改配三个可独立验证的交付包推进。

## 初步事实
- FinanceLedgerTemplate.tsx:392 将 currentData 作为 allRows 传入底栏，记录数却是服务端 total；底栏不能据此计算全部金额。
- FeeLedgerSummary 返回 amountsByBaseCurrency，FinanceSummaryBoard.tsx:101 仍读取旧平铺字段，未正确消费正式汇总契约。
- 六个财务列表在 request 内直接 setSummary/setMetricStats；真实已安装 ProTable hook 的 A→B 乱序实验已确认表格保留 B、指标被迟到 A 覆盖，1 项研究实验通过，证据见 research/finance-summary.md。
- routeUtils.ts 独立手写标题表，航空共享主单和我的冲减来源路由未覆盖，直接解析输出错误标题。
- SeaOrderReassignmentModal.tsx:261 以 isValid===false 显示失败原因，non-optional false 省略时分支失效。canExecute 已要求 isValid===true，提交守卫应保持。
- matched 在 queryFn 已归一化，不属于本次缺陷；canReassign 需结合加载和外层门控验证，不机械替换。

## 初步范围
财务汇总与采纳快照统一、路由标题复用配置、改配提示复用正确 presence 语义；补精确回归和规范。只规划，不修改产品代码。

## 待研究
后端各列表能提供的全量/分币种字段及语义；非费用实体是否适用利润底栏；最薄 snapshot 通知设计；路由既有业务标题与动态覆盖规则；改配提示完整失败场景。

## 已确认的补充事实
- 六个现有列表汇总契约均以本币分组，不提供全部原币金额；费用/账单/流水/发票/核销/对冲各自存在不同的状态统计口径。
- 流水、核销行是 amount/baseAmount，对冲行是 amount/baseCurrencyAmount；通用费用底栏读取 totalAmount，不能直接用于这些实体。
- 只有费用的应收减应付可称为费用利润；对冲没有方向，其他类型不能显示虚构利润。

## 交付包与初步验收
1. 财务：六页按正确字段和范围统计，不跨币种相加；指标、底栏、表格、导出基于同一已采纳快照；乱序/失败响应不能覆盖新快照。底栏最终范围等待下述产品决策。
2. 导航：配置与标题统一入口，覆盖航空共享主单和我的冲减来源，保留 SE/AE 新建标题、动态订单号回填、重定向及页面归组，不把合法别名都视为错误。
3. 改配：成功取得无效预览时显示后端原因，未加载/查询失败单独处理；执行仍要求有效预览；matched 已归一化逻辑不动。已打开弹窗的操作能力失效时正确禁用，保留成功同步保护。
4. 规范与验证：按范围补快照/汇总/导航/ProtoJSON presence 规范，采用受影响定向测试、独立 review 及风险匹配完整门禁，不重构无关页面。

## 用户确认的底栏交互（2026-11-09）
- 底栏不同时铺两行：有勾选显示已选合计，无勾选显示全部筛选结果合计。
- 支持手动跨页勾选：翻页保留先前已选，跨页记录共同计数和汇总；表头全选作用于当前页，不引入后台一键选择全部结果的平台。
- 顶部指标随筛选，但要明确现有额外有效/已确认/已开票状态口径，不把业务有效指标误称所有可见行金额。对冲汇总目前独立列表状态，需研究并在最终方案明确，不能静默改变业务汇总。
- 全部筛选结果合计不能从本页行推导；保留原币及折本币需要正式扩展服务端汇总契约，同步 Proto/生成物/前端。
- 跨页选择基础已存在（FinanceLedgerTemplate preserveSelectedRowKeys，AntD preserveRecordsRef）；本期复用框架补计数、合计及边界验证。

## 当前待确认的选择边界
