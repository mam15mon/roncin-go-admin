# 费用异常闭环总验收

## 原审查结论

R1 自动锁单金额判定、R2 批准/建账后费用更正、R3 补录与提成纠错出口、R4 待审批补录结案阻断均成立，已按三个子任务处理。R5 由用户明确决定继续人工判断费用完整性，没有加入清单、估算成本或漏费检测流程。一个人持有审核权限不是缺陷。

## 已确认的业务边界

业务结案与回款分别处理。结案不要求收款或付款完成；存在待审费用变更时先处理申请，已结案后仍可受控补录/更正且不反结案。更正批准认可经济变化，实际退款、补收、提成补付/追回由财务执行，历史账务不被审批动作改写。

## 跨任务验收映射

| 验收项 | 交付与证据 |
| --- | --- |
| AC1 合并账/币种正确性 | 自动锁逐张确认应收账单全结判断，部分合账不推断订单归属；更正内部清偿准确作用于原费用行，不占其他订单 |
| AC2 待审与结案竞态 | 待审补录/更正阻断业务结案；并发由订单锁串行；结案后新申请合法且不反结案 |
| AC3 已批准更正历史 | 追加/替换/作废申请，现有权限审批，完整冲回/替代，批准时利润及提成快照和审计留存 |
| AC4 补录1000→100 | 未执行-100取消后重建-10，已执行-100保留并补+90；人工调整独立；不删除原补录与批准 |
| AC5 相邻流程 | 自动锁、共享主单、建账、发票红冲/重开、核销/对冲反转、提成发放均有定向实际库回归；付款实际等锁及旧预览失效验证 |
| AC6 验证与生成物 | 正式迁移、Ent/Proto/OpenAPI/Wire/前端客户端同步；独立审查；全量门禁和真实数据库最终结果见更正子任务验收 |
| AC7 业务与资金分离 | 无回款可业务结案，结案后正常资金动作及受控费用更正，普通编辑冻结仍有效 |
