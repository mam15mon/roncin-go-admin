# 分阶段实施计划

## 本次规划评审

第一阶段候选为自动锁单与结案门禁；PRD/design/implement 和上下文均已准备。须用户确认本次规划总览后逐个 task.py start 子任务；父任务保持协调用途，不直接启动产品实现。更正子任务只完成需求和技术研究，不以第一阶段批准替代其最终设计评审。

## 第一阶段

1. 激活自动锁单子任务，以其 implement.jsonl 派发 trellis-implement；明确仅拥有自动锁单实现/测试文件，告知共享工作区不得回退其它改动。实现后 trellis-check 复核，主会话更新规范并提交。
2. 激活结案子任务，按其计划派发实现与检查；复用已确认的 CLOSED 后受控补录规则。相关测试通过后单独提交。
3. 在真实 PostgreSQL 正式迁移隔离环境验证两子任务回归；执行 `pnpm run check:fast`，记录实际结果。新增数据库测试若 SKIP，不算完成。
4. 按通过的阶段验收归档对应子任务，保留总任务和更正子任务，不宣称全部异常闭环完成。

## 第二阶段

1. 完成更正的费用经济影响、账单调整、资金执行、提成调整技术设计及调用方清单。
2. 写完更正 design.md、implement.md，收敛 PRD，展示具体方案后获用户确认再实施。
3. 契约/Schema 经源文件及正式生成/迁移同步，按阶段验证提交；最后联合回归自动锁单、结案、建账、核销/对冲和提成发放。

## 当前验证边界

本轮只编辑规划文档，验证 Markdown 引用、JSON/JSONL、父子关系、任务状态及 git diff --check；不运行产品测试、不操作数据库、不修改产品代码。实施阶段按各子任务计划运行风险匹配检查。
