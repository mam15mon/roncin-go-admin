# 汇率管理完全下沉分公司：技术设计

## 状态与边界

本文为待实施审阅的设计方案；当前仅授权补齐规划文档，不启动实施。
目标对应 PRD R1—R4：公司独立维护、移除公共基线取值、按单据公司解析、保护已固化快照。
本方案不新增事务机制、版本字段或汇率平台；复用现有事务、锁、导入预检和周同步机制。

## 归属与权限

1. 维护请求从服务端 principal 取得组织，不接受客户端指定写入公司。组织解析后使用 OwnerOrganizationID 作为列表、编辑、停用、同步、导入的作用域。
2. 部门只共享所属公司配置，不产生部门汇率。组织解析不授予权限：仍需 principal 对应操作权限与所属公司范围匹配。
3. 系统工作台不能读写汇率配置、下载维护模板、预检/确认导入或抓取/同步维护预览；直接请求 API 同样被拒绝。
4. 权限键 `system.finance.exchange_rate.*` 保持不变；前缀不是工作台归属的判断依据。调整 Manifest 分组说明、工作台过滤及相关测试，再生成权限键文件。禁止更改其他费用设置权限的范围。
5. 前端复用 access 及现有公司经营工作台判定，路由和按钮使用同一结果。组织切换沿用现有缓存清理机制，检查在途请求不能将上一公司数据显示到新工作台。
6. 审计保留真实操作人和请求组织信息，记录实际目标公司；批次与公司归属检查覆盖预览 token、批次 ID 和幂等键，不能仅靠页面隐藏。

## 汇率解析与业务数据流

```text
业务请求 → 单据访问权限校验 → 单据所属组织 → 所属公司及本币
  → 同币种：1
  → 本公司目标日期覆盖行
  → 本公司最近有效历史周行
  → ErrExchangeRateMissing：提示维护本公司汇率
```

- 保留公司内历史周继承与 `INHERITED_LAST_WEEK` 来源提示，不扩大本次行为变化。
- 应收取 ar_rate，应付取 ap_rate，现有基准价及金额精度规则保持；禁止缺失汇率静默取 1。
- 删除公共直连、公共历史回溯、公共 pivot 套算及 `PivotCurrency` 内部参数；所有 Go 接口实现和测试桩一次性同步。
- 不新增公司内任意货币对套算。现有业务接口将外币折为公司本币，维护与同步已支持该直连报价；非 CNY 公司继续同步外币→本币。
- 外部牌价预览中的交叉盘计算属于报价获取机制，继续使用并明示来源；它不读取数据库公共基线。
- 已有显式手工汇率覆盖及覆盖权限保持，不新增自动覆盖。缺失系统配置时，已有允许手工输入的场景仍按原权限校验；无有效配置且未合法手工输入才阻止提交。
- 保留同币种恒等结果的 SYSTEM 来源值；移除公共基线不等于删除所有名为 SYSTEM 的来源。旧快照来源只作事实展示，不作为新取值分支。

### 调用方清单

直接入口：`biz/order_fee.go`、`finance_bill.go`、`finance_bill_batch.go`、`finance_cashflow.go`、`finance_invoice.go`。
逐个核对传入组织来自单据/费用/账单归属，不能只使用当前会话组织；批量建账分组不可混公司。
提成、核销、对冲等消费既有费用和账单快照的链路继续消费快照，不引入实时重算。
跨组织业务保持原币记账的既有契约，不用任一方本币配置新增跨公司折算。

## 写入、同步与并发

- 新写入必须有合法公司 ID；删除创建、导入、同步中的 NULL 基线分支。批量写入在进入数据库前校验全部行同属一家公司。
- 复用现有 WithTx、公司作用域 advisory 锁、行锁、周唯一索引、导入预检过期与幂等机制。锁作用域从已有组织语义收口为公司，不引入新锁协议。
- 事务内读取仍通过 Data.client(ctx)，汇率快照读取继续 ForShare；不能删除已有共享事务保护。
- 周同步和批量导入失败全部回滚，审计与业务写入保持原子。此任务不将原生独立事务方法引入共享 txCtx。
- 周提醒只检查 company，确认权限范围变更后收件人筛选仍可命中公司维护人员。

## 存储与旧记录处理

本期不删除、不分发、不自动重归属已有 NULL 基线记录，不重算快照，不收紧 organization_id 为 NOT NULL。
保留现有可空列与索引用于保存旧记录及快照引用；运行时彻底停止读取公共行用于新业务解析，维护列表不展示公共行，所有写入口禁止新增公共行。这是保留既有事实，不是双读或兼容接口。

因此本方案无需结构迁移；若实施发现必须修改 Schema，先补设计，按 Ent 源→生成→正式 SQL 迁移流程完成，不能直接改旧迁移或删除数据。
核对 `cmd/import-historical-exchange-rates`、`cmd/sync-dev` 及其 data 实现，消除公共基线写入入口。历史导入工具如没有明确公司目标则拒绝执行，不默认全公司分发；开发种子按测试公司生成必要汇率。
本轮文档工作不运行数据导入或迁移。

## API 与生成物

保留现有 HTTP 路径、分页与周配置字段；organization_id 对新返回的配置始终为公司 ID。
API proto 的公共基线注释或语义如需调整，修改源文件后执行 make -C server api 与 pnpm run generate:web-client，禁止手改生成文件。
变更 Manifest 后执行 pnpm run generate:permission-keys，即使输出无差异也记录执行结果。
不新增兼容路由、旧新权限双轨或兜底配置。

## 风险与验证

- 曾依赖公共基线的公司在移除后可能无法提交缺汇率单据：验收必须构造此场景并验证明确提示，由公司维护真实业务报价，不自动复制公共价。
- 系统本币不应再影响公司汇率：覆盖系统节点不可用而合法公司仍可解析的用例。
- 旧 NULL 记录需保留但不可用于新计算：用有公共价而无公司价的真实库场景证明。
- 非 CNY 公司、部门归属、越权批次确认、在途组织切换、事务内并发改汇率是重点回归。
- 专项规范目前有“DERIVED 已退役”与“公共套算仍用 DERIVED”的矛盾，以代码证据和本任务新契约收敛；实施后同步规范，不提前把待实现行为写成已生效规范。
