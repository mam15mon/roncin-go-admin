# 执行计划

## 开始条件

- 最新规划摘要获用户确认后才执行 task.py start。
- 实施前再次检查 git status 与费用列任务差异；不得覆盖或混入其他工作。
- 采用 Trellis implement/check 子代理，主会话协调、审阅、提交、记录与归档；上下文清单见同目录 JSONL。

## 阶段一：费用状态简化（阶段二前置）

1. 枚举所有费用状态消费者、RPC 和自动锁单触发，记录改动清单；读取目标包与生成/迁移规范。
2. 修改 Ent/领域/Proto 状态及费用单行生命周期；生成正式 SQL 迁移并审阅数据保留和状态约束。
3. 一次性同步建账、取消账单、补录、拆票、自动锁单、种子及测试；删除确认/撤回入口与调用。
4. 按仓库生成流程更新 Ent/绑定及 OpenAPI：make -C server api；pnpm run generate:web-client；涉及权限 Manifest 时额外生成 permission-keys。
5. 定向验证保存即建账、未建账修改、账单占用、取消账单、未建账应付阻止锁单及消除阻断后的重评。迁移验证使用有序正式迁移，不使用运行期 Schema.Create。
6. 相关测试、git diff --check 与类型检查通过后提交本阶段。

## 阶段二：五项批量维护

1. 新增批量字段修改/删除契约及后端原子用例，核对共享事务及固定锁序；实现后补充回滚、版本冲突、越权、越订单、混合状态测试。
2. 接入应收/应付批量入口及选择资格，复用订单标签接口；删除二次确认、修改表单使用已有 ModalForm 生命周期。
3. 成功清理选择并 actionRef.reload，刷新汇总及锁状态；失败保留可核对上下文且提示原因。建账入口显式拒绝不合格目标。
4. 生成契约产物；定向测试草稿合并后的全选、临时行排除、五种操作及建账回归。费用表格重型测试按功能拆分。
5. 相关测试、git diff --check、pnpm --dir web tsc 通过后提交。

## 最终验证与交付

- 后端按改动运行 go -C server test -p 32 ./internal/biz ./internal/service ./internal/data，集成测试按现有规范配置数据库并验证真实事务回滚。
- 前端用 pnpm --dir web exec vitest run <相对 web 的受影响测试文件>；开发阶段仅检查修改文件 Biome。
- 本次跨契约、状态、数据库迁移及自动锁单，最终运行 pnpm run check:fast。无构建入口/依赖变更不固定运行 build。
- Check 子代理复核状态残留、事务/审计一致性、并发建账与删除、正式迁移及生成物；问题修复后只重跑相关验证。
- 更新领域术语、状态/事务及自动锁单相关规范；提交本任务改动，记录门禁结果和迁移注意项，归档。
