# 技术设计

## 状态与契约

费用持久化采用 UNBILLED（未建账）、BILLED（已建账），现存 CANCELLED 仅按现有作废业务需要保留，不作为可选有效费用。删除费用确认/撤回 RPC 及其调用，Proto 退役字段/枚举编号按生成规范保留 reserved，新增明确未建账枚举，禁止复用退役数字。账单状态不变。

Ent Schema、领域类型、Proto 同步；正式迁移一次性把费用 DRAFT/CONFIRMED 合并为 UNBILLED，更新状态约束/默认值，保留行、金额及版本。先调整数据库允许值再转数据再收紧约束；不重置数据库，不改已应用迁移。新增/补录/拆票流转及取消账单恢复状态统一使用新状态。同步开发种子、测试、状态过滤和汇总查询。

## 单行与批量维护

单行费用修改资格由草稿改为未建账；现有已建账字段策略保持。订单费用页应收/应付分别提供批量入口；选择已保存有效行，临时新行及正在编辑尚未保存的行不提交批量请求。已建账行可选择用于标签，操作资格由具体动作校验，禁止静默过滤不合格行。

新增订单范围的专用批量修改与删除契约：明确费用 ID + expectedVersion 列表；修改类型限结算单位或费用发生时间，每次指定一个目标值。拒绝空目标、重复 ID、非法版本、越订单目标。各端传输层只作转换与边界校验，biz 持有用例及权限/业务约束，data 负责锁内复核与写入。复用既有 fee.update / fee.delete 权限，不增加重复授权体系。

标签沿用订单范围批量加/删接口，复用现有标签弹窗能力或其最小扩展；添加保留其他标签，删除只解关联。标签事务必须复核目标集合及组织、订单锁状态，避免与删除并发产生遗漏。现有重复添加幂等语义保留。

批量修改采用字段定向更新，避免完整 DTO 回写导致无关税率、名称、金额快照被重算。改结算单位不改变金额及汇率；改费用时间按分钟保存，系统来源汇率按新日期重新解析并更新折本币金额，原手工汇率保持原值和手工来源（本次不提供覆盖汇率入口）。缺少必要汇率时整批失败。

## 事务与并发

一次批量命令一个统一事务；沿用费用写入订单行锁，再按费用主键固定排序加行锁，核对全部版本、归属、状态和账单占用后写入，版本递增与审计同事务。禁止前端逐条循环单行接口。共享事务通过 biz.Transactor / Data.WithTx 现有封装，仓储经 Data.client(ctx) 访问。锁序须核对建账、取消账单、标签等相邻链，出现冲突统一现有锁序。

任一行失败整批回滚，返回具体费用/原因供界面定位；不给部分成功计数。删除及建账引起的自动锁单重评在主事务成功后执行，复用现有幂等触发语义，不在未提交事务中触发独立事务。

## 自动锁单

任意未建账应收/应付阻止自动锁单；有效应收结清事实、应收全结清、生命周期等原有条件保留。不要求应付付款。同步原因码、前端说明与触发点，覆盖最后一笔未建账应付进入账单或删除后重新评估锁单的路径。

## 影响范围与交付

仓库全量搜索旧费用状态与确认/撤回调用，覆盖建账候选/预览/执行、财务台账、补录、拆票、自动锁单、种子、生成物及测试。费用表格已有其他未提交修改，实施前记录差异并隔离本任务修改，提交不得携带他人改动。

作为同一任务按状态简化、批量维护两阶段执行；后者依赖前者的新状态契约，同一费用表和端到端验收紧密耦合，暂不建立可独立并行的子任务。各阶段均可验证并单独提交，最终统一验收。

## 部署及回退

本次为上线前契约同步，无旧接口兼容层。正式迁移与源文件/生成物一起交付。状态合并丢失草稿与已确认的历史区分，旧程序无法直接安全回退；迁移前保留数据库备份，出错优先前向修复，恢复数据必须另获用户授权。
