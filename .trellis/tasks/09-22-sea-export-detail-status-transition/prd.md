# 海运出口详情状态流转与表单信息架构统一

## Goal

让业务人员在海运出口订单详情页的“订单状态”卡片中直接操作主流程、退关和结案三个状态
维度，并让订单从新建到详情保持同一套五卡片信息架构。创建成功后直接进入详情继续办理，
不再返回列表，也不因页面切换而改变核心字段的分块、顺序或布局。

## Background

- 目标页面：`/orders/sea-export/01a0c7d8-09b4-779e-8ad3-6f8711f94ee1`。
- 数据库只读核对结果：订单号 `SE2026092200001`，所属公司为
  `融迅（上海）供应链管理有限公司`。
- 初次排查时主流程为 `DRAFT`，退关维度为 `ACTIVE`，结案维度为 `OPEN`，版本为 `1`，
  未锁定，无活动异常，无未开账费用。
- 生命周期记录只有创建时写入的 `FLOW: 空 → DRAFT`，尚未发生后续流转。
- 服务端固定主流程状态机为：
  `草稿 → 已订舱 → 已配舱 →（拖车已安排 →）已截单 → 报关已安排 → 已放单`；
  “已配舱”可直接进入“已截单”，因此拖车节点可跳过。
- 当前详情页状态流程条是纯展示，普通主流程入口仅位于订单列表行内的
  “更多 → 流转状态”，与用户在详情页查看和维护订单的主工作流割裂。
- 退关与结案当前显示为不可交互的“未退关 / 未完结”徽标，实际动作按钮散落在详情页头部，
  状态展示与状态操作没有形成同一入口。
- 详情响应已经提供 `allowedTargetFlowStatuses`、`allowedActions` 和 `version`，现有
  `loadData` 能在成功后刷新订单，因此状态流转 UI 无需新增接口或复制状态机。
- 实际操作发现订单从 `DRAFT` 流转到 `BOOKED` 后详情立即只读。根因是服务端动作投影只在
  `DRAFT` 返回 `EDIT`，且更新仓储另有 `flow_status = DRAFT` 的重复状态门禁；这与统一订单
  内容写门禁已经定义的“未退关、未完结、未业务锁定即可编辑”口径冲突。
- 新建页和详情页虽复用同一批字段组件，但采用了两套分节信息架构：新建页为“业务归属、
  订舱与主单识别、航线与船期、MBL 主单内容、HBL 分单内容、补充与内部信息”六块；详情页
  的核心表单则为“业务信息、配舱信息、货物与提单信息、备注、内部信息”五块。相同字段在
  两页的归属、顺序和列布局不同，用户创建后进入详情会产生页面结构跳变。
- 用户希望两页结构一致、减少页面长度，并要求内部人员独立于备注。此次计划以五张核心卡片为
  基础，吸收后续复核中的备注可见性、底部记录页签及隐藏字段错误定位建议，供最终审阅。

## Requirements

- 详情页“订单状态”流程条必须以服务端 `allowedTargetFlowStatuses` 为唯一可点击目标来源，
  不在前端复制状态机规则。
- 当前已完成节点和尚不可达节点只展示、不可点击；服务端允许的下一节点呈现明确的可点击
  和键盘聚焦状态。
- 点击可流转节点后使用当前订单 `version` 调用既有
  `orderServiceTransitionOrderStatus`，不得新增接口或手工拼接 URL。
- 点击合法下一节点后弹出一次简洁确认框，固定展示“当前状态 → 目标状态”，保留可选的
  流转原因输入，但不再让用户二次选择目标状态；同一时间只允许存在一个流转确认框。
- 提交期间必须阻止重复点击；成功后提示并刷新详情、锁状态和状态流程条；失败继续使用统一
  请求错误处理，不伪造成功状态。
- 主流程节点入口只对当前公司工作台、具备服务端返回流转动作且业务写门禁允许的订单开放；
  无权限、已锁定、退关中/已退关或已结案时主流程保持只读，并给出不可操作提示。
- 从订单列表“更多”菜单移除“流转状态”入口及其仅列表使用的弹窗挂载，避免两套交互并存。
- 退关徽标必须准确区分 `未退关 / 退关中 / 已退关`，并仅呈现服务端 `allowedActions`
  允许的操作：发起退关、完成退关、取消退关或恢复订单。
- 结案徽标必须准确区分 `未完结 / 已完结`，并仅呈现服务端 `allowedActions` 允许的完结或
  反结案操作；不满足完结条件时保留不可操作状态和原因提示，不通过请求试探非法状态。
- 锁定门禁按服务端生命周期契约区分：主流程推进和 `ACTIVE → TERMINATING` 发起退关受业务锁
  阻断；完成/取消退关、恢复订单、完结和反结案不受业务锁阻断，但仍须满足允许动作、当前
  工作台和各自的服务端业务校验。
- 从详情页头部移除退关与结案动作按钮，把三个状态维度统一收口到“订单状态”卡片，避免重复入口。
- 三个维度继续相互独立，不改变后端状态机、既有确认表单和领域门禁。
- 完结与反结案确认框的原因均按现有服务端契约设为必填，修正当前“完结原因选填”与服务端
  非空校验不一致的问题。
- 订单内容编辑资格必须与统一内容写门禁保持一致：`termination_status = ACTIVE`、
  `closure_status = OPEN`、未业务锁定，并具备当前工作台的订单更新权限时，所有合法主流程状态
  都返回 `EDIT`，不得因从草稿流转到已订舱或后续节点而自动只读。
- 订单更新事务继续保留 `ForUpdate`、`expectedVersion` 乐观锁、统一内容写门禁、组织范围和
  引用校验；删除仅允许 `DRAFT` 更新的重复状态判断，不放宽退关、结案、锁定或并发门禁。
- 新建成功后必须读取创建响应中的订单 `id`，直接进入 `/orders/sea-export/{id}` 详情页；仅在
  返回了有效订单数据时提示成功并跳转，禁止空响应误跳转，创建失败继续留在当前表单。
- 不增加底部吸附按钮；新建页继续只在页头提供“创建订单 / 取消”。
- 新建页与详情页必须使用同一套 SE 核心表单分节定义，使核心区块的标题、顺序、字段归属和
  栅格布局一致；详情页只允许在核心区块之外增加订单状态、类型专属业务区和操作记录。
- 新建与详情的核心表单固定为五张卡片，顺序与字段归属如下；详情特有的业务动作和只读态允许
  依据服务端结果变化，但不得把同一字段搬入其他卡片：

| 顺序 | 区块 | 字段 / 内容 |
| --- | --- | --- |
| 1 | 业务与客户 | 订单编号、订单编号时间（仅新建可改）、委托单位及代码、集运/跨境、托运类型、服务类型、客户业务编号、企业内部编号 |
| 2 | 订舱与运输 | “订舱与主单”：订舱号、船公司、MBL 主单号、订舱代理、国外代理、船代、DIRECT/HOUSE 提单模式、关联分单号、主单候选匹配与更正提示；“航线与船期”：船名航次、起运港、目的港、卸货港、中转港、ETD、WEEK、ETA；“箱量与截关”：箱型箱量计划、货主箱标记、SI/单证/报关/VGM 截关时间；订舱备注就近放第一组、配舱备注放第三组，操作备注放卡片底部平级的“操作补充” |
| 3 | 货物与商业 | 货物品类、危险品 UN NO./CLASS NO./截申报时间、委托品名/货物描述、特殊要求、贸易条款、合约号、货值及币种、保费及币种、接单时间、货好时间、工厂、委托件重尺与散杂计费吨提示 |
| 4 | 提单信息 | 同一张卡片内的 MBL/HBL 页签，一次只显示一个正文：MBL 含发货人、收货人、通知人/第二通知人、外国代理、唛头、提单货描、件数、包装、毛重、体积及现有主单字段；HOUSE 模式下的 HBL 含分单号、分单备注、签发主体/合作方、收发货及通知人、外国代理、唛头、货描、件重尺；详情的版本、改单等已落库动作保留，DIRECT 模式不出现 HBL 页签 |
| 5 | 内部人员 | 创建人员、操作人员、业务人员、客服人员、关联人员、单证人员、商务人员、关联人员 2；不混入业务备注 |

- 两页复用同一个五卡片构建器；共享字段保持同区同位置及响应式栅格。详情版本、改单和独立
  保存操作放在卡片标题操作区或提单页签工具栏，不挤占字段位置；订单编号时间仅新建可改。
- 备注采用“空内容初始收起、有内容初始展开”：详情回填与新建草稿恢复均按此初始化；完整
  内容可读，展开后直接编辑，不新增摘要或编辑模式。用户主动收起后显示“有备注”，同一订单
  的普通重绘不强制重新展开；切换订单重新初始化。折叠不清值、不跳过适用字段校验。
- 详情页在五张核心卡片之前增加“订单状态”，后面仅增加一张“关联与记录”卡片，页签顺序为
  “操作记录｜同批订单｜拆票与改配记录”，默认操作记录；原长标题统一缩为“操作记录”。
- 记录数量只使用现有完整结果或服务端准确 total；未加载、失败或缺少总数时不显示数字，
  确认无记录时可显示 0。不为角标新增接口，不以最近五条等预览条数冒充总数；沿用现有请求
  与刷新时机，本期不承诺全面改造为懒加载。
- 提交校验失败时按页面字段顺序找到首个错误，自动切换对应 MBL/HBL 页签或展开备注，随后
  滚动并聚焦错误字段；从未打开过的适用页签也必须参与校验。DIRECT 不校验或提交 HBL 隐藏草稿。

## Acceptance Criteria

- [x] `DRAFT` 订单详情中的“已订舱”节点可直接发起 `DRAFT → BOOKED`，其他未来节点
  不可点击。
- [x] `SPACE_ALLOCATED` 同时允许“拖车已安排”和“已截单”两个服务端目标，两个节点均可点击，
  不由前端自行裁剪分支。
- [x] 无 `TRANSITION_FLOW` 动作、非订单所属公司工作台、业务锁定、退关或结案状态下，流程条
  不得发起写请求。
- [x] `ACTIVE` 显示“未退关”并可按 `START_TERMINATION` 发起退关；`TERMINATING` 显示
  “退关中”并提供“完成退关 / 取消退关”；`TERMINATED` 显示“已退关”并可按
  `CANCEL_TERMINATION` 恢复订单。
- [x] `OPEN` 显示“未完结”，仅在存在 `CLOSE` 动作时可点击完结；否则以禁用状态解释当前
  暂不可完结。`CLOSED` 显示“已完结”，存在 `REOPEN` 动作时可点击反结案。
- [x] 完结与反结案均未填写原因时不发送请求，并显示明确的必填提示。
- [x] 流转请求只提交一次并携带最新 `expectedVersion`；成功刷新详情并展示新状态，并发冲突
  保持服务端稳定错误提示。
- [x] 订单列表“更多”中不再出现“流转状态”，详情页成为普通主流程的唯一前端入口。
- [x] 详情页头部不再重复展示发起/完成/取消退关、完结或反结案按钮；这些动作只在状态卡呈现。
- [x] 已锁定订单不能推进主流程或发起退关，但合法的完成/取消退关、恢复、完结和反结案仍可
  从状态卡执行，不被前端通用内容写门禁误杀。
- [x] 定向组件测试覆盖可点击目标、不可点击节点、双分支、权限/门禁和成功刷新；Biome、TypeScript
  与 `git diff --check` 通过。
- [x] `BOOKED` 及后续所有合法主流程状态的 `ACTIVE + OPEN + 未锁定` 订单仍返回 `EDIT`，详情
  表单和保存入口保持可用。
- [x] `TERMINATING`、`TERMINATED`、`CLOSED` 或已业务锁定订单仍不可编辑；无订单更新权限或
  非可写组织范围时，`EDIT` 仍被权限投影移除。
- [x] 非草稿状态更新继续校验最新 `expectedVersion`，并在同一事务中执行统一内容门禁与引用
  校验；版本冲突、生命周期阻断和业务锁错误语义保持不变。
- [ ] 新建成功后直接进入服务端返回订单 ID 对应的详情页，不再返回订单列表；创建失败或响应
  缺少订单 ID 时不跳转、不清空当前填写内容。
- [ ] 新建页与详情页核心表单的区块标题、区块顺序、字段归属和同区字段顺序一致；详情页增加
  的状态、类型业务和审计区块不得改变核心表单信息架构。
- [ ] 新建页不出现底部操作栏，页头创建与取消入口保持不变。
- [ ] 两页均按固定五卡片顺序渲染；“提单信息”内 MBL/HBL 页签一次只展示一个正文，HOUSE
  可切 HBL，DIRECT 不出现 HBL；切换模式与页签不丢已输入数据。
- [ ] 空备注初始折叠，有备注及恢复草稿时完整展开；主动折叠后显示“有备注”，重新展开值不丢，
  普通重绘尊重手动选择，切单不沿用上一单的展开状态；内部人员卡不出现备注。
- [ ] 详情仅七个外层区域：订单状态、五张核心卡片、关联与记录；底部默认操作记录，三页签
  可切换，原独立三卡及“操作记录与历史流转日志”标题消失，记录查询与查看全部能力保持可用。
- [ ] 页签数字来自准确完整结果或 total；未加载/失败不显示 0，预览返回五条而 total 大于五时
  显示 total，缺少准确 total 时省略数字。
- [ ] HBL 从未打开但存在校验错误时，提交被阻断并自动切到 HBL、定位字段；备注折叠时校验
  失败自动展开定位；修正后可以提交，DIRECT 的隐藏 HBL 不产生阻断。

## Out of Scope

- 不调整服务端主流程迁移边、权限码、数据范围或结案规则。
- 不允许回退到上一主流程状态，也不允许点击任意未来节点跨级流转。
- 不改变退关、恢复、结案、反结案的服务端接口、原因字段和业务校验；只迁移前端入口并优化
  状态标签。
- 不修改目标订单或开发数据库中的业务数据。
- 不按流程节点拆分字段级可编辑范围；本期按统一内容门禁开放整张订单表单。
- 不要求新建页展示订单状态、审计记录、锁单、费用、拆票或改配等仅在已落库订单上成立的能力。
- 本轮 UI 不新增数量统计接口、备注摘要/二次编辑模式、通用记录平台或无关请求层重构。

## Technical Notes

- 主流程规则继续由 `server/internal/biz/order_transition.go` 和响应字段
  `allowedTargetFlowStatuses` 决定。
- 状态 UI 的主要改动边界为 `OrderStatusSection.tsx`、`detail.tsx`、订单详情定向测试，以及
  列表页旧入口清理；编辑资格修复位于服务端动作投影与 `UpdateDraft` 仓储状态门禁，不新增
  API 字段、不修改数据库 Schema。
- Ant Design 6 采用原生 `Button` 语义实现可聚焦节点，确认交互采用 `App.useApp()` 提供的
  `modal.confirm`；异步 `onOk` 返回 Promise，由组件接管确认按钮 loading。
