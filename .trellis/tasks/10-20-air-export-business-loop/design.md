# 空运出口技术设计草案

状态：planning。prd.md 中 D1 已确认共享主单进入首期；Q2/Q3 仍待收敛。以下是基于该决策的设计建议，作为最终计划评审的内容。

## 1. 变更边界与数据流

差距主要在 AE 准入、空运专属字段、流程分支和前端注册。公共订单、权限、财务继续是唯一入口；空运和海运单证各自表达领域含义。

建议数据流：空运表单 → 生成客户端 → service 转换 → biz 按类型校验 → 公共订单事务和空运扩展 → 同事务版本及审计 → 重读详情。费用沿用现有用例，计费重作为明确的数量来源。

## 2. 订单和运输数据

- 公共 Order 保留公司、客户、业务类型、人员、货量摘要、编号、状态及版本。
- 建议一对一空运扩展仅保存本票空运专属资料；共同航司、航班和运输信息归共享主单/运输计划，不在各票重复形成可独立修改的副本；不用 shipping_line_id 保存航司，不用 vessel_voyage 保存航班。
- 机场复用已有 AE/AI 地点校验与主数据，先核对现有字段语义，避免重复存储。
- SE/AE 分别做领域校验，未知业务继续拒绝；草稿允许暂缺操作资料，节点完成时校验已确定的必需字段。
- 时间契约携带明确时区，持久化为明确时刻，展示复用 formatDate；不能把本地字符串直接视为 UTC。
- 公共订单和空运扩展同事务；一对一扩展建议由订单版本统一管理。

## 3. 共享航空主运单（D1 已确认）

### 3.1 实体与归属

一个 MAWB 通过显式关联连接多票 AE Order；每票维护自己的客户、人员、货物、费用及分单信息。建议沿用当前海运“一操作票对应一活动分单”的管理方式，但不把海运的 DIRECT/HOUSE 限制、号码复用规则自动搬到空运；具体分单基数和无分单场景在最终字段矩阵中明确。

| 建议实体 | 职责和关键约束 |
| --- | --- |
| AirMasterWaybill | 共同公司归属、主运单身份、航司、内容/确认状态、版本；同公司身份唯一规则由号码契约明确 |
| AirMasterWaybillOrderLink | 主单与订单关联、ACTIVE/ENDED、版本、建立/结束时间及原因；建议每票同时最多一个活动主单，保留历史关联 |
| AirHouseWaybill | 本票分单及其主单关联、签发资料、状态、版本；读取和修改校验真实归属 |
| 共享运输计划 | 权威机场、航班和起降时间；首期建议一个计划，优先放在主单内容中，只有独立修改生命周期确有必要才拆实体 |
| 本票空运扩展 | 本票专属资料与确认货量；随 Order 版本管理，不重复拥有共享运输事实 |

上表名称为设计建议，未创建 schema。MAWB/HAWB 的号码格式、规范化和唯一范围需形成明确契约；不能套用海运号码规则。通用 OrderShippingDocument 无法承载上述关系，采用空运专属实体；不在 SeaMasterBill/SeaHouseBill 中保存航空单证。

### 3.2 创建、关联与解除

1. 建单可选择新建主单或关联同公司已有主单。候选展示号码、航司、共享运输信息及版本，用户明确选择后提交 ID 和 expected version。
2. 服务端在事务内验证主单身份、公司、状态和版本；同号冲突返回候选/冲突提示，不静默拼单，不按字符串相同复制或合并主单。
3. 草稿建议允许暂未关联主单，进入需主单的业务节点前必须完成关联；具体必填时点写入状态矩阵。
4. 解除关联须显示影响、校验本票及必要共享门禁、记录原因并结束 Link；不删除主单、其他成员和历史分单。终止订单在同一事务结束活动关联，恢复不自动复活旧关联。
5. 换主单是独立明确命令，禁止借普通整单保存暗中改配；复杂改配仍为延期建议。关联历史可追溯到当时主单及分单关系。

### 3.3 共享修改、权限与并发

- 共享字段通过主单明确操作修改，展示受影响成员和阻断原因；普通整单更新不能携带旧副本覆盖共享字段。
- 对共享修改校验所有受影响订单的业务权限和组织范围；无权成员的细节不泄漏，不能仅凭能编辑 A 就修改 A/B 的共同资料。
- 按既有共享海运规范建议：任一活动成员锁定、终止中或结案时，阻止改变其共享事实；本票私有字段未影响主单时只校验本票。该行为作为 AC3b 的最终评审规则。
- 建议所有相关写入采用统一锁序：预读成员 ID → 参与订单按 ID 排序 FOR UPDATE → 主单 → Link → 分单及后续实体。锁后重验成员集合、权限、状态和 expected versions；集合变化返回冲突，不在锁主单后追加订单锁。
- 加入/退出、共享更新、业务锁、终止等路径共同遵循锁序；主单版本变化应覆盖成员关系变化，防止候选确认期间成员集合悄悄改变。
- 共享主单内容版本与关键关联变更留历史；AE 锁单如需单证快照，新增空运专属引用，不能复用仅供 SE 的海运快照外键。解锁不改写过去版本。
- 先预览影响再提交，执行端锁内重验，不将预览当作最终授权。主单、关联、版本和审计同事务提交。

### 3.4 汇总与费用边界

主单展示有效成员的件数、毛重、体积汇总；单证申报/确认数量若不同应独立标明，不自动覆盖票货量。解除关联后当前汇总重算，历史版本保留原事实。

费用继续按订单独立维护；主单确认重量不直接复制给每票，不能将整主单费用或总量重复计入所有订单。自动成本分摊不因共享主单获准而进入本期范围。

### 3.5 界面行为

订单页提供“新建/关联主运单”和主单摘要；共享主单详情显示共同资料、成员票及分单、汇总和历史。修改共享信息前展示影响范围；本票字段清楚标为本票维护。成员列表和候选均按现有分页、权限及服务端搜索规范实现。

## 4. 计费数量与金额边界

- 毛重与确认计费重分开；计费重使用 decimal/numeric，登记确认人、时间、依据和修改审计。
- KG 保持重量单位语义；毛重/确认计费重由明确来源区分，不能改写原 KG 分支。
- 当前预览契约仅有 PLANNED/ACTUAL。实施时选择扩展来源或新增数量依据参数，一次性同步 Proto、后端、OpenAPI、前端和测试。
- 缺确认计费重时返回不可带入及原因；人工录费继续受原审核、锁、数值约束。
- 首期建议人工确认；如 Q2 要自动计算，规则必须明确单位、除数、汇总层级和舍入，展示输入与公式，人工覆盖留痕。
- 修改货量不自动更改旧费用；应收、应付可分别确认费用数量，不能强制使用同一个最终结算重量。共享主单的航司确认重量与本票费用数量分层记录；本票来源不足时不能自动取整主单重量，分摊规则不在本次确认之内。

## 5. 流程、时效与生命周期

建议节点：草稿 → 已订舱 → 已配舱 → 拖车已安排（可跳过）→ 已截单 → 报关已安排 → 已签单。这是待确认方案，不是普遍行业流程声明。

biz 按业务类型给出允许动作，仓储锁内复验。现有状态语义足够时不新增枚举；若 Q3 改变语义，同步数据库 CHECK、Proto、前端文案及完成条件。

节点明确必需资料、适用条件、责任人与完成记录，复用里程碑，不恢复退役模板平台。订舱/配舱与费用审核分别管理，不假定配舱自动冻结运价。

签单、业务锁、终止及财务结案独立。AE 结案复用活动异常、未建账费用、待审补录等门禁；关联结束/恢复遵循第 3 节，不隐式复活历史关系。主单签发状态和成员订单操作状态分别记录，不因主单一次更新自动推进所有成员订单。

超时建议先在列表/详情呈现，复用异常记录；定时外发通知或逾期硬阻断需明确范围后加入。

## 7. 服务端与一致性

重点入口：order_usecase.go、order_transition.go、order_write*.go、order_sync.go、订单 Proto、空运 schema、费用预览和读取投影。

组织校验绑定目标 ID 和允许公司；人员使用现有成员校验。复用幂等键、expected_version 和事务封装，共享写入按第 3 节锁序统一实现。新增空运主单/关联/分单命令时同步 ProviderSet、HTTP/gRPC 注册与 Wire，服务分组在契约设计中确定。

## 8. 迁移和回退

Ent Schema 为源，追加正式迁移，在隔离测试库验证；契约生成物与源文件同步提交。按上线前规范一次性更新内部调用方，不添加历史双读/双写，不清空业务数据。

按阶段提交可验证变更，菜单在闭环具备条件时开放。若已有 AE 数据，不能直接回退到无法识别它的旧代码；暂停 AE 入口并使用兼容当前数据的已验证版本或修复迁移，保留业务记录。

主要回归风险为公共订单/费用契约以及公共页面；SE 与 AE 分别验证。
