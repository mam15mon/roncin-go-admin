# 总部工作台只读与分公司业务办理边界

## 目标
总部工作台仅进行治理、公共配置维护和授权范围内的业务查看；所有经营办理必须进入获授权的分公司工作台，避免总部上下文误办或跨公司写入。

## 已确认决策与现状
- 用户明确选择限制「总部工作台」，不限制总部人员身份；有资格和权限的人员可切换分公司办理。
- 用户已批准最终方案并明确「好的，开始吧」；进入实施。
- 现有组织层级为 headquarters/company/department/team，复用 company 为经营主体，不引入租户实体。
- `server/internal/biz/auth.go:326` 目前将角色组织范围同时放入读写集合，初始化管理员覆盖全部启用组织。
- `server/internal/data/organization_operating.go:17` 已限制经营根对象归属启用公司；现行经营归属规范仍放行显式目标公司的部分跨组织财务路径，本任务收紧这条例外。
- 现有组织切换已轮转会话、重算权限、确认脏表单、清理订单候选缓存并重建工作区。

## 需求
- R1：总部禁止经营写入，包括客户及其经营附属资料、订单及附件/人员/标签/单证/状态、费用/补录/解锁审批、账单/发票/收付款/核销/对冲/提成及业务申请审批。读取、下载和只读导出沿用授权范围；会产生经营记录或状态变化的操作属于写入。
- R2：分公司办理同时满足当前工作台为启用 company、相应操作权限、目标归属为当前公司。读取权限不自动授权写入；初始化管理员不能绕过工作台边界。
- R3：总部组织、账号、角色、公共主数据及现有总部基线/治理配置维护继续按现有权限与归属规则办理。企业资源等现有主数据分类不因权限前缀被误禁。提成配置与业务计提/确认/付款须按实际动作区分。
- R4：总部业务列表及详情只读，保留现有授权查看和公司筛选；业务办理按钮、快捷入口、编辑路由及首页经营待办入口同步受控。第一期复用现有统计能力，不新增经营指标接口。
- R5：组织切换保留现有资格校验和会话轮转；切换成功后权限、页面、缓存按新工作台生效，取消脏表单确认或切换失败维持原工作台。切换权限不自动授予业务权限。
- R6：不自动迁移或清理总部存量业务。发现不合规数据时只输出按实体计数及关系问题，另行明确处置；新写入必须受约束。

## 验收
- A1（R1/R2）：总部普通用户及管理员直接调用经营写 API 均失败，无单据、号码、文件关联或审批状态副作用；显式传入分公司 ID 不能绕过。
- A2（R2）：A 公司可正常完成授权业务链；以 B 公司 ID、B 公司单据 ID 或混合批量请求写入失败且不部分提交。
- A3（R3/R4）：总部既有公共配置维护与授权读取正常；业务页面、详情和首页无可办理入口；只读导出不因统一禁写误伤。
- A4（R5）：同一用户总部→获授权分公司→总部，业务能力随会话变化；未授权切换拒绝；脏表单取消、切换失败、旧请求返回均不污染新工作台。
- A5（R6）：不得清库、自动改挂组织或重置数据；检查如未连接数据库明确报告未核验。
