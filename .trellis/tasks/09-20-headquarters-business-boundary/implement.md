# 执行计划

## 启动门槛
- [x] 用户确认总部工作台不能办理、总部人员可获授权切换。
- [x] 创建规划任务，完成 PRD、设计和上下文清单。
- [ ] 用户审阅并批准最新最终摘要后，运行 task.py start。

## 实施步骤
1. 检查工作区与目录 AGENTS，保留其他任务改动；按 Trellis 要求加载规范并安排 implement/check 子代理，明确文件所有权。
2. 枚举权限与端点映射，形成管理/只读/经营办理动作清单。重点覆盖订单动态权限、客户附属资料、财务批量动作、审批、标签附件、导入、业务重试及混合权限。不得仅按命名后缀匹配。
3. 实现 biz 工作台动作边界与权限输出一致性；经营写范围收敛为当前公司，并检查管理员及显式目标旁路。实施后补针对性测试，禁止 TDD。
4. 检查服务端写路径与仓储过滤，验证关联对象及批量跨公司拒绝；后台任务不受交互总部身份误判。
5. 更新前端 access 消费、路由/按钮/详情/首页入口；复用切换机制并补实际缓存或旧请求缺口。如契约发生变化先生成。
6. 核查存量归属（仅在有可用连接时只读执行），输出结果；不自动改挂或清理。
7. 更新经营归属与权限规范，删除已被本任务替代的跨组织业务办理例外；审查改动并提交。

## 验证
- 后端按变更运行 `go -C server test -p 32 ./internal/access ./internal/biz ./internal/service ./internal/server`，数据层变化时加定向 data 测试。
- 前端用 `pnpm --dir web exec vitest run <受影响测试路径>`；修改文件 Biome 与 `pnpm --dir web tsc`。
- 权限/契约变更执行 `pnpm run generate:permission-keys`、必要的 `make -C server api` 和 `pnpm run generate:web-client`，检查生成差异。
- 每组提交前 `git diff --check`；最终因跨领域权限风险运行 `pnpm run check:fast`。
- 集成验证检查数据库环境是否可用及用例是否实际运行，不能将 skip 记作通过；不得打印连接秘密或重置开发数据库。

## 风险检查
权限投影与 API 鉴权不一致、管理员绕过、混合权限误禁总部配置、共享上传间接写入、批量部分成功、组织切换旧请求污染。以 PRD A1—A5 为最终验收映射。
