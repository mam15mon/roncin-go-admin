# 锁单后费用补录与提成冲减建议

## Goal

用最小闭环解决“提成已确认或发放后发现漏录成本”的问题：锁定前的费用保持不可修改、不可删除；业务人员可以发起一笔新的锁后补录费用，经有资格人员审批后进入原订单台账；系统自动生成可追溯的提成冲减调整草稿，由财务在后续提成处理时确认。

## Background

- 当前订单一旦业务锁定，费用新增、修改、状态流转和作废都会被后端统一拒绝；提成确认或发放且有效净额大于零时，还会形成独立的财务锁。
- 因此，即使用户完成订单解锁，只要财务锁仍存在，仍然无法录入真实发生的迟到成本，解锁申请会成为无效工作。
- 提成调整记录只能处理员工提成差额，不能代替订单应收、应付事实；真实费用仍必须进入订单台账，才能参与后续对账、账单、收付和实际利润。
- 当前系统已有提成增提/冲减调整及确认、标记已发放或已扣回能力，可以复用为冲减建议确认后的执行记录。
- 当前费用金额必须为正数，尚无负数费用、红字账单、贷项通知单和已核销费用冲销闭环；本期不建设这些重型能力。
- 现有毛利提成按累计已实现收入比例分摊总成本；现有外币费用按费用发生日期解析并固化汇率。本期沿用现有计算口径，不重新定义会计制度。

## Requirements

### 1. 锁定与既有费用

- 订单锁定后，锁定前已经存在的费用不可修改、不可删除、不可作废、不可变更状态。
- 订单解锁只恢复普通业务资料和未形成财务不可变事实的编辑能力；不得绕过提成确认或发放形成的财务约束。
- 本期仅支持“新增一笔真实费用”的补录，不支持引用旧费用做减额更正，也不支持用负数费用伪装冲销。
- 既有费用错录，尤其是已建账、已开票或已核销费用的更正，继续按现有财务处理或线下处理，后续另立专项能力。

### 2. 锁后补录费用申请

- 对目标订单具备相应费用新增权限和数据范围的业务人员，可以在不解锁订单的情况下发起【补录费用】。
- 补录仅允许新增正数应收或应付，必须填写费用发生日期、币种、金额、结算对象、补录原因及现有费用所需字段。
- 补录申请提交时固化申请内容快照；审批过程中不得静默修改金额或关键字段。需要改动时撤回或驳回后重新申请。
- 审批人复用现有“对目标订单具有直接解锁资格”的人员范围，可配置为一人或多人；发起人同时具备该资格时允许自行审批。
- 审批补录费用不解除订单锁，也不开放原费用编辑入口。
- 审批通过后，在同一事务中创建一条与申请关联的已确认订单费用；审批驳回不产生订单费用。
- 同一申请只能生成一条费用，重复请求或并发审批不得重复入账。

### 3. 补录费用进入订单财务链路

- 审批通过的补录费用与普通已确认费用使用相同的订单费用、建账、对账、开票、收付和利润展示链路。
- 新费用保留真实费用发生日期，并沿用现有规则按该日期解析、固化外币汇率；不得用审批日期、提成日期或订单月份静默替代。
- 本期不新增财务记账期间、关账、总账凭证或历史报表重述能力；费用发生日期不等同于会计过账期间。

### 4. 提成冲减建议与现有调整记录

- 补录应付审批生效后，如果该订单已经存在已确认或已发放的提成，系统按原提成的人员归属、计提口径、比例、规则版本、计算版本和现有已实现范围重新计算其影响。
- 对每笔受影响的原提成，系统直接生成现有提成调整模型中的 DECREASE + DRAFT 记录；页面将这种系统来源的调整草稿展示为【待处理的提成冲减建议】，不新增第二套建议实体。
- 系统来源必须扩展为可识别的“锁后费用补录”，并关联补录申请、新费用、原订单、原提成和员工，禁止与人工调整或核销/对冲冲减混淆。
- 建议金额由系统计算，不允许手工改金额；计算结果为零时不生成建议。
- 多人参与提成时按人员分别生成建议，不得把多人影响合并成一条不可追溯的总额。
- 补录应收正常进入订单台账；尚未产生新核销或对冲时，不提前生成正向增提建议。正向增提继续由现有提成生成流程按实际实现处理。
- 原提成记录、原发放记录和原费用事实均不得回写。DRAFT 只表示“建议以后少发”，不表示员工已经退钱，也不表示财务已经实际扣回。
- 财务在当月或后续月份处理提成时，可以一键确认建议，使现有冲减调整由 DRAFT 转为 CONFIRMED；实际在线下少发后，继续复用现有“标记已扣回”动作转为 PAID。
- 系统不计算员工跨月余额、不自动从工资或下月提成中扣款，也不控制实际发放金额。
- 被建议冲减的员工必须收到通知并能查看来源明细；通知用于知情，不赋予其否决真实费用的权力。

### 5. 并发、幂等与审计

- 同一订单的补录审批、费用创建、提成影响计算和建议生成必须以订单为互斥点串行执行，并处于同一事务中。
- 建立申请到费用、申请与原提成/员工到冲减建议的唯一约束，保证审批重试和并发请求不会重复生成费用或重复冲减。
- 必须记录发起人、审批人、申请时间、审批时间、补录原因、费用快照、计算依据、建议金额、财务确认人及确认时间。
- 任何一步失败时不得出现“费用已入账但建议未生成”或“建议已生成但费用未入账”的部分成功状态。

### 6. 业务完结与锁定语义

- 业务锁由具备权限的人员通过提交业务完结显式触发，不依赖开航、到港或固定天数自动判断。
- 业务完结时不得存在费用草稿；已确认但尚未建账的费用不阻塞业务完结，后续仍可正常进入财务流程。
- 提成确认或发放后的财务约束由系统自动判定，不要求用户再点一次财务锁定。

## Acceptance Criteria

- [ ] 锁单后原有费用的修改、删除、作废和状态变更继续被后端拒绝，前端不展示可误导的普通编辑入口。
- [ ] 有费用新增权限的业务人员无需先解锁订单，即可发起一笔正数应收或应付补录申请。
- [ ] 任一对该订单具有直接解锁资格的人员可以审批；具备资格的发起人可以自行审批，审批不改变订单锁定状态。
- [ ] 审批通过只新增一条已确认费用；审批驳回不产生费用；重复或并发审批不会重复入账。
- [ ] 新费用可以正常进入订单账单、对账、开票、收付和利润展示链路，并保留费用发生日期及对应汇率事实。
- [ ] 补录应付影响已确认或已发放提成时，系统按受影响的原提成分别生成现有模型中的 DECREASE + DRAFT 调整，金额不可手改且来源明确为锁后费用补录。
- [ ] 原费用、原提成和原发放记录保持不变；冲减建议草稿不会被展示成已经扣回。
- [ ] 财务可以在当月或后续月份查看来源并一键确认冲减建议；确认只把现有调整转为 CONFIRMED，实际少发后仍由现有“标记已扣回”转为 PAID。
- [ ] 补录应收在未形成新核销或对冲前不会提前生成增提；按收入计提且实现收入未变化时，补录应付不会错误冲减提成。
- [ ] 多人提成时每名受影响员工都能收到通知并查看订单、原提成、补录费用和建议金额。
- [ ] 同一订单多笔补录并发审批时串行计算；事务失败、接口重试或重复点击均不会产生重复费用、重复建议或部分成功。

## Out of Scope

- 既有费用的追加式更正、负数费用、贷项通知单、红字账单、退款和抵扣下一张账单。
- 员工负余额台账、跨月自动滚存、自动抵扣算法、月度提成发放批次和系统控制实际打款。
- 自动扣工资、要求员工退现、离职员工追偿、公司核销及其总账处理。
- 财务会计期间、月结开关、总账过账、税务申报和外部财务系统集成。
- 未实现应收对应的自动正向增提建议。
- 历史数据兼容、双读双写或数据库自动重建。

## Key Decisions

- 【待处理的提成冲减建议】复用现有 FinanceCommissionAdjustment，数据状态为 DECREASE + DRAFT，不新增建议表。
- 财务确认复用现有调整确认状态机；确认后为 CONFIRMED，线下实际少发后再标记为 PAID。
- 本期不建设员工余额和自动发放控制；未处理草稿跨月份持续可见，本身即为待办事实。
- 审批人资格复用现有订单直接解锁资格，不新增另一套主管或负责人配置。

## Risks and Deferred Items

- 当锁后新增成本造成的理论负向影响超过该原提成尚可冲减金额时，现有调整状态机不得使有效提成小于零；超出部分不转为员工欠款，后续是否建设余额追偿另立任务。
- 人工调整与系统建议并发确认时，现有乐观锁和有效金额校验可能要求财务刷新后重新处理；系统不得为保证“自动成功”而突破有效提成不小于零的约束。
- 原费用减额、已建账/开票/核销后的冲销仍是独立财务专题，不得用本功能的正数补录入口绕过。
