# 锁单后费用补录与提成冲减建议

## Goal

用最小闭环解决“提成已确认或发放后发现漏录成本”的问题：锁定前的费用保持不可修改、不可删除；业务人员可以发起一笔新的锁后应付成本补录，经有资格人员审批后进入原订单台账；系统自动生成可追溯的提成冲减调整草稿，由财务在后续提成处理时确认或忽略。同时在最后一笔有效应收结清后自动封存符合条件的订单，降低依赖人工锁单造成的漏锁风险。

## Background

- 当前订单一旦业务锁定，费用新增、修改、状态流转和作废都会被后端统一拒绝；提成确认或发放且有效净额大于零时，还会形成独立的财务锁。
- 当前业务锁由具备权限的人员通过独立「锁定订单」动作人工触发，依赖人工执行，存在忘记锁定导致业务资料长期不封存的风险。
- 因此，即使用户完成订单解锁，只要财务锁仍存在，仍然无法录入真实发生的迟到成本，解锁申请会成为无效工作。
- 提成调整记录只能处理员工提成差额，不能代替订单应付事实；真实费用仍必须进入订单台账，才能参与后续对账、账单、付款和实际利润。
- 当前系统已有提成增提/冲减调整及确认、标记已发放或已扣回能力，可以复用为冲减建议确认后的执行记录。
- 当前费用金额必须为正数，尚无负数费用、红字账单、贷项通知单和已核销费用冲销闭环；本期不建设这些重型能力。
- 现有毛利提成按累计已实现收入比例分摊总成本；现有外币费用按费用发生日期解析并固化汇率。本期沿用现有计算口径，不重新定义会计制度。

## Requirements

### 1. 锁定与既有费用

- 订单锁定后，锁定前已经存在的费用不可修改、不可删除、不可作废、不可变更状态。
- 订单解锁只恢复普通业务资料和未形成财务不可变事实的编辑能力；不得绕过提成确认或发放形成的财务约束。
- 本期仅支持“新增一笔真实费用”的补录，不支持引用旧费用做减额更正，也不支持用负数费用伪装冲销。
- 既有费用错录，尤其是已建账、已开票或已核销费用的更正，继续按现有财务处理或线下处理，后续另立专项能力。

### 2. 锁后补录费用申请

- 对目标订单具备相应费用新增权限和数据范围的业务人员，可以在不解锁订单的情况下发起【补录费用】。
- 补录仅允许新增正数应付成本，应收方向由后端拒绝；必须填写费用发生日期、币种、金额、结算对象、补录原因及现有费用所需字段。
- 补录申请提交时固化申请内容快照；审批过程中不得静默修改金额或关键字段。需要改动时，由发起人在待审批状态撤回，或由审批人驳回后重新申请。
- 发起人只能撤回本人仍处于 PENDING 的申请；撤回必须携带 expectedVersion。撤回与审批并发时在同一申请行锁内竞争，只有先提交的一方成功，另一方返回状态冲突；撤回成功不得创建费用或提成调整。
- 审批人复用现有“对目标订单具有直接解锁资格”的人员范围，可配置为一人或多人；发起人同时具备该资格时允许自行审批。
- 审批补录费用不解除订单锁，也不开放原费用编辑入口。
- 审批通过后，在同一事务中创建一条与申请关联的已确认订单费用；审批驳回不产生订单费用。
- 同一申请只能生成一条费用，重复请求或并发审批不得重复入账。

### 3. 补录费用进入订单财务链路

- 审批通过的补录应付与普通已确认应付使用相同的订单费用、建账、对账、付款和利润展示链路；不生成应收或正向增提。
- 补录费用审批通过即为 CONFIRMED，应直接出现在现有应付建账候选中；订单处于业务锁或财务锁不阻断后续建账。建账后费用按现有链路转为 BILLED，取消一个没有有效发票、核销或对冲占用的账单后，费用按现有链路恢复为 CONFIRMED，无需解锁订单。
- APPROVED 申请本身保持不可变，不允许撤回。确需作废它生成的补录费用时，使用专用【作废补录费用】动作，不开放普通费用删除入口：操作者必须实时具备与补录审批相同的直接解锁资格，填写必填原因，并携带费用 expectedVersion。
- 专用作废只允许处理仍为 CONFIRMED、没有活动账单行、没有更晚生效且尚未作废的补录费用，并且其关联冲减调整全部仍为 DRAFT 或 CANCELLED 的费用；同一订单多笔补录需要按审批生效时间倒序作废。作废事务把费用转为 CANCELLED，并把该补录来源仍为 DRAFT 的冲减建议同步转为 CANCELLED，申请仍保持 APPROVED 并展示生成费用已作废，所有事实永久保留。
- 补录费用已经 BILLED 时，必须先按现有财务链路取消账单；账单已有发票、核销或对冲时，先按现有能力撤销对应下游事实。任一关联冲减已为 CONFIRMED 或 PAID 时，不允许直接作废补录费用，因为这将需要正向恢复提成；该恢复能力和已建账后无法撤销事实的红冲处理不在本期范围。
- 新费用保留真实费用发生日期，并沿用现有规则按该日期解析、固化外币汇率；不得用审批日期、提成日期或订单月份静默替代。
- 本期不新增财务记账期间、关账、总账凭证或历史报表重述能力；费用发生日期不等同于会计过账期间。

### 4. 提成冲减建议与现有调整记录

- 补录应付审批生效后，如果该订单已经存在已确认或已发放的提成，系统按每条原提成订单行独立计算该笔新增成本造成的边际影响；不得先算订单或员工总冲减额后再按 FIFO、LIFO 或人为比例分摊到多张原提成单。
- 同一订单存在多张原提成单时，每张原提成单只承担其自身历史已实现收入对应的影响。系统使用该原提成行固化的人员归属、已实现收入、历史总应收/总应付分母、计提口径、比例、规则版本和计算版本计算，并把调整挂回该原提成单；不同原提成单之间不得相互占用或顺延可冲减额度。
- 对每笔受影响的原提成，系统直接生成现有提成调整模型中的 DECREASE + DRAFT 记录；页面将这种系统来源的调整草稿展示为【待处理的提成冲减建议】，不新增第二套建议实体。某张原提成单的可冲减余额不足时，只在该单上截断到零，超出部分进入审计，不转扣其他原提成单。
- 系统来源必须扩展为可识别的“锁后费用补录”，并关联补录申请、新费用、原订单、原提成和员工，禁止与人工调整或核销/对冲冲减混淆。
- 建议金额由系统计算，不允许手工改金额；计算结果为零时不生成建议。
- 多人参与提成时按人员分别生成建议，不得把多人影响合并成一条不可追溯的总额。
- 历史影响计算必须使用原提成生成时固化的显式计算输入和对应版本的纯计算器，严禁通过原 RuleID 查询当前提成规则表，也不得读取当前总应收来改变历史分母。规则后来被修改或停用，不得改变已经形成的冲减结果；未来即使允许删除规则，也不得影响历史复算。
- 每次补录应付只计算该笔费用加入前后的增量影响；此前已审批且尚未作废的补录费用，无论其建议后来确认还是被忽略，都只作为历史计算事实，不得在后续补录时重复生成同一段冲减。已经按专用动作作废的补录费用不再进入后续补录的成本基线。
- 原提成记录、原发放记录和原费用事实均不得回写。DRAFT 只表示“建议以后少发”，不表示员工已经退钱，也不表示财务已经实际扣回。
- 财务在当月或后续月份处理提成时，可以一键确认建议，使现有冲减调整由 DRAFT 转为 CONFIRMED；实际在线下少发后，继续复用现有“标记已扣回”动作转为 PAID。
- 财务可以对 DRAFT 系统建议选择【忽略建议】，复用现有调整取消能力转为 CANCELLED；必须填写原因并保留操作人、时间和来源。被忽略的建议不再参与有效提成，但不删除补录费用和历史建议事实。
- 系统不计算员工跨月余额、不自动从工资或下月提成中扣款，也不控制实际发放金额。
- 被建议冲减的员工必须收到通知并能查看来源明细；通知用于知情，不赋予其否决真实费用的权力。

### 5. 并发、幂等与审计

- 同一订单的补录审批、费用创建、提成影响计算和建议生成必须以订单为互斥点串行执行，并处于同一事务中。
- 建立申请到费用、申请与原提成/员工到冲减建议的唯一约束，保证审批重试和并发请求不会重复生成费用或重复冲减。
- 必须记录发起人、审批人或撤回人、申请时间、审批或撤回时间、补录原因、费用快照、原提成计算输入快照、计算依据、建议金额、财务确认/忽略人及时间和忽略原因。
- 任何一步失败时不得出现“费用已入账但建议未生成”或“建议已生成但费用未入账”的部分成功状态。

### 6. 业务锁定触发

- 现状是业务锁由具备权限的人员通过独立「锁定订单」动作人工触发；本任务增加结清事件驱动的系统自动锁定，人工锁定保留为提前封存的兜底，不新建业务完结状态或完结流程。
- 自动锁定由有效结清事件驱动：应收核销创建生效或应收对冲确认生效后，系统逐一检查该动作实际影响的订单；某订单至少发生过一次有效应收结清事件，且动作完成后不再存在任何未结清的已确认应收时，进入自动锁定资格检查。
- 自动锁定资格除复用现有订单锁定校验与 SE 单证版本快照外，额外要求订单不存在费用草稿。仅有部分应收结清、仍有未建账的已确认应收或存在费用草稿时不得自动锁定。
- 从未发生有效应收结清事件的订单，包括纯成本订单、从未产生应收的订单以及仅有已作废应收的订单，不纳入自动锁定，继续由有权限人员手动锁定；是否为其增设触发点留待出现真实需求时另议。
- 自动锁定资格不满足或执行失败时，不得阻塞、回滚或改变已经成功的核销、对冲或费用状态流转；由后续费用草稿确认/作废及下一次应收核销创建生效、应收对冲确认生效事件重新检查，不建全量定时扫描。极少数仍未自动锁定的订单由人工锁定兜底。
- 自动锁定事务必须先取得目标订单的 FOR UPDATE 行锁，并在同一锁持有期内重新检查有效结清事实、订单级未结清应收、费用草稿及现有锁定条件，然后写入锁定事实。订单费用新增、修改、确认、作废，补录审批、补录费用作废，反核销和反对冲必须按 Order 优先的固定锁序与自动锁定串行；等待锁后发现条件变化时放弃本次自动锁定。反核销或反对冲取得 Order 行锁只用于并发互斥，不得因订单已经锁定而禁止财务反转。
- SE 订单只有一个活动成员时按单票自动锁定；多张活动订单共用同一 MBL 时采用组级自动锁定门禁。系统必须定位该 MBL 的全部活动成员并按 Order UUID 升序一次性加锁，只有所有尚未锁定成员各自满足自动锁定条件时，才在同一事务中锁定全部尚未锁定成员；任一成员不满足时整组不自动锁定。已经人工或自动锁定的成员视为已完成，但必须属于锁内重验后的同一活动成员集合。
- 共用 MBL 组级自动锁定在全部成员 Order 之后再锁 MBL、全部活动 Link、共享运输执行与各成员 HBL，锁后重验活动成员集合；集合变化或快照条件冲突时整体放弃，不产生部分锁定。整组锁定复用同一份 MBL/运输执行不可变版本，每张成员票仍生成自己的锁定记录和 HBL 快照。手工锁单保持现有单票语义，用户主动锁定任一成员仍会冻结共享 MBL；自动锁单不得因某一成员提前结清而抢先冻结其他未完成成员的共享主单。
- 自动锁定在页面和审计中归属为【系统自动锁定】，不归责给触发核销、对冲或费用状态流转的操作人，也不要求该操作人具备订单锁定权限；系统另行记录触发类型、触发单据和触发操作人。人工锁定仍归属实际锁定人。
- 自动锁定一旦成功，后续反核销、反对冲或应收余额恢复不会自动解锁或删除锁定事实；需要修改业务资料时继续走现有显式解锁流程。
- 可手动锁定的人员范围沿用现有权限配置，手动锁定与自动锁定走同一锁定事务与快照逻辑。
- 不以发车、开航、到港或固定天数等时间条件自动判断业务完成。
- 提成确认或发放后的财务约束由系统自动判定，不要求用户再点一次财务锁定。

## Acceptance Criteria

- [ ] 锁单后原有费用的修改、删除、作废和状态变更继续被后端拒绝，前端不展示可误导的普通编辑入口。
- [ ] 有费用新增权限的业务人员无需先解锁订单，即可发起正数应付成本补录申请；应收方向即使绕过页面直接请求也被后端拒绝。
- [ ] 任一对该订单具有直接解锁资格的人员可以审批；具备资格的发起人可以自行审批，审批不改变订单锁定状态。
- [ ] 审批通过只新增一条已确认费用；审批驳回不产生费用；重复或并发审批不会重复入账。
- [ ] 发起人可以撤回本人仍待审批的申请；撤回与审批并发时只有一个状态迁移成功，撤回成功不产生费用或提成调整。
- [ ] 新应付可以正常进入订单应付账单、对账、付款和利润展示链路，并保留费用发生日期及对应汇率事实。
- [ ] 审批生成的 CONFIRMED 补录应付无需解锁即可进入现有建账候选并转为 BILLED；无有效发票、核销或对冲的账单取消后，费用恢复为 CONFIRMED。
- [ ] 最新一笔仍为 CONFIRMED、未进入活动账单且冲减建议尚未确认/扣回的补录费用，可以由合格人员填写原因后通过专用动作作废；费用与仍为 DRAFT 的关联建议在同一事务转为 CANCELLED。存在更晚有效补录、活动账单行或 CONFIRMED/PAID 冲减时稳定拒绝，不出现费用作废但冲减仍生效的部分状态。
- [ ] 补录应付影响已确认或已发放提成时，系统按每条原提成订单行的历史快照独立生成 DECREASE + DRAFT 调整；同一订单多张原提成不做 FIFO/LIFO 分摊，也不把某张单的不足额顺延到其他原提成。
- [ ] 修改或停用当前规则配置不影响冲减复算；补录应付不会改变原提成历史总应收分母，历史计算路径不读取当前总应收。
- [ ] 原费用、原提成和原发放记录保持不变；冲减建议草稿不会被展示成已经扣回。
- [ ] 财务可以在当月或后续月份查看来源并一键确认冲减建议；确认只把现有调整转为 CONFIRMED，实际少发后仍由现有“标记已扣回”转为 PAID。
- [ ] 财务可以填写必填原因忽略 DRAFT 冲减建议，建议转为 CANCELLED 并永久保留审计，不形成僵尸待办。
- [ ] 按收入计提且实现收入未变化时，补录应付不会错误冲减提成。
- [ ] 多人提成时每名受影响员工都能收到通知并查看订单、原提成、补录费用和建议金额。
- [ ] 同一订单多笔补录并发审批时串行计算；事务失败、接口重试或重复点击均不会产生重复费用、重复建议或部分成功。
- [ ] 应收核销创建生效或应收对冲确认生效后，系统逐一检查本次动作影响的订单；订单至少发生过一次有效结清事件、无未结清已确认应收、无费用草稿且现有锁定校验通过时，自动完成业务锁定及必要的 SE 单证版本快照。
- [ ] 部分结清、存在未建账已确认应收、存在费用草稿，或者从未发生有效应收结清事件的订单不会被自动锁定；纯成本和仅有作废应收的订单仍可由有权限人员手动锁定。
- [ ] 自动锁定失败不影响原核销、对冲或费用状态流转成功；后续费用草稿确认/作废或新的有效结清事件会重新检查，不运行全量定时扫描。
- [ ] 自动锁定与订单费用写入、补录审批/作废、反核销或反对冲并发时按同一 Order 优先互斥线性化；自动锁定事务提交时，锁内复核仍满足无未结清已确认应收、无费用草稿及其他全部前置条件。若反核销或反对冲在锁定提交后发生，订单按既定规则保持锁定，不视为自动锁定错误。
- [ ] 共用 MBL 的多个活动成员不会因其中一票先结清而被部分自动锁定；全部尚未锁定成员均合格时才整组原子锁定并复用同一 MBL/运输执行版本，任一成员不合格、成员集合变化或快照失败时整组零写入。手工锁定任一成员的现有语义保持不变。
- [ ] 自动锁定显示为【系统自动锁定】并记录触发类型、触发单据和触发操作人；触发操作人未持有订单锁权限也不影响自动锁定，且不会被展示为实际锁定人。
- [ ] 自动锁定后发生反核销、反对冲或应收余额恢复时，订单仍保持业务锁定且原锁定记录/快照不变；只有现有显式解锁流程可以解除业务锁。

## Out of Scope

- 既有费用的追加式更正、负数费用、贷项通知单、红字账单、退款和抵扣下一张账单。
- 员工负余额台账、跨月自动滚存、自动抵扣算法、月度提成发放批次和系统控制实际打款。
- 自动扣工资、要求员工退现、离职员工追偿、公司核销及其总账处理。
- 财务会计期间、月结开关、总账过账、税务申报和外部财务系统集成。
- 锁后补录应收及其跨期累计成本分摊和自动正向增提建议；应收仍通过现有普通费用入口在允许写入时处理，不通过本期锁后补录入口。
- 已有关联冲减进入 CONFIRMED/PAID 后因补录费用作废产生的正向提成恢复，以及无法通过现有取消/反转释放的账单、发票、核销或对冲红冲。
- 业务完结状态、完结审批流程或按时间条件自动锁定的调度机制。
- 历史数据兼容、双读双写或数据库自动重建。

## Key Decisions

- 【待处理的提成冲减建议】复用现有 FinanceCommissionAdjustment，数据状态为 DECREASE + DRAFT，不新增建议表。
- 本期锁后补录只接受正数应付成本；应收补录和成本跨期重分摊另立任务。
- 财务确认复用现有调整确认状态机；确认后为 CONFIRMED，线下实际少发后再标记为 PAID。
- 财务忽略建议复用现有 CancelCommissionAdjustment：仅处理 DRAFT 建议，必填原因后转为 CANCELLED，不新增驳回表或第二套状态机。
- 多张原提成按各自不可变订单行快照独立重算并各自封顶；不采用 FIFO/LIFO，也不跨原提成单顺延不足额。
- 规则快照采用不可变显式字段与版本化计算器，不依赖当前规则主数据；现有行模型需补足历史总应收、总应付等复算输入。
- 补录申请增加 WITHDRAWN 终态；只有发起人可以在 PENDING 状态按版本撤回。
- 审批通过的补录应付直接复用现有建账链路；尚未被下游占用且冲减未确认的最新有效补录允许通过专用动作作废，费用和 DRAFT 建议原子取消，不改变 APPROVED 申请历史。
- 业务锁触发改为有效应收核销创建/对冲确认事件驱动，人工锁定保留为提前兜底；自动锁定额外要求不存在费用草稿，从未发生有效结清事件的订单不自动锁；失败重试挂在费用草稿确认/作废与后续有效结清事件上，不建全量定时扫描。
- 共用 MBL 的自动锁单采用活动成员组级门禁和全有或全无事务；任一尚未锁定成员未满足资格时整组不自动锁，避免一票提前结清冻结仍在操作的共享 MBL。手工锁单仍允许用户主动冻结单票及共享主单。
- 自动锁单归属系统，触发业务人员只作为审计操作者；锁定记录必须区分 MANUAL 与 AUTO_SETTLEMENT，不得伪造用户或借 bootstrap admin 绕过。
- 结清反转不自动解除业务锁；自动锁单与人工锁单一样，只能由现有显式解锁流程解除。
- 本期不建设员工余额和自动发放控制；未处理草稿跨月份持续可见，本身即为待办事实。
- 审批人资格复用现有订单直接解锁资格，不新增另一套主管或负责人配置。

## Risks and Deferred Items

- 当锁后新增成本造成的理论负向影响超过该原提成尚可冲减金额时，现有调整状态机不得使有效提成小于零；超出部分不转为员工欠款，后续是否建设余额追偿另立任务。
- 人工调整与系统建议并发确认时，现有乐观锁和有效金额校验可能要求财务刷新后重新处理；系统不得为保证“自动成功”而突破有效提成不小于零的约束。
- 本期不建设持久事件队列、后台补偿调度或全量扫描；若进程恰好在核销、对冲或费用流转事务提交后、自动锁定检查开始前中断，订单可能暂时保持未锁，依赖下一次相关事件重试或人工锁定兜底。需要消除此极小失败窗口时另立可靠事件投递任务。
- 共用 MBL 组内只要存在纯成本、从未产生有效应收结清事实或长期未完成的活动成员，整组就不会自动锁定；这是为避免自动冻结其他成员共享单证而接受的取舍，由有权限人员在确认整组业务完成后手工锁定兜底。
- 原费用减额、已建账/开票/核销后的冲销仍是独立财务专题，不得用本功能的正数补录入口绕过。
