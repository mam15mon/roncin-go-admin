# 移除费用独立状态，统一依据账单关联判断

## 目标

费用不再维护或展示独立的「费用状态」。是否已建账由有效账单关联决定，界面通过已有财务进度与账单信息表达进展，消除状态回写、重复筛选和统计口径分裂。

## 已确认事实

- 用户要求去掉冗余费用状态，不只是把数据库字段改为 API 计算枚举。
- 普通费用单条与批量删除已经是硬删除，且具有事务内账单占用检查、版本检查和审计：`server/internal/data/order_fee.go:685`、`:857`。本次保留该机制，不重新建设删除流程。
- 补录专用撤销仍把费用置为 CANCELLED，包含审批资格、批准时间倒序、冲减调整联动等业务规则：`server/internal/data/order_fee_supplement_cancel.go`。
- 取消账单后仍可能存在引用费用的历史账单行。历史行保留快照，费用删除后来源外键置空：`server/internal/data/ent/schema/finance_bill_line.go:14`。
- 影响面及旧清单修正见 `research/status-consumer-inventory.md`，本 PRD 与 design.md 是本次实施决策源。

## 需求

### R1：彻底移除费用状态

删除持久化费用状态、领域费用状态枚举、API 费用状态字段及前端费用状态列/筛选/映射；不保留 UNBILLED/BILLED 两态的 OrderFee.status 兼容投影。范围覆盖订单费用表、费用面板、建账工作台、费用台账、补录申请生成结果与提成费用明细。

账单状态、财务进度、订单锁定及补录申请自身的审批状态保留。费用是否被账单占用属于关联事实，不是一套新的状态机。

### R2：统一关联事实与操作限制

有效账单关联指活动账单行且所属账单未取消，草稿账单也构成占用。展示、候选查询、统计与最终写入校验保持一致。

保留已建账费用现有编辑策略、信用控制、汇率快照和单行账单换币约束。建账/取消账单后费用版本继续递增；最终占用判断在写事务内复核，不能只依赖前端或事务外查询。

各门禁保持原有业务方向：存在未建账费用阻止结案；存在已建账费用阻止相关拆票/改配等操作；自动锁定、工位统计、提成来源按各自既有规则改用关联事实。

### R3：普通费用删除

保留普通费用硬删除、组织范围、订单锁、费用版本、整批原子性及审计。有效账单占用时拒绝删除。历史账单快照不随费用删除而删除。

补录生成费用通过专用撤销处理，普通单条及批量删除入口均拒绝并提示前往补录申请撤销；不因删除状态字段绕过审批资格、倒序或冲减规则。批量中含一条不允许删除的费用时整批失败。

普通删除审计记录费用 ID、科目、方向、金额、币种、结算单位、版本与填写的原因。成功提交后按原机制触发自动锁定重新评估。

### R4：补录撤销改硬删除

专用撤销完整保留实时权限、锁依据、费用版本、批准时间倒序与冲减限制；关联调整曾确认或已扣回时仍拒绝，允许撤销时原子取消待处理调整并删除生成费用。

申请及其不可变费用快照、历史调整和审计保留。申请保持 APPROVED；申请列表明确展示「生成费用已删除」，不显示空白，也不重新引入费用状态枚举。重复撤销返回明确业务拒绝，不重复处理调整。响应不再返回已经不存在的费用实体。

### R5：Schema、迁移与开发数据

删除费用 status、cancelled_at、cancelled_by、cancellation_reason 及相关 CHECK、边、索引依赖，通过正式生成流程同步 Schema、绑定与客户端。种子和夹具以真实账单关联表达建账事实。

正式迁移不得使存量 CANCELLED 费用重新成为有效费用。迁移方案包含这些行的校验、必要审计快照与删除处置，保留历史账单、补录申请和调整。发现活动账单占用或冲减事实异常时明确失败，不自动纠正。

本任务文档不授权清空、重建或删除现有开发库数据。实施时先完成代码和专用测试库验证；应用包含数据删除的迁移前，提供实际影响清单取得明确授权。空库初始化不依赖开发库清空。

## 不在范围内

- 改造账单状态机、财务进度档位、核销/开票/对冲规则。
- 改造补录审批状态机或允许普通删除绕过补录撤销。
- 历史双读双写、兼容旧 API、通用状态平台或新的权限体系。
- 自动清空/重建开发数据库，以及不相关的前端未提交修改。

## 验收标准

- [ ] A1（R1）：所有费用入口无独立费用状态列与筛选；服务端/客户端无 OrderFeeStatus 和费用 status 字段；财务进度与账单信息正常展示。
- [ ] A2（R2）：未建账→草稿建账→确认→取消→重新建账各路径关联投影正确，草稿即占用；列表、候选和统计一致。
- [ ] A3（R2）：已建账编辑限制、换币/信用/汇率规则不变；建账与编辑/删除竞争、取消与重新建账竞争保持原子性，旧版本请求返回 409，无重复有效账单关联。
- [ ] A4（R2）：结案、拆票、改配、单据变更、主单换版、自动锁定、工位与提成消费按各自正反条件回归，不能仅抽查一个入口。
- [ ] A5（R3）：普通删除及批量删除保留现有正确性；批量失败零写入；补录费用被普通入口拒绝；历史账单快照保留且来源置空；审计内容可追溯。
- [ ] A6（R4）：补录撤销删除费用并原子处理调整；权限不足、版本过期、非最新补录、调整曾确认/扣回均拒绝；申请列表展示生成费用已删除；重复撤销无额外写入。
- [ ] A7（R5）：空库正式迁移与含已作废费用夹具的升级迁移通过；异常关联使迁移失败且不部分删除；已作废费用不复活，正常费用/历史快照不丢失。
- [ ] A8（R5）：Ent、Proto、OpenAPI、前端客户端、种子、测试和验收脚本同步；专用 PostgreSQL 集成测试实际执行，SKIP 不算通过；最终 check:fast 通过。
