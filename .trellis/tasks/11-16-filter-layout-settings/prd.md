# 统一筛选设置与布局能力

## 目标与来源

在公共层完成已批准的五项筛选布局能力及账号保存，为全站不同搜索机制提供一致适配。

父任务：[全站筛选与表头设置](../11-16-global-filter-settings/prd.md)。本子任务不独立扩大父需求。

## 需求

- 对应父 R2、R3、R6、R7：显隐、拖拽排序、单项宽度、收起数量和恢复默认，统一齿轮入口及即时自动保存。
- 布局保存字段标识和展示属性，不保存关键词／日期／候选 label 等业务值；宽度为24栅格的4/6/8/12/16/24。
- 覆盖 grid/bar/自定义独立表单/ProTable 官方搜索的适配能力，保留官方 request 数据流。
- 隐藏清除该条件并刷新，普通折叠保留条件；纯展示变更不触发查询或清空其他未提交输入。

## 验收

- 五项能力实际改变筛选区且可跨浏览器恢复，必需项不可隐藏；单字段区域入口仍可达。
- 排序作用于真实渲染而非只改变设置面板；响应式布局不横向溢出，窄屏变化不回写偏好。
- 日期范围和复合字段清除完整，chips／生效查询／页签恢复一致，读取未完成时不会误清真实查询。
- 原生Pro搜索与候选弹窗不形成嵌套form，编辑输入／选择／分配草稿按各业务规则保留。

## 前置依赖

前两个子任务完成生成 API 与前端 display-preferences Provider 后实施；先在既有财务区域验证，再交付全站接入。

## 范围外与约束

遵守父任务范围外与数据保护规则；不自动重置开发数据库、不覆盖其他会话改动、不新增兼容回退。当前为规划，随父方案审阅后按依赖激活。
