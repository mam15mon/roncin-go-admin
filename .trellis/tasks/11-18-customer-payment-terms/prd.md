# 客户收款约定收口

> 父任务：`11-18-payment-terms-due-date`。不依赖 `11-18-bill-due-date-fixed`，但建议在它之后做；
> 两个子任务都要改规范，由后完成的一方负责让 `glossary.md` 等共用规范保持一致。

## 问题（2026-11-18 已对照代码核实）

客户档案的「财务结算规则」（`PartnerSettlementRule`）有 9 个可填字段，真正参与业务计算的只有两个：

| 字段 | 是否被业务使用 |
|---|---|
| `payment_terms_days` 默认账期（天） | ✅ 建应收账单时带出「账单日 + N 天」 |
| `credit_limit_minor` + `credit_currency` 信用额度 | ✅ 应收信用额度判断 |
| `statement_mode` 对账方式（单票、汇总） | ❌ 只存不用 |
| `settlement_method` 结算方式（单票、月结、周结、半月结、双月结、季结、45 天、预付） | ❌ 只存不用 |
| `settlement_day` 每月固定结算日 | ❌ 只存不用 |
| `settlement_cycle_days` 周期天数（主档页上标作「账期 … 天」） | ❌ 只存不用 |
| `settlement_base` 起算基准（账单日、开航日、到港日） | ❌ 只存不用 |
| `settlement_currency` 结算币种 | ❌ 只存不用 |
| `is_active` 启用 | 只用于筛选，多条启用时取最大值 |

由此带来几个具体问题：

- 主档页同时有「账期：起算基准 + 天数」和「默认账期（天）」，第一个根本不生效。
- 选「月结 25 日」会让人以为系统会按 25 日算到期，实际不会。
- 一个客户角色可以有多条启用中的规则：主档页只显示列表第一条，建账却取所有启用规则里最长的账期和最大的额度，
  两边看到的约定可能不一致（`web/src/pages/partners/partner-detail.tsx` 取 `[0]`；
  `server/internal/data/finance_bill_credit.go` 的 `partnerCreditSummaries` 取最大值）。
- 供应商、国外代理角色也能填账期，甚至国外代理还能填信用额度，但这些都不会被业务使用。
- 维护入口有两个：主档详情页的「财务结算规则」分节，以及列表页侧边抽屉的「结算规则」页签。
  后者是多行表格，可以给同一角色建多条规则。

## 需求

### R1 一个客户只有一条「收款约定」
- 收款约定只属于**客户角色**（`role_type = customer`），每个客户角色最多一条，由数据库唯一索引保证。
- 约定只有两部分：
  - **收款期限**，三选一：
    - 未约定（`payment_terms_days = NULL`）；
    - 现结（`0`，当天到期）；
    - 建账后 N 天（`1–3650`）。
  - **信用额度**（公司本币，可空）。沿用现有「本币额度」口径与 `PARTNER_CREDIT_CURRENCY_MISMATCH` 校验。
- 删除字段：对账方式、结算方式、固定结算日、周期天数、起算基准、结算币种、启用状态。
  不需要约定时，就把收款期限设为「未约定」并清空额度。
- 供应商、国外代理角色不再有结算规则：界面不显示这一分节，服务端拒绝为非客户角色新建或更新规则。

### R2 档案和建账使用同一条约定
- 主档页显示的约定，就是建账时带出的约定：建应收账单时，默认账期直接取该客户唯一一条约定的
  `payment_terms_days`，信用额度取同一条的额度，不再取最大值。
- 散客口径不变：散客应收组默认账期仍硬编码为 0，不读取约定（见 `partner-casual-contract.md`）。

### R3 界面
- 主档详情页的分节标题改为「收款约定」，只在当前角色为客户时显示。内容只有：
  - 收款期限：`Radio`（未约定 / 现结 / 建账后 N 天），选「N 天」时出现天数输入；
  - 信用额度（本币）。
- 列表页侧边抽屉里的「结算规则」页签，从多行表格改成单条约定表单，字段与主档页一致（共用同一组件）；
  只对有客户角色的往来单位显示。权限仍按现有 `settlement_rule.read/create/update` 区分（零条用 create，一条用 update）。
- 新建客户的默认值为「未约定」、无额度。不再预填「月结 25 日、账期 30 天」这类默认值。

### R4 数据迁移（正式 SQL 迁移）
需要一次性把现有数据收成「每个客户角色最多一条」：
1. 删除非客户角色的规则；
2. 删除停用的规则；
3. 同一客户角色有多条启用规则时：保留最近更新的一条，并把它的账期设为该组的最大值、
   额度设为该组的最大值（这与当前建账的实际取值一致，迁移后客户的实际约定不变）；删除其余各条。
4. 删除废弃字段和旧索引，建立 `partner_role_id` 唯一索引。

> ⚠️ 迁移会删除开发库中的部分规则数据（非客户角色规则、停用规则、重复规则）。这是正式 Schema 迁移的一部分，
> 不是清库；但按 AGENTS.md，实施者在执行迁移前要向用户说明影响，取得确认后再执行。

### R5 开发种子
`pnpm run sync:dev` 只为客户角色写入收款约定（例如 30 天、50 万额度），不再给供应商写规则；可重复执行。

## 验收标准

- [ ] 客户档案「收款约定」只有收款期限（三选一）和信用额度；供应商、国外代理档案不显示该分节。
- [ ] 同一个客户角色无法建第二条约定（数据库唯一索引 + 服务端 `PARTNER_SETTLEMENT_RULE_EXISTS`）。
- [ ] 为供应商或国外代理角色新建、更新规则，服务端返回参数错误，且零写入。
- [ ] 客户约定「建账后 30 天」→ 建账预览默认账期为 30；改为「未约定」→ 预览不带默认账期；
      改为「现结」→ 默认账期为 0。主档页显示与建账带出一致。
- [ ] 散客应收组默认账期仍为 0。
- [ ] 迁移：在含「非客户规则 + 停用规则 + 同一客户两条启用规则（账期 15/45、额度 10 万/30 万）」的迁移前数据上执行，
      结果为每个客户角色一条，账期 45、额度 30 万；空库完整迁移链也能执行；`TestMigrationManifestCoversEntSchema` 通过。
- [ ] 全仓（排除生成物）不再出现 `settlement_method`、`statement_mode`、`settlement_base`、`settlement_day`、
      `settlement_cycle_days`、`settlement_currency`、`is_active`（仅指结算规则的这些字段）及其前端对应字段。
- [ ] `pnpm run sync:dev` 可以重复执行。
- [ ] `pnpm run check:fast` 通过。
