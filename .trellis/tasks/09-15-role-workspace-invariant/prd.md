# 角色库工作台归属不变量固化

## 背景

- 权限模型为「组织树 + 工作台（总部/公司）+ 角色库 + 成员关系授予」。
- 已实现（c50c8536）：部门/团队不再自建角色库，角色查询、分配、提权校验沿组织树解析到所属公司工作台；公司工作台聚合子树成员关系角色。
- 残留问题：该口径靠各查询点自觉保证——角色写入路径未走同一规则（当前仅因会话组织恒为工作台而未出错）；组织→角色库解析对组织树异常静默回退；前端复制了第二份「是否工作台」判定规则；存量可能仍有部门/团队锚定的角色。

## 目标

1. 「角色库只归属工作台（总部/公司），部门/团队共享所属公司角色库」成为数据事实与全链路强制规则，而非调用约定。
2. 所有违规与数据异常显式失败，禁止静默纠错。
3. 存量数据一次性归一，服务端/前端/测试口径一致。

## 非目标

- 不调整 data_scope 的定义级模型（scope 从角色定义移到授予列为远期项，仅记录不实施）。
- 不引入独立工作台实体（workspaces 表/外键）。
- 不合并总部与各公司的角色库（公司间隔离为既有设计）。
- 不改动现有 HTTP/gRPC 契约、权限码与前端请求结构（无生成物变更）。

## 需求

- R1 写入守门：角色创建/更新/删除的锚定组织必须是总部/公司节点；部门/团队锚点返回明确业务错误（提示如「角色只能在公司/总部维护」）。
- R2 读口径显式失败：组织→角色库解析遇到组织不存在、断链、成环时，返回组织不存在类业务错误；移除静默回退为原值的行为。
- R3 存量归一：迁移完成后不存在锚定在部门/团队的角色；同公司 code 冲突按 Q1 结论处理，不得静默丢弃配置。
- R4 前端口径统一：「是否工作台」判定收敛为单一出口（1=总部、2=公司），组织层级名展示复用它；删除枚举序号硬编码与字符串猜测分支。
- R5 规则沉淀：将「角色库归属工作台 + 部门共享 + 违规显式失败」写入 server 端 spec，供后续会话遵循。

## 验收标准

- A1 现有「部门继承公司角色」集成测试保持通过（ListRoles/GetRole/提权画像/部门成员分配）。
- A2 新增集成测试：以部门为锚点创建/更新/删除角色 → 收到 R1 业务错误。
- A3 新增测试：未知组织或断链组织查询角色 → 返回组织不存在业务错误，而非回退原值继续执行。
- A4 迁移自检：迁移完成后断言角色表不存在部门/团队锚定行，违反时迁移报错终止。
- A5 前端：`formatOrganizationHierarchyName` 定向测试通过（部门拼层级、工作台返回自身名）；修改文件 Biome 通过。
- A6 `go -C server vet ./...` 与 `go -C server test ./internal/data/` 通过；`pnpm --dir web tsc` 通过。
