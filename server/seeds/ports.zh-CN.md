# 港口中文对照数据编制说明

编制日期：2026-10-27。配套底表：`loc251csv.zip`（UN/LOCODE 2025-1）。

## 覆盖与字段

`ports.zh-CN.csv` 按标准五字码排序，包含当前解析口径的全部 **17,524** 个海港，覆盖 **232** 个国家/地区，中文覆盖率 **100%**。不增加旧行业代码、不合并同城港区，也不更改官方英文身份。

| 字段 | 含义 |
| --- | --- |
| `un_locode` | 当前 ZIP 解析后的标准代码，一码一行 |
| `name_en` | 与 ZIP 逐字一致的原始名称，用于防止错版或错配 |
| `name_zh` | 已有中文地名或本次编制的中文翻译、音译 |
| `name_kind` | `existing` 表示可追溯的已有名称；`translated` 表示本次编制或修订 |
| `source_ref` | 实体链接、字典出处或译名编制依据 |

本版有 **7,357** 条 `existing`、**10,167** 条 `translated`。`existing` 说明有中文来源，不承诺该来源是官方海港中文标准；`translated` 不代表错误或仅适用于冷门地点，未逐条取得可引用中文来源的熟悉地名也保守归入此类。

## 清洗决策与异常记录

- 海管家原调查样本按来源 ID 去重后为 142 条，其中 14 条中文位置没有汉字、7 条代码格式不符合本项目标准；50 个同码中文候选只作参考，不整体导入。空查询 100 条无总数，不能作为全量字典。
- 海管家 `MYPKE` 同时出现巴生、西港、南港等记录；爱尔兰 `VALENTIA` 与西班牙 `VALENCIA` 的中文搜索也有混淆。最终按底表代码、国家、英文身份判定，禁止按中文模糊合并。
- 上海 `CNSHG/CNSGH`、宁波 `CNNBO/CNNBG`、青岛 `CNQDG/CNQIN`、深圳 `CNSNZ/CNSZP` 按现有底表独立保留。`CNSHA/CNNGB/CNTAO/CNSZX` 等参考字典代码没有自动补入本版海港集合。
- Wikidata 一码多实体需要消歧；GeoNames 同名地点需结合行政区及坐标。不同来源的同义译法优先采用可核对到明确实体的来源；无法确定时保守编译并标注，不凭英文同名跨国传播中文结论。
- `Terminal/Wharf/Jetty` 按码头语义处理，避免译为航站楼或终点站；岛、湾、海角、南北及城市/港区区分保留。`B12`、`UTC1/UTC3`、`A/B` 等真实设施标识保留，不改成另一套编号。
- 南极条目按原名称的科考站、基地等语义命名，不一律追加“港”。底表的海港功能筛选口径本次不变，部分地点仍可能包含机场、内河设施或科考站功能。
- 日本官方表复核将 `JPUCN` 从来源候选的“内海湾”纠正为港名“内海”，并校正御崎、轻野等汉字；`JPAOM` 的官方表青森与本底表 Omi/新潟身份不一致，`JPSCH` 的新版更名及部分合并港也不自动套用，保留本版英文身份对应译名。
- `ES8TC` 的底表英文确实为 `Rejected`：中文保留音译及“原文意为已拒绝”的异常说明，没有伪造正常城市名。`CNLIJ` 的 `Lijiang/SD` 存在地理与用字疑点，暂以编译名“利江”保留并在来源说明中标记；`CNJMU` 原英文 `Jimusi` 的拼写疑点保留，中文编译为“佳木斯”。这些条目未改变代码、国家或英文。

## 同步与维护

```bash
# 仓库根目录：离线完整校验，不写库
go -C server run ./cmd/sync-unlocode

# 配置 DATABASE_SOURCE 后显式写入；根命令本身包含 -apply
pnpm run sync:unlocode

# 自定义配套版本：先预览，确认后加 -apply
go -C server run ./cmd/sync-unlocode -source /path/to/loc252csv.zip -chinese-source /path/to/ports.zh-CN.csv -release 2025-2
```

日常同步只读取 ZIP 与 CSV，不联网获取字典或调用翻译。代码集合、英文身份、中文有效性、类别与来源全部校验成功后才检查数据库。新增及同来源更新都写入中文并刷新全拼、首字母检索；重复同步保留记录 ID，其他来源同码冲突明确失败。

升级官方发布包时同步处理中文表的新增、撤销及英文更名；仅替换 ZIP 会因不配套而报错。已有名称修订不需要 Schema 迁移或前端生成。ZIP 和 CSV 摘要分别打印，`source_hash` 为两个摘要的固定格式联合指纹，中文修订也能追溯。
