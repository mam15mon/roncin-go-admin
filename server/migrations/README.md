# 数据库迁移

所有环境关闭 Ent 自动迁移，通过服务端内置迁移命令顺序执行本目录中的版本化 SQL。
执行器使用 PostgreSQL advisory lock 防止并发部署；每个文件与迁移记录在同一事务
中提交，并校验已执行文件的 SHA-256，禁止修改历史迁移。

迁移链包含冷启动基础结构和后续增量变更，可从空 PostgreSQL 数据库顺序执行。在
仓库根目录配置 `.env.local` 的 `DATABASE_SOURCE` 后执行：

```bash
pnpm run migrate:server
```

迁移不使用 `IF EXISTS` 或 `IF NOT EXISTS`，数据库结构与预期不一致时会立即失败，
由部署人员核查差异，禁止静默跳过。个别历史迁移的约束置换语句
（`DROP CONSTRAINT IF EXISTS`）属既成事实，该规则约束此后新增的迁移，不作追溯
改写。

校验和差异按环境区分处理：

- 开发环境执行 `pnpm dev` 或 `pnpm run migrate:dev`：迁移文件在应用到本地库之后
  继续修改属于正常迭代，执行器会把迁移记录的校验和重录为当前文件并打印提示后
  继续前进。重录只更新迁移记录，不会补执行文件修改对应的 DDL；若运行时报缺表
  缺列，请核对迁移差异或重建开发库。
- 生产发版执行 `pnpm run migrate:server`：保持严格校验，已执行迁移与文件不一致
  时立即失败，禁止任何自动修复。

历史迁移的正式修订仍要求验证等价，即旧库重跑与新库冷启动必须产生相同结果。
正式上线的数据库初始化是空库执行完整迁移链，不依赖任何开发期数据或迁移记录。
